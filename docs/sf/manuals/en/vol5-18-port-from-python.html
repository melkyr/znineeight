Port a Python File to Z98

This guide translates a small Python program to Z98 one idiom at a time. Python is the first language in this volume that carries none of its discipline in the source: there are no type annotations at rest, no manual memory, and no declared failures, so every convention the C and C++98 ports could read off the page has to be reconstructed and then written down. The Python original is committed at docs/sf/manuals/src/vol5/portpy/tally.py; its Z98 twin is docs/sf/manuals/src/vol5/portpy/tally.z98. It is the dynamic-language companion to Port a C File to Z98 and Port a C++98 File to Z98, and the hardest of the three to estimate, because Python's brevity hides the work the interpreter is doing at run time.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with the system python3, to run the original, and a 32-bit-capable gcc, which the emitted Z98 build script uses. The Python transcript below was measured with Python 3.11.2.
  • The repository checked out, so the two source files above are present. Every command runs from the repository root, /workspace/znineeight.
  • The language practices the port rests on: Model and propagate errors for error unions and Use the arena correctly for object lifetime. The static type system is Volume II chapter 2 and Volume IV — Types.

The idea

A Python program is short because most of its structure is implicit. A name carries whatever object it was bound to last; a dict and a list are supplied by the language; a missing key is a KeyError and an invalid state is a ValueError; and memory is reclaimed whenever the interpreter decides it is unreachable. None of those facts is written in the file, and the reader is expected to hold them in their head.

Z98 makes each of them explicit, and that is the whole port. The dynamic type becomes a declared one, the dict becomes a table you write and scan, the exception becomes a value in the return type, and the garbage collector becomes an arena over a buffer you supply and reset. The behavior is unchanged; the bookkeeping Python did for you is now on the page. The guide keeps the original and the twin side by side so the trade is visible rather than asserted.

Steps

  1. Read the Python original. It is a tally: a list of (name, quantity) rows, a dict that accumulates by key, a division that fails on an empty input, and an automatic-free lifetime. 

    # tally.py - a Python original: dynamic types, a dict and a list, an exception,
# and automatic memory. Its Z98 twin is tally.z98.
rows = [("apples", 3), ("pears", 2), ("apples", 5), ("pears", 4)]


def tally(rows):
    totals = {}
    for name, qty in rows:
        totals[name] = totals.get(name, 0) + qty
    return totals


def average(totals):
    if len(totals) == 0:
        raise ValueError("empty tally")
    return sum(totals.values()) // len(totals)


def main():
    totals = tally(rows)
    for name in ("apples", "pears"):
        print(name, totals[name])
    print("average", average(totals))
    try:
        average({})
    except ValueError:
        print("caught empty tally")


main()

    Nothing in the file says what a row is, what a key is, what average can fail with, or when the memory is released. Every one of those omissions is a line the Z98 twin has to state.

  2. Run the Python original, so you have the behavior to match. The interpreter is the system python3; there is no build step and no declared failure. 

    $ cd /workspace/znineeight
$ timeout 120 python3 docs/sf/manuals/src/vol5/portpy/tally.py
apples 8
pears 6
average 7
caught empty tally

    The four lines are the contract the port must meet: the accumulated totals in first-seen order, the integer average of the totals, and the caught failure on the empty input.

  3. Dynamic typing to static types. A Python name is a reference with no declared type; name is whatever the tuple held and qty is whatever the caller put there. Z98 states both. The row and the running total become structs with bounded integer fields: 

    rows = [("apples", 3), ("pears", 2), ...]   # Python: no element types
totals[name] = totals.get(name, 0) + qty    # name: any hashable, qty: any number

    const Row = struct { name: u32, qty: i32 };   /* Z98: both fields declared */
const Total = struct { name: u32, sum: i32 };

    The Python key is a string; the Z98 twin uses an interned integer id, which is how the compiler's own concrete hash maps key their entries. The id is turned back into a name only at the print. The type rules are Volume II chapter 2 and Volume IV — Types.

  4. Dicts and lists to a manual table and a slice. The dict is the part with no Z98 counterpart you can reach for; the language has arrays and slices, not hash tables. The twin writes the table Python supplied as a struct over a slice plus a length, and scans it linearly. The list of tuples becomes a fixed array of Row; the accumulation becomes one lookup loop: 

    def tally(rows):
    totals = {}
    for name, qty in rows:
        totals[name] = totals.get(name, 0) + qty
    return totals

    fn tally(rows: []const Row, out: []Total) Tally {
    var t = Tally{ .items = out, .len = 0 };
    for (rows) |row| {
        var found = false;
        var i: u32 = 0;
        while (i < t.len) : (i += 1) {
            const slot = t.items[@intCast(usize, i)];
            if (slot.name == row.name) {
                t.items[@intCast(usize, i)].sum += row.qty;
                found = true;
            }
        }
        if (!found) {
            t.items[@intCast(usize, t.len)] = .{ .name = row.name, .sum = row.qty };
            t.len += 1;
        }
    }
    return t;
}

    Two Python conveniences are deliberately gone. A dict lookup by key is this scan, written out; and the negative index and step slice have no Z98 form, because a slice is a pointer plus a length and its bounds are checked. The shipped samples docs/sf/manuals/src/vol2/lookup.z98 and docs/sf/manuals/src/vol2/strings.z98 are the worked versions of the found-or-absent search and of the array-to-slice view. The rules are Volume II chapter 9 and Volume IV — Arrays and Slices.

  5. Exceptions to error unions. Python signals an invalid state by raising and leaves the recovery to any frame that installs a handler. Z98 puts the failure in the function's return type, so the caller cannot ignore it and the handler is an ordinary expression: 

    def average(totals):
    if len(totals) == 0:
        raise ValueError("empty tally")     # Python: unwinds the stack
    return sum(totals.values()) // len(totals)

    fn average(t: Tally) error{EmptyTally}!i32 {
    if (t.len == 0) return error.EmptyTally; /* Z98: a value in the return type */
    var sum: i32 = 0;
    var i: u32 = 0;
    while (i < t.len) : (i += 1) {
        sum += t.items[@intCast(usize, i)].sum;
    }
    return sum / @intCast(i32, t.len);
}

    try propagates an error and catch handles one, exactly where Python wrote try/except. The shipped sample docs/sf/manuals/src/vol2/error_unions.z98 is the worked version; the mechanics are Model and propagate errors and Volume IV — Errors. One Python habit does not carry over: / in Z98 truncates toward zero where Python's // floors, so a negative operand is where the two languages disagree.

  6. Garbage collection to the arena. Python reclaims a dict or a node whenever it becomes unreachable. Z98 has no collector and no per-object free; the program allocates out of a buffer it supplies and releases the whole region in one reset. The twin takes a stack buffer, initializes the arena over it, and allocates the total table from it: 

    totals = {}                                 # Python: reclaimed when unreachable

    var buf: [4096]u8 = undefined;
var arena = std.arena.init(buf[0..]);
const raw = try std.arena.alloc(&arena, @sizeOf(Total) * 8);
const space = @ptrCast([*]Total, raw)[0..8];

    std.arena.alloc returns an error union, so exhausting the buffer is a caught error.OutOfMemory rather than a null dereference, and there is no free to forget or to call twice. The shipped sample docs/sf/manuals/src/vol2/arena.z98 measures the full surface; the guide is Use the arena correctly, and the rules are Volume IV — Memory.

  7. Read the Z98 twin. It is the whole program, and it ships at docs/sf/manuals/src/vol5/portpy/tally.z98: 

    const std = @import("std");

const Row = struct { name: u32, qty: i32 };
const Total = struct { name: u32, sum: i32 };
const Tally = struct { items: []Total, len: u32 };

fn nameOf(id: u32) []const u8 {
    if (id == 0) return "apples";
    return "pears";
}

fn tally(rows: []const Row, out: []Total) Tally {
    var t = Tally{ .items = out, .len = 0 };
    for (rows) |row| {
        var found = false;
        var i: u32 = 0;
        while (i < t.len) : (i += 1) {
            const slot = t.items[@intCast(usize, i)];
            if (slot.name == row.name) {
                t.items[@intCast(usize, i)].sum += row.qty;
                found = true;
            }
        }
        if (!found) {
            t.items[@intCast(usize, t.len)] = .{ .name = row.name, .sum = row.qty };
            t.len += 1;
        }
    }
    return t;
}

fn average(t: Tally) error{EmptyTally}!i32 {
    if (t.len == 0) return error.EmptyTally;
    var sum: i32 = 0;
    var i: u32 = 0;
    while (i < t.len) : (i += 1) {
        sum += t.items[@intCast(usize, i)].sum;
    }
    return sum / @intCast(i32, t.len);
}

pub fn main() !void {
    var buf: [4096]u8 = undefined;
    var arena = std.arena.init(buf[0..]);
    const raw = try std.arena.alloc(&arena, @sizeOf(Total) * 8);
    const space = @ptrCast([*]Total, raw)[0..8];

    var rows: [4]Row = undefined;
    rows[0] = .{ .name = 0, .qty = 3 };
    rows[1] = .{ .name = 1, .qty = 2 };
    rows[2] = .{ .name = 0, .qty = 5 };
    rows[3] = .{ .name = 1, .qty = 4 };

    const t = tally(rows[0..], space);
    var i: u32 = 0;
    while (i < t.len) : (i += 1) {
        const total = t.items[@intCast(usize, i)];
        std.io.print("{s} {}\n", .{ nameOf(total.name), total.sum });
    }
    std.io.print("average {}\n", .{ try average(t) });

    const empty = tally(rows[0..0], space);
    _ = average(empty) catch {
        std.io.print("caught empty tally\n", .{});
        return;
    };
    std.io.print("unreachable\n", .{});
}

    tally is the accumulation loop in one place; average is the same division, now able to say how it fails; main owns the one buffer that replaced the collector. The rows index each other by integer and the names are interned ids, which is what lets the whole program live without a heap.

  8. Build and run the Z98 twin, exactly as in Build a single file. The emitted gcc prints many warnings from the runtime's unused static helpers; the build is not red and the binary runs. 

    $ rm -rf /tmp/portpy_z98
$ mkdir -p /tmp/portpy_z98
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/portpy_z98 docs/sf/manuals/src/vol5/portpy/tally.z98
$ cd /tmp/portpy_z98 && timeout 120 sh build_target.sh linux tally
Building for linux...
Built: tally
$ timeout 120 ./tally
apples 8
pears 6
average 7
caught empty tally

    The compiler requires the output directory to exist, which is why the commands create /tmp/portpy_z98 first.

  9. Confirm the port by the emitted type. The failure Python described in prose — raise ValueError — is now a real return type in the generated C89: 

    $ grep -n 'average(' /tmp/portpy_z98/tally_*.c | head -1
189:zT_0DA61B72_EU_6 zF_175EB228_average(zT_851341DD_Tally t) {

    zT_..._EU_6 is the emitted error-union struct: the six-byte payload plus the error tag the caller must check. The slice type carries the table's length into the function, and the mangled name is the ordinary C symbol the linker sees. The mangling rules are in docs/reference/name_mangling.md and docs/reference/c89_emission.md.

  10. Know what a Python reader will miss. These are the conveniences with no Z98 form; each is a place a direct transliteration stalls:

    Python reaches for Z98 shape instead
    dict literals and d[key] a struct over a slice and a scan; the compiler writes its own maps the same way
    list methods (append, sort, extend) a fixed array plus a length, or the std sort/containers you call by free function
    negative indices and s[a:b:c] with a step a slice is a pointer plus a length; bounds are checked and there is no step
    duck typing and hasattr a declared type at the call site; the manual vtable if a run-time choice is truly needed
    exception hierarchies and finally a named error set with try/catch/ errdefer
    garbage collection and object graphs one arena over a buffer and its reset; no per-object release
    strings as objects (s.upper(), +) []const u8 bytes and the std string functions
    generators, decorators, and comprehensions an explicit coroutine (Write and drive a coroutine) or an ordinary loop

Verify it worked

Both programs print the same four lines and exit 0: 

apples 8
pears 6
average 7
caught empty tally

The first two lines are the accumulation: three apples plus five is eight, two pears plus four is six, printed in the first-seen order both languages preserve. The third is the average, (8 + 6) / 2 is seven. The fourth is the failure path: the empty tally reaches the raise and reports it instead of dividing by zero.

Agreement of the two outputs is the port's acceptance test. The Python version raised ValueError and the Z98 version returned error.EmptyTally, but the observable behavior is identical, and the Z98 side did it with no collector, no per-object release, and no unchecked failure. If you see all four lines from both programs, the translation holds at the two places a dynamic-language port can silently break: the keyed lookup and the failure path.

Common mistakes

  • Ignoring the error union. The Python habit of catching broadly, or of letting an exception fall through, meets a compiler that refuses a dropped result: 
    error[3015]: error union result is ignored; use 'try', 'catch', or assign the result
    Use try to propagate or catch to handle, as main does.
  • Propagating from a void function. Python can raise from anywhere; a Z98 try needs a return type that can carry the error: 
    error[3075]: expected type 'void', found error set
note: function cannot return an error
    Declare the function error{EmptyTally}!i32, not void.
  • Reaching for a dict literal. There is no hash-table literal in Z98. Write the table as a struct over a slice and the lookup as a scan, or call a std container; do not transliterate {} and d[key].
  • Expecting automatic memory. There is no collector and no per-object free. Allocate from an arena and decide where the reset goes; a Python-style object graph that outlives its region has no Z98 shape and must be re-homed.
  • Using a negative index or a step slice. A Z98 slice has no negative offset and no a:b:c step; both are Python list conveniences, not language primitives.
  • Assuming / floors. Python's // floors toward negative infinity; Z98's / truncates toward zero. They agree on the positive quantities here and diverge on a negative one.
  • Treating a string as an object. A Z98 string is a []const u8 byte view; there is no .upper(), no +-concatenation, and compared with the std string functions rather than by value.
