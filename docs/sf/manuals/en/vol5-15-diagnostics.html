Read the Diagnostics

This guide reads a compiler diagnostic: the printed ordinal, the source line and caret, the notes that name the two types, and the fix for a handful of the codes you will meet most often.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • The repository checked out, so the deliberately wrong samples docs/sf/manuals/src/vol1/errors/err1.z98 through err5.z98 and the reject fixtures under repro/mi_matrix/ are present. Every command runs from the repository root, /workspace/znineeight.
  • A POSIX shell. Diagnostics go to standard error; the shell's exit-status variable and a way to read standard error are all the tooling needed.
  • No prior guide is required. The language rules behind these messages are in Volume IV — Errors, and the full code list is Volume IV — Diagnostics.

Steps

  1. Read one diagnostic from the first line to the last. Compile a program that uses a name it never declared: 

    $ cd /workspace/znineeight
$ mkdir -p /tmp/manual_out/err1
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err1 docs/sf/manuals/src/vol1/errors/err1.z98
docs/sf/manuals/src/vol1/errors/err1.z98:7:36: error[20]: identifier 'total' is not declared or imported in this module
    std.io.print("total is {}\n", .{total});
                                    ^^^^^

    Four pieces, each with one job. The header is file:line:column: level[code]: message: the line is counted from 1, but the column is counted from 0, so column 36 is where total begins on line 7. The second line repeats the offending source line. The third line is the caret line: spaces to the column, then one ^ under every character of the span the compiler is complaining about — five carets under the five letters of total. The message says what the caret shows: nothing named total is declared here.

    The compiler reports the errors it finds and emits no program. The exit status proves it: 

    $ echo $?
2

    The fix is to use a name that exists. The only variable in err1.z98 is count; a second print of the same value should name count. If the program really wants a total, declare it (var total: i32 = 0;) and give it a value before line 7.

  2. The number in the brackets is the code the emission site attached to the diagnostic — not simply the digits in the code's name. Many sites pass the enum member's position, so anytype (named ERR_2012_ANYTYPE_NOT_SUPPORTED) prints error[16]: 

    $ mkdir -p /tmp/manual_out/anytype
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/anytype repro/mi_matrix/anytype_reject_xmod/main.zig
repro/mi_matrix/anytype_reject_xmod/main.zig:11:15: error[16]: anytype not supported in Z98
fn declOnly(x: anytype) void {}
               ^^^^^^^
repro/mi_matrix/anytype_reject_xmod/main.zig:12:13: error[16]: anytype not supported in Z98
fn called(x: anytype) void {}
             ^^^^^^^
repro/mi_matrix/anytype_reject_xmod/main.zig:13:16: error[16]: anytype not supported in Z98
fn returnsAny() anytype { }
                ^^^^^^^
repro/mi_matrix/anytype_reject_xmod/main.zig:14:18: error[16]: anytype not supported in Z98
fn nested(cb: fn (anytype) void) void {}
                  ^^^^^^^

    The 2012 is only a label on the enum member; here the compiler printed the member's position, 16. The two numbers do not track each other, and several names share a suffix. ERR_3001_UNDEFINED_SYMBOL prints error[20] (step 1), and ERR_1001_UNTERMINATED_BLOCK_COMMENT prints error[1]. But the bracket number is whatever the site passed, and some sites pass a literal numeric code instead of the ordinal: ERR_3002_INVALID_ASSIGNMENT, whose enum position is 21, is printed as error[3002], and other 30xx sites print error[3000], error[3003], or warning[3000]. So read the number as printed and match on the message; the Printed column of Volume IV — Diagnostics lists the enum-ordinal rows and omits the literal numeric codes. The four diagnostics above are one per anytype node, not four findings about one line.

  3. The first word is the level: error stops the build, warning does not. Warnings are printed at normal exit, and the program is still emitted. This compiler repro leaks eight allocations in labeled blocks and loops: 

    $ mkdir -p /tmp/manual_out/leaks
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/leaks repro/labeled_analyzer.z98
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
warning[3038]: memory leak: pointer 'p' not freed
$ echo $?
0
$ ls /tmp/manual_out/leaks/*.c | wc -l
6

    Eight warnings and exit status 0, with the program's C files written. A warning tells you the compiler found something to report but will still build what you asked. warning[3038] is WARN_6005_MEMORY_LEAK in the Reference table. Notice that these warnings print no file and line: a code raised without a source location is written as warning[N]: message with no second or third line. A warning that does carry a span prints the same four-part shape as an error, with warning in place of error.

  4. The note: lines come last and belong to the diagnostic above them. A type mismatch prints two of them, one for each side of the mismatch. Compile a type-alias value used in a value position: 

    $ mkdir -p /tmp/manual_out/alias
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/alias repro/mi_matrix/alias_value_reject_xmod/main.zig
...
repro/mi_matrix/alias_value_reject_xmod/main.zig:8:8: error[3000]: type mismatch in variable declaration -- initialization type may not be compatible with declared type
var x = A;
        ^
note: source: type
note: target: type
...
repro/mi_matrix/alias_value_reject_xmod/main.zig:17:11: error[3000]: type mismatch in return statement -- value type may not be compatible with the function return type
    return A;
           ^
note: source: type
note: target: i32
...

    The message belongs to ERR_3000_TYPE_MISMATCH; this site passed the literal code 3000 (the enum member's position is 19). The message is site-dependent, so the two notes are the part that carries the meaning: source: names the kind the expression produced, target: the kind the site required. This fixture reports six such diagnostics; the ellipses stand for the sites not shown. In the var x = A; one, a type value is being stored in a type-typed variable — a type value where a value was expected. In the return A; one, the alias A (which is i32) is returned from a function that returns i32; the compiler saw a type value, not an i32. The fix is to stop using the type name as a value: return a real i32, or remove the binding.

    The other note kind carries a position of its own. The shadowing reject ends with the location of the declaration that is being hidden: 

    $ mkdir -p /tmp/manual_out/err5
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err5 docs/sf/manuals/src/vol1/errors/err5.z98
docs/sf/manuals/src/vol1/errors/err5.z98:6:14: error[3057]: local declaration shadows an earlier declaration in an enclosing scope
        const count: i32 = 5;
              ^^^^^
docs/sf/manuals/src/vol1/errors/err5.z98:4: note: previous declaration here

    error[3057] is ERR_3057_LOCAL_SHADOW. The main caret marks the inner count; the note: points at line 4, where the outer count lives. The fix is a different name for the inner value, or an assignment to the outer var if the block meant to change it.

  5. Some notes explain the rule the site depends on. Let a try appear in a function that does not return an error union: 

    $ mkdir -p /tmp/manual_out/try
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/try repro/mi_matrix/try_return_type_reject_xmod/main.zig
...
repro/mi_matrix/try_return_type_reject_xmod/main.zig:41:4: error[3075]: expected type 'void', found error set
    try gA1();
    ^^^
note: function cannot return an error
...
repro/mi_matrix/try_return_type_reject_xmod/main.zig:61:4: error[3075]: expected error union type, found 'comptime_int'
    try 5;
    ^^^
note: consider omitting 'try'
...

    error[3075] is ERR_3075_TRY_ENCLOSING_RETURN. This fixture reports nine of them; the ellipses stand for the sites not shown. Both shown mark the three letters of try. In the try gA1(); one the function returns void, so it cannot pass an error on; the note says so. The try 5; operand is a plain integer, not an error union, and the note suggests dropping the try. The rules for error sets and try are the subject of Model and propagate errors.

  6. With that vocabulary, a diagnostic reads as a sentence. Compile each of the five shipped error samples and match the line the compiler prints: 

    $ mkdir -p /tmp/manual_out/err2 /tmp/manual_out/err3 /tmp/manual_out/err4
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err2 docs/sf/manuals/src/vol1/errors/err2.z98
docs/sf/manuals/src/vol1/errors/err2.z98:4:4: error[3014]: variable must be initialized; use '= undefined' to opt out
    var count: i32;
    ^^^^^^^^^^^^^^^
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err3 docs/sf/manuals/src/vol1/errors/err3.z98
docs/sf/manuals/src/vol1/errors/err3.z98:4:4: error[3002]: cannot assign to immutable variable
    n = n * 2;
    ^
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err4 docs/sf/manuals/src/vol1/errors/err4.z98
docs/sf/manuals/src/vol1/errors/err4.z98:3:0: error[3003]: missing return: not all control paths return a value
fn sign(n: i32) i32 {
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

    The caret width is part of the message. error[3014] (ERR_3014_USE_OF_UNDEFINED_VARIABLE) spans the whole declaration, so the fix is a starting value: var count: i32 = 0;. error[3002] (ERR_3002_INVALID_ASSIGNMENT) covers the single letter n, a parameter, which is read-only; copy it into a local var to change it. error[3003] (ERR_3003_MISSING_RETURN) spans the whole function, because the compiler followed the paths and one reaches the closing brace without a value; add the missing return.

  7. The handful you will meet most, with the code as printed, the enum name, and the fix. The names and emission sites are catalogued in Volume IV — Diagnostics; its Printed column lists the enum ordinals and omits the literal numeric codes.

    Printed Name What it means Fix
    error[16] ERR_2012_ANYTYPE_NOT_SUPPORTED anytype in a signature or type position write the concrete type the function needs
    error[20] ERR_3001_UNDEFINED_SYMBOL a name that is not declared or imported declare it, import it, or use the name that exists
    error[3014] ERR_3014_USE_OF_UNDEFINED_VARIABLE a variable with no starting value give it a value, or = undefined
    error[3002] ERR_3002_INVALID_ASSIGNMENT assignment to a const or a parameter a new local, or a var declaration
    error[3003] ERR_3003_MISSING_RETURN a path leaves a function without a value a return for the missing case
    error[3057] ERR_3057_LOCAL_SHADOW a local name hides an enclosing one a different name, or assign the outer var
    error[3075] ERR_3075_TRY_ENCLOSING_RETURN try whose set the function cannot return match the error sets, or drop the try
    error[3000] ERR_3000_TYPE_MISMATCH two types do not agree (message is site-dependent) read the source:/target: notes, fix the type
    error[2000] ERR_2000_UNEXPECTED_TOKEN the parser stopped at a token it did not expect fix the token or the grammar at the caret
    error[3058] ERR_3058_CONDITION_NOT_BOOL condition is not a bool (e.g. an error-union capture) use catch, switch, or orelse
    warning[3038] WARN_6005_MEMORY_LEAK a tracked pointer is not freed free it, or let an arena own it
    warning[3000] numeric 3000 (type mismatch) a mismatch the compiler tolerates fix the type before a later rebuild makes it an error

    Two more parser rejects worth recognising: the assignment-as-expression fixture prints error[2000]: expected ';' but found token with the caret on the second = (return a = 3;), and a copied enum tag compared against a bare literal prints error[3076]: unable to infer type of enum literal in comparison with a numeric operand. The first says assignment is a statement; the second says a copied tag compared with a bare .Circle has no type to infer — compare s.tag directly against Shape.Circle, or switch on the tag instead of copying it into a local first.

  8. Read the exit status last. It is the one-line summary the message stream does not give you: 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err1 docs/sf/manuals/src/vol1/errors/err1.z98 >/dev/null 2>&1
$ echo $?
2
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/leaks repro/labeled_analyzer.z98 >/dev/null 2>&1
$ echo $?
0

    Status 2 means errors and no program; status 0 means success, even when warnings were printed. A status 1 is the compiler reporting a problem with the invocation itself, such as an output directory that does not exist. In a build script, test the status before you test the text.

Verify it worked

The transcripts above are the captured output of those commands against the seed compiler at /tmp/manual_seed; long streams are excerpted with a ... line in the transcript. Together they prove the reading method. Step 1 shows one error's four parts and exit status 2. Step 2 shows ERR_2012_ANYTYPE_NOT_SUPPORTED printing error[16], so the bracket number is not the name's digits. Step 3 shows eight warning[3038] lines, exit status 0, and six .c files written, so a warning does not stop the build. Step 4 shows error[3000] with the note: source: and note: target: pair, and error[3057] with a located previous declaration here. Step 5 shows the rule notes on error[3075]. If your output matches, you can decode any diagnostic against the code table of Volume IV — Diagnostics.

Common mistakes

  • Reading the digits in the name as the printed code. ERR_3001_UNDEFINED_SYMBOL prints error[20], not error[3001]. The suffix is a label, and the bracket number is whatever the emission site passed — usually the enum ordinal, but sometimes a literal numeric code such as error[3002], whose member position is 21. Read the number as printed and match on the message; the Reference's Printed column lists the ordinal rows and omits the literal numbers.
  • Counting the column from 1. The line is 1-based but the column is 0-based. In step 1, column 36 is the t of total.
  • Stopping at the message. The source line, the caret width, and the notes carry as much as the text. A whole-declaration span means "start here"; a single-letter span means "this name"; source: and target: name the two types.
  • Treating a warning as a failure. Warnings print at normal exit and the program is still built; only error[N] stops the build. Check the exit status instead of scanning only for the word.
  • Assuming the compiler will guess the name. error[20] reports what is missing, not what you meant. The fix is a declaration or the existing name.
  • Fixing the caret instead of the rule. error[3014] points at var x: T;; adding = undefined silences it, but an ordinary counter should start with the value you mean.
  • Expecting a note to have a position. note: source:, note: target:, note: function cannot return an error, and note: consider omitting 'try' have none; they describe the error above them. A related-span note such as previous declaration here does carry a file and line.
