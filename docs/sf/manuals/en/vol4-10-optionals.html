Optionals

An optional type ?T is "a value of type T, or null". The literal null is the absent value and is optional-only. A plain T coerces to ?T (present); the two ways to get the payload back are orelse and a capture (if (opt) |v|, while (opt) |v|). This page is the lookup for the type, its representation, the unwrap forms, and the diagnostics that bound them.

Authority: the parser parserParseOptionalType (parser.zig:1206); the type layer and emitter (emitOptionalType, c89_emit.zig:2415); the semantic rules (orelse semantic_analyzer.zig:3530, field access :1667, value if :3609, condition and capture :5456); and the -fsafe unwrap guard (lower.zig:744, c89_emit.zig:9668). Every rule below was reproduced on the fixed compiler (md5 2794fe04e0828c95dd5c2c6fecdea362); reused fixtures are named where one exists.

The type: ?T and null

?T is the prefix ? applied to a type, so ?i32, ?*Entry, ?[]u8, and ?bool are all optionals. The payload is T, and null is the only literal the optional family introduces.

Coercion Rule (measured)
T → ?T Allowed; wraps the value as present (wrap_optional). Works at initialization, assignment, a ?T argument, and return.
null → ?T Allowed for any optional type (wrap_optional_null).
?T → ?T Allowed; an ordinary copy, present or absent.
?T → T Not implicit. A payload-position use without an unwrap is a level-1 warning[3000] type mismatch at a declaration, not a silent unwrap. 
var a: ?i32 = 42;     // T -> ?T, present
var b: ?i32 = null;   // absent
var c: ?i32 = a;      // copy
a = null;             // present -> absent

Representation: one struct, pointers included

A non-void optional is one C struct: the payload plus an int flag named has_value. There is no special case for pointers. 

typedef struct { int value; int has_value; } zT_..._Opt_...;        // ?i32
typedef struct { zT_..._T* value; int has_value; } zT_..._Opt_...;  // ?*T
typedef struct { int has_value; } zT_..._Opt_...;                   // ?void
Type @sizeOf Note
?i3284-byte payload + 4-byte flag.
?u88Size does not track payload width; alignment pads the int flag.
?bool8—
?*T8An optional pointer is not a pointer.
*T4The raw pointer, half the optional's size.
?f6416Payload is align 8; the flag floats to offset 8 and the struct pads to 16.

Measured on the fixed compiler, the size line is 8 8 8 4 16 8 for ?i32 ?u8 ?*T *T ?f64 ?bool. The uniform shape is the single rule the C89 emitter renders; it is not the official-Zig optional-pointer optimization, where an all-zero address doubles as null.

Capture: if (opt) |v| and while (opt) |v|

A capture binds the payload on the present branch. The binding is an immutable copy of the payload; advance a loop by reassigning the loop variable, never the binding. On an if, the else arm sees the absent case.

Form Meaning (measured)
if (opt) |v| ... else ...Binds v (payload type) on present; the else arm runs on null.
if (opt) |v| expr else exprValue form; the else arm is required when the result is used (see error[3059]).
while (opt) |v| ...Loops while the optional is present; ends when it becomes null.
if (opt) ... (no capture)error[3058] condition must be of type 'bool'.
if (non-opt) |v| ...error[3058] capture condition must be an optional or error union type.
assigning through |v|error[3002] cannot assign to immutable variable.
if (lookup(head, 20)) |e| {
    std.io.print("value {}\n", .{e.value});
} else {
    std.io.print("missing\n", .{});
}

const a = if (get(3)) |x| x else 0;   // value form: else is required

var cur: ?i32 = 0;
while (cur) |v| {
    sum = sum + v;
    cur = next(v);                    // reassign the loop variable
}

A capture condition must be an optional or an error union; a plain bool condition is written without bars. The value form with a capture and no else is the error[3059] case in the diagnostic index.

orelse: the fallback operator

expr orelse fallback yields the payload on the present path and evaluates the fallback on the null path. The result type is the payload type, and the fallback must produce that type or diverge. orelse is right-associative, so a orelse b orelse c is a orelse (b orelse c); its precedence is level 2, below catch (3), as listed on the grammar page.

Form Meaning (measured)
opt orelse valueValue fallback; the payload or the value.
opt orelse { ... }Block fallback; use return/break to diverge.
opt orelse unreachableAccepted; a live pal_trap() on the null path.
opt orelse return XReturn fallback; the current function exits on null.
non-opt orelse ...error[3016] orelse requires an optional operand; use 'catch' for error unions (also for an error-union operand).
var a = maybe(5) orelse 0;            // 5
var b = maybe(-1) orelse 99;          // 99
var c = maybe(7) orelse unreachable;  // 7
var d = useReturn(-1) orelse 88;      // 88 (fallback returns)
var e = useBlock(-1) orelse 77;       // 77 (fallback block returns)

The value, block, unreachable, and return fallbacks are pinned by repro/mi_matrix/orelse_optional_control_xmod (printed lines 5, 99, 7, 88, 77). The reject is pinned by repro/mi_matrix/orelse_requires_optional_xmod (rc 2, zero .c). An error union is handled with catch, never orelse.

orelse unreachable is a live trap. unreachable lowers to pal_trap(), not a no-op; a null operand terminates with SIGTRAP (exit status 133) under both -fsafe and -ffast. Pinned by repro/mi_matrix/trap_orelse_unreachable_xmod (stdout empty, rc 133). Use it only when the optional is provably present.

Fall-through block residual. A block fallback that does not diverge (no return/break/continue) leaves the orelse result reading the uninitialized join temporary. The program compiles with no diagnostic and does not trap; the result is undefined. Measured: 

var x = get(-1) orelse { std.io.print("fallthrough\n", .{}); };
// prints "fallthrough"; x is then uninitialized (measured x=-338013008,
// varying per run) -- no error and no trap.

Write a value expression (opt orelse 0) when a value is what you have, or make the block diverge ({ return 0; }), which is the useBlock path of orelse_optional_control_xmod.

.? and the unwrap trap

Z98 has no .? unwrap operator. p.? is a parser reject: 

error[2000]: expected field name or index after '.'

Direct field access on an optional is rejected too, and its message names .?: 

error[3000]: cannot access field on optional type; use .? to unwrap first

The suggestion is a spelling the parser does not implement. Under -fsafe, a payload read is preceded by the guard if (!(opt.has_value)) { pal_trap(); } (emitUnwrapOptional, lower.zig:744); on the capture and orelse paths the branch condition has already checked has_value, so that guard is redundant, and the trap a program can actually reach is orelse unreachable. The unwraps the language has are orelse, if (opt) |v|, and while (opt) |v|.

Shape Result (measured)
p.?error[2000] expected field name or index after '.'
p.x on ?Serror[3000] cannot access field on optional type; use .? to unwrap first
if (p) |v| ...Accepted; v is the payload.
p orelse dAccepted; payload or d.
p orelse unreachableAccepted; live trap on null (rc 133).

The rejected field-access shape is pinned by repro/mi_matrix/field_access_optional (rc 2, zero .c).

Assignment, null, and undefined

Shape Result (measured)
var x: ?T = v;Accepted; present.
var x: ?T = null;Accepted; absent.
x = null;Accepted; resets a present optional to absent.
x = v;Accepted; wraps an absent optional to present.
var x: ?T;error[3014] variable must be initialized; use '= undefined' to opt out.
var x: ?T = undefined;Accepted; the flag is poison and any use is undefined.
var n: T = opt;warning[3000] type mismatch in variable declaration; the payload is not unwrapped.
var x: ?i32 = undefined;   // opts out of error[3014]
if (x) |v| { ... }         // v reads the poison storage (measured v=-1431655766)

undefined is not a valid absent value. Under -fsafe the optional's storage is poison-filled, so the flag is whatever the poison bytes happen to be; compare with null or assign a real payload instead.

Optionals in signatures and structs

?T is usable in every type position: a parameter, a return type, a struct field, or a const alias. A plain T wraps at the call/return boundary, and null is a legal argument for a ?T parameter. 

const Box = struct { item: ?i32, name: []const u8 };

fn find(b: Box) ?i32 {
    if (b.item) |v| return v + 100;   // capture, then use the payload
    return null;
}
fn pick(seed: i32) ?i32 { if (seed > 0) return seed; return null; }
fn unwrapOr(o: ?i32, d: i32) i32 { return o orelse d; }

var a = Box{ .item = 7, .name = "a" };
var b = Box{ .item = null, .name = "b" };
// find(a) orelse -1 -> 107 ; find(b) orelse -1 -> -1
// pick(5) orelse 0 -> 5 ; unwrapOr(pick(-1), 42) -> 42

An optional struct field must be unwrapped with a capture or orelse before its payload is read; accessing a field through the optional itself is the error[3000] above. An optional pointer field such as next: ?*Entry is the replacement for a sentinel-terminated chain: the tail is a null the type system sees [see docs/sf/manuals/src/vol2/lookup.z98, whose while (cur) |e| walk follows ?*Entry links].

Diagnostic index

Code Message
error[2000]expected field name or index after '.' (.? does not parse)
error[3000]cannot access field on optional type; use .? to unwrap first
error[3002]cannot assign to immutable variable (assignment through a capture)
error[3014]variable must be initialized; use '= undefined' to opt out
error[3016]orelse requires an optional operand; use 'catch' for error unions
error[3058]condition must be of type 'bool'; with a capture, capture condition must be an optional or error union type
error[3059]if expression without 'else' cannot be used as a value (its type is 'void')
warning[3000]type mismatch in variable declaration (an optional bound where the payload type is declared)

For the error[3059] rule: a value if needs an else unless the condition is comptime-known true. const v = if (true) 5; compiles; const v = if (false) 5; and const v = if (get()) |x| x; both reject error[3059].
