Errors

An error set error{ Foo, Bar } is a named type whose values are error tags. An error union E!T (or the anonymous !T) is "a T, or one error from the set". The literal error.Tag is the value of one tag. This page is the lookup for the set/union syntax, the try/catch/errdefer operators and their enclosing-return rules, the error-capture printing rules, and the absence of a universal error type.

The authority is the parser (parser.zig:2185 Prec, :566-593 catch right-hand side, :869-875 try), the type layer (type_registry.zig:87 ErrorSetPayload, :665-699 error-set identity/member lookup, :1234-1247 error-union assignability, :1375-1395 errorSetIsSubset), the semantic rules (semantic_analyzer.zig:3482-3528 try, :4589-4623 error literal, :4912-4948 catch), and the emitter (c89_emit.zig:2265-2292 emitErrorSetType, :2459-2480 emitErrorUnionType). Every rule below was reproduced on the fixed compiler (md5 2794fe04e0828c95dd5c2c6fecdea362); reused fixtures are named where one exists.

Error sets: error{ ... }

A named error set is a const-bound error{ ... } declaration. The tags are the members, each a distinct value; the name is a type usable as an error-set type and as the left side of an error union. 

const MyErrors = error{ DivideByZero, Bad };
const Both     = error{ DivideByZero, Bad, Worse };

fn divide(a: i32, b: i32) error{DivideByZero}!i32 {
    if (b == 0) return error.DivideByZero;
    return a / b;
}

An error set is emitted as an int typedef plus one #define per tag (emitErrorSetType); the numeric value is the compiler-assigned global error code, not the declaration order. A qualified member access on a set that has no such tag is error[3060]: 

typedef int zT_..._E;
#define zT_..._E_Foo 1

const E = error{ Foo, Bar };
fn f() E { return E.Zzz; }
// error[3060]: no field or member function named 'Zzz' in error set type

An error set with no members (error{}) is legal and empty; it can flow through an error-union type but no error.Tag literal fits it.

Error literals: error.Tag

error.TagName is an unqualified literal. Its type is resolved from the expected type (an error set, or the set of an expected error union); the tag must be a member of that set. Assigning an error literal to any error union is the failure coercion.

Shape Result (measured)
return error.DivideByZero; in a function returning error{DivideByZero}!T Accepted; a failed error union.
return error.Nope; where the expected set has no Nope Level-0 error[3011] error literal not found in error set.
err == error.Bad inside a catch |err| Accepted; compares by tag (the same value that was returned).
@enumToInt(err) on a named-set capture Accepted; yields the tag's numeric code. 
const E = error{ Foo, Bar };
fn f() E!void { return error.Nope; }
// error[3011]: error literal not found in error set

Tags of different sets that share a spelling compare equal through the shared value; named sets with different membership still compare by tag. This is pinned by repro/mi_matrix/anon_errset_comparison (anonymous !T operand) and repro/mi_matrix/errset_cross_set_compare (anonymous into a named set, and a subset set into a superset set).

Error unions: !T and E!T

E!T names the set; !T is the anonymous form. Both are the same runtime shape. The emitter uses a C struct with a union payload/error code and an is_error flag: 

typedef struct { union { int payload; int err; } data; int is_error; } zT_..._EU_6;
typedef struct { int err; int is_error; } zT_..._EU_...;   // T is void
Coercion Rule
T → !T / E!T Allowed; the success value (wrap_error_success).
error literal → any error union Allowed when the tag is a member of the union's set (wrap_error_err).
Fs!T → Ft!T Allowed when the payload TypeId is identical and Fs is a subset of Ft (errorSetIsSubset). A narrower destination set rejects with error[3000], as does a differing payload.
anonymous ↔ named set Always treated as compatible (the opaque side is error_set == 0); an anonymous !T value may be assigned to a named union and vice versa.
!void / E!void falling off the end of the body Implicit success; no final return is required. 
const E = error{X};
const F = error{X, Y};

fn g() F!i32 { return 7; }
var a: E!i32 = 0;
a = g();            // error[3000]: E is not a superset of F
var b: F!i32 = 0;
b = a;              // accepted (E subset F, same i32 payload)

The same-payload subset path and the anonymous/named path run at runtime in repro/mi_matrix/stdlib_try_return_type_ok_xmod and repro/mi_matrix/errset_cross_set_compare. The payload-differing EU-to-EU reject is pinned by repro/mi_matrix/eu_payload_diff_reject_xmod.

try and the enclosing-return rules (FX12)

try expr unwraps an error union: on success it yields the payload; on error it returns that error from the current function. Since FX12 the enclosing function is checked, level-0 error[3075], in this order:

Prong Message (verbatim) Note
context: try at container/global scope 'try' outside function scope —
operand is not an error union expected error union type, found '<kind>' consider omitting 'try'
enclosing function does not return an error union expected type '<ret-kind>', found error set function cannot return an error
operand's set is not a subset of the function's set try error set may not be compatible with the enclosing function's return type —

<ret-kind> is the enclosing return kind (void, i32, optional, …); <kind> is the operand kind (comptime_int, void, i32, …). Each prong is deduped per try node and emits zero .c on reject. 

fn g() E!void { return error.Boom; }
fn bad1() void { try g(); }
// error[3075]: expected type 'void', found error set
// note: function cannot return an error

fn bad2() i32 { return try 5; }
// error[3075]: expected error union type, found 'comptime_int'
// note: consider omitting 'try'

const ctry = try g();
// error[3075]: 'try' outside function scope

The set comparison is set-only: payloads need not match, so an E!void operand in an E!i32 function is legal, and a named set versus an anonymous !T set always passes. A function with a non-error-union return is rejected unconditionally: the opaque !T side (error_set == 0) cannot be distinguished from an empty set, so the Zig-valid empty-inferred-set shape is a documented bounded divergence (docs/reference/Language_Spec_Z98.md §7.2).

The positive and negative contracts are pinned by repro/mi_matrix/stdlib_try_return_type_ok_xmod (stdout 41 12 11 11 13 33 77 ok) and repro/mi_matrix/try_return_type_reject_xmod (rc 2, 0 .c, 3075 9 across the four prongs).

catch: handle it

expr catch |err| fallback evaluates expr; on success the payload is yielded and the fallback is skipped; on error the tag is bound to err and the fallback is evaluated. The result type is the payload type of the operand; the fallback must produce that type or diverge.

Form Meaning
eu catch |err| expr Binds the error tag; err is typed as the union's error set.
eu catch expr Capture omitted; the fallback is evaluated on error.
eu catch { ... } Block fallback; use return/break to diverge.
eu catch unreachable Accepted; a live trap (pal_trap) on the error path.
opt orelse fallback on an error union Rejected: error[3016] orelse requires an optional operand; use 'catch' for error unions.

catch is right-associative, so a catch b catch c is a catch (b catch c). On a named set the capture is an ordinary error-set value (it prints as error.Name and compares by tag); on a bare !T union the capture keeps the numeric i32 code (a documented residual — see the printing table below). The catch forms are pinned by repro/mi_matrix/eu_err_catch and .../eu_val_catch (fallbacks on the error and success paths).

errdefer: undo on the error path

errdefer statement schedules code that runs only when the scope exits with an error; it is skipped on every success exit. Multiple errdefers run in reverse order of declaration, and an errdefer/defer pair runs the errdefer first. 

fn g() E!i32 { return error.Boom; }

fn work() E!i32 {
    errdefer std.io.print("undo\n");
    const v = try g();
    return v;
}

An explicit return error.Tag; is an error exit, and a dynamic error-union return (return x; where x: E!T, or return try x;) also runs the pending errdefer when the value is in its error state and skips it on success. This is pinned by repro/mi_matrix/stdlib_errdefer_dyn_xmod (cases varErr, varOk, callErr, callOk, voidErr, voidOk, ctrlErr, tryDyn, and the nested errdefer-then-defer order).

The body of a defer/errdefer may not redirect the scope's exit:

Inside the body Result
returnerror[3051] cannot return from defer expression
break out of the bodyerror[3052] cannot break out of defer expression
continue out of the bodyerror[3053] cannot continue out of defer expression
tryerror[3054] 'try' not allowed inside defer expression

Control flow that stays inside the body (a break/continue targeting a loop or labeled block declared inside it) is allowed.

Error-capture and error-set printing

An error-set value prints with {} as error.Name; the explicit numeric specifiers are rejected for it. The bare !T capture is the one residual shape.

Value / format Result (measured)
named-set value or capture, print("{}", .{e}) error.Name (e.g. error.Bar).
error-set value, {d} or {x} error[3013] invalid print format specifier for the argument type.
bare !T capture, print("{}", .{e}) The numeric i32 code (no set name to bind). 
const E = error{ Foo, Bar };
fn f() E!i32 { return error.Bar; }

fn show() void {
    const v = f() catch |e| { std.io.print("e={}\n", .{e}); return; };
    _ = v;
}
// e=error.Bar

The named-set capture path is pinned by repro/mi_matrix/stdlib_errset_capture_qualified_xmod (direct=error.Bar, cap=error.Bar, xcap=error.Bar) and by repro/mi_matrix/stdlib_print_enum_errset_xmod (errs error.A error.B).

No universal error type

Z98 has no anyerror and no @errorName. Both names are errors, not silently accepted types or builtins.

Shape Result (measured)
var x: anyerror = undefined; error[20] identifier 'anyerror' is not declared or imported in this module (plus error[3000] unknown type in variable declaration at the declaration).
fn f(e: anyerror) void The same error[20]: anyerror is not exempt from the signature name rule.
@errorName(e) error[3000] unsupported builtin function (@errorName is not a Z98 builtin).
anytype in a type or signature position error[16] anytype not supported in Z98, once per anytype node (Amendment A1: fn f(x: anytype), fn f() anytype, ?anytype, [*]anytype, fn (anytype) void).

Without a universal error type there is no universal name to look up: group tags by naming a set, or use the anonymous !T when the set genuinely should not be written down.

Operator precedence interactions

try is a prefix operator parsed at the prefix level (parser.zig:869-875), so it binds to the tightest following operand. catch and orelse are infix operators at the two loosest binary levels (orelse 2, catch 3; parser.zig:2185-2201), both right-associative; the full table is on the grammar page.

Written Parses as Why
try f() + 1 (try f()) + 1 try binds its operand at the prefix level, above every infix operator.
try f() catch d (try f()) catch d try consumes f() before the infix loop sees catch.
a catch b catch c a catch (b catch c) catch is right-associative.
a catch b == c a catch (b == c) catch sits below ==, so the comparison is part of the catch right-hand side.
a orelse b catch c a orelse (b catch c) Larger level binds tighter; catch (3) > orelse (2), so the catch is the orelse right-hand side.

The practical consequence: to compare a caught value, parenthesize the catch — (a catch b) == c. As measured, the unparenthesized fi(0) catch 0 == 0 types as the payload (source: i32), so binding it to bool is a warning[3000] rather than the bool comparison of the parenthesized form. 

const x = (f() catch 0) == 0;   // compare the caught result
const y = f() catch (0 == 0);   // fallback is the bool comparison

Ignoring an error union

A statement whose result is an error union may not be discarded: 

fn f() E!i32 { return error.Foo; }
pub fn main() void { f(); }
// error[3015]: error union result is ignored; use 'try', 'catch', or assign the result

The three legitimate answers are exactly the message's list: propagate (try), handle (catch), or keep it in a variable.
