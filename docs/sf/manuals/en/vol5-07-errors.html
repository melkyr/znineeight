Model and Propagate Errors

This guide declares an error set, returns a failure as an error union, propagates it with try, handles it with catch and errdefer, and gets the compiler's diagnostic when a try has no error-returning function to propagate into.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc (the emitted script uses gcc -m32 -std=c89).
  • The repository checked out, so the shipped sample docs/sf/manuals/src/vol2/error_unions.z98, the error-union fixtures under repro/mi_matrix/, and the standalone reject program repro/try_enclosing_return_reject.z98 are present. Every command runs from the repository root, /workspace/znineeight.
  • For the lookup rules behind the operators, keep the Volume IV Errors page open.

The sample

An error set error{DivideByZero} is a named type whose values are error tags. An error union error{DivideByZero}!i32 is "an i32, or one error from that set". The literal error.DivideByZero is the value of one tag. The shipped sample docs/sf/manuals/src/vol2/error_unions.z98 is the whole idea in nineteen lines: 

const std = @import("std");

fn divide(a: i32, b: i32) error{DivideByZero}!i32 {
    if (b == 0) return error.DivideByZero;
    return a / b;
}

pub fn main() !void {
    const ok = try divide(10, 2);
    std.io.printInt(@intCast(i32, ok));
    std.io.print("\n");

    const bad = divide(1, 0) catch |err| {
        std.io.print("caught: DivideByZero\n");
        return;
    };
    std.io.printInt(@intCast(i32, bad));
    std.io.print("\n");
}

divide promises, in its signature, exactly one failure: DivideByZero. try divide(10, 2) unwraps the success payload and binds ok; on an error it would return that error from the current function, so the line after it would not run. The second call does not propagate: divide(1, 0) catch |err| { ... } handles the failure where it happens and the capture err is the tag. There is no status variable and no sentinel value anywhere.

The anonymous form !T is the same runtime shape with no named set; main returns !void, so it can pass any error on. Z98 has no anyerror: errors are declared, not erased. The three ways to answer a call that can fail are try (pass it on), catch (handle it), or assign the union to a variable for later.

errdefer statement schedules cleanup that runs only when the scope leaves with an error. It is the structured replacement for a goto cleanup tail: you put the undo next to the resource it undoes, the compiler runs pending errdefers in reverse order of declaration, and it runs none of them on a success exit. An explicit return error.Tag; and a dynamic error-union return (return x; where x is an error union) are both error exits, so both run the pending errdefer when the value is in its error state.

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Create the output folder. The compiler writes its emitted tree there but will not create the folder itself. 

    $ mkdir -p /tmp/manual_out

  3. Translate the sample to C89. -o names the output folder; the last argument is the source file. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol2/error_unions.z98

    The command is silent on success. It emits one C89 pair per module, the runtime, and the companion build script.

  4. Build the executable. Run the emitted script from inside the output folder and give it the target linux and the program name error_unions. 

    $ cd /tmp/manual_out && timeout 120 sh build_target.sh linux error_unions
Building for linux...
Built: error_unions

    The generated C draws many gcc warnings; they are expected and do not stop the build, because the script does not pass -Werror. Look for Built: error_unions.

  5. Run it. 

    $ timeout 120 ./error_unions
5
caught: DivideByZero

    The first line is the successful try divide(10, 2). The second is the catch block handling divide(1, 0); the program never reaches the printInt(bad) line after the catch, because the block diverges with return. The program exits with status 0.

  6. Check the errdefer contract against the committed fixture. The fixture pins five cases: an explicit return error.Boom, a conditional explicit error return, a try propagation, a catch |err| { return err; } re-raise, and a plain successful return. The standard-library gate emits the fixture, links it through build_target.sh, runs it three times, and diffs the result byte-for-byte against the committed expected.txt and expected.rc. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_errdefer_xmod
== std-lib runtime gate ==
   zig1: /tmp/manual_seed/zig1_5_clean
PASS repro/mi_matrix/stdlib_errdefer_xmod
----------------------------------------
run_fixtures: 1 PASS / 0 FAIL over 1 dirs
STDLIB GATE OK

    The fixture's nine-line transcript is direct-undo, direct-caught, cond-undo, cond-caught, try-undo, try-caught, errvar-undo, errvar-caught, done. The success-undo line is absent on every run: errdefer did not fire on the successful exit.

  7. Check the dynamic error-union return. Returning an error-union value (return x; or return g();) has no static error literal to classify, so the compiler inspects the value at run time and runs the pending errdefer only when it is in its error state. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_errdefer_dyn_xmod

   zig1: /tmp/manual_seed/zig1_5_clean

STDLIB GATE OK

    Across twenty-one lines, every error case prints undo before its -caught line and every success case prints its payload (42, 7, voidOk-ok, 9) with no undo. The nested case prints nested-errdefer before nested-defer: the errdefer runs first on the error exit, in reverse order of declaration.

  8. Check that an error-union-to-error-union coercion with the same payload is legal. Widening a subset set into a superset set (F!i32 into E!i32, with F a subset of E) is accepted and runs the errdefer on the error arm only. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_eu_samepayload_xmod
== std-lib runtime gate ==
   zig1: /tmp/manual_seed/zig1_5_clean
PASS repro/mi_matrix/stdlib_eu_samepayload_xmod
----------------------------------------
run_fixtures: 1 PASS / 0 FAIL over 1 dirs
STDLIB GATE OK

    The six-line transcript is undo, ederr-caught, 7, noederr-caught, 7, done. The tag is checked with if (c != error.Boom), so the widened set preserves the tag value, not just the payload. A destination set that is not a superset, or a different payload type, rejects with error[3000].

  9. Meet the enclosing-return rule. try already returns the error from the current function, so the compiler checks that the enclosing function can actually carry it. The standalone reject program combines all four prongs; run the compiler directly and read the diagnostics (no program is built). 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out repro/try_enclosing_return_reject.z98
repro/try_enclosing_return_reject.z98:21:4: error[3075]: expected type 'void', found error set
    try g();
    ^^^
note: function cannot return an error
repro/try_enclosing_return_reject.z98:25:4: error[3075]: expected type 'i32', found error set
    try g();
    ^^^
note: function cannot return an error
repro/try_enclosing_return_reject.z98:34:4: error[3075]: try error set may not be compatible with the enclosing function's return type
    try gE2();
    ^^^
repro/try_enclosing_return_reject.z98:38:4: error[3075]: expected error union type, found 'comptime_int'
    try 5;
    ^^^
note: consider omitting 'try'

    The command exits with status 2 and emits no .c file. The four messages are the four prongs, in order: the enclosing function does not return an error union (a1, a2); the operand's set is not a subset of the function's set (a3); and the operand is not an error union at all (a4). A fifth prong, 'try' outside function scope, fires for a try at container scope. The fix is always in the signature: make the enclosing function return the union (or a superset), or replace try with catch.

  10. Confirm the rule is reject-only. The positive control exercises every legal shape — same set, superset set, anonymous operand and signature, E!T from E!void, if/switch values, a nested block, a local error-union variable, and a !void fall-off — and must stay accepted and runtime-correct. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_try_return_type_ok_xmod
== std-lib runtime gate ==
   zig1: /tmp/manual_seed/zig1_5_clean
PASS repro/mi_matrix/stdlib_try_return_type_ok_xmod
----------------------------------------
run_fixtures: 1 PASS / 0 FAIL over 1 dirs
STDLIB GATE OK

    Its nine-line transcript is 41, 12, 11, 11, 13, 33, 77, ok. The set comparison is set-only: payloads need not match, so an E!void operand in an E!i32 function is legal. The block-bodied catch re-propagation shapes are pinned separately by repro/mi_matrix/catch_ret_err_*.

Verify it worked

The two-line error_unions transcript in Step 5 is the recorded measured output of docs/sf/manuals/src/vol2/error_unions.z98; running the four commands in Steps 2–5 reproduces it exactly and exits with status 0. Steps 6–8 are the second half: three committed standard-library fixtures pass byte-for-byte, pinning errdefer on every error exit and none on a success exit, the dynamic error-union return path, and the same-payload widening coercion. Step 9 shows the enclosing-return rule reject with four level-0 error[3075] messages and no output file; Step 10's positive control shows that every legal try shape stays accepted.

Common mistakes

  • Ignoring an error union. A statement whose result is an error union and is discarded is rejected: error[3015]: error union result is ignored; use 'try', 'catch', or assign the result. There are exactly three answers: pass it on, handle it, or keep it in a variable.
  • Reaching for orelse. orelse belongs to optionals (?T), not to error unions. Asking it to handle one is rejected: error[3016]: orelse requires an optional operand; use 'catch' for error unions.
  • Propagating into a function that cannot return an error. A try in a void (or otherwise non-union) function is rejected with error[3075]: expected type 'void', found error set and note: function cannot return an error; a set the function did not promise is rejected with error[3075]: try error set may not be compatible with the enclosing function's return type; and a try on a non-union is rejected with error[3075]: expected error union type, found 'comptime_int' and note: consider omitting 'try'. Fix the signature or use catch.
  • Naming anyerror. There is no universal error type. anyerror is not in the token set, so naming it is error[20]: identifier 'anyerror' is not declared or imported in this module; the companion @errorName is an unsupported builtin (error[3000]). Name a set, or write the anonymous !T.
  • Redirecting the exit from cleanup. A defer/errdefer body runs while the scope is being left, so it may not redirect that exit: return in the body is error[3051], and try in the body is error[3054] (propagating from cleanup would replace the error already on its way out). Control flow that stays inside the body is fine.
  • Expecting errdefer on success. An errdefer runs only on an error exit; the success cases in the Step 6 and Step 7 fixtures deliberately print no undo line. If you need undo on both paths, use defer; if you need it next to the resource, use errdefer and let reverse order do the unwinding.
  • Assuming reset-style cleanup frees memory. An errdefer only calls the code you wrote; it has no allocator magic. The arena undo discipline is the subject of the previous guide.
