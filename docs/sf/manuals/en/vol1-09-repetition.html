Doing Things Repeatedly

The last chapter gave the program a choice; it could take a different path for each kind of input. It still did every step once. This chapter gives it repetition. It adds the while loop, which repeats a block as long as a condition holds; the for loop, which walks a range of numbers; and the two words that change a loop's path from inside, break and continue. After this chapter a program can do a small job any number of times, which is the thing computers are actually for.

The program

const std = @import("std");

pub fn main() void {
    var countdown: i32 = 3;
    while (countdown > 0) {
        std.io.print("countdown {}\n", .{countdown});
        countdown = countdown - 1;
    }
    std.io.print("liftoff\n", .{});

    var total: usize = 0;
    for (0..10) |n| {
        total = total + n;
    }
    std.io.print("sum of 0..10 is {}\n", .{total});

    var odds: usize = 0;
    for (0..10) |n| {
        if (n % 2 == 0) {
            continue;
        }
        odds = odds + n;
    }
    std.io.print("sum of odd numbers in 0..10 is {}\n", .{odds});

    var stop: i32 = 0;
    while (true) {
        stop = stop + 1;
        if (stop == 4) {
            break;
        }
        std.io.print("checking {}\n", .{stop});
    }
    std.io.print("stopped at {}\n", .{stop});
}

It does four things. It counts down from 3 with a while loop, printing each value, and then prints liftoff. It adds the numbers in the range 0..10 with a for loop, which gives 45. It walks that range again and uses continue to skip the even numbers, leaving the sum of the odd numbers, 25. Finally it runs a while (true) loop and uses break to stop at 4. Each of those is a separate piece of the chapter.

Repeating while a condition holds

A while loop tests a condition and runs its block for as long as the answer stays yes: 

var countdown: i32 = 3;
while (countdown > 0) {
    std.io.print("countdown {}\n", .{countdown});
    countdown = countdown - 1;
}

The condition is the same kind of question an if asks, and it must be a bool. The difference is what happens when the answer is yes: the if block runs once, while the while block runs and then the condition is asked again. The program prints 3, 2, and 1, and then the question countdown > 0 is false at last and the loop ends. Execution moves to the next statement after the loop, which prints liftoff.

Two facts control every while loop. The condition is tested before the first pass, so a condition that is already false means the block never runs at all. And something inside the block must move the loop toward that false answer; here it is the line countdown = countdown - 1;. Remove that line and the question stays true forever, which is the first mistake below.

Note. The braces around the loop body are optional when it holds a single statement, exactly as they are for if. The manual writes them anyway, for the same reason: they make the extent of the loop visible at a glance.

Walking a range with for

Counting with a while loop means writing three parts by hand: a variable to count with, a condition to test it, and a line that changes it. The for loop packages all three when the values to visit are a range of numbers: 

var total: usize = 0;
for (0..10) |n| {
    total = total + n;
}

Read the first line as "for each n in the range 0 up to 10". A range is written start..end, and the two dots mean up to, but not including, the end. 0..10 therefore visits ten numbers: 0 through 9. The name between the vertical bars, n, is the capture: a fresh, read-only name that holds the current number on each pass. The body adds it to the running sum, so the total is 0 + 1 + 2 + ... + 9, which is 45.

The capture is a count: it holds the current number of the walk, and it is never negative. The program keeps its two running totals in usize, the count type from chapter 6, which is the natural home for a number built by counting. The same for shape also walks arrays and slices, which arrive in a later chapter; here the iterable is always a range.

The range end does not have to be a literal. A variable of an integer type works just as well, as long as the name resolves — that is, as long as you declared it before the loop: 

var limit: usize = 10;
var total: usize = 0;
for (0..limit) |n| {
    total = total + n;
}

Leaving early and skipping ahead

Two words change a loop's path from inside its body. break ends the loop immediately, and execution continues at the first statement after it. continue ends only the current pass, and execution jumps to the next pass of the same loop: 

var stop: i32 = 0;
while (true) {
    stop = stop + 1;
    if (stop == 4) {
        break;
    }
    std.io.print("checking {}\n", .{stop});
}

The condition true is always yes, so this loop has no natural end; the break is the only way out. On the first three passes the test stop == 4 is false, and the loop prints checking 1, checking 2, and checking 3. On the fourth pass stop is 4, the break runs, and the print inside the loop is skipped. The program then prints stopped at 4, which is why the output has the pattern it does.

The second for loop uses continue to skip the even numbers: 

for (0..10) |n| {
    if (n % 2 == 0) {
        continue;
    }
    odds = odds + n;
}

When n is even, n % 2 is 0 and the continue runs; the rest of the body, the addition, is skipped for that pass and the loop proceeds to the next n. Only the odd numbers 1, 3, 5, 7, and 9 are added, so odds is 25. A while loop accepts both words in exactly the same way.

When loops are nested, either word can name an outer loop. You name a loop by writing label: in front of it and then break :label or continue :label to choose it. The program keeps to single loops, but here is the shape: 

outer: for (0..3) |i| {
    for (0..3) |j| {
        if (j == 2) {
            continue :outer;
        }
        std.io.print("{} {}\n", .{i, j});
    }
}

It prints six pairs: (0, 0), (0, 1), (1, 0), (1, 1), (2, 0), and (2, 1). Each time the inner walk reaches 2, continue :outer abandons the rest of the inner walk and moves straight to the next value of the outer loop. Without the label, a plain continue would only skip that one inner pass.

Building and running it

The commands are the ones from the last three chapters, with count in place of classify. The compiler is still at /tmp/manual_seed, built in chapter 4: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/count.z98
$ cd /tmp/manual_out && sh build_target.sh linux count
Building for linux...
Built: count
$ ./count
countdown 3
countdown 2
countdown 1
liftoff
sum of 0..10 is 45
sum of odd numbers in 0..10 is 25
checking 1
checking 2
checking 3
stopped at 4

Read the output against the source. The first three lines are the countdown; the fourth is the statement after the loop. The fifth line is the range sum: 45, not 55, which is the visible proof that 0..10 stopped before 10. The sixth is the odd-only sum. The last four lines are the break loop: three values were printed inside the loop and the fourth ended it. The program exits with status 0, because reaching a loop's end is not an error.

Common mistakes

These are the mistakes a first loop attracts. Two of them are silent; two are reported by the compiler.

The loop that never ends. A while loop stops only when its condition turns false, and only the body can turn it false. This loop prints the digit 0 forever: 

var i: i32 = 0;
while (i < 5) {
    std.io.print("{}\n", .{i});
}

The condition tests i, but nothing in the body changes i, so the question is true on every pass. The program never reaches the statement after the loop and never exits; you have to stop it yourself (Ctrl-C in the Linux shell, or closing the window under Windows 98). The branch in the countdown loop, countdown = countdown - 1;, exists precisely so that the condition can become false. When a while loop misbehaves, look first for the line that changes what the condition tests.

Expecting 0..10 to include 10. The two dots are half-open: the end is not visited. for (0..10) walks 0 through 9, and the program's total of 45 proves it: the inclusive sum 0 + 1 + ... + 10 would be 55. This off-by-one is the most common range mistake. To add the numbers 1 through 10, write the end one past the last value you want: for (1..11). A useful habit is to say the range out loud as "from the start, up to but not including the end".

Assigning to the capture. The capture is read-only, exactly like a const. The compiler rejects an assignment to it by name: 

capture_mistake.z98:5:8: error[3002]: cannot assign to immutable variable
        n = n + 1;
        ^

The caret points at the capture. If a pass needs a number it can change, keep that number in a var declared before the loop and update it in the body, the way total and odds are updated. The capture also lives only inside the loop body; naming n after the loop ends is the same "not declared" error the next mistake shows.

A range end that has to resolve. The end of a range may be a variable, but it must be one that exists. Here the name limit was never declared, so the compiler cannot know where the walk stops: 

range_mistake.z98:5:12: error[20]: identifier 'limit' is not declared or imported in this module
    for (0..limit) |n| {
            ^^^^^

The caret points at the name, and the message is the same "not declared" error from chapter 6. Declare the end before the loop (var limit: usize = 10;), or write the number you mean directly. This is also what you see when the end is misspelled: the compiler resolves names exactly, and it has no way to guess which name you meant.

Check yourself

Answer these before moving on. The last three ask you to change the program and run it.

  1. When is the condition of a while loop tested, and how many times does the body run if the condition is false the first time?
  2. What does break do, and what does continue do? How do they differ?
  3. Which numbers does for (0..10) visit, and how many are there?
  4. Why is total declared usize and not i32?
  5. Why must the countdown loop contain countdown = countdown - 1;? What happens without it?
  6. How does continue :outer in the labeled example differ from a plain continue?
  7. Change the sum loop from 0..10 to 1..11, rebuild, and run it. What total is printed now, and why?
  8. Change stop == 4 to stop == 7, rebuild, and run it. What is the last line of output, and how many checking lines are printed? What happens if you change it to stop == 0?
  9. Add a third for loop over 0..10 that adds only the even numbers, using continue when n % 2 != 0, and prints the sum. What do you expect the sum to be before you run it?
