Your First Program

This is the smallest complete Z98 program. It is not a sketch or a fragment: it is a whole program that you type into a file, build, and run, and it prints one line. Everything later in the manual is built from pieces like this one, so it is worth reading every character of it before you type it.

The program

const std = @import("std");

pub fn main() !void {
    std.io.print("Hello from Z98!\n");
}

That is the whole file. It is five lines. The blank line between the import and the function is for the reader; the compiler does not care about it.

What the lines mean

Read the program one line at a time. Nothing here is decoration; every token has a job.

const std = @import("std");

const introduces a name whose value cannot be reassigned. The name is std, and the value is whatever follows the equals sign.

@import is a builtin, one of the names that begin with an at sign. It takes a string and resolves it to a module. @import("std") resolves to the standard library that ships with the compiler, so you do not copy library files into your own folder. The library is a set of modules gathered behind one name — io, arena, str, mem, math, debug, net, async, bits, os, time, and buf.

std is the name you use for the library in the rest of the file. You could call it something else, but std is the convention and the name every other Z98 program uses. The semicolon ends the declaration.

pub fn main() !void {

fn starts a function declaration. main is its name, and main is special: the compiler looks for a public function of that name and wraps it in the C int main that the operating system calls. Every program has exactly one.

pub makes the function visible outside its own module. It is not optional for main. Without it the compiler emits an ordinary private function and no C main at all, and the final link step fails with undefined reference to 'main'.

The empty parentheses mean the function takes no arguments.

!void is the return type, and it is written as punctuation rather than a word. void means "no value": the function returns nothing to its caller. The ! in front makes it an error union: the function either finishes normally (the void case) or stops with an error. A later chapter in Volume II takes error unions apart; for now read !void as "this function may fail, and this program does not." A function that returns !void and reaches its closing brace is treated as having succeeded, so main needs no return at the end. (main may also return plain void when it cannot fail; the manual uses !void because a real program can.)

The opening brace begins the body. Everything indented under it is what main does.

std.io.print("Hello from Z98!\n");

std is the name imported on the first line. .io selects the input/output module inside it, and .print selects the function that writes text. The dots are member access: read the whole call as "the print function in the io part of the standard library."

The string in the parentheses is the text to write. A string is enclosed in double quotes. Inside it, a backslash begins an escape: \n is a single newline character. It is one character in the program, not a backslash followed by an n. Without it the program's output would not end with a line break, and the shell prompt would appear immediately after the exclamation mark.

The semicolon ends the statement. Z98, like C, uses the semicolon to mark where one statement stops and the next begins.

print is special in Z98. With nothing to show it takes just the string, as here. When there are values to show, it also takes a tuple of arguments, and the compiler fills the format string in for you: 

std.io.print("count: {}\n", .{n});

The {} is a placeholder; .{n} is a one-element tuple holding the value to put there. The supported placeholders are {} and {d} for decimal, {x} for hexadecimal, {c} for a character, and {s} for a string. This first program has nothing to substitute, so the string is all it needs.

The closing brace

The last line's } closes the body of main that opened after !void. Braces come in pairs, and the compiler refuses a file whose braces do not balance.

Building it

Chapter 4 built the compiler from the committed seed and left it at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If you have not done that yet, do it now, from the repository root: 

bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed

The compiler is not an interpreter: it does not run your .z98 file directly. It translates the file to C89, and you compile that C with the C compiler already on the machine. Two steps, then a third to run the result: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/hello.z98
$ cd /tmp/manual_out && sh build_target.sh linux hello
Building for linux...
Built: hello
$ ./hello
Hello from Z98!

Read the transcript left to right:

  • mkdir -p /tmp/manual_out creates the output folder. The compiler requires the folder to exist already; it will not create it for you.
  • zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/hello.z98 translates hello.z98 into C89 and writes a self-contained tree of files into /tmp/manual_out. Among them are the generated C, a copy of the runtime, and a build script named build_target.sh.
  • sh build_target.sh linux hello runs that script. It invokes gcc -m32 on the generated C, links the runtime, and produces an executable named hello. The Building for linux... and Built: hello lines are the script's own report.
  • ./hello runs the program, and it prints its one line.

The generated C draws a long list of warnings from gcc. They are expected, and the emitted script does not pass -Werror, so they do not stop the build. A successful build ends with Built: hello; the warnings scroll past above it.

Talking to the standard library

The one interesting call is std.io.print. Its job is to write text to standard output, the stream the terminal shows. The shipped declaration is a C-style variadic function, std.io.print(s: [*]const c_char, ...) void, but the compiler treats a call to a function named print as a special case: it reads the format string at compile time and emits one small print for each placeholder, so no runtime format machinery is needed on a 1998 machine.

Honest note. print is a compiler special case, not an ordinary variadic function you could write yourself. The language has no anytype and no generics, so a user-defined function cannot accept a variable number of arguments; only the compiler can. That is why the format string has to be a literal the compiler can read, and why the arguments have to be a tuple.

That is also why the argument after the format string is a tuple. It is the only variadic form Z98 supports. A later chapter in Volume II covers the format string in full.

Common mistakes

These are the mistakes a first program attracts. Each one has a symptom you can recognize.

Forgetting the import. If you leave off const std = @import("std"); and write std.io.print(...) anyway, the compiler does not know the name std and says so: 

hello.z98:2:4: error[20]: identifier 'std' is not declared or imported in this module
    std.io.print("Hello from Z98!\n");
    ^^^

The caret points at the first use of the missing name.

Forgetting pub on main. The compiler accepts fn main() !void, but it emits a private function and no C main. The failure comes later, from the linker, not from Z98: 

...
(.text+0x1e): undefined reference to `main'
collect2: error: ld returned 1 exit status

If the link fails with that message, check the first word of the main declaration.

Leaving off the closing brace. A file that opens a brace and does not close it is rejected before any C is written: 

hello.z98:5:0: error[2000]: expected '}' but found token
hello.z98:5:0: error[2000]: unexpected token

The compiler names the end of the file as the place it expected the brace. Count the braces in the function; they must balance.

Forgetting \n. This one is not an error at all, which is why it is easy to miss. The program still builds and runs, but its output has no line break, so the shell prompt is printed immediately after the exclamation mark. If your transcript looks wrong, look at the end of the string first.

Check yourself

Answer these before moving on. The last one asks you to change the program and run it.

  1. What does @import("std") do, and where does the compiler find the standard library?
  2. Why does main need pub? What fails if it is missing, and at which step?
  3. What does !void mean, and why does main not need a return at the end?
  4. What is \n, and what changes if you remove it?
  5. Change the string to "Goodbye from Z98!\n", rebuild, and run it. Then add a second std.io.print line that prints your name on its own line.
