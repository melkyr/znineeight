Contribute

This guide maps the repository, states the edit and verification conventions a change must follow, explains the seed and amendment protocol that governs the compiler, and prepares a patch: the files to stage, the output that proves it, and the commit shape the project uses.

Prerequisites

  • The repository checked out at /workspace/znineeight and git. This guide ships no program; it is a repository task.
  • Build the Static Site, which introduces the two halves of the documentation pipeline (check.sh and the search-index regeneration) used as this guide's verification.
  • The contributor guidelines in docs/sf/AGENTS.md, which carry the repo layout, the seed model (§9.4), and the edit discipline (§X.3, §X.7), and the manual's own contributor guide docs/sf/manuals/README.md.
  • The HTML contract every page obeys, on Volume IV — HTML style.

The idea

The repository is one tree. The compiler is sf/src, written in Z98 and compiled by the bootstrap zig0 or rebuilt from the committed seed; the specifications are docs/sf; the language and ABI reference is docs/reference; the manual you are reading is docs/sf/manuals; the reproduction fixtures are repro/; the example programs are examples/z98; the helper scripts are scripts/; and the reference compiler seed is release/seed.

A contribution is a small, verified change, and two rules frame it. First, edits are made by hand: a single controlled edit or fastedit at a time, never an unattended text transform. Second, every claim is verified before it ships — a documentation change against the manual's checker and search index, a compiler change against the seed's fixed point. Compiler source is special: it is staged through the committed seed, and a change to it is admitted only by an operator-ruled amendment.

Steps

  1. Read the tree layout. The layout is documented in docs/sf/AGENTS.md; confirm it from the root: 

    $ cd /workspace/znineeight
$ ls -d sf scripts repro release docs examples
docs
examples
release
repro
scripts
sf
$ ls sf
build
docs
lib
scripts
src
tests

    Each top-level directory owns one thing:

    • sf/src — the compiler, written in Z98. main.zig is the entry point; lexer.zig, parser.zig, the type and analysis modules, lower.zig, and c89_emit.zig are the pipeline stages described in docs/sf.
    • sf/tests — the compiler's test binaries; sf/scripts — the release/test build scripts.
    • docs/sf — the design documents, AGENTS.md (the binding contributor rules), and QUICK_REF.md (the operational recipes).
    • docs/reference — the language and C89-emission reference.
    • docs/sf/manuals — the source of this manual.
    • repro/ — reproduction fixtures; repro/mi_matrix/ holds the large pinned corpus of green and reject cases.
    • examples/z98 — the canonical example programs.
    • scripts/ — the helpers: seed/, corpus/, stdlib/, win32_cross/, closeout/.
    • release/seed — the committed zig1-seed.tgz and its rotation changelog.

  2. Keep edits manual. Change source and pages one controlled edit at a time. Use the edit tool with an exact old/new pair, or the fastedit tool with a line range; re-read the target region immediately before each fastedit and edit bottom-to-top so line numbers stay valid. Regular-expression text transforms (sed, Python str.replace, bulk scripts) are prohibited because they corrupt newlines, string literals, and multi-line structures and cannot be reverted without discarding real work (see docs/sf/AGENTS.md §X.3 and §X.7). Run every binary under a timeout so a hung tool cannot stall the session: 

    $ timeout 120 ./sf/build/zig1 --test

  3. Verify a change before you ship it. The manual's gate and its generated search index are the two checks for a documentation change. The gate parses every page and fails nonzero on the first broken link, missing rel, wrong charset, forbidden tag, orphan figure, or CSS dependency; the search index must match a fresh regeneration byte for byte: 

    $ bash docs/sf/manuals/check.sh
check.py: OK - 112 HTML pages, links, rel, lang, forbidden list, figures, no-CSS baseline
$ bash /tmp/z98_build_tmp.sh
build_tmp: indexed 109 pages, copied 151 files to /tmp/z98_dist_tmp
$ diff /tmp/z98_search-data.regen.js docs/sf/manuals/en/search-data.js
$

    A silent diff exits zero and means the shipped docs/sf/manuals/en/search-data.js is the current generation. If it differs, copy the regenerated file over and re-run the gate; never hand-edit the index. For a change to the compiler, the verification is the seed's two-hop closure instead (step 4). Do not re-run an existing recorded result unless it is suspicious or contradicts the tree: the reuse-first rule prefers the measured artifact already in the corpus, and a new transcript is captured only for a step that has none.

  4. Respect the seed and amendment protocol. The reference compiler is not built from zig0; it is rebuilt from the committed seed, and the compiler source may only use constructs that seed already compiles. The seed lives under version control with its provenance: 

    $ ls release/seed
CHANGELOG.md
zig1-seed.tgz
$ FIXED_POINT_MD5=0b8c3e4ac0b1fc49c0bdf8caf9d39945 \
    bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed
...
=== [seed] Done: /tmp/manual_seed ===

    The result is /tmp/manual_seed/zig1_5_clean plus its lib/, and the closure gate proves the rebuilt compiler reproduces the recorded fixed point 0b8c3e4ac0b1fc49c0bdf8caf9d39945 (docs/sf/AGENTS.md §9.4; the seed archive is rotated only at a plan closeout, and only if an amendment moved the fixed point). Three consequences govern a compiler contribution. A real defect found while verifying a step stops the task: report the minimal reproduction, do not patch sf/src around it, and do not re-scope the work. A compiler change enters only as an operator-ruled amendment: a read-only investigation task followed by a fix task that adds a repro/mi_matrix/ fixture and a standalone repro/ program and runs the gate battery verbatim. And only those amendment tasks may touch sf/src, scripts/, repro/, or release/seed/.

  5. Prepare a patch. Stage only the files the change owns and write the commit subject the project expects. Inspect before staging — the working tree carries build leftovers and scratch files that must stay out of the commit: 

    $ git status --short
$ git diff

    Add the intended paths explicitly rather than the whole tree, then commit with the task's exact subject. A guide task, for example, stages its new page, the new link in every shipped page's sidebar, the toc.html entry, the index entries, vol5-21-static-site.html's new next, and the regenerated search-data.js: 

    $ git add docs/sf/manuals/en/vol5-22-contribute.html
$ git add docs/sf/manuals/en/vol5-*.html docs/sf/manuals/en/toc.html
$ git add docs/sf/manuals/en/search-data.js
$ git commit -m "docs(manual): add Volume V guide 22 — contribute"
$ git log --oneline -3
236ccf26 docs(manual): add Volume V guide 21 — build the static site
aa0c3efa docs(manual): add Volume V guide 20 — build a translated manual
c927f370 docs(manual): add Volume V guide 19 — pack for a diskette

    Do not commit build outputs (*.o, stray *.z98, compiler .c/.h dumps), the mnemoria/ or .opencode/ stores, or unrelated fixes, and do not push unless asked. The commit is the patch.

Verify it worked

A documentation patch is ready when the gate is green, the regenerated index is byte-identical to the shipped one, and the diff contains only the files the change owns: 

$ cd /workspace/znineeight
$ bash docs/sf/manuals/check.sh
check.py: OK - 112 HTML pages, links, rel, lang, forbidden list, figures, no-CSS baseline
$ bash /tmp/z98_build_tmp.sh
build_tmp: indexed 109 pages, copied 151 files to /tmp/z98_dist_tmp
$ diff /tmp/z98_search-data.regen.js docs/sf/manuals/en/search-data.js
$

The gate walked 112 pages with no broken link, missing rel, wrong charset, forbidden tag, orphan figure, or CSS dependency; the generator indexed all 109 English pages and copied the tree into /tmp/z98_dist_tmp, leaving dist/ untouched; and the silent diff confirms the index is current. The committed diff should contain only the guide page, the sidebar and toc.html links, the index entries, the neighbouring rel/footer, and en/search-data.js. Any other path is either a build leftover to discard or scope that does not belong in this patch.
