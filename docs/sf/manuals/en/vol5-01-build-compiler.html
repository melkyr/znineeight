Rebuild the Compiler from Seed

This guide rebuilds the reference compiler zig1 from the committed seed archive and checks that the two-hop build closes on the recorded fixed point.

Prerequisites

  • A Linux host with bash and a 32-bit-capable gcc (the build uses gcc -m32 -std=c89).
  • The repository checked out with the committed seed release/seed/zig1-seed.tgz (current seed v91) and the script scripts/seed/build_from_seed.sh present.
  • Every command runs from the repository root, /workspace/znineeight. No zig0 is needed: this is the zig0-independent rebuild path, and gcc alone builds it.

What the seed build is

zig0 is retired. The only supported way to rebuild zig1 is from the rotating seed: the archive release/seed/zig1-seed.tgz holds a reference compiler binary, its self-emission C89, its runtime, and the standard library. The build script runs that reference compiler over the current sf/src to produce a new compiler, then does it a second time and checks that the two builds are byte-identical. That is the two-hop closure: the compiler reproduces itself. The provenance and rotation history of the seed live in release/seed/CHANGELOG.md.

Steps

  1. Start at the repository root. The dump must run with the relative sf/src/main.zig path because the module basename-hash tokens are path-derived, so a run from elsewhere does not reproduce the fixed point. 

    $ cd /workspace/znineeight

  2. Run the seed build with the recorded fixed point as a hard gate. The first argument is the committed seed archive; the second is a fresh output folder (the script removes it first). 

    $ FIXED_POINT_MD5=0b8c3e4ac0b1fc49c0bdf8caf9d39945 \
>   bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed

    FIXED_POINT_MD5 is optional, but with it a closure that does not equal the recorded point fails the build instead of passing silently.

  3. Read the gate. A successful run prints the hop md5s, the closure verdict, the fixed-point check, and the Done marker: 

    [seed] hop1 binary md5: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] hop2 binary md5: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] two-hop closure OK: hop1 == hop2 == 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] recorded fixed point OK: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
=== [seed] Done: /tmp/manual_seed ===

    === [seed] Done: <out_dir> === is the success marker. If the committed seed predates the current source, hop1 differs and the script verifies the moving point as hop2 == hop3 and prints a three-hop closure line instead.

  4. The compiler and its standard library land beside each other in the output folder: 

    $ ls /tmp/manual_seed
_unpack  gen  hop2  lib  zig1_5_clean

    The compiler is /tmp/manual_seed/zig1_5_clean; the standard library is /tmp/manual_seed/lib/ (30 .zig files). The compiler resolves @import("std") from the lib folder beside itself, so keep them together. _unpack/ is the unpacked seed, and gen/ and hop2/ are build scratch; none of the three is needed afterward.

  5. Confirm the compiler's identity. It must be the fixed point recorded for the current seed: 

    $ md5sum /tmp/manual_seed/zig1_5_clean
0b8c3e4ac0b1fc49c0bdf8caf9d39945  /tmp/manual_seed/zig1_5_clean

Verify it worked

A clean run of the two commands produces exactly this transcript (long gcc warning output omitted). The two hop md5s are equal, the closure is OK, the recorded fixed point matches, and the compiler binary hashes to the same value on disk. 

$ cd /workspace/znineeight
$ FIXED_POINT_MD5=0b8c3e4ac0b1fc49c0bdf8caf9d39945 \
>   bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed
[seed] hop1 binary md5: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] hop2 binary md5: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] two-hop closure OK: hop1 == hop2 == 0b8c3e4ac0b1fc49c0bdf8caf9d39945
[seed] recorded fixed point OK: 0b8c3e4ac0b1fc49c0bdf8caf9d39945
=== [seed] Done: /tmp/manual_seed ===
$ md5sum /tmp/manual_seed/zig1_5_clean
0b8c3e4ac0b1fc49c0bdf8caf9d39945  /tmp/manual_seed/zig1_5_clean
$ ls /tmp/manual_seed/lib | wc -l
30

Common mistakes

  • Running from the wrong directory. The dump needs the relative sf/src/main.zig path from the repository root; from anywhere else the basename-hash tokens change and the fixed point does not reproduce. Always cd /workspace/znineeight first.
  • Pointing the output folder at something you need. The script does rm -rf <out_dir>. Never point it at /tmp/fx_subfolder (that holds the zig0 current-cycle reference compiler) or any other working directory. Use a dedicated folder such as /tmp/manual_seed.
  • Leaving out the gate. Without FIXED_POINT_MD5 a closure can still finish on a moved point when the seed predates the source. Set the gate to the fixed point recorded for the current seed.
  • Mistaking the missing-seed fallback for an error. If the seed binary is absent, the script auto-reconstructs it from the archive's own gen/ C with gcc and prints a [seed] seed binary missing — falling back line. That is expected and still produces the fixed point.
  • Looking for a binary named zig1. The output binary is named zig1_5_clean in the output folder, with lib/ beside it.
