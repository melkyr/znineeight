Print and the Format String

Chapter 17 ended with a promise. It listed std.fmt among the thirteen modules and said the format string would be this chapter's subject. Every line of output in this volume came through the same entry point, and this chapter is where that entry point is taken apart: the one variadic call Z98 has, the five specifiers it accepts, the rules that decide whether a value can be printed at all, and the exact diagnostics that fire when a format string and its argument disagree.

The chapter's program is docs/sf/manuals/src/vol2/print.z98. It prints one line for each specifier and for each kind of value the printer supports. The whole program compiles with no diagnostics, and its twelve output lines are captured below byte for byte.

Honest note. You will reach for printf; here is how small the format language is instead. There are five specifiers and no others: no width, no precision, no fill, no alignment, no positional arguments, no field selection, no {any}, and no percent verbs. A specifier is a single letter between braces, and the one value it can name is printed in its natural form. The smallness is the point and the trade. Because every placeholder is checked against the static type of its argument at compile time, a format that cannot be printed is a compile error rather than a garbled line of output. What you give up is the formatting layer a larger language would have built on top of the call. What you keep is that a printed value is always the value.

The one variadic form

A call whose callee is named print is special-cased by the compiler. The shipped wrapper is: 

pub fn print(s: [*]const c_char, ...) void

The wrapper's body is never reached. When the compiler lowers a call to this name it does not call the function; it reads the format string, walks it once, and emits one runtime print for each placeholder it finds. The format string is therefore not a value at run time at all; it is a compile-time template. This is the only variadic form Z98 supports. There is no anytype, and there is no second form.

Two rules govern the call, and both are enforced before emission:

  • The arguments must be a tuple. The last call argument is the argument container. It must be a tuple literal, .{arg1, arg2}, or a tuple variable. Anything else — a bare value, an expression, a non-tuple variable, a struct or array initializer — is rejected with error[3065]. The compiler decomposes the container and hands one element to each placeholder in order.
  • There are exactly two arguments. A format string and one container. A call with more than the format plus one container is rejected with error[3061], the ordinary wrong-arity diagnostic.

You do not import std.fmt to use print. The compiler auto-imports the formatting module whenever a print is lowered; the only import your program needs is the one that names the std.io namespace: 

const std = @import("std");

Everything after that is the format string itself.

The five specifiers

A placeholder is a pair of braces. Inside them is either nothing, which selects the default form, or one letter naming a form. The letters are d for decimal, x for hexadecimal, c for a single character, and s for a string.

Form Writes
{} The value in its default form: a decimal integer, true/false, a decimal float, the member name of an enum, a named error, the generated form of an aggregate, or a tagged pointer address.
{d} Decimal. For an enum this is the numeric value even though {} prints the member name.
{x} Lowercase hexadecimal. A negative signed value prints a minus sign followed by the hex magnitude. For a float it is the C89 hex-float form.
{c} One byte, written as a character. This is the only form that accepts a u8 as text.
{s} A byte slice, written raw. The slice is not quoted and not escaped.

The forms are not interchangeable, and the type of each argument decides which ones are legal. The table below is the measured matrix. A cell that names a diagnostic is a compile-time rejection, not a run-time branch.

The last row is not a formatting rule; it is the edge of the printer. There is no route that turns an optional or an error union into text, so the compiler refuses the argument outright. The same is true of a dynamic slice under {}: a slice has no single default rendering, and Zig agrees, so the slice must be named with {s}. A one-item pointer does have a rendering — the pointee's type name, an at sign, and the address in lowercase hex — but because the address changes from run to run this chapter's transcript does not pin one.

Aggregates are the one recursive case, and the word covers several printer routes. A plain struct and a tuple walk their fields and write Zig's struct-literal shape; a nested normal struct descends. A bare union has no tag to walk, so it prints the placeholder .{ ... } instead. A tagged union prints its active variant, as long as every variant carries a payload; a naked tag makes the whole value unprintable. A packed union prints when all of its members are scalars; a packed-struct member makes it unprintable. The walk is capped at depth three; past that the generated printer writes .{ ... } instead of descending further. 

plain struct   .{ .x = 1, .y = 2 }
nested struct  .{ .inner = .{ .a = 1, .b = true }, .z = 9 }
tuple          .{ 1, 2, 3 }
bare union     .{ ... }
tagged union   .{ .a = 5 }
tagged union with a naked tag
  error[3063]: print argument type is not supported (no std.fmt printer)
packed union with a packed-struct member
  error[3063]: print argument type is not supported (no std.fmt printer)
struct with a packed-struct field
  error[3063]: print argument type is not supported (no std.fmt printer)

A struct holding a packed-struct field, a packed union holding a packed-struct member, a tagged union with a naked tag, and any aggregate holding a slice, an optional, an error union, or a void are all refused as a whole, because the generated printer would have no final route for one of the fields. Print those fields individually.

Literal braces are written by doubling them. {{ becomes one { and }} becomes one }, which is the only way to put a brace in the output of a call that takes a format string.

The example

One program, every form, one line each. It is docs/sf/manuals/src/vol2/print.z98: 

const std = @import("std");

const Point = struct { x: i32, y: i32 };
const Color = enum { Red, Green, Blue };
const MathError = error{ DivideByZero, Overflow };

pub fn main() void {
    const greeting: []const u8 = "hi";
    var small: i32 = -10;
    var large: u32 = 65535;
    var letter: u8 = 'A';
    var ratio: f64 = 1.0 / 3.0;
    var ok: bool = true;
    var c: Color = Color.Red;
    var bad: MathError = error.Overflow;
    const p = Point{ .x = 1, .y = 2 };
    const t = .{ 7, 8 };

    std.io.print("default {} d {} x {x} c {c} s {s}\n", .{ 42, 42, 42, letter, greeting });
    std.io.print("negative {} {x}\n", .{ small, small });
    std.io.print("unsigned {} {x}\n", .{ large, large });
    std.io.print("bool {} {}\n", .{ ok, false });
    std.io.print("float {} {x}\n", .{ 7.0, 7.0 });
    std.io.print("ratio {}\n", .{ratio});
    std.io.print("enum {} {d}\n", .{ c, Color.Green });
    std.io.print("error {}\n", .{bad});
    std.io.print("struct {}\n", .{p});
    std.io.print("tuple {}\n", .{ .{ 1, 2, 3 } });
    std.io.print("tuplevar {} {}\n", t);
    std.io.print("braces {{ }}\n", .{});
}

Twelve lines and an exit status of 0. Read them back against the table. The first line exercises all five specifiers on one integer literal and on two variables: {} and {d} are the same for 42, {x} is 2a, {c} turns the u8 into A, and {s} writes the slice hi. The second line is the signed-hex rule: -10 prints -a, not a two's-complement word. The fourth line shows that {} is true or false, and that the literal false prints the same way. The float line shows both float forms: 7.0 loses its .0 under {} and is 0x1.cp2 under {x}. The ratio is the bounded decimal path and stops at six places. The enum line shows the difference between the two forms of the same value: .Red for {}, the number 1 for {d}. The error line shows the named form. The struct and the first tuple print through the generated aggregate printer, the tuple variable prints through the same parser as the literal, and the last line proves the brace escape.

When the format and the type disagree

There are three ways a print can be refused, and it helps to keep them apart because each names a different mistake. The compiler reports all three at the argument or container node and stops before emitting C.

error[3013] — the format and the value disagree. This is either a letter that is not one of the five specifiers, or a specifier that is wrong for the type of its argument. An unknown specifier is reported on the format string itself: 

std.io.print("q {q}\n", .{ 1 });
// error[3013]: invalid print format specifier

A known specifier that does not fit the argument is reported at the argument: 

var v: i32 = 65;
std.io.print("s {s}\n", .{v});
// error[3013]: invalid print format specifier for the argument type

The same message covers {}, {d} or {c} on a slice, {d} or {x} on a bool, and {c} on any integer that is not a u8. The rule is one sentence: a specifier must be legal for the argument's static type.

error[3063] — this type has no printer. When the type has no route at all, no specifier can save it: 

var o: ?i32 = null;
std.io.print("opt {}\n", .{o});
// error[3063]: print argument type is not supported (no std.fmt printer)

The same diagnostic is what an optional, an error union, a fixed array, a void value, or a bare string literal under {s} produces. A bare string literal is a fixed-size array of bytes, not a slice, so it needs to be bound before it can be printed: 

std.io.print("s {s}\n", .{"hi"});
// error[3063]: print argument type is not supported (no std.fmt printer)

const hi: []const u8 = "hi";
std.io.print("s {s}\n", .{hi});
// s hi

That one catches people twice: the string is right there, but its type is *const [N]u8, and the string form wants a slice. Binding it to a []const u8 is the whole fix.

error[3065] — the arguments are not a tuple. A print container is not an ordinary argument, and a value alone will not do: 

std.io.print("non {}\n", 5);
// error[3065]: print arguments must be a tuple literal

The correction is to wrap it: .{5}. A tuple variable is accepted the same way a tuple literal is, so a helper can return an argument group and the caller can print it.

Common mistakes

The mistakes below come from arriving with printf, with modern Zig, or with a language whose print takes its arguments one at a time. Each has a measured correction.

Reaching for percent verbs. There is no %d and no %s. A percent verb is not a placeholder, so it is copied to the output as literal text, and the argument it was meant to name is never read: 

var v: i32 = 5;
std.io.print("x = %d\n", .{v});
// x = %d

Notice that this one does not stop the build. It is a silent mistake, which is why it is the first one listed. The value v is dropped because no placeholder asked for it. Write {} in the format and a % never appears in the source.

Printing a slice with {}. A byte slice is not a string to the default form; it has no single rendering. The compiler says so: 

const hi: []const u8 = "hi";
std.io.print("brace {}\n", .{hi});
// error[3013]: invalid print format specifier for the argument type

Use {s}. The same applies to []u8. This matches modern Zig, where a slice also needs an explicit form.

Forgetting the tuple. The argument group is a tuple literal or a tuple variable, and nothing else. Passing the value directly is error[3065], which is the diagnostic to look for when the mistake is the container rather than the format.

Naming a character with {}. {} on a u8 prints its decimal value; {c} prints the character. If you have an i32 and want a character, cast the value to u8 first, because {c} accepts only a u8: 

var i: i32 = 65;
std.io.print("c {c}\n", .{@intCast(u8, i)});
// c A

Expecting an error to print its name through a capture. An error-set value prints as error.Name, and a capture from a named error union is such a value. A bare !T, with no named set, is the exception: its capture keeps the numeric form, a documented residual of this compiler. If you need the name there, copy the capture into a variable declared with the error-set type first.

Printing a whole aggregate whose fields cannot be printed. A struct containing a slice, an optional, or an error union is refused with error[3063], because the generated printer would read a field with no route. Print the fields individually instead. The same cap shows up at depth: past three levels the aggregate printer writes .{ ... } rather than misleading you with a truncated walk.

Expecting width and precision. The five specifiers are the whole language. There is no padding, no argument order to rearrange, no field to pick out of a struct inside the format string, and no {any}. An unknown letter is rejected as error[3013], and text with no placeholder at all is copied through unchanged. Format the value before you print it if it needs a shape the printer does not give it.

Running under Windows 98

The same program builds for Win9x. src/build_owc.bat compiles the emitted C89 with OpenWatcom's wcc386 and links a console print.exe; run from a Windows 98 command prompt, it prints the same twelve lines. The format engine is not target-dependent: the same decomposition and the same std.fmt bodies are emitted for both targets, so nothing in the transcript changes.
