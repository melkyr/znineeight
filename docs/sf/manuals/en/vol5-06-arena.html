Correct Arena Use

This guide wraps an arena around a fixed backing buffer, allocates a record from it, resets the cursor, and splits the work across a permanent and a scratch arena so long-lived data survives a scratch reset.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc (the emitted script uses gcc -m32 -std=c89).
  • The repository checked out, so the shipped sample docs/sf/manuals/src/vol2/arena.z98 and the committed per-arena fixture repro/mi_matrix/stdlib_arena_xmod/ are present. Every command runs from the repository root, /workspace/znineeight.

The sample

An arena is a bump allocator over a buffer you supply. It has no malloc and no free: alloc hands out the next slice and advances a cursor, and reset puts the cursor back to zero. In Z98 the whole surface is four names in std.arena (the source is sf/src/std_arena.zig): 

pub const Arena = struct {
    data: [*]u8,
    capacity: usize,
    used: usize,
};

pub fn init(data: []u8) Arena
pub fn alloc(self: *Arena, size: usize) ArenaError![*]u8
pub const ArenaError = error{OutOfMemory};
pub fn reset(self: *Arena) void

init records the buffer's base pointer and length and sets used to zero; each alloc returns self.data + self.used and advances used, or returns error.OutOfMemory when the request does not fit. The shipped sample docs/sf/manuals/src/vol2/arena.z98 exercises both the single-arena arc and the dual-arena pattern. Its two driver functions are: 

fn single() !void {
    var buf: [32]u8 = undefined;
    var arena = std.arena.init(buf[0..]);
    std.io.print("cap={} used={}\n", .{ arena.capacity, arena.used });

    const p = try Point_init(&arena, 3, 4);
    std.io.print("p={} {} used={}\n", .{ p.x, p.y, arena.used });

    std.arena.reset(&arena);
    std.io.print("used after reset={}\n", .{arena.used});

    const p2 = try Point_init(&arena, 9, 8);
    std.io.print("p2={} {} reused p.x={}\n", .{ p2.x, p2.y, p.x });

    const big = allocBytes(&arena, 64) catch |err| {
        std.io.print("caught: {}\n", .{err});
        return;
    };
    std.io.print("unreachable {}\n", .{@intFromPtr(big)});
}

fn dual() !void {
    var perm_buf: [128]u8 = undefined;
    var scratch_buf: [64]u8 = undefined;
    var perm = std.arena.init(perm_buf[0..]);
    var scratch = std.arena.init(scratch_buf[0..]);

    const p = try Point_init(&perm, 3, 4);
    const q = try Point_init(&scratch, 5, 6);
    std.io.print("perm={} {} scratch={} {}\n", .{ p.x, p.y, q.x, q.y });
    std.io.print("perm used={} scratch used={}\n", .{ perm.used, scratch.used });

    std.arena.reset(&scratch);
    std.io.print("scratch used after reset={} perm used={}\n", .{ scratch.used, perm.used });
}

The key property to watch: reset rewinds the cursor, it does not zero the bytes and it does not invalidate the pointers the arena already handed out. That is why the sample prints reused p.x=9 after the reset — the old p now aliases the new object. This is the ownership rule that makes the split-arena discipline necessary: a value whose lifetime must outlive a reset has to come from an arena that is not being reset.

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Create the output folder. The compiler writes its emitted tree there but will not create the folder itself. 

    $ mkdir -p /tmp/manual_out

  3. Translate the sample to C89. -o names the output folder; the last argument is the source file. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol2/arena.z98

    The command is silent on success. It emits one C89 pair per module, the runtime, and the companion build script.

  4. Build the executable. Run the emitted script from inside the output folder and give it the target linux and the program name arena. 

    $ cd /tmp/manual_out && timeout 120 sh build_target.sh linux arena
Building for linux...
Built: arena

    The generated C draws many gcc warnings; they are expected and do not stop the build, because the script does not pass -Werror. Look for Built: arena.

  5. Run it. 

    $ timeout 120 ./arena
cap=32 used=0
p=3 4 used=8
used after reset=0
p2=9 8 reused p.x=9
caught: error.OutOfMemory
perm=3 4 scratch=5 6
perm used=8 scratch used=8
scratch used after reset=0 perm used=8

    Read the output as the arena's arc. The 32-byte buffer starts at cap=32 used=0. One Point is eight bytes (2 × i32), so used=8 and the fields read back as written. reset returns the cursor to used=0, then the same eight bytes are handed out again — the old p is not invalidated, it is simply reused, so p.x now reads the new object's 9. The 64-byte request cannot fit in the 32-byte buffer and the failure is typed and caught: caught: error.OutOfMemory; the program never reaches the unreachable line. The second half allocates from two distinct buffers: the permanent arena holds its object, the scratch arena holds its own, and after reset(&scratch) the scratch cursor is zero while perm used=8 still stands.

  6. Confirm the per-arena guarantee against the committed fixture. This is the sanity check that a second arena over a distinct buffer is truly independent: exhausting one must not affect the other, and resetting one must not corrupt the other's bytes. The standard-library gate emits the fixture, links it through build_target.sh, runs it three times, and diffs the result byte-for-byte against the committed expected.txt and expected.rc. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_arena_xmod
== std-lib runtime gate ==
   zig1: /tmp/manual_seed/zig1_5_clean
PASS repro/mi_matrix/stdlib_arena_xmod
----------------------------------------
run_fixtures: 1 PASS / 0 FAIL over 1 dirs
STDLIB GATE OK

    PASS means the fixture's 13-line transcript (a 1 for each guarantee, then 2, 0, 99) and the exit code 0 matched the goldens on all three runs; STDLIB GATE OK is the wrapper's overall verdict.

Verify it worked

The eight-line arena transcript above is the recorded measured output of docs/sf/manuals/src/vol2/arena.z98; running the four commands in Steps 2–5 reproduces it exactly and exits with status 0. The per-arena fixture pass in Step 6 is the second half of the check: it pins that two arenas over different buffers do not alias, that an alloc past one arena's capacity returns its own failure, and that reset frees only the arena it names.

Common mistakes

  • Forgetting to create the output folder. The compiler requires the folder to exist and fails with error: output directory does not exist: /tmp/manual_out (exit code 1). Run mkdir -p first.
  • Believing reset frees or clears memory. It only sets used back to zero. The bytes stay put and every pointer the arena returned stays valid but aliases whatever is allocated next — that is why p.x reads 9 after the reset. Do not read through an old pointer after a reset.
  • Letting a long-lived value share the scratch arena. If a value must outlive a reset, allocate it from the permanent arena and reset only the scratch one. The dual-arena pattern is exactly this: perm is never reset, scratch is reset as often as needed, and perm used=8 survives reset(&scratch).
  • Forgetting to check the error union. alloc returns ArenaError![*]u8. A try propagates error.OutOfMemory; a catch handles it, as the sample's allocBytes(&arena, 64) catch |err| does. There is no orelse path for this type.
  • Under-sizing the backing buffer. An arena never grows. If the total of all live allocations can exceed capacity, alloc returns error.OutOfMemory; budget the buffer for the worst case, or fall back to a larger one.
  • Assuming arenas share state. Each arena owns the buffer passed to init. Two arenas over distinct buffers are independent: exhausting or resetting one leaves the other's cursor and bytes untouched, which is what the Step 6 fixture proves.
