Tuples

A tuple is a struct with no field names: an ordered bundle of values addressed by position. Its type is written as a struct whose members are only types (struct { i32, i32 }), its value as a positional anonymous literal (.{ 7, 3 }), and its elements are read through an ordinal. This page is the lookup for the type and literal syntax, the three access spellings and the comptime-index rules, tuple reads, writes and address, coercion and named-tuple assignability, element typing, layout and introspection, printing, globals, and the limits.

The authority is the parser (parserParseStructType at sf/src/parser.zig:1318-1385, positional branch at :1352-1369), the .N/._N member path (sf/src/semantic_analyzer.zig:1683-1707), the t[N] index path (sf/src/semantic_analyzer.zig:6192-6247), the ordinal decoder (sf/src/type_registry.zig:610-628), tuple assignability (sf/src/type_registry.zig:1340-1359), the array-element reject (sf/src/type_resolver.zig:1505-1522), and the emitted C model (emitTupleType at sf/src/c89_emit.zig:2173-2195). Every rule below was reproduced on the fixed compiler (md5 7fc608358f4f6af5abab43e633d44f83); the reused fixture or sample is named where one exists.

Type syntax and literals

A tuple type is a struct declaration whose members are plain types instead of name: T fields. It is named through a const, the way every aggregate in Z98 is. A value is built with a positional anonymous literal, .{ v1, v2 }, whose elements appear in declaration order; the literal takes its shape from context, or is inferred from its element values. 

const Pair = struct { i32, i32 };   // a tuple type: two i32 positions
const t = .{ 7, 8 };                 // inferred tuple literal
const p: Pair = .{ 7, 3 };           // literal coerced to the named type
fn divmod(a: i32, b: i32) Pair {     // grouped return
    return .{ a / b, a % b };
}
Form Spelling Meaning
type const T = struct { T1, T2 }; Every member is a type in position order; no names.
literal .{ v1, v2 } Anonymous positional value; the surrounding type supplies the shape.
inline type fn f() struct { i32, i32 } The type may be written in a signature; it behaves as a named tuple type.

Members must be all named or all positional. A mixed declaration rejects level-0 error[2000] struct fields must be all named or all positional (tuple) at the offending member, and a positional member in a packed struct rejects error[2000] packed structs cannot have positional tuple fields. A trailing comma is optional. The empty literal .{ } is accepted as a print argument container with zero elements.

Element access: the three spellings

An element is addressed by its ordinal. All three spellings lower to the same positional field: .0/.1 (the original spelling), ._0 / ._1 (the emitted C field spelling), and t[0]/t[1] (a comptime-known index). 

const p: Pair = .{ 7, 3 };
std.io.print("{} {} {}\n", .{ p.0, p._0, p[1] });   // 7 7 3
Spelling Lowering
t.N, t._N The parser canonicalizes the numeric member to its decimal text; sema decodes the ordinal textually and reads the positional field. The name-id space is never consulted.
t[N] The index is folded to a comptime value, bounds-checked, and recorded for lowering (local const indices count as comptime-known); the element type is then used as the field type.

The C89 representation is exactly what ._0 suggests: a tuple lowers to a C struct whose fields are _0, _1, and so on, in declaration order. 

typedef struct {
	unsigned int _0;
	zT_C69B2266_i64 _1;
} zT_F9C653E5_Tup_343;

The reused fixture repro/mi_matrix/stdlib_tuple_model_ok_xmod exercises all three spellings on the same element (writes through .0, ._1, and [0], and a local-const index) and prints tp=12/20 us0=11 e1=20 ci=20 ..., reproduced here.

Index shape Code Message (measured)
runtime index, var i: usize = 1; p[i] error[3069] tuple field index must be comptime-known (at the index expression)
ordinal past the end, p.9, p._9, p[9] error[3070] index 9 outside tuple of length 2 (at the index expression)

The reject census is pinned by repro/mi_matrix/tuple_model_reject_xmod (a local const index is accepted; .73 on a non-tuple, a runtime index, and both ordinal forms past the end reject; a negative index uses the array path's error[3062]).

Reads, writes, and address

Every spelling is an lvalue on the tuple's real storage: a write through .0, ._1, or [0] updates the same positional field, and the address of an element may be taken and dereferenced. 

var p: Pair = .{ 7, 3 };
p.0 = p.0 + 1;
p._1 = p._1 + 1;
p[0] = p[0] + 1;
const ep: *i32 = &p.0;
ep.* = ep.* + 1;

A tuple is copied field-wise. A named tuple type and a shape-identical tuple assign to each other, cross a call as one value (parameter or return), and may be a tuple-typed field or a module global. The reused fixture stdlib_tuple_model_ok_xmod covers the literal-to-named copy, the named-to-named copy, a cross-module parameter and return, a cross-module module global, and the address-and-deref write.

Coercion and named-tuple assignability

From → to Result
anonymous literal .{ 1, 2 } → named Pair Assignable; lowered field-wise.
inferred tuple → shape-identical named tuple Assignable (same arity and element types).
named tuple → shape-identical named tuple Assignable; a field-wise copy (declaration, assignment, argument, return).
literal .{ 1, 2, 3 } → fixed array [3]u32 Assignable when the count matches and every element coerces to the element type (the array path; see the arrays page).
mismatched arity or element type Level-0 error[3000]; a distinct spelled tuple type with an array element is a separate error[3000] (below).

An arity mismatch (A = struct { i32, i32 } assigned to B = struct { i32, i32, i32 }) and an element mismatch (A assigned to C = struct { i32, f32 }) both report the level-0 declaration mismatch with the tuple identity: 

error[3000]: type mismatch in variable declaration -- initialization type may not be compatible with declared type
note: source: tuple
note: target: tuple

Element typing (FB2)

An inferred tuple literal types each element by what it is, not by a fallback. An untyped integer literal element takes its value-chosen carrier: i32 when the value fits, otherwise u32/i64/u64. The tuple's C field type matches the value, so a wide literal is not silently truncated.

Literal Tuple type Printed
.{ 3000000000, -3000000000 } {u32, i64} 3000000000 -3000000000
.{ 1 << 100, 1 } level-0 error[3000] comptime integer value does not fit the target type —
.{ vf(), 1 } (vf() void) void element; print rejects error[3063] —
.{ i32, 5 } (a TYPE as an element) print rejects error[3063] —

A void-typed struct field read is a real void value (struct { v: void, a: i32 } is legal; s.v reads void), so it rejects in a tuple print the same way. These value-chosen carriers and rejects are pinned by repro/mi_matrix/stdlib_print_tuple_var_ok_xmod and repro/mi_matrix/tuple_elem_type_reject_xmod.

Layout and introspection

A tuple takes the struct layout arithmetic of the frozen 32-bit model: each element sits at its natural offset, the tuple's alignment is its widest element's alignment, and the total is padded to that alignment. @sizeOf, @alignOf, and @bitSizeOf accept a tuple type.

Type Elements @sizeOf / @alignOf / @bitSizeOf
Pair {i32, i32} 8 / 4 / 64
Wide {u8, i64, u8} 24 / 8 / 192

Wide shows the 64-bit pin: the i64 element is size 8 and alignment 8, so the leading u8 pads to offset 8 and the tuple ends at 24 bytes. @offsetOf and @bitOffsetOf expect a struct and reject a tuple type outright — there is no field name to ask about: 

error[3072]: expected struct type, found 'Pair'

Put the tuple's elements in a named struct, or ask for the offset of a struct that holds the tuple, when an offset is part of the question.

Printing a tuple

When a tuple is an element of the printed container ({p}), it prints through the aggregate printer with {}, in positional braces. A tuple variable used as the container itself prints element-wise: each {} consumes one element in declaration order, so the tuple braces do not appear. The argument container of print may be a tuple literal or a tuple variable; a variable reads each element through the same positional-field mechanism as .N/t[0]. 

const p: Pair = .{ 7, 3 };
std.io.print("pair {}\n", .{p});          // pair .{ 7, 3 } (tuple is an element)
std.io.print("pair {} {}\n", p);           // pair 7 3 (variable container, element-wise)
std.io.print("pair {}\n", p);              // pair 7 (one placeholder consumes p[0])
Print shape Result (measured)
{} on a tuple .{ 1, 2 } (all elements, declaration order).
nested tuple deeper than three levels the deepest level prints the depth placeholder .{ ... }, e.g. .{ .{ .{ .{ ... }, 3 }, 4 }, 5 }.
element with no printer (a void element, a TYPE element) error[3063] print argument type is not supported (no std.fmt printer).
container that is neither a tuple literal nor a tuple variable error[3065] print arguments must be a tuple literal.
a format plus more than one container error[3061] expected 2 argument(s), found 3.

A placeholder beyond the container's arity is silently dropped, and a placeholder-free format does not evaluate the container. An explicit specifier such as {d} on a tuple is the ordinary format-specifier reject (error[3013]) documented on the builtins page. The tuple-variable print path is pinned by stdlib_print_tuple_var_ok_xmod; the container gate by repro/mi_matrix/print_nontuple_container_reject_xmod.

Globals and cycles

A module-level tuple literal may reference a global declared later in the file: the module's initializers are emitted in dependency order, so the referenced value is materialized first. A global tuple variable is read and written like any other. 

var g = .{ b, 7 };
const b = 5;
// prints: g 5 7

A cycle in that dependency graph has no valid order and clean-rejects the level-0 error[3064] cyclic global initializer dependency. This is pinned by repro/mi_matrix/stdlib_print_tuple_fwd_ok_xmod (a forward reference) and repro/mi_matrix/tuple_fwd_global_reject_xmod (a cycle).

Limits

Shape Rule (measured)
spelled tuple type with an array element, struct { [2]i32, i32 } Level-0 error[3000] tuple types with array elements are not supported at the array element (no field-wise C assignment for an array element).
inferred tuple literal holding an array Accepted for layout and element reads by position; an element read t[0] decays to *i32, and printing the whole tuple (literal aggregate or variable) rejects error[3063].
chained access after an ordinal, e.0.w Level-0 error[2000] expected field name or index after '.'; parenthesize or index the element ((e.0).w, e[0].w) and the struct access works.
@offsetOf / @bitOffsetOf on a tuple type Level-0 error[3072] expected struct type, found '<T>' (the tuple type name varies).
runtime index or loop-variable iteration Not supported: the index must be comptime-known (error[3069]); a tuple is a bundle, not a collection.
field names and type identity There are no field names (p.x is the unknown-member reject error[3060]), and two tuples of the same shape are the same type for assignment purposes.
