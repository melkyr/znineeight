Arrays and slices

An array is an aggregate whose length is part of its type: [N]T is exactly N values of type T, known at compile time. A slice is the runtime pair { pointer, length } written []T, so one parameter type can accept an array of any size. A many-item pointer [*]T is a pointer with no length, and a pointer-to-array *[N]T is a pointer whose pointee length is still in the type. This page is the lookup for the type syntax, the literals, indexing and bounds, slicing, .len/.ptr, the coercion and const rules, string literals, the operators, and for iteration.

The authority is the parser bracket type (parserParseBracketType at sf/src/parser.zig:1175-1204), the single-item-pointer slice gate and the comptime index/slice-bound checks (sf/src/semantic_analyzer.zig:1052-1250), the array-size fold (sf/src/type_resolver.zig:2010-2060), and the emitted slice structure (emitSliceType at sf/src/c89_emit.zig:2383-2414). Every rule below was reproduced on the fixed compiler (md5 7fc608358f4f6af5abab43e633d44f83); reused fixtures and samples are named where one exists.

Type syntax

Form Meaning
[N]T Fixed-size array; N is a compile-time constant and is part of the type.
[_]T Inferred length; legal only on the array literal's own type prefix ([_]i32{ ... }). In any position that needs a concrete type (a declaration, field, parameter, return, alias or cast target) it rejects level-0 error[3000] unable to infer array size.
[]T, []const T Slice: a pointer plus a runtime length; []const T is the read-only view.
[*]T, [*]const T Many-item pointer: a pointer with no length.
*[N]T, *const [N]T Pointer whose pointee is a fixed-size array; the length stays in the type. 
var scores: [5]i32 = .{ 10, 20, 30, 40, 50 };   // fixed array
var inferred = [_]i32{ 1, 2, 3 };               // [_] infers length 3
var s: []i32 = scores;                          // slice: pointer + length
const view: []const i32 = scores[0..];          // read-only slice
const pa: *[5]i32 = &scores;                    // pointer-to-array

N must be a compile-time constant. A non-constant size rejects level-0 error[3050] array size is not a constant expression at the size expression. The inferred [_]T needs no size because its length comes from the literal it annotates; used where a concrete type is required it rejects level-0 error[3000] unable to infer array size at the _ (Zig 0.15.2 wording). 

var n: i32 = 4;
var a: [n]i32 = undefined;
// error[3050]: array size is not a constant expression

var x: [_]i32 = .{ 1, 2, 3 };
// error[3000]: unable to infer array size

Sentinel and volatile forms are not supported

Form Result (measured)
[N:0]T (sentinel-terminated array) Parse reject: level-0 error[2000] expected ']' but found ':' (plus unexpected token). Z98 has no sentinel array type; a string literal is typed *const [N]u8, not *const [N:0]u8.
[]volatile T Parse reject (error[2000]); use [*]volatile T for memory-mapped I/O (the spec's qualified-pointer scope).

Array literals

Spelling Shape
.{ v1, v2, v3 } Untyped positional literal; takes its element type from the surrounding array type.
[N]T{ v1, v2, v3 } Typed literal; the element type is spelled on the literal. Required when the literal sits inside a larger initializer.
[_]T{ v1, v2, v3 } Typed literal with the length inferred from the element count. 
var a: [3]i32 = .{ 1, 2, 3 };            // untyped
var b: [3]u8 = [3]u8{ 1, 2, 3 };         // typed
var c: [3]i32 = [_]i32{ 4, 5, 6 };       // inferred length, annotated array
var d = [_]i32{ 7, 8, 9 };               // inferred array type (length 3)

The literal's count and element types are not hard-enforced against the declared array type. An element-count mismatch is accepted with a level-1 warning[3000] type mismatch in variable declaration -- initialization type may not be compatible with declared type (with source: tuple and target: array); extra elements are ignored and a short literal leaves the remaining elements uninitialized. A non-conforming element type is the same warning. 

var a: [3]i32 = .{ 1, 2 };
// warning[3000]: ... source: tuple / target: array ; a[2] is uninitialized

Slices: a pointer plus a length

A slice lowers to an 8-byte C struct, one 32-bit pointer plus one 32-bit length, so @sizeOf([]i32) and @sizeOf([]const u8) are both 8. An array's size is N times its element size. 

typedef struct { int* ptr; unsigned int len; } zT_..._Slice_...;   // c89_emit.zig:2409
Base .len .ptr
[N]T usize Reject error[3060] no field or member function named 'ptr' in array type.
[]T usize [*]T
[]const T usize [*]const T
[*]T Reject error[3000] many-item pointer has no field 'len' n/a (already a many-item pointer)
*[N]T / *const [N]T N as usize n/a
struct/union array field usize (the declared length) n/a 
const hello: []const u8 = "z98 rocks";
const bytes: [*]const u8 = hello.ptr;
std.io.print("{s} len {} first {}\n", .{ hello, hello.len, bytes[0] });
// z98 rocks len 9 first 122

The .len of an array field is pinned by repro/mi_matrix/len_array_field_xmod (local, by-value, by-pointer, global, union and nested positions all report 4).

Indexing and bounds

base[i] accepts a fixed array, a slice, a many-item pointer, a pointer-to-array, and a struct/union array field. For a slice the index is the pointer index, base.ptr[i]. A bare single-item pointer *T whose pointee is not an array does not support indexing.

Shape Result (measured)
index a *T, p[0] or p[i] error[3066] type '*i32' does not support indexing, note operand must be an array, slice, tuple, or vector.
comptime index past the end, scores[5] on [5]i32 error[3062] index 5 outside array of length 5.
scores[scores.len] The same error[3062]; .len folds to the constant.
negative comptime index, scores[-1] error[3062] type 'usize' cannot represent integer value '-1'.

A runtime index is not a compile-time error. Under the default -fsafe it keeps a bounds check that traps (check_trap{kind=5}, exit status 133); under -ffast the guard is removed and the access reads whatever is there. 

var arr: [4]i32 = .{ 10, 20, 30, 40 };
var i: usize = 7;
std.io.print("{}\n", .{ arr[i] });   // default -fsafe: traps (exit 133)
                                      // -ffast: runs, prints 40

The positive boundaries are pinned by repro/mi_matrix/stdlib_comptime_index_ok_xmod: in-range comptime indexes (a literal, a const, a *[5]i32, a struct field) and a runtime in-range index all compile and run.

Slicing

base[start..end] is inclusive of start, exclusive of end. The end may be omitted (base[start..], running to the end of the source); the start may not be (base[..end] does not parse). base[len..] and base[len..len] are legal empty slices. 

const mid: []i32 = scores[1..3];    // two elements
const tail: []i32 = scores[3..];    // runs to the end
const none: []i32 = scores[5..5];   // the empty slice
var bad = scores[..2];
// error[2000]: expected expression
// error[2000]: unexpected token
Base Result type Rule
[N]T / []T []T ([]const T when the base is const) Slicing a const array or a []const T yields []const T.
*[N]T / *const [N]T []T / []const T Legal for every comptime or runtime bound; the omitted end is N; the pointer scales by ONE element ((T*)pa + start).
[*]T, open end mp[s..] [*]T Accepted: the pointer offset by start, still with no length (Zig 0.15.2 parity). Constness carries.
[*]T, closed mp[s..e] []T A real slice; length e - s.
single-item *T *[0]T / *[1]T Only p[0..0], p[0..1], p[1..1]. Any other bound is error[3067]. 
const pa: *[4]i32 = &arr;
const s1: []i32 = pa[1..3];
const s2: []i32 = pa[2..];
const s3: []i32 = pa[4..];
pa.*[0] = 11;                        // index the dereferenced array
// pa 1..3 -> len 2, [0] 20 ; pa.* -> index 0 is now 11

Comptime-known bounds on a fixed-length base are checked at compile time with error[3062], matching Zig 0.15.2:

Shape ([4]i32 base) Message (measured)
scores[1..5] end index 5 out of bounds for array of length 4
scores[3..1] start index 3 is larger than end index 1
scores[6..] start index 6 is larger than end index 4 (the open-ended effective end is the length)
scores[-1..2] type 'usize' cannot represent integer value '-1'

A closed range whose present end is runtime (arr[7..ri]) is not compile-checked. The single-item-pointer rejects are: 

var a = p[0..2];   // error[3067]: slice of single-item pointer must have bounds [0..0], [0..1], or [1..1]
var b = p[0..];    // error[3067]: slice of single-item pointer must be bounded
var c = p[0..n];   // error[3067]: unable to resolve comptime value
                   // note: slice of single-item pointer must have comptime-known bounds

Runtime bounds checks

Under the default -fsafe, a runtime-capable slice range traps the same way an index does: for base[start..end] the checks are start <= end and, when the length is known, end <= len; for base[start..] the check is start <= len. A many-item pointer has no length, so only start <= end applies. A bound that is a signed integer wider than usize also requires >= 0. -ffast emits none of these guards. Compile-time-known bound pairs on a static-length base are already checked by error[3062] and emit no runtime guard.

Signed-bound residual. A runtime equal-width signed bound is neither coerced nor rejected: var i: i32 = -1; var s: []i32 = arr[i..4]; compiles rc 0 and bypasses the guards (under -fsafe it reads before the array). A literal or comptime-folded negative bound still rejects error[3062] type 'usize' cannot represent integer value '-1'.

Coercion and const correctness

The implicit coercions below are allowed at assignments to [*]T or []T variables, at call arguments, and at returns; they are not allowed in arithmetic or comparisons. The rule is one line: a conversion may add const, never discard it.

Conversion Result
mutable [N]T → []T / [*]T Allowed
[]T → []const T / [*]const T Allowed
[]T / []const T → [*]T / [*]const T Allowed (via .ptr)
[]const T → []T / [*]T error[3000]
const-bound [N]T → []T / [*]T error[3000]
string literal "abc" → []u8 / [*]u8 / []u8-element error[3000]
&constarr (*const [N]T) → []T / [*]T error[3000]
const aggregate's array field, cs.a[0..] / &cs.a → mutable error[3000]

Every forbidden conversion is the level-0 diagnostic error[3000] cannot implicitly discard 'const' qualifier, emitted at the site that would discard the qualifier; no C is emitted. 

const ca: [3]i32 = [3]i32{ 1, 2, 3 };
var s: []i32 = ca;        // error[3000]: cannot implicitly discard 'const' qualifier
var p: [*]i32 = ca;       // error[3000]
var q: []i32 = ca[0..];   // error[3000]
var r: [*]i32 = &ca;      // error[3000]

Propagation follows the decay through slicing: slicing a const array or a []const T produces a []const T, which then rejects at a mutable target. The same guarantee reaches an array through a field of a const aggregate (FX11): cs.a[0..] is []const i32 and &cs.a is *const [3]i32, while a mutable aggregate's field keeps its mutability. An array-literal element whose declared element type is mutable may not take a const slice/string element (FX6): 

const S = struct { a: [3]i32 };
const cs: S = .{ .a = [3]i32{ 4, 5, 6 } };
const ok1: []const i32 = cs.a[0..];       // accepted
const ok2: *const [3]i32 = &cs.a;         // accepted
var bad1: []i32 = cs.a[0..];              // error[3000]
var bad2: [*]i32 = &cs.a;                 // error[3000]

const c: []const i32 = &.{ 1, 2, 3 };
var arr: [2][]i32 = [2][]i32{ c, c };     // error[3000] at each element

String literals

A string literal is a constant byte array: "hello" is typed *const [5]u8 (a pointer to a fixed-size array, no sentinel). It coerces implicitly to the const byte views []const u8, [*]const u8, and the legacy single-item pointer *const u8; the mutable forms reject error[3000]. 

const hello: []const u8 = "z98 rocks";   // len 9
const p: [*]const u8 = hello.ptr;        // many-item, const
const q: *const [9]u8 = "z98 rocks";     // pointer-to-array form (q.len == 9)

The legacy *const u8 binding is accepted without a diagnostic, but a single-item pointer does not support indexing: one[0] is error[3066]. Bind the literal to a slice and index that, or use one.* for the first byte. 

const one: *const u8 = "hello";
var bad = one[0];
// error[3066]: type '*const u8' does not support indexing

Printing follows the byte view: {s} prints a []u8 or []const u8 as text and {c} prints one byte as its character. Plain {} on a slice is error[3013]; plain {} on an array is error[3063].

Operators

Expression Result
a[i], s[i], p[i], pa[i] Element access (see indexing and bounds).
a.len, s.len, pa.len, field.len usize; a many-item pointer has no .len.
s.ptr / cs.ptr [*]T / [*]const T; an array value has no .ptr (error[3060]).
a == b, a != b on two arrays Accepted; compares the two storage addresses, not the element contents. Two identically filled arrays compare false; an array compares true only against itself. In a bool context it behaves as a boolean; the comparison expression itself types as void, so binding it to an explicit bool emits warning[3000].
arithmetic (+, -, ...) on an array or slice Rejected: the result types void (error[3000] cannot declare variable of type void).
==, !=, <, ... on slices Not supported: the frontend accepts the comparison but the emitted C is invalid (invalid operands to binary !=). Compare .len and elements.

for iteration

Iterable / form Behavior
for (arr) |v|, for (slice) |v|, for (pa) |v| Visits every element; a pointer-to-array auto-derefs and iterates the pointee array. A *[0]T iterates zero times.
for (arr) |v, i| The index capture is allowed without an explicit range; i runs 0..len-1.
for (arr, start..) |v, i| Iterates every element; the capture is start + j (j = the 0-based count) and is not clamped.
for (arr, start..end) |v, i| Same, but end - start must equal the iterable's length; otherwise error[3000] non-matching for loop lengths: the index range and the iterable differ in length.
explicit index range without an index capture error[3000] explicit index range requires an index capture ('|item, index|').
a range iterable (0..5) Iterated as a range of integers; the same list applies to the control-flow page. 
for (arr) |v| { }                 // every element
for (arr) |v, i| { }              // index 0..len-1
for (arr, 1..) |v, i| { }         // index 1..len
for (arr, 0..arr.len) |v, i| { }  // explicit full range

These rules are pinned by repro/mi_matrix/stdlib_ptr_array_slice_ok_xmod (pointer-to-array iteration, open-ended many-item-pointer slices, and pa.*[i] reads/writes) and by the for forms in the same fixture's cross-module helper.

Limits and residuals

Shape Rule (measured)
runtime signed slice bound, var i: i32 = -1; arr[i..4] Accepted rc 0 and unguarded; under -fsafe it reads out of bounds. A literal or folded negative bound rejects error[3062]. Systemic pre-existing laxity, no fix scheduled.
address of a const array's element, &ca[0] Still yields a mutable *i32, and a write through it reaches the storage, though ca[0] = 9 rejects error[3002]. The aggregate-field form &cs.a[i] carries the qualifier correctly; direct-binding residue, not scheduled.
module-scope array from an untyped literal, var ga: [3]i32 = .{ 1, 2, 3 }; The untyped literal is typed as a tuple and the emitted C assigns it to a C array (gcc: assignment to expression with array type). Spell the element type ([3]i32{ ... }) at module scope or initialize locally. The struct-field .{ ... } variant is covered on the Volume II page.
[_]T as a declaration type, var x: [_]i32 = ... Rejected level-0 error[3000] unable to infer array size (the _ span). Write the length ([N]T) or infer from the literal (var x = [_]i32{ ... }). The same reject covers a struct field, a parameter, a return type, a bare alias and an @as target.
[N:0]T sentinel arrays / []volatile T Not supported (parse rejects); strings are *const [N]u8, and []volatile T is spelled [*]volatile T.
slice comparison, s == t / s != t Frontend-accepted, emitted C invalid. Compare .len and elements.
