Reading the Errors

Every program in this volume has ended with a build that succeeds. This chapter is about the other outcome: the compiler reads the source, finds something it cannot accept, prints a message, and refuses to produce a program. That message is the compiler doing its job. It names the file, the line, the column, and the thing that is wrong, and the fastest way to fix a program is to read it without panic.

The chapter is a tour of five small programs, each deliberately wrong in a different way. They live beside the working examples, in docs/sf/manuals/src/vol1/errors/, one error per file (err1.z98 through err5.z98). Compile one with the compiler from chapter 4 and it stops with exactly the diagnostic quoted here. There is no working program in this chapter: the transcripts are the figures, and the "Check yourself" asks you to read a diagnostic the way earlier chapters asked you to read a program.

How to read a diagnostic

A diagnostic is written to standard error and the compiler stops, without producing a program; the exit status is nonzero. One build can print more than one diagnostic, but each is a small block of lines, and every line has one job.

  • The first line is the position, the code, and the message: file:line:column: error[code]: message. The line is counted from 1, the way a text editor counts lines. The column is counted from 0, the way this manual counts the indices of a list, and it is the column of the first character of the span the compiler is complaining about.
  • The second line repeats the offending source line, so you do not have to go looking for it.
  • The third line is the caret line: spaces up to the column, then one ^ under every character of the span. Some spans are a single name; some cover a whole statement; a function that must return has a span that covers the whole function, and its carets run to the end of the span.
  • note: lines come last, and only when the compiler has more to say. A note carries no position of its own; it belongs to the diagnostic above it. Error 5 ends with one.

The code in brackets is a label the compiler puts on each kind of diagnostic. It is not a line number and not a count. Language-level errors use codes in the 30xx block, but a code is only a label: error 1 below is error[20]. Read the message and the caret, not the digits.

Error 1: a name that is not there

The first program counts one value and then prints a total. It builds until line 7, where it asks for a name that was never declared: 

const std = @import("std");

pub fn main() void {
    var count: i32 = 3;
    count = count + 1;
    std.io.print("count is {}\n", .{count});
    std.io.print("total is {}\n", .{total});
}

$ mkdir -p /tmp/manual_out/err1
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err1 err1.z98
err1.z98:7:36: error[20]: identifier 'total' is not declared or imported in this module
    std.io.print("total is {}\n", .{total});
                                    ^^^^^

Read the header first: file err1.z98, line 7, column 36. Count the line from 1 — it is the second print — and the column from 0: column 36 is where the name total begins. The caret line agrees: five carets under the five letters of total, and nothing else underlined. The message says what the caret shows: nothing named total is declared in this module. The only variable here is count.

The fix is to use a name that exists. If the second print was meant to show the same count, write count; if the program really wants a total, declare it first (var total: i32 = 0;) and give it a value before line 7 uses it. The compiler will not guess which name you meant.

Error 2: a variable with no starting value

The second program declares a variable and assigns to it on the next line. Z98 refuses to let a variable exist without a starting value: 

const std = @import("std");

pub fn main() void {
    var count: i32;
    count = 3;
    std.io.print("count is {}\n", .{count});
}

$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err2 err2.z98
err2.z98:4:4: error[3014]: variable must be initialized; use '= undefined' to opt out
    var count: i32;
    ^^^^^^^^^^^^^^^

The position is line 4, column 4 — the first character of var — and the span is the whole declaration, so the carets cover all fifteen characters from var to the semicolon. The message names both the rule and the escape hatch: var x: T; is rejected, and writing = undefined tells the compiler that the first value will be supplied some other way. For a counter, the honest fix is a real starting value: 

var count: i32 = 0;
count = 3;

or simply var count: i32 = 3;, dropping the next line. The opt-out exists for the cases where the first value really does arrive another way; for an ordinary counter, start with the value you mean.

Error 3: a value that cannot change

Chapter 6 drew the line between const and var, and chapter 10 applied it to parameters: a parameter is a name for a value the caller supplied, and Z98 does not let the function change it. The third program tries: 

const std = @import("std");

fn double(n: i32) i32 {
    n = n * 2;
    return n;
}

pub fn main() void {
    std.io.print("double is {}\n", .{double(21)});
}

$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err3 err3.z98
err3.z98:4:4: error[3002]: cannot assign to immutable variable
    n = n * 2;
    ^

Line 4, column 4; the span is the single character n, so there is a single caret. The message is the one chapter 6 met for a const and chapter 11 met for a struct field: immutable. n is a parameter, so it is read-only no matter how convenient changing it in place would be.

The fix is a second name for the second value: 

fn double(n: i32) i32 {
    const doubled: i32 = n * 2;
    return doubled;
}

The parameter n is still there, unchanged; doubled is a new const holding the new value. When a value must change inside a function, declare a local var and copy the parameter into it.

Error 4: a function that does not always return

Chapter 10's rule was short: a function that promises a value owes a value on every path. The fourth program returns on two of the three possible inputs and forgets the third: 

const std = @import("std");

fn sign(n: i32) i32 {
    if (n < 0) return -1;
    if (n > 0) return 1;
}

pub fn main() void {
    std.io.print("sign is {}\n", .{sign(5)});
}

$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err4 err4.z98
err4.z98:3:0: error[3003]: missing return: not all control paths return a value
fn sign(n: i32) i32 {
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The position is line 3, column 0 — the first character of the function itself — and the span is the whole function body, which is why the caret line is much wider than the printed source line. The message is about reachability: the compiler followed the paths, and some path reaches the closing brace without a value. sign returns -1 for negative input and 1 for positive input; input 0 satisfies neither if, so it falls off the end.

The fix is to answer the missing case, exactly as a person reading the function would: 

fn sign(n: i32) i32 {
    if (n < 0) return -1;
    if (n > 0) return 1;
    return 0;
}

The compiler is not guessing that 0 is the missing case; it is telling you that some path has no return. Read the conditions and find the path that slips through.

Error 5: a name declared twice

The last program declares count outside an if and then declares another count inside it. Both names would be legal on their own; the problem is that the second one hides the first: 

const std = @import("std");

pub fn main() void {
    const count: i32 = 3;
    if (count > 0) {
        const count: i32 = 5;
        std.io.print("inner count is {}\n", .{count});
    }
}

$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out/err5 err5.z98
err5.z98:6:14: error[3057]: local declaration shadows an earlier declaration in an enclosing scope
        const count: i32 = 5;
              ^^^^^
note: previous declaration here

Line 6 is the inner declaration, and column 14 is where the inner count begins; the carets mark it. The message uses the word shadows: the new name stands in front of an older one, so inside the if block count would mean the new variable and the outer one could not be reached by name. The note: line is the compiler's hint that an earlier declaration exists: the const count: i32 = 3; in the enclosing block. A note has no file and line of its own; it is an aside attached to the error above it.

The fix is a name that means what it says: 

const count: i32 = 3;
if (count > 0) {
    const inner: i32 = 5;
    std.io.print("inner count is {}\n", .{inner});
}

If the inner block really means to change the outer value, the outer declaration must be a var, and the inner block should assign to it instead of declaring a second name. What Z98 does not allow is one name with two meanings in nested scopes.

The five in one look

Diagnostic What the compiler saw What to write instead
error[20] a name that was never declared declare it, or use the name that exists
error[3014] a variable with no starting value var count: i32 = 0;
error[3002] an assignment to something read-only a new local, or a var declaration
error[3003] a path that leaves a function without a value a return for the missing case
error[3057] a name that hides an enclosing name a different name, or an assignment to the outer one

Check yourself

Answer these before moving on. The first three can be answered from the transcripts above; the rest ask you to read an error and state the fix.

  1. In err1.z98:7:36: error[20]: ..., which line holds the mistake, and which character does the caret point at? Why is the column 36 and not 37?
  2. What does the code in brackets tell you, and what does it not tell you?
  3. Why does error 4's caret line run past the end of the printed source line, while error 3's caret line is a single ^?
  4. State the fix for each of the five errors in one sentence.
  5. A program reports error[3014]: variable must be initialized; use '= undefined' to opt out on the line var total: i32;. What is the fix?
  6. A function fn max(a: i32, b: i32) i32 ends with if (a > b) return a;. The compiler reports error[3003]. Which input falls off the end, and what line would you add?
  7. A block declares const total, and an inner block declares const total again; the compiler reports error[3057] with note: previous declaration here. Which declaration does the note mean?
  8. Fix err4.z98 by adding the missing return, rebuild, and run it. What does it print? Then change the call to sign(0) and rebuild; what prints now?
