Targeting Win9x

This guide turns one .z98 file into a 32-bit Windows 9x executable: it emits the Windows tree with -osw, reads the three build scripts it writes, cross-builds and runs the result on this host with mingw and wine, and states the step that has to happen on the real machine.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • The mingw cross compiler i686-w64-mingw32-gcc and a 32-bit wine prefix at /tmp/wine32. These are what let this host build and run the Windows binary; a host without them can still run the emit step, and the emitted build scripts remain the path on the era machine.
  • The repository checked out, so the committed sample docs/sf/manuals/src/vol3/hello.z98 is present. Every command runs from the repository root, /workspace/znineeight.

The sample

The sample is Volume III's hello, the same source Volume III built for the Linux host and then cross-built for Windows. It uses nothing but std.io.print, so it has no platform import and no #ifdef: -osw chooses the emitted build scripts and headers, not the source. 

const std = @import("std");

pub fn main() void {
    std.io.print("Hello from Z98!\n");
    std.io.print("this is Volume III, chapter 8\n");
    std.io.print("built for the 1998 machine\n");
}

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Create the output folder. The compiler writes its emitted tree there but will not create the folder itself. 

    $ mkdir -p /tmp/manual_osw

  3. Emit the Windows tree. -osw selects the Windows target; -o names the output folder; the last argument is the entry source file. -osl is the Linux target and is the default. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -osw -o /tmp/manual_osw docs/sf/manuals/src/vol3/hello.z98

    The command is silent on success.

  4. Look at what it emitted. There is a paired .c and .h for the program module and for each standard-library module it reaches, the runtime sources and shared headers, and three build scripts: 

    $ cd /tmp/manual_osw && ls -1
build_owc.bat
build_target.bat
build_target.sh
c_exit.c
hello_9C12B390.c
hello_9C12B390.h
net_prelude.h
std_io_59DB29D9.c
std_io_59DB29D9.h
std_net_A15200CC.c
std_net_A15200CC.h
zig_compat.h
zig_pal.c
zig_runtime.c
zig_runtime.h
zig_special_types.h

    The module file names are <source-basename>_<hash>.c and .h; the hash is derived from the module's resolved path, so it changes if you move the tree and you should not hard-code it. net_prelude.h is present because every @import("std") program emits the network module, std_net; that is why the Windows link needs the winsock library below.

  5. Read the build scripts, because they are the whole Windows target. The first is one script with two targets. Its mingw branch is the one this host can run, and it is where the link libraries are chosen: 

      mingw)
    CC=i686-w64-mingw32-gcc
    CFLAGS="-m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign -Wno-implicit-function-declaration -I ."
    LDFLAGS="-m32"
    LIBS="-lwsock32"
    [ -n "$OUT" ] || OUT=prog.exe
    ;;

    -m32 pins the 32-bit ABI, -std=c89 -O0 asks for the dialect the emitted code targets, and -lwsock32 is the winsock library every std importer needs. The script compiles each emitted .c and links the objects in a deterministic modules-then-runtime order (comment and header lines omitted): 

    $CC $CFLAGS -c hello_9C12B390.c
$CC $CFLAGS -c std_io_59DB29D9.c
$CC $CFLAGS -c std_net_A15200CC.c
$CC $CFLAGS -c zig_runtime.c
$CC $CFLAGS -c zig_pal.c
$CC $CFLAGS -c c_exit.c
# Link order: modules first, runtime sources last (intentional).
# The GNU linker is link-order-sensitive; this is our deterministic order,
# not the seed recipe's alphabetical *.o glob.
$CC $LDFLAGS hello_9C12B390.o std_io_59DB29D9.o std_net_A15200CC.o zig_runtime.o zig_pal.o c_exit.o -o "$OUT" $LIBS
echo "Built: $OUT"

    The second script is the MSVC cl build, build_target.bat (comment lines omitted): 

    @echo off
REM build_target.bat - generated by zig1 (MSVC cl)
setlocal
if "%~1"=="" (set OUT=prog.exe) else (set OUT=%~1)
set CFLAGS=/c /Za /W3 /WX /DZIG_WIN32 /I .
echo Compiling...
cl %CFLAGS% hello_9C12B390.c
cl %CFLAGS% std_io_59DB29D9.c
cl %CFLAGS% std_net_A15200CC.c
cl %CFLAGS% zig_runtime.c
cl %CFLAGS% zig_pal.c
cl %CFLAGS% c_exit.c
echo Linking...
link /subsystem:console kernel32.lib hello_9C12B390.obj std_io_59DB29D9.obj std_net_A15200CC.obj zig_runtime.obj zig_pal.obj c_exit.obj wsock32.lib /out:%OUT%
echo Built: %OUT%

    and the third is the OpenWatcom wcc386/wlink build, build_owc.bat (comment lines omitted): 

    @echo off
REM build_owc.bat - generated by zig1 (OpenWatcom wcc386/wlink)
setlocal
if "%~1"=="" (set OUT=prog.exe) else (set OUT=%~1)
echo Compiling...
wcc386 /za /we /dZIG_WIN32 /i=. hello_9C12B390.c
wcc386 /za /we /dZIG_WIN32 /i=. std_io_59DB29D9.c
wcc386 /za /we /dZIG_WIN32 /i=. std_net_A15200CC.c
wcc386 /za /we /dZIG_WIN32 /i=. zig_runtime.c
wcc386 /za /we /dZIG_WIN32 /i=. zig_pal.c
wcc386 /za /we /dZIG_WIN32 /i=. c_exit.c
echo Linking...
wlink system console op q opt stack=65536 file hello_9C12B390.obj,std_io_59DB29D9.obj,std_net_A15200CC.obj,zig_runtime.obj,zig_pal.obj,c_exit.obj library wsock32 name %OUT%
echo Built: %OUT%

    /Za and /za are strict-ANSI switches, the counterparts of -std=c89; /DZIG_WIN32 and /dZIG_WIN32 are the target guard the scripts define; and the MSVC and OpenWatcom links both pull in wsock32. The emitted scripts are the interface to three toolchains, but only mingw is installed here. cl and wcc386 are emitted and documented, not executed on this host; they are the path on the era machine.

  6. Build the Windows executable with the emitted script's mingw branch. Run it from inside the output folder and give it a program name (without the .exe): 

    $ cd /tmp/manual_osw
$ timeout 120 sh build_target.sh mingw hello
Building for mingw...
Built: hello

    The generated C draws a long list of gcc warnings; they are expected and do not stop the build, because the script does not pass -Werror. hello.exe is the result.

  7. Run it under wine. The 32-bit prefix is the one the committed harness uses: 

    $ timeout 120 env WINEPREFIX=/tmp/wine32 WINEARCH=win32 wine hello.exe
Hello from Z98!
this is Volume III, chapter 8
built for the 1998 machine

    This is a real run of the Windows executable, not a claim about Windows 98. The program writes through the C runtime's text mode, so Windows translates each \n into \r\n; the raw captured stdout therefore has a carriage return at the end of every line (^M). The comparison that matters is against the Linux baseline after those carriage returns are stripped.

  8. Use the committed harness for the gated verification. It composes the whole pipeline — emit with -osw, mingw cross-compile and link, wine run, and an LF-normalized byte comparison against a Linux baseline — and prints three verdict lines. Build the Linux baseline first, then point the harness at it: 

    $ mkdir -p /tmp/manual_win/ref
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_win/ref docs/sf/manuals/src/vol3/hello.z98
$ cd /tmp/manual_win/ref && timeout 120 sh build_target.sh linux hello && timeout 120 ./hello > /tmp/manual_win/hello.linuxstdout
$ cd /workspace/znineeight
$ timeout 120 env ZIG1=/tmp/manual_seed/zig1_5_clean PARITY_STRIP_CR=1 \
    WINEPREFIX=/tmp/wine32 WINEARCH=win32 \
    bash scripts/win32_cross/cross_parity.sh \
    docs/sf/manuals/src/vol3/hello.z98 /dev/null \
    /tmp/manual_win/hello.linuxstdout /tmp/manual_win/hello
XRUNRC=0
WINE_RC=0
PARITY=OK

    XRUNRC=0 means the emit and the mingw compile and link all succeeded. WINE_RC=0 means the Windows executable ran to completion under wine. PARITY=OK means the captured stdout matches the Linux baseline once PARITY_STRIP_CR has removed the carriage returns. That is the whole of the Windows verification this host can make.

Verify it worked

The verification is the three verdict lines above: XRUNRC=0, WINE_RC=0, and PARITY=OK. If you prefer to see the raw Windows stdout, it is the wine output in step 7 with a trailing ^M on each line; the LF-normalized copy is byte-for-byte the Linux baseline printed by the same source.

Real machine. The run above is wine on a 32-bit mingw cross-build, not Windows 98. It proves the emitted C89 compiles with a Windows toolchain and that the program logic runs; it does not prove behavior under the era kernel. To take the last step, copy the whole output directory to the Windows machine and run the script that matches the toolchain installed there — build_target.bat for MSVC cl or build_owc.bat for OpenWatcom wcc386/wlink — then run hello.exe from a command.com prompt. Without period hardware, the usual alternative is an emulator such as 86Box, which runs the real operating system on emulated hardware. Common mistakes

  • Forgetting to create the output folder. The compiler requires the folder to exist and fails with error: output directory does not exist: /tmp/manual_osw (exit code 1). Run mkdir -p first.
  • Running the build script from the wrong folder. build_target.sh, build_target.bat, and build_owc.bat all use relative paths and a current-directory include root, so cd into the output folder before running one.
  • Trying to run the .bat scripts on the Linux host. The compiler emits all three scripts on every -osw emit, but cl and wcc386 are Windows toolchains. On this host only the mingw branch of build_target.sh runs; the two .bat files are for the era machine.
  • Linking by hand without -lwsock32. Every @import("std") program emits std_net, so a hand-written mingw link fails with undefined reference to '_imp__recv@16' or '_imp__WSAStartup@8'. The emitted script already passes -lwsock32; prefer running it.
  • Reading the gcc warnings as failure. The mingw build prints hundreds of warnings but succeeds; look for Built: hello, not for an empty error stream.
  • Expecting byte-identical stdout without normalization. The CRT text mode turns \n into \r\n on Windows, so the harness compares an LF-normalized copy and keeps the raw file as evidence. A parity mismatch on carriage returns alone is not an emission bug.
  • Assuming -osw changes the language. It selects the emitted target scripts and headers, not the parser or the type checker. The source-level target predicate, if you need one, is @isWindows(), not a ZIG_WIN32 test in Z98 source.
  • Moving one file instead of the output directory. The emitted program is not a single .c; it is the whole directory of translation units, runtime sources, headers, and the build script. Copy the directory to the era machine, or the link loses the runtime.
