Read, Write, and Check Files

This guide writes a file byte-for-byte and reads it back through the two Z98 file surfaces — the low-level std.io PAL wrapper, which reports failure through an optional, and the higher-level std_file layer, which reports failure through a returned error union — then probes for a path's existence and catches an open failure.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc (the emitted script uses gcc -m32 -std=c89).
  • The repository checked out, so the file fixtures under repro/mi_matrix/stdlib_file*_xmod and the standard-library gate scripts/stdlib/verify_stdlib.sh are present. Every command runs from the repository root, /workspace/znineeight.
  • For the two surfaces and the PAL contract beneath them, keep the Volume IV Standard library and The PAL pages open.

The idea

Z98 ships two file surfaces, and the difference is only in how they report failure. The lower one, std.io (sf/src/std_io.zig), wraps the compiler's Platform Abstraction Layer directly: the four pal_file_* externs are declared in that module and resolve at link time against zig_pal.c. A descriptor is a usize; fileOpen returns ?usize, so null is the only open-failure channel and it is consumed with orelse, never catch. 

pub fn fileOpen(path: []const u8, write_mode: bool) ?usize
pub fn fileWrite(fd: usize, data: []const u8) void
pub fn fileRead(fd: usize, buf: []u8) usize
pub fn fileClose(fd: usize) void

fileWrite writes the whole slice and discards the count. fileRead returns the bytes read, and in v1 that same 0 means both end of file and a read error: there is no separate read-error channel, so fileOpen is the one place an open failure surfaces. There is no delete: the PAL wrapper has no remove primitive.

The higher surface, std_file (sf/src/std_file.zig), is binary-safe and owns the opaque OS handle (CreateFileA on Win32, open(2) on POSIX). Every fallible call returns a FileError!… union that you check with try or catch; readAll allocates the whole file from the arena you pass, and writeAll loops on short writes and flushes. Its error set is one per module: 

pub const FileError = error{ OpenFailed, ReadFailed, WriteFailed,
    SeekFailed, SizeFailed, FlushFailed, RemoveFailed, RenameFailed,
    OutOfMemory };
pub const Mode = enum { Read, Write, Append, ReadWrite };
pub const SeekWhence = enum { Set, Cur, End };

The public names are open, read, write, close, seek, size, flush, exists, remove, rename, readAll, and writeAll. One of them is deliberately different: exists(path) bool is a pure probe with no error channel. It returns false for an absent or inaccessible path and true for a present regular file, and it is never wrapped in catch.

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Round-trip through the low-level std.io PAL surface. The fixture repro/mi_matrix/stdlib_fileio_xmod imports std, opens a temp file in write mode, writes "round trip\n", closes it, reopens it in read mode, reads it back, and asserts the bytes are identical. Run it through the standard-library gate, which emits the fixture, links it with the binding gcc -m32 -std=c89 flag set, runs it three times, and diffs the result byte-for-byte against the committed expected.txt and expected.rc. 

    $ bash scripts/stdlib/verify_stdlib.sh /tmp/manual_seed/zig1_5_clean repro/mi_matrix/stdlib_fileio_xmod

    Its six-line golden is 1, 1, 11, 1, 5, 1: the write-mode open returned a valid handle, the read-mode open did too, 11 bytes came back (the length of "round trip\n"), the buffer compared byte-equal to what was written, findChar found the space at index 5 through its optional and orelse, and a for loop over the slice counted one t.

    stdlib_file_write_xmod opens with f.Mode.Write, writes "hello " and "world" as two calls — each returning FileError!usize, checked 6 then 5 — reads the eleven bytes back with readAll, and prints file write ok. stdlib_file_read_xmod reads 5, then 6, then 0 at end of file (end of file is not an error), and prints file read ok. stdlib_file_exists_xmod asserts false before creation, true after writeAll, and false again after remove, printing file exists ok.

    stdlib_file_openerr_xmod is the returned-error check. It calls f.open(&g_arena, "t_openerr_missing.txt", f.Mode.Read) on a path that does not exist; POSIX open(2) returns ENOENT, the layer maps it to error.OpenFailed, and the fixture catches exactly that value and prints file openerr ok. Only Read mode is a failure path here: Write, Append, and ReadWrite create-or-open by design, so they never fail on a missing path.

    Each prints one … ok line. The seek fixture drives SeekWhence.Set (absolute), .End (from the end, negative offset), and .Cur (relative) and checks the returned absolute offset; size shows the length is stable across a read; close proves a closed handle no longer blocks a rename; flush forces the OS buffer to disk. The stress fixture is the binary contract: it writes a 10000-byte pattern with embedded CR, LF, NUL, and 0xFF bytes at pinned offsets, reads it back in 777-byte chunks to end of file, seeks around it, and overwrites a 500-byte region in place — preserving the bytes before and after. Binary safety is byte-exact, not line-oriented.

Verify it worked

The three gate runs in Steps 2–4 are the recorded measured output of the committed fixtures; re-running the commands reproduces them exactly, and each ends in STDLIB GATE OK and 0 FAIL. Step 2 shows the std.io PAL round-trip: a valid write handle, a valid read handle, 11 bytes back, a byte-equal buffer. Step 3 shows the std_file error-union layer writing and reading with checked counts, probing existence three times around create and remove, and catching error.OpenFailed from a Read-mode open of a missing path. Step 4 pins the remaining operations plus the 10000-byte binary stress round-trip. A passing gate means the emitted program's stdout matched the committed expected.txt byte-for-byte and its exit code matched expected.rc.

Common mistakes

  • Consuming the wrong layer with the wrong operator. std.io.fileOpen returns ?usize, so consume it with orelse; writing catch against an optional is a type error. std_file.open returns FileError!File, so consume it with try or catch; orelse there is wrong. The two surfaces look alike and fail differently.
  • Reading a 0 from std.io.fileRead as a failure. 0 is end of file, and in v1 it is also what a read error returns — there is no separate read-error channel. Use std_file.read when you need error.ReadFailed distinguished from a clean 0-byte end of file.
  • Wrapping exists in catch. std_file.exists returns a plain bool and is a pure probe: false for an absent or inaccessible path, true for a present regular file. There is no error to catch; it tests access(2) on POSIX and GetFileAttributesA on Win32.
  • Assuming open never truncates. Mode.Write maps to O_WRONLY|O_CREAT|O_TRUNC (CREATE_ALWAYS) and destroys any existing content; Mode.ReadWrite maps to O_RDWR|O_CREAT (OPEN_ALWAYS) and opens without truncating; Mode.Append seeks to the end. A Read-mode open of a missing path is error.OpenFailed. If you want to keep what is there, seek before you write.
  • Leaving a handle open before rename or remove. A live handle can block MoveFileA/DeleteFileA on Win32. Call close(&file) first; stdlib_file_close_xmod demonstrates that the rename only succeeds after the close.
  • Assuming std_file.write writes everything. It may return fewer bytes than buf.len; loop on the returned count, or call writeAll, which loops and flushes for you. The write/stress fixtures assert the exact per-call count for this reason.
  • Overflowing the path buffer. std.io.fileOpen copies into a 512-byte stack buffer and returns null for a path of 511 bytes or more; std_file uses a 4096-byte PATH_BUF. Neither creates directories, so a missing parent directory is an error.OpenFailed, not a created tree.
