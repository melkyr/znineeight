HTML style

HTML Style

This page is the manual's HTML contract. Every page is hand-authored to the same skeleton, so the set stays consistent, renders on 1998 browsers, and survives the loss of its stylesheets. Copy the skeleton below, fill in the placeholders, and follow the rules that follow it.

The page skeleton

Copy this block verbatim into a new file, then replace the angle-bracket placeholders with the page's real title, keywords, and neighbour links. Keep the <link rel> order: screen stylesheet, print stylesheet, home, up, prev, next. The sidebar cell carries class="sidebar", the language bar carries class="langbar", and the volume table of contents carries id="toc"; those are the hooks the print stylesheet and doc.js use. 

<!DOCTYPE HTML PUBLIC "-//W3C//DTD HTML 4.0 Transitional//EN"
  "http://www.w3.org/TR/REC-html40/loose.dtd">
<html lang="en">

<meta http-equiv="Content-Type" content="text/html; charset=iso-8859-1">

<meta name="keywords" content="&lt;KEYWORDS&gt;">

<link rel="stylesheet" type="text/css" href="z98-print.css" media="print">

The rules

Doctype and encoding

The doctype is HTML 4.0 Transitional, exactly as shown, and pages are authored in the conservative HTML 3.2/4.0 intersection: nothing a 1998 browser cannot parse. The encoding is ISO-8859-1, declared with <meta http-equiv="Content-Type" content="text/html; charset=iso-8859-1">. Do not use UTF-8 for the English edition. The root element carries lang="en".

No <div>; tables for layout

Structure is carried by tables, never by <div>. The page body is the three-column table in the skeleton: a 160-pixel sidebar, a one-pixel gutter, and the content column. Do not use the HTML5 structural elements: 

<section>  <article>  <nav>  <header>  <footer>  <main>  <figure>
<div>

None of these existed in 1998. A browser of the era ignores them, and the layout collapses without the table.

Baseline appearance

Appearance that matters is carried by presentational attributes, not by CSS: bgcolor, text, link, vlink, alink, align, width, border, cellpadding, cellspacing, and valign, together with <font>, <b>, <i>, and <center>. With both stylesheets removed the page must remain legible, navigable, and correctly ordered.

CSS as progressive enhancement

CSS is optional decoration. It ships as two external linked stylesheets: z98.css for the screen and z98-print.css for print, linked with media="print". Both are CSS1 only; there is no CSS2 or CSS3. Do not write inline <style> blocks: a pre-CSS browser would render their text as body content. If a style block is ever unavoidable it must be wrapped in SGML comments, but the manual has none. CSS carries no meaning and no layout.

JavaScript

There is exactly one behaviour script, doc.js, loaded at the end of the body with <script type="text/javascript" src="doc.js"></script>. It contains four functions: swap, tocToggle, doSearch, and preload. It does not use document.write and does not sniff the browser. Every feature degrades to working HTML; the manual is fully usable with JavaScript switched off.

Assets

Images are GIF only: no PNG, no SVG, no web fonts. Keep the exact sizes: logo 240×48, bullets 8×8, icons 16×16, buttons 88×24 plus a -over rollover pair, navrule 150×8. The icon set is note, tip, warn, caution, era, and honest. XBM alternates for the button GIFs live in gfx/xbm/.

Admonitions

Five callouts are defined: note, tip, warn, caution, and honest. Each is a table with its 16×16 icon and a coloured background. The honesty callout uses the warmer background #ece0e0 so a reader recognises the manual being straight with them.

Note. A neutral aside: something true that the reader does not need in order to proceed.
Tip. A shortcut or a habit that makes the material easier to work with.
Warn. Something that will bite if ignored, but is not dangerous.
Caution. A mistake that costs data, time, or a rebuild.
Honest note. The manual being straight with you: friction, a limitation, or the case for another tool.

Terminal transcripts

Output captured from a real run is rendered in a <pre> block, monospaced and unadorned. Never invent a transcript; capture it and paste it verbatim. 

$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out hello.z98
$ cd /tmp/manual_out && sh build_target.sh linux hello
$ ./hello
Hello from Z98!

Win9x figure placeholders

A Win9x screenshot that has not yet been captured is reserved with a dashed-border box that names the figure and says what is missing. The box is a table carrying class="placeholder"; z98.css supplies the dashed border, and the presentational border="1" keeps a solid box when the stylesheet is absent. The operator captures the real screenshot on real hardware later.

Figure N — Win9x screenshot pending

Every on-page placeholder must have exactly one matching row in the pending figure list, and every row there must have exactly one on-page placeholder. A figure that appears in neither place is a gap; a placeholder without a row, or a row without a placeholder, is an orphan. Terminal transcripts are not listed in that file; they live on the page in a <pre> block.
