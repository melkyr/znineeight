Grouping data

The last chapter gave a block of steps a name. This chapter gives related values a home. A point on a grid is two numbers that belong together: the column and the row, or x and y. Held in two separate variables they can drift apart, and every function that wants the point has to take both. Z98 groups them into one value with a struct: a named shape with named parts, called fields. A value of the shape travels as a single argument, and a dot selects the part you want. The chapter adds the keyword struct, and it gives the dot you already know from std.io.print a second job: naming a field inside a value.

The program

const std = @import("std");

const Point = struct {
    x: i32,
    y: i32,
};

fn sum(p: Point) i32 {
    return p.x + p.y;
}

fn shifted(p: Point, dx: i32, dy: i32) Point {
    return Point{ .x = p.x + dx, .y = p.y + dy };
}

pub fn main() void {
    const origin = Point{ .x = 0, .y = 0 };
    std.io.print("origin is ({}, {})\n", .{ origin.x, origin.y });

    const corner = Point{ .x = 3, .y = 4 };
    std.io.print("corner is ({}, {})\n", .{ corner.x, corner.y });
    std.io.print("corner sums to {}\n", .{sum(corner)});

    var cursor = Point{ .x = 10, .y = 20 };
    cursor.x = cursor.x + 5;
    std.io.print("cursor moved to ({}, {})\n", .{ cursor.x, cursor.y });

    const far = shifted(corner, 100, 200);
    std.io.print("far is ({}, {})\n", .{ far.x, far.y });
    std.io.print("sizeOf(Point) is {}\n", .{@sizeOf(Point)});
}

It defines a type called Point, builds four values of it, prints their fields, changes one field, and passes points to two functions. sum takes a point and answers with the sum of its fields. shifted takes a point and two offsets and returns a new point, with both fields moved. The last line asks the compiler how many bytes the shape takes: 8, four for each i32.

Declaring a struct

A struct declaration lists the fields and their types between braces: 

const Point = struct {
    x: i32,
    y: i32,
};

Read it piece by piece. const names the declaration, exactly as it names a value in chapter 6, but here the name is a type: Point. struct is the keyword that starts a group of named fields. The braces hold the field list; each line inside is one field, written name: type, in the style of a variable declaration without var or const. The semicolon after the closing brace ends the whole declaration.

The declaration itself stores no numbers. struct describes a shape; values of that shape are made later, one construction at a time. Z98's rule is that an aggregate type declaration must be named with const; the name is how the rest of the program writes the type. The Common mistakes section shows what the compiler says when the const is left out.

Because the fields are stored in the order they are declared, the shape has a size. Point holds two i32 fields, so @sizeOf(Point) is 8: four bytes for x, then four bytes for y, the sizes chapter 6 printed. That is also why field order is worth thinking about before the type is used: it is the order the values sit in memory.

Making a Point

Construction writes the type's name and then one .field = value for each field: 

const origin = Point{ .x = 0, .y = 0 };
const corner = Point{ .x = 3, .y = 4 };

The dot in front of a field name marks it as a field, and the value after the equals sign is stored there. Both fields are written by name, so the order does not matter: Point{ .y = 4, .x = 3 } makes exactly the same value as Point{ .x = 3, .y = 4 }. That is the point of naming them; the reader, and the compiler, never has to remember a positional order.

There is a shorter form once the type is already written on the left of the equals sign: 

const p: Point = .{ .x = 3, .y = 4 };

Here the annotation : Point supplies the type, so the literal leaves it out. It is the same brace-and-dot literal you have been writing around print arguments; beside a type, the literal fills in that type's fields.

Reading and changing a field

A field is read with a dot and the field's name: 

std.io.print("corner is ({}, {})\n", .{ corner.x, corner.y });

corner.x is an expression like any other: it can be printed, stored, passed as an argument, or used in arithmetic. The dot here means "the x inside corner", just as the dot in std.io.print means "print inside io". A dot always names something inside; what stands before it decides whether that is a module or a value.

The fields of a var can be assigned like the var itself: 

var cursor = Point{ .x = 10, .y = 20 };
cursor.x = cursor.x + 5;

The right side is computed first and then stored into the x field. y is untouched, because assigning to one field changes that field and nothing else. A const struct is read-only down to its fields; the Common mistakes section shows the message that answers an assignment to one.

Structs as parameters and results

A struct is an ordinary value, so it goes where an i32 goes: into a parameter, out of a return: 

fn sum(p: Point) i32 {
    return p.x + p.y;
}

fn shifted(p: Point, dx: i32, dy: i32) Point {
    return Point{ .x = p.x + dx, .y = p.y + dy };
}

sum takes one argument instead of two, because the point carries its fields with it. shifted builds a new point and returns it; the return type is written Point, the name declared at the top of the file. Inside the body, p.x reads a field of the parameter. Writing p.x = ... there would not compile: parameters are read-only, the rule of chapter 10, and the rule reaches the parameter's fields too. When a point must change, a function returns a new point built from the old one, as shifted does; when the caller owns a var, the caller assigns to the field directly, as the program does with cursor.

corner is (3, 4)
corner sums to 7
cursor moved to (15, 20)

Read the output against the source. The first two lines print the fields of the constructed points: origin is (0, 0) and corner is (3, 4). corner sums to 7 is sum(corner), 3 + 4. cursor moved to (15, 20) is the one field that changed, 10 + 5. far is (103, 204) is the new point shifted returned, 3 + 100 and 4 + 200. The last line is the size of the shape. The program exits with status 0.

Common mistakes

These are the mistakes a first struct attracts. Three of them are reported by the compiler; the first is a rule of the language rather than a message, and it is the habit other languages bring.

There are no methods. In Z98 a dot means "a name inside": std.io.print names print inside the module io, and corner.x names the field x inside the value corner. It never means "a function that belongs to this value". Functions are not attached to struct values: the value is handed to the function as an argument, which is why the program writes sum(corner). Every function you write for a struct is an ordinary function that takes the struct as a parameter, exactly like sum and shifted.

Writing the fields without names. A C programmer's hand reaches for a positional list, and Z98's parser stops at the first value: 

const Point = struct { x: i32, y: i32 };

pub fn main() void {
    const p = Point{ 3, 4 };
}

order_mistake.z98:4:21: error[2000]: expected '}' but found integer literal
    const p = Point{ 3, 4 };
                     ^
order_mistake.z98:4:21: error[2000]: unexpected token
    const p = Point{ 3, 4 };
                     ^
order_mistake.z98:5:0: error[2000]: expected expression
}
^
order_mistake.z98:5:0: error[2000]: unexpected token
}
^

The first line names the problem: after Point{ the parser wanted a }, because a struct literal is a list of named fields, and found the 3 instead. The lines after it repeat the complaint at the same spot and then show the recovery: with the stray token left behind, the parser looks for an expression at the closing brace. The fix is to name every field, in any order: Point{ .x = 3, .y = 4 } or Point{ .y = 4, .x = 3 }, both the same value.

Assigning to a field of an immutable struct. A const struct cannot change, and neither can its fields: 

const Point = struct { x: i32, y: i32 };

pub fn main() void {
    const p = Point{ .x = 3, .y = 4 };
    p.x = 5;
}

field_mistake.z98:5:6: error[3002]: cannot assign to immutable variable
    p.x = 5;
      ^

The caret points at the field name, and the message is the one chapter 6 met for a const variable: immutable. The same error answers an assignment to a field of a parameter, because parameters are read-only too. The fix depends on who owns the value: declare it with var if it must change (var p = Point{ .x = 3, .y = 4 };), or return a new struct instead of changing an incoming one.

Declaring a struct without const. The C spelling leaves off the name binding, and the compiler reports the missing name at the place that uses it: 

struct Point {
    x: i32,
    y: i32,
};

pub fn main() void {
    const p = Point{ .x = 3, .y = 4 };
}

struct_mistake.z98:7:4: error[3000]: cannot declare variable of type void
    const p = Point{ .x = 3, .y = 4 };
    ^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^
struct_mistake.z98:7:14: error[20]: identifier 'Point' is not declared or imported in this module
    const p = Point{ .x = 3, .y = 4 };
              ^^^^^

The error[20] line is the one that names the real problem: nothing in the file declared a name called Point. The struct line describes a shape, but without const it never binds the shape to a name, so the rest of the file has no type to use. With no type for the declaration, the compiler's first line reports what it saw instead: error[3000]: cannot declare variable of type void. Read both lines together, and write the declaration the named way: const Point = struct { ... };.

Check yourself

Answer these before moving on. The last three ask you to change the program and run it.

  1. What does const Point = struct { x: i32, y: i32 }; do when it runs? What is Point afterwards, and how many numbers does it hold?
  2. In Point{ .x = 3, .y = 4 }, what do the dots mark? Does the order of the two fields matter, and why is the answer the same in memory either way?
  3. How many bytes does Point take, and how is that number related to the declarations of its two fields?
  4. What does corner.x mean? How is that dot the same kind of dot as the one in std.io.print?
  5. Why is cursor.x = cursor.x + 5; accepted while p.x = 5; on a const point is rejected? What about a parameter's field?
  6. What does sum(corner) return? How many arguments does sum take?
  7. Change shifted(corner, 100, 200) to shifted(corner, -100, -200), rebuild, and run. What is printed now? Predict before you run.
  8. Add a field z: i32 to Point, give it a value in every construction, and print it for far. Rebuild and run. What is the new @sizeOf(Point)?
  9. Write fn double(p: Point) Point that returns a point whose fields are each multiplied by two, call it from main with corner, and print the fields of the result. What is printed?
