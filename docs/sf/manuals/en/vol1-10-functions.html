Functions

The last chapter gave the program a loop, which repeats steps inside one place. A loop still belongs to the one spot where it is written. This chapter gives a block of steps a name, so the rest of the program can ask for that job whenever it needs it. The name is a function. It takes input values, called parameters, does its work, and hands a return value back to whoever called it. The chapter also adds pub, the word that marks a function as part of the module's public surface, and it explains why the values a call passes in cannot be rewritten inside the function.

The program

const std = @import("std");

fn add(a: i32, b: i32) i32 {
    return a + b;
}

fn max(a: i32, b: i32) i32 {
    if (a > b) {
        return a;
    }
    return b;
}

fn show(n: i32) void {
    std.io.print("show({}) prints this\n", .{n});
}

pub fn square(n: i32) i32 {
    return n * n;
}

pub fn main() void {
    const sum = add(2, 3);
    std.io.print("add(2, 3) is {}\n", .{sum});

    std.io.print("max(4, 9) is {}\n", .{max(4, 9)});
    std.io.print("max(12, 3) is {}\n", .{max(12, 3)});

    const nine_squared = square(9);
    std.io.print("square(9) is {}\n", .{nine_squared});

    std.io.print("square(10) is {}\n", .{square(10)});

    show(7);
    std.io.print("add(20, 22) is {}\n", .{add(20, 22)});
}

It defines four functions and calls each of them from main. add takes two numbers and returns their sum. max takes two numbers and returns the larger one, using the if of chapter 8 to pick between its two return statements. show takes one number, prints a line, and returns nothing at all — its result type is void. square is a pub fn, the public kind. The body of main mixes calls with prints: the results of add, max, and square are printed, and show(7); does its own printing while returning nothing.

Declaring a function

A function declaration gives a name to a block, and describes exactly what goes in and what comes out: 

fn add(a: i32, b: i32) i32 {
    return a + b;
}

Read it piece by piece. fn starts the declaration. add is the function's name — the name a caller writes. The parentheses hold the parameter list: a: i32 says the first parameter is named a and holds an i32, and b: i32 says the same for the second. After the closing parenthesis comes the result type, here i32: the kind of value the function hands back. The braces hold the body, the steps that run when someone calls the function. The last of those steps is return a + b;, which ends the call and sends the sum back.

The caller writes the name and supplies one value, called an argument, for each parameter, in order. In add(2, 3) the 2 goes into a and the 3 goes into b. A call is an expression: it can be stored in a variable, printed, or passed as an argument. The program uses calls in both roles: 

const sum = add(2, 3);
std.io.print("max(4, 9) is {}\n", .{max(4, 9)});

The first line stores the returned 5 in sum. The second passes the value returned by max straight into print, inside the argument tuple where a number would go.

Note. A function may be called before its declaration appears in the file. main comes last in the program and calls everything above it, but that order is a reading choice, not a rule: the compiler reads the whole file before it builds the program, so declaration order does not matter.

Parameters are read-only

A parameter is the function's own name for one argument. It exists only for the duration of the call, and Z98 treats it as read-only, exactly like the const names of chapter 6. This function does not compile: 

fn bump(n: i32) i32 {
    n = n + 1;
    return n;
}

The compiler rejects the assignment inside bump, because parameters and loop captures share one rule: every value a call puts into a function is immutable. There is a reason. A parameter is not the caller's variable; it is a value handed in for this one call. If the body could overwrite it, the function's first lines could change the meaning of the very value the name described, and the signature at the top would no longer tell the truth about what the body works with. Z98 closes that door: values in, one value out. A function that needs a number it can change declares a local var and copies the parameter into it: 

fn bump(n: i32) i32 {
    var result = n;
    result = result + 1;
    return result;
}

result is an ordinary local variable, so it can change; n is the incoming value and stays as it arrived. bump(4) returns 5. The same trick applies to counters and running totals: copy the parameter into a var on the first line that needs one. Chapter 9's loop captures obey the same rule, which is why that chapter's running totals live in vars declared outside the loop.

Returning a value

return expression; does two things at once: it computes the expression and ends the call, handing the value back to the caller. Nothing after it on that path runs. max shows what that means when a function has more than one way out: 

fn max(a: i32, b: i32) i32 {
    if (a > b) {
        return a;
    }
    return b;
}

On max(4, 9) the test 4 > 9 is false, so the first return is skipped and the second one sends back 9. On max(12, 3) the test is true, the first return sends back 12, and the second line never runs. Exactly one of the two returns finishes a call; that is how one function can answer with different values. The choice itself is just the if from chapter 8, which means a function body is a block like any other and may use everything the earlier chapters taught.

A function that has no value to send back writes void where the result type would go. show is that kind: 

fn show(n: i32) void {
    std.io.print("show({}) prints this\n", .{n});
}

void is the type that means "no value", as chapter 5 put it: nothing comes back. There is no result to store or print, so a call to a void function is written as a statement by itself — show(7); in the program. Falling off the end of a void function is fine, just as main falls off its end when the last print is done. A function with any other result type must return a value on every path; the Common mistakes section shows what the compiler says when one does not.

pub fn: the public kind

The program writes pub fn square(n: i32) i32. pub marks the function as part of the module's public surface — a name the file offers to the rest of the program. The standard library is built that way: std.io.print is a pub fn inside its module. The program's other functions are written without the keyword; they are this file's own helpers.

Inside a single file, pub changes nothing at the call site: main calls add, max, show, and square in exactly the same way. The keyword's effect lives at the edge of a module — how other files see this one — and the manual returns to it when programs grow beyond a single file.

main itself is public. pub fn main is the entry point, the function the toolchain looks for to start the program. The manual has written it that way since chapter 5, and the compiler builds the C entry point of the whole program around it.

Building and running it

The commands are the ones from the last four chapters, with functions in place of count. The compiler is still at /tmp/manual_seed, built in chapter 4: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/functions.z98
$ cd /tmp/manual_out && sh build_target.sh linux functions
Building for linux...
Built: functions
$ ./functions
add(2, 3) is 5
max(4, 9) is 9
max(12, 3) is 12
square(9) is 81
square(10) is 100
show(7) prints this
add(20, 22) is 42

Read the output against the source. The value-returning calls account for six of the seven lines: add(2, 3) is 5; max picked 9 for the first call and 12 for the second; square(9) is 81 and square(10) is 100; and the last line is the first function called with new arguments, add(20, 22) is 42. The sixth line is the one call that prints from inside the function: show(7) returns nothing, but its body still prints. The program exits with status 0.

Common mistakes

These are the mistakes a first function attracts. Three of them are reported by the compiler; the first is a habit from other languages that Z98 meets with a different shape.

Calling with a dot: there are no methods. In Z98 a dot means "a name inside", the way std.io.print names print inside the module io. It never means "a function that belongs to this value". Functions are not attached to values: the value is handed to the function as an argument. Write square(nine), not nine.square(). The same goes for add, max, show, and every function you will write.

Assigning to a parameter. The parameter is read-only, so this function is rejected: 

fn bump(n: i32) i32 {
    n = n + 1;
    return n;
}

param_mistake.z98:2:4: error[3002]: cannot assign to immutable variable
    n = n + 1;
    ^

The caret points at the parameter name, and the message names the rule: immutable. The fix is the one from earlier in the chapter: declare a local var, copy the parameter into it, and change the copy (var result = n;). The rule covers every parameter of every function, and chapter 9's loop captures behave the same way.

Forgetting the return. A function like half promises an i32 in its signature, but its body has no return: 

fn half(n: i32) i32 {
    n / 2;
}

Computing n / 2 and then doing nothing with it is not returning it, so the compiler refuses the function: 

return_mistake.z98:1:0: error[3003]: missing return: not all control paths return a value
fn half(n: i32) i32 {
^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^^

The message is exact: a path through this function reaches the closing brace with no value to send back. The caret spans the signature — the place that made the promise. Add return n / 2; and the function is whole. When the compiler reports error[3003], look for a path that can fall off the end, usually a missing final return or an if whose branch does not end.

Using the result of a void function. show returns nothing, so there is no value to store. Asking for one is rejected: 

const x = show(3);

void_mistake.z98:8:4: error[3000]: cannot declare variable of type void
    const x = show(3);
    ^^^^^^^^^^^^^^^^^^

The message names the problem exactly: a variable cannot have the empty type. A void function's call is a complete statement by itself: write show(3); and let the work happen. If you truly need a value back, the function must be declared with a result type other than void, and it must return that value.

Check yourself

Answer these before moving on. The last three ask you to change the program and run it.

  1. In the declaration fn add(a: i32, b: i32) i32, what are the three pieces after fn — the name, the parameters, and the part after the parenthesis?
  2. What does return a + b; do? What runs after it on the same path?
  3. How many of max's two return statements run during one call to max(4, 9), and which one?
  4. Why is n = n + 1; inside a function rejected? What can the function do instead when it needs a number it can change?
  5. What does show return, and how do you call a function that returns nothing?
  6. What does pub mark, and where does the marking matter? Why does main carry it?
  7. Change square(10) to square(12), rebuild, and run. What is printed now? Predict before you run.
  8. Add a function fn triple(n: i32) i32 { return n * 3; }, rebuild, and call it from main with 14. What is printed?
  9. Change max(12, 3) to max(3, 12), rebuild, and run. Which line of the program changed, and why does the output stay the same?
