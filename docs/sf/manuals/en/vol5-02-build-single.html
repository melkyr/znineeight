One .z98 to an Executable

This guide compiles a single-file Z98 program to C89, links it with the emitted script, and runs the native executable.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc (the emitted script uses gcc -m32 -std=c89).
  • The repository checked out, so the shipped sample docs/sf/manuals/src/vol1/hello.z98 is present. Every command runs from the repository root, /workspace/znineeight.

The sample

The program is the hello from Volume I, kept at docs/sf/manuals/src/vol1/hello.z98: 

const std = @import("std");

pub fn main() !void {
    std.io.print("Hello from Z98!\n");
}

The compiler is not an interpreter. It translates the file to C89; you compile that C with the C compiler already on the machine, and then run the result.

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Create the output folder. The compiler writes its emitted tree there but will not create the folder itself. 

    $ mkdir -p /tmp/manual_out

  3. Translate the program to C89. -o names the output folder; the last argument is the source file. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/hello.z98

    This writes a self-contained tree into /tmp/manual_out: the generated per-module .c/.h files, a copy of the runtime (zig_runtime.c, zig_pal.c, zig_compat.h and its headers), and a build script named build_target.sh. A success is silent: the command prints nothing and exits 0.

  4. Build the executable. Run the emitted script from inside the output folder and give it the target linux and the program name hello. 

    $ cd /tmp/manual_out
$ timeout 120 sh build_target.sh linux hello
Building for linux...
Built: hello

    The script invokes gcc -m32 on the generated C and links the runtime. The Building for linux... and Built: hello lines are its own report. The generated C draws a long list of gcc warnings; they are expected and do not stop the build, because the script does not pass -Werror. A successful build still ends with Built: hello.

  5. Run it. 

    $ timeout 120 ./hello
Hello from Z98!

Verify it worked

A clean run produces exactly this transcript, with the gcc warning text omitted. The emit prints nothing, the build script reports Built: hello, and the program prints its one line. 

$ cd /workspace/znineeight
$ mkdir -p /tmp/manual_out
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/hello.z98
$ cd /tmp/manual_out && timeout 120 sh build_target.sh linux hello
Building for linux...
Built: hello
$ timeout 120 ./hello
Hello from Z98!

The compile-to-C89 step is silent on standard output; the build script reports Building for linux.../Built: hello, and its gcc warnings go to standard error. ./hello prints Hello from Z98! and exits 0.

The Windows (-osw) variant

To emit for 32-bit Windows instead of Linux, add -osw. The same command produces a self-contained tree with the Windows build scripts: 

$ timeout 120 /tmp/manual_seed/zig1_5_clean -osw -o /tmp/manual_out_osw docs/sf/manuals/src/vol1/hello.z98

The output adds build_target.bat and build_owc.bat beside build_target.sh; a net_prelude.h is present in both the Linux and Windows emitted trees. Every @import("std") program emits the network module, so its Windows link needs the winsock library: the mingw branch of build_target.sh passes -lwsock32, and the .bat scripts link wsock32.lib (MSVC) or library wsock32 (OpenWatcom). On this host the Windows build runs through the committed cross-compile harness. The full procedure is the guide Target Win9x (planned), and Volume III carries the measured Win9x build and run.

Common mistakes

  • Forgetting to create the output folder. The compiler requires the folder to exist and fails with error: output directory does not exist: /tmp/manual_out (exit code 1). Run mkdir -p first.
  • Running the build script from the wrong folder. build_target.sh uses relative paths to the generated files, so cd into the output folder before running it.
  • Naming the target wrong. The script takes the operating system (linux, or mingw for Windows) and then the program name: sh build_target.sh linux hello.
  • Reading the gcc warnings as failure. The build prints hundreds of warnings but succeeds; look for Built: hello, not for an empty error stream.
  • Expecting a binary named zig1. The rebuilt compiler is zig1_5_clean, and the produced program is named after the argument you pass to the build script (hello).
