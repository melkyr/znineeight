Error expressions

Error expressions are the operators and capture forms that consume an error union or an optional inside a larger expression: try, catch, orelse, and the if/while capture. This page is the lookup for each form, the capture it binds, the value it yields, and the diagnostics that bound it. The ?T type itself is on the Optionals page; the error-union type and error.Name literals are on the Errors page.

Authority: the parser parses try at the prefix level (parser.zig:869-875) and catch/orelse as the two loosest right-associative infix levels (catch 3, orelse 2; parser.zig:2198-2202, :2229); the if/while capture node is parserParseIfStmt (parser.zig:1789) and parserParseWhileStmt (:1867); the semantic rules are semantic_analyzer.zig:3502-3573 (try), :3574 (orelse), :3787 (value if), :5109 (catch), :5662 (condition/capture type); the capture binding is bindOptionalCapture (lower.zig:3676). Every rule below was reproduced on the fixed compiler (md5 0b8c3e4ac0b1fc49c0bdf8caf9d39945) unless the text says otherwise; reused fixtures are named where one exists.

try: propagate the error

try expr unwraps an error union: on a success it yields the payload, on an error it returns that error from the current function. It is a prefix operator, so it binds its operand more tightly than any infix operator. 

fn mightFail() !i32 { return error.Bad; }

fn callIt() !i32 {
    const val = try mightFail();   // error returns; success yields the payload
    return val + 1;
}

The enclosing function is checked, level-0 error[3075], in this order:

Prong Message (verbatim) Note
try outside any function (module initializer) 'try' outside function scope —
operand is not an error union expected error union type, found '<kind>' consider omitting 'try'
enclosing function does not return an error union expected type '<ret-kind>', found error set function cannot return an error
operand set is not a subset of the function's set try error set may not be compatible with the enclosing function's return type —

<kind> is the operand's kind (comptime_int, void, i32, optional, …); <ret-kind> is the enclosing return kind. Each prong is deduped per try node and emits zero .c on reject. 

fn g() E!void { return error.Boom; }
fn bad1() void { try g(); }
// error[3075]: expected type 'void', found error set
// note: function cannot return an error

fn bad2() i32 { return try 5; }
// error[3075]: expected error union type, found 'comptime_int'
// note: consider omitting 'try'

const ctry = try g();
// error[3075]: 'try' outside function scope

The set comparison is set-only: payloads need not match, so an E!void operand in an E!i32 function is legal, and a named set versus an anonymous !T set (error_set == 0) always passes. A function with a non-error-union return is rejected unconditionally, because the opaque anonymous side cannot be distinguished from an empty set; the Zig-valid empty-inferred-set shape is a documented bounded divergence (docs/reference/Language_Spec_Z98.md §7.2). The positive contract is pinned by repro/mi_matrix/stdlib_try_return_type_ok_xmod (stdout 41 12 11 11 13 33 77 ok); the four reject prongs by repro/mi_matrix/try_return_type_reject_xmod (rc 2, 0 .c, 3075 9).

Note the binding: an unparenthesized try g() catch 5 parses as (try g()) catch 5, so it reports the enclosing-return rule; write try (g() catch 5) to make the operand the catch result.

catch: handle the error

expr catch |err| fallback evaluates expr; on success the payload is yielded and the fallback is not evaluated; on error the tag is bound to err and the fallback is evaluated. The result type is the payload type of the operand, and the fallback must produce that type or diverge (return, break, …). catch is right-associative, so a catch b catch c is a catch (b catch c).

Form Meaning (measured)
eu catch |err| expr Binds the error tag; err is typed as the union's error set (err: E for E!T).
eu catch expr Capture omitted; the fallback is evaluated on the error path.
eu catch { ... } Block fallback; use return/break to diverge, or make the block yield the payload type.
eu catch unreachable Accepted; a live trap (pal_trap) on the error path, not a no-op. 
const res = mightFail() catch |err| {
    if (err == error.Bad) return 0;
    return 1;
};

On a named set the capture is an ordinary error-set value: it prints with {} as error.Name and rejects an explicit {d}/{x} with error[3013], like any other error-set value. On a bare !T union (no named set) the capture keeps the numeric i32 code — a documented residual. The success and error fallback paths are pinned by repro/mi_matrix/eu_val_catch and eu_err_catch; the named-set capture print by repro/mi_matrix/stdlib_errset_capture_qualified_xmod (direct=error.Bar, cap=error.Bar, xcap=error.Bar).

orelse: the optional fallback

expr orelse fallback yields the payload on the present path and evaluates the fallback on the null path. It requires an optional operand; an error union is handled with catch. The result type is the payload type, the fallback must produce that type or diverge, and orelse is right-associative.

Form Meaning (measured)
opt orelse value Value fallback; the payload or value.
opt orelse { ... } Block fallback; make it yield a value or diverge.
opt orelse return X The current function exits with X on null.
opt orelse unreachable Accepted; a live pal_trap() on the null path (rc 133), not a no-op.
non-opt orelse ..., or an error-union operand error[3016] orelse requires an optional operand; use 'catch' for error unions. 
var a = maybe(5) orelse 0;             // 5
var b = maybe(-1) orelse 99;           // 99
var c = maybe(7) orelse unreachable;   // 7
var d = useReturn(-1) orelse 88;       // 88 (the fallback returns)
var e = useBlock(-1) orelse 77;        // 77 (the fallback block returns)

The value, block, unreachable, and return fallbacks are pinned by repro/mi_matrix/orelse_optional_control_xmod (printed lines 5, 99, 7, 88, 77); the non-optional reject by repro/mi_matrix/orelse_requires_optional_xmod (rc 2, zero .c) and the trap by trap_orelse_unreachable_xmod (rc 133). A block fallback supplies the fallback value; a block that neither yields a value nor diverges cannot be used as a value. In a value position (a typed var/const, a return, or a nested expression) it is a clean level-0 reject, error[3059] orelse block fallback without a value cannot be used as a value (Volume IV Amendment A9); an empty fallback block (orelse {}) is rejected the same way (Zig 0.15.2: expected type 'i32', found 'void'). The direct _ = discard and a bare-statement use stay accepted. Write a value or make the block diverge.

Capture: if (opt) |v|, while (opt) |v|

A capture binds the unwrapped value of its condition. The condition must be an optional; an error-union condition is not supported (see the next section) — anything else is rejected. The binding is an immutable copy — reassign the source, never the capture.

Form Meaning (measured)
if (opt) |v| ... else ... Binds v (payload type) on present; the else arm runs on null.
if (opt) |v| expr else expr Value form; the else arm is required when the result is used.
while (opt) |v| ... Loops while the optional is present; ends when it becomes null.
if (cond) |v|, cond not an optional error[3058] capture condition must be an optional or error union type (a non-capturable condition; an error-union condition instead gets the dedicated reject below).
if (non-bool), no capture error[3058] condition must be of type 'bool'.
assigning through |v| error[3002] cannot assign to immutable variable. 
if (lookup(head, 20)) |e| {
    std.io.print("value {}\n", .{e.value});
} else {
    std.io.print("missing\n", .{});
}

const a = if (get(3)) |x| x else 0;   // value form: else is required

var cur: ?i32 = 0;
while (cur) |v| {
    sum = sum + v;
    cur = next(v);                    // reassign the loop variable, not v
}

The capture is scoped to the then-arm (and to each loop body). A use in the else arm is a compile error — the capture does not exist there (Zig use of undeclared identifier; Amendment A7 scopes the current build to match). A value if with no else and a non-void type is error[3059] unless its condition is comptime-known true. A non-diverging value-less orelse block in a value position reuses error[3059] with the orelse-tailored message (Volume IV Amendment A9; see the optionals page and the diagnostic index).

Capture over an error union: not supported

An error-union condition may not be captured. There is no payload or error binding, and the Zig error arm else |e| does not parse. Use catch (with an error capture), a switch (eu), or orelse on an optional instead.

Form Rule (measured)
if (eu) |v| ..., while (eu) |v| ... Rejected: error[3058] error union capture is not supported; use 'catch', 'switch', or 'orelse'. rc 2, no C emitted.
if (eu) |v| ... else |e| ... Rejected: error[2000] expected expression at the else | arm (the error arm is not implemented).
if (opt) |v| ... else ... Accepted; the ordinary optional capture above is unaffected.
if (cond) |v|, cond not an optional error[3058] capture condition must be an optional or error union type. 
// Supported: capture an optional.
var maybe: ?i32 = 3;
if (maybe) |v| {
    std.io.print("got {}\n", .{v});
} else {
    std.io.print("none\n", .{});
}

// Not supported: an error-union condition capture. Use `catch` instead.
// if (h(flag)) |v| { ... }                  // error[3058]
// if (h(flag)) |v| { ... } else |e| { ... } // error[2000]
const v = h(flag) catch |e| {
    std.io.print("err {}\n", .{e});
    return;
};
_ = v;

Residual (parked). Zig 0.15.2 accepts if (eu) |v| ... else |e| ... (and the while form), binding the payload v: T on success and the error e: E on failure; Z98 does not implement that form yet. The no-else form is rejected by both: Zig reports expected optional type, found 'E!T', Z98 reports the error[3058] above. The Zig else |e| parity gap is documented here as a deferred residual (Amendment A8, reduced to reject-only).

orelse, catch, and try precedence

try is a prefix operator and binds more tightly than every infix operator. catch (level 3) binds tighter than orelse (level 2); both are right-associative. The full table is on the grammar page.

Written Parses as
try f() + 1(try f()) + 1
try f() catch d(try f()) catch d
a catch b catch ca catch (b catch c)
a orelse b orelse ca orelse (b orelse c)
a orelse b catch ca orelse (b catch c)

As measured, catch and orelse sit below ==, so fi(0) catch 0 == 0 types as the payload (source: i32) and binding it to bool is a warning[3000]. To compare a caught value, parenthesize the catch: (f() catch 0) == 0.

Discarding an error union

A statement whose result is an error union may not be silently discarded: 

fn f() E!i32 { return error.Foo; }
pub fn main() void { f(); }
// error[3015]: error union result is ignored; use 'try', 'catch', or assign the result

The three legitimate answers are exactly the message's list: propagate (try), handle (catch), or keep the result in a variable.
