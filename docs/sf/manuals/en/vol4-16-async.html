Async and coroutines

Async is Z98's cooperative, stackless coroutine facility: four @async* builtins in the language plus the ordinary library module std.async. There is no async/await keyword and no Future(T); coroutine state is type-erased to *void. This page is the lookup for the builtins, the frame/step ABI, the std.async surface, and the rule that decides which context may call which primitive.

Authority: the builtins are resolved and typed in semantic_analyzer.zig:4840-4876 and lowered in lower.zig:5924-6087; the suspension analysis and state-width rule are async_analysis.zig:317-524; the frame layout is async_frame_layout.zig:606-666; the library is sf/src/std_async.zig (re-exported as std.async at std.zig:9). The normative prose is docs/reference/Language_Spec_Z98.md §4.1. Every value and message below was reproduced on the fixed compiler (md5 821481e69df63fc0cf69176fdaaf9dd9); reused fixtures are named where one exists.

Suspending functions

A function is suspending when its body directly contains @asyncSuspend, or directly calls a function that is suspending. The property propagates over the direct-call graph (mutual recursion is ordinary propagation) and is computed once, program-wide, before type resolution. It is never declared.

Every suspending function is replaced by a step machine with the fixed shape below; the original synchronous body is not emitted. Only the root pub fn main keeps its source name and signature plus a synthesized synchronous driver that zero-initializes its root frame and drives its own step to completion. main and export fn are ordinary for suspension analysis: either may be suspending, and a non-suspending main/export fn/helper may host a std.async loop. 

fn __Z98Step_<f>(frame: *void, arg: ?*void) ?*void

The step loads its hidden state word, jumps to the resume segment for the current suspension point, runs to the next suspension or the end, saves the values it will need, and returns null at completion (a non-null result means still suspended). A suspending function's address may not be taken: error[3017]. 

fn worker(out: *i32) void {
    var i: i32 = 0;
    while (i < 3) : (i += 1) {
        @asyncSuspend(null);      // suspension point
    }
    out.* = i;
}

The four builtins

Signature Result Semantics
@asyncInit(ctx, buf, fn, args) *void Initialize a fresh root frame for the suspending function fn in buf, using the per-task pool ctx, and return the frame. It zero-fills the frame, writes the __Z98Step_<fn> word at offset 0, stores ctx and state = 0, resets the Context header (used = 0, sticky oom = 0; the caller supplied capacity), and copies the args record positionally into fn's parameters.
@asyncSuspend(data) *void An explicit suspension point. Valid only inside a suspending function (error[3018] otherwise) and rejected inside defer/errdefer (error[3019]). data is accepted and type-checked but is not propagated: a suspended step returns a non-null ?*void sentinel.
@asyncResume(frame, arg) ?*void Load the step word at frame + 0, call __Z98Step_<f>(frame, arg), and return its result: null when the coroutine has finished, non-null while it is still suspended. It updates no scheduler state; the caller owns that.
@asyncFrameSize(fn) untyped integer literal Compile-time byte size of fn's root frame. fn must resolve to a known suspending function, else error[3046].

args must be a plain *const void, written @ptrCast(*const void, &record). A ?*const void is a non-scalar optional in this position and emits invalid C89. The record's fields are the coroutine's parameters, so their number and order must match fn exactly. A minimal initialize-and-drive loop over the reusable sample docs/sf/manuals/src/vol2/builtins/async.z98 (measured frame=88, n=3 steps=4): 

var args: *const void = @ptrCast(*const void, &wa);
var frame: *void = @asyncInit(ctxp, &fbuf, worker, args);
var more: ?*void = @asyncResume(frame, null);
while (more != null) {
    more = @asyncResume(frame, null);
}

A direct call from one suspending function to another is an implicit await: the caller's step allocates a child frame from its Context pool, copies the arguments into it, and drives the child; while the child is still suspended the caller yields to its own driver. There is no await keyword — the call is the await. Reused from repro/mi_matrix/async_await_xmod (measured @asyncFrameSize(caller) == 72): 

fn callee(out: *i32) void { @asyncSuspend(null); out.* = 10; }
fn caller(out: *i32) void { var t: i32 = 0; callee(&t); out.* = t; }

Frame and step ABI

Each coroutine owns one root frame in a caller-supplied, 8-aligned buffer. The frame is laid out in a fixed order; on the 32-bit target a pointer is four bytes, so the header is step@0, ctx@4, state@8, and the first parameter follows at the next aligned offset (offset 12 for a 4-byte parameter). The exact order:

# Field Meaning
0step pointer-sized address of __Z98Step_<f> at offset 0
1ctx the per-task Context pool pointer, at the next pointer-sized slot
2state u8, u16, or u32 (see below)
3param each coroutine parameter, in declaration order
4live each local live across at least one suspension
5child one child-frame slot when the function awaits
6result one slot for a value returned through an await
7parent_result one slot per value-returning await, in program order

The real layout is built by async_frame_layout.zig:606-666, which appends the fields in that order, aligns each to its type's alignment, then pads the whole frame up to a multiple of 8 (Rule A). The authoritative @asyncFrameSize is a conservative, per-function upper bound, not a universal constant. The emitted C for the sample docs/sf/manuals/src/vol3/tasks.z98 shows the header directly (frame pointer zT_67, step zF_CD850BCC___Z98Step_task): 

zT_100 = (unsigned int*)(...zT_67... + 0);
*zT_100 = (unsigned int)(zT_95);              /* step word  @ offset 0 */
zT_104 = (void**)(...zT_67... + 4);
*zT_104 = zT_65;                              /* ctx pointer @ offset 4 */
zT_109 = (unsigned char*)(...zT_67... + 8);
*zT_109 = (unsigned char)(0);                 /* state = 0  @ offset 8 */
zT_113 = (...TaskArgs**)(...zT_67... + 12);
*zT_113 = zT_85;                              /* parameter  @ offset 12 */

State word

The state word is the smallest integer that can name every suspension point in the function (async_analysis.zig:517-524):

Suspension points State type
at most 255u8
at most 65535u16
moreu32

Measured: the sample task has one suspension point, so the state store is an unsigned char at offset 8; repro/mi_matrix/async_state_width_xmod's worker has 300 points, so its state store is an unsigned short at offset 8 (@asyncFrameSize and the runtime loop both pass).

Frame sizes are per function

Never hard-code a frame size; use @asyncFrameSize(fn) to size the buffer. Fresh measurements on the fixed compiler:

Function (source) @asyncFrameSize
worker (vol2/builtins/async.z98)88
task (vol3/tasks.z98)168
worker (async_frame_xmod)72
caller (async_await_xmod)72
level1 (async_pool_xmod)80

Context header (16 bytes)

A Context sits at the head of a caller-supplied buffer; HEADER_SIZE is 16, not 12, so that pool_base = ctx + 16 stays 8-aligned whenever ctx is 8-aligned. The caller's buffer must be 8-aligned; contextInit traps on a misaligned buffer rather than corrupting every child frame. Back it with an 8-aligned type such as [K]u64, never a bare [N]u8. On the 32-bit target:

Offset Field Meaning
0used: usize bump pointer; rounded up to 8 before each contextAlloc
4capacity: usize usable pool bytes after the header (buf.len - 16)
8oom: bool sticky exhaustion flag
9..15padding keeps the pool base at 8-alignment

The pool itself is a per-task LIFO bump stack, not a general allocator. A root frame lives in buf outside the pool; the Context owns child frames only. contextAlloc rounds used up to 8, and on exhaustion sets the sticky oom and returns error.OutOfFrame instead of crashing. A child is reclaimed when it returns, or explicitly with contextMark/contextRelease. Verified by stdlib_async_headerexact_xmod (a buffer of exactly 16 bytes yields capacity == 0 and OutOfFrame with used == 0) and stdlib_async_f64align_xmod (an allocated f64 container is 8-aligned and round-trips).

-fsafe checks

Under the default -fsafe mode, the coroutine builtins add two runtime checks; -ffast emits neither. The alignment check in contextInit is independent of the mode and always traps.

Site Condition
@asyncResume(frame, arg) Traps if the frame's step word (offset 0) is zero (lower.zig:6057-6062).
@asyncInit(ctx, buf, fn, args) Traps when the frame size is compile-time known and buf points at a concrete [N]u8 array with N < @asyncFrameSize(fn) (lower.zig:5966-5997). A slice or many-pointer buffer ([]u8/[*]u8) has no compile-time length, so the check is skipped.
contextInit(buf) Traps (both modes) if buf.ptr is not 8-aligned; under -fsafe the buf.len - 16 subtraction also traps when buf.len < 16.

The std.async surface

The scheduler and per-task child-frame pool are library code, re-exported as std.async (std_async.zig). Concrete only — no generics.

Symbol Definition
TaskState enum(u8) { ready = 0, running = 1, suspended = 2, done = 3, cancelled = 4 }
FrameError error{OutOfFrame}
StepFn fn(frame: *void, arg: ?*void) ?*void — the documented __async_step_<f> ABI alias only; the scheduler never stores or passes one.
HEADER_SIZE usize = 16
Context { used: usize, capacity: usize, oom: bool } plus padding to 16 bytes; the pool header.
Task { frame: *void, ctx: *Context, state: TaskState, cancel_requested: bool, result: *void, arg: *void, waiting_on: *Task, has_waiting_on: bool }. Stores no step pointer.
Scheduler { tasks: [*]*Task, capacity: usize, count: usize, current: usize, in_task: bool }; wraps a caller-owned array of pointers.

Functions

Signature Semantics (measured)
schedulerInit(tasks: []*Task) Scheduler Wrap a caller-owned array of task pointers; count = 0, current = 0, in_task = false.
addTask(s, t) bool Register t. Idempotent: a registered, settled (done/cancelled) task is reset in place to ready (clearing cancel_requested and has_waiting_on) and true is returned; a registered, still-active task is left untouched (false); a new task is appended (false when at capacity).
removeTask(s, t) void Retire t, compacting the tail so count drops by one; no-op when t is not registered. Valid from any non-suspending context; do not remove a task a coroutine is currently awaiting.
tick(s) FrameError!void Resume every ready or suspended task once, in registration order. Sets running before the resume, then done if the step returned null and suspended otherwise. A task with cancel_requested becomes cancelled; a task with has_waiting_on is skipped until its dependency settles. Returns error.OutOfFrame (stopping further resumes) if a resumed task's pool overflowed.
waitAll(s) FrameError!void Tick until every registered task is done or cancelled.
waitFor(s, t) FrameError!void Tick until t settles, even if other tasks also run. Panics if t is neither registered nor already settled (hang guard).
awaitTask(s, t) void Suspend the currently running task until t settles; does not tick. Panics if there is no running task (in_task == false) or no registered task.
suspend(s, t) void Mark t suspended (yield bookkeeping only).
suspendUntil(pred: fn() bool) void Yield via @asyncSuspend(null) once per tick until pred() is true. pred is a non-suspending function pointer; the caller must be suspending.
cancel(s, t) void / cancelAll(s) void Request cooperative cancellation, observed at the next tick boundary.
contextInit(buf: []u8) *Context Place the Context at the head of buf; trap if misaligned; set capacity = buf.len - 16, used = 0, oom = false.
contextAlloc(ctx, size) FrameError![*]u8 Round used up to 8, return an 8-aligned pointer, and advance used; on exhaustion set sticky oom and return error.OutOfFrame.
contextMark(ctx) usize / contextRelease(ctx, mark) void Bracket a child frame like a stack: contextMark returns the current used; contextRelease restores used to mark.

Because Task stores no step pointer, one scheduler drives tasks built from different suspending functions: tick calls @asyncResume(t.frame, t.arg) and the frame's offset-0 step word supplies the function. The setup shape from docs/sf/manuals/src/vol3/tasks.z98 (three tasks, round-robin, measured stdout ending done = 3): 

var ctx = std.async.contextInit(@ptrCast([*]u8, &pools[i])[0 .. POOL_WORDS * 8]);
task_ptrs[i].ctx = ctx;
task_ptrs[i].frame = @asyncInit(ctx, @ptrCast([*]u8, &frames[i]), task,
                                @ptrCast(*const void, &recs[i]));
_ = std.async.addTask(&sched, task_ptrs[i]);
...
std.async.waitAll(&sched) catch { ... };

A predicate-driven yield, from repro/mi_matrix/stdlib_async_suspenduntil_stress_xmod (each coroutine resumes on the first tick its predicate flips — measured resume ticks 3 1 6 2 7 4 for flip ticks 3 1 6 2 7 4): 

fn ready0() bool { return g_tick >= g_flip[0]; }   // non-suspending predicate
fn worker0(c: *CoCtx) void { _ = c; sa.suspendUntil(ready0); g_resume[0] = g_tick; }

The two-context rule

awaitTask and waitFor look alike but are not interchangeable, because awaitTask suspends the current task and so needs a current task to suspend.

Caller context waitFor awaitTask
main, export fn, or any plain non-suspending helper Valid. Ticks the scheduler; needs no caller frame. Panics: std.async: awaitTask called from a non-suspending context.
Inside a running task (s.in_task == true) Valid, but also ticks unrelated ready tasks. Valid. Parks only the current task on the dependency.
std.async.waitFor(&s, t) catch { ... };   // from main / a helper
...
std.async.awaitTask(&s, t);               // from inside a task only

Verified: repro/mi_matrix/stdlib_async_waitfor_helper_xmod calls waitFor from a plain helper and prints 10 then 3 (done); stdlib_async_await_nonctx_xmod calls awaitTask from main and traps (rc 133) with the exact message above. A task whose awaited dependency also has other registered work should use awaitTask; a driver with no current task must use waitFor.
