Codecs and crypto

These codec and hash modules are also imported by path: @import("std_base64.zig"), @import("std_zstd.zig"), and so on. None is part of the thirteen-name std re-export list. The codecs split into text encodings (std_base64, std_hex, std_utf8), hashing and stream ciphers (std_crypto), and block or frame decompressors (std_lz4, std_zstd).

The base64 and hex codecs allocate only their output from a caller arena; std_utf8 allocates nothing. The hash functions allocate nothing and keep all state in caller-owned values. std_lz4 and std_zstd decompress into a caller destination and have no allocator parameter at all. The bencode and HTTP consumers live on the data page and the I/O page.

std_base64

std_base64 implements RFC 4648 section 4 standard base64 with the alphabet ABCDEFGHIJKLMNOPQRSTUVWXYZabcdefghijklmnopqrstuvwxyz0123456789+/ and mandatory = padding to a multiple of four output characters. Encoding emits no whitespace. Decoding accepts only canonical padded base64: whitespace, a length that is not a multiple of four, and misplaced or malformed padding all produce error.InvalidInput. An empty input is a valid empty result. An invalid decode allocates nothing.

Function Signature Returns / error Purpose
encodedLen pub fn encodedLen(n: usize) usize usize; no allocation Exact encoded size, 4 * ceil(n / 3).
decodedLen pub fn decodedLen(n: usize) usize usize; no allocation Maximum decoded size, (n / 4) * 3.
encode pub fn encode(arena: *arena_mod.Arena, src: []const u8) ![]u8 ![]u8; error.OutOfMemory (inferred) Allocate and return the padded base64 text.
decode pub fn decode(arena: *arena_mod.Arena, src: []const u8) DecodeError![]u8 error{OutOfMemory, InvalidInput}![]u8 Allocate and return the decoded bytes.

decodedLen is an upper bound because the exact size depends on trailing padding. encode allocates only its output and can fail only with error.OutOfMemory. decode validates before allocating, so a malformed input leaves the arena unchanged.

std_hex

std_hex writes two hexadecimal characters per byte, high nybble first. encodeLower emits 0-9 a-f, encodeUpper emits 0-9 A-F, and decode accepts either case. There is no separate length helper in the source: the encoded size is src.len * 2 and the decoded size is src.len / 2. Decoding does not skip whitespace and rejects an odd-length string or any byte outside the hexadecimal ranges.

Function Signature Returns / error Purpose
encodeLower pub fn encodeLower(arena: *arena_mod.Arena, src: []const u8) ![]u8 ![]u8; error.OutOfMemory (inferred) Allocate and return lower-case hexadecimal text.
encodeUpper pub fn encodeUpper(arena: *arena_mod.Arena, src: []const u8) ![]u8 ![]u8; error.OutOfMemory (inferred) Allocate and return upper-case hexadecimal text.
decode pub fn decode(arena: *arena_mod.Arena, src: []const u8) DecodeError![]u8 error{OutOfMemory, InvalidInput}![]u8 Allocate and return the bytes; case-insensitive, no whitespace.

As with base64, an empty input decodes to a valid empty slice. Invalid input does not allocate. encodeLower and encodeUpper can fail only with error.OutOfMemory.

std_utf8

std_utf8 is a pure UTF-8 code point walker. A sequence is valid only when every continuation byte is in 0x80..0xBF, the code point is not overlong, is not a surrogate in U+D800..U+DFFF, and is not above U+10FFFF. Lead bytes 0x80..0xBF, 0xC0, 0xC1, and 0xF5..0xFF are invalid. A truncated sequence is invalid.

Name Signature / declaration Returns / error Purpose
Codepoint pub const Codepoint = struct { cp: u32, len: u8 }; — A decoded code point and its encoded byte length.
codepointLen pub fn codepointLen(first_byte: u8) u8 u8; 1..4, or 0 for a byte that cannot begin a valid sequence Lead-byte sequence length; only the first byte is consulted.
decode pub fn decode(s: []const u8) ?Codepoint ?Codepoint; null when empty or not valid UTF-8 at the start Decode the first code point after full validation.
encode pub fn encode(buf: []u8, cp: u32) ?[]u8 ?[]u8; null for a surrogate, a code point above U+10FFFF, or a short buffer Write the encoding to buf and return its slice.
countCodepoints pub fn countCodepoints(s: []const u8) usize usize Walk the whole slice; each valid code point counts one and each invalid lead advances one byte.

decode validates before returning, so it never yields a value outside the Unicode scalar range. codepointLen does not enforce the second-byte rules for E0, ED, F0, or F4; decode does. encode refuses a buffer smaller than the encoding rather than writing a partial sequence.

std_crypto

std_crypto is pure and allocation-free. Every hash is a streaming value-type state: an Init returns the state, every Update takes a pointer to it, and every Final writes the digest into a caller-supplied array. Updates may be called any number of times with any chunk sizes. CRC-32 uses the IEEE 802.3 polynomial and the usual pre- and post-inversion. RC4 keeps its state in a caller value and XORs a caller buffer in place. modpow is the fixed-limb modular exponentiation helper used by the MSE/PE handshake.

Every function in the module is total: there is no error set and no allocation. The hash states are values the caller owns; Final mutates the state and writes the digest, and the caller decides when the state may be reused. RC4 itself does not discard any key-stream bytes; a protocol that requires the MSE discard step must do it in its own layer.

std_lz4

std_lz4 exposes one function, lz4DecompressBlock, and it decompresses a raw LZ4 block, not an LZ4 frame. The destination buffer is the whole output; there is no allocator and no internal buffer. A token carries a four-bit literal length and a four-bit match length. For the match, the low nibble encodes match_len - 4; a length of fifteen means the real value continues in following bytes, each added with 255 continuing the extension, and the mandatory +4 (MINMATCH) step is applied after that extension. The match offset is a little-endian 16-bit value after the literals. A match is copied forward from the already-written history, so overlapping matches work byte by byte. After at least one match, the final block rules are enforced: the last literals must be at least five bytes, and the last match must start at least twelve bytes before the end of the output.

Function Signature Returns / error Purpose
lz4DecompressBlock pub fn lz4DecompressBlock(src: []const u8, dst: []u8) !u32 !u32; error.Corrupt or error.OutputTooSmall Decompress one raw LZ4 block into dst and return the byte count.

error.Corrupt covers an empty input, a truncated token or extension, a zero offset, an offset beyond the written output, and a final literals or match-distance rule violation. error.OutputTooSmall means the caller's destination cannot hold the decoded block. The input is not modified and no allocation occurs.

std_zstd

std_zstd decodes an RFC 8878 zstd stream into a caller destination. It supports standard frames with raw, RLE, and compressed blocks; predefined, RLE, and FSE-compressed Huffman and FSE tables; repeat modes; and skippable frames. Dictionaries are not supported: a nonzero dictionary id is error.Corrupt. The history is the destination itself (dst[0..written]), and the decoder has no heap and no buffer beyond dst; entropy tables are function-local.

Name Signature / declaration Returns / error Purpose
ZSTD_DEFAULT_WINDOW_LOG pub const ZSTD_DEFAULT_WINDOW_LOG: u8 = 21; — The default window-log value, a 2 MiB window.
zstdDecompress pub fn zstdDecompress(src: []const u8, dst: []u8, max_window_log: u8) !u32 !u32; error.Corrupt, error.OutputTooSmall, or error.WindowTooBig Decompress a complete zstd stream into dst and return the bytes written.

error.Corrupt covers malformed, truncated, unsupported, or dictionary-backed frame data. error.OutputTooSmall means the destination cannot hold the decoded content. error.WindowTooBig means the frame's window log exceeds max_window_log. A sensible default cap is ZSTD_DEFAULT_WINDOW_LOG (21, or 2 MiB); raise it for large or higher-level frames. The function writes only into dst and allocates nothing.
