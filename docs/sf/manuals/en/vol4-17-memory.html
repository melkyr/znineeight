Memory and the arena

Z98's dynamic memory is arena allocation: a program declares a byte buffer, hands std.arena a cursor over it, and reclaims everything at once with reset. There is no malloc, no free, and no general-purpose allocator in the std surface. The compiler is built on the same pattern, extended to five tiers under one static pool and guarded by the -mm budget gate. This page is the lookup for the arena API, the init/reset patterns, the dual-arena rule, the compiler's tiers, and the 16 MB target budget.

Authority: the library arena is sf/src/std_arena.zig (re-exported as std.arena at std.zig:3); the compiler's own tiers and budget constants are sf/src/allocator.zig; the -mm/-s flags are parsed in sf/src/main.zig (parseMMBytes, parseSLevel). The normative prose is docs/reference/Language_Spec_Z98.md §2. Every value and message below was reproduced on the fixed compiler (md5 821481e69df63fc0cf69176fdaaf9dd9); reused material is named where one exists.

The std.arena API

The standard library re-exports the arena as std.arena (std.zig:3). The module sf/src/std_arena.zig is a struct, three functions, and one error set: 

pub const Arena = struct {
    data: [*]u8,
    capacity: usize,
    used: usize,
};

pub fn init(data: []u8) Arena { ... }

pub const ArenaError = error{OutOfMemory};

pub fn alloc(self: *Arena, size: usize) ArenaError![*]u8 { ... }

pub fn reset(self: *Arena) void { ... }

Z98 has no method syntax, so the three functions are free functions called with the arena as the first argument. The fields are public, so the cursor is observable.

Signature Semantics
std.arena.init(data: []u8) Arena Record data.ptr as data, data.len as capacity, and set used = 0. Infallible: the buffer already exists, so there is nothing to fail.
std.arena.alloc(self: *Arena, size: usize) ArenaError![*]u8 If used + size > capacity, return error.OutOfMemory; otherwise return data + used and advance used by size. There is no alignment argument; the result is a raw byte position.
std.arena.reset(self: *Arena) void Set used = 0. Every allocation made through the arena is reclaimed at once. It does not zero the bytes and runs no code.
Arena.data, Arena.capacity, Arena.used Public fields: the backing byte pointer, the buffer length, and the live cursor. There is no deinit. 
var arena = std.arena.init(buf[0..]);   // buf is a caller-declared [N]u8

Allocation and the init-function pattern

alloc is a cursor bump. Because the result carries no type, the standard shape is a constructor that allocates, casts with @ptrCast, sizes with @sizeOf, fills the fields, and returns the typed pointer. Reused from docs/sf/manuals/src/vol2/arena.z98: 

const Point = struct {
    x: i32,
    y: i32,
};

fn Point_init(arena: *std.arena.Arena, x: i32, y: i32) std.arena.ArenaError!*Point {
    const raw = try std.arena.alloc(arena, @sizeOf(Point));
    const p = @ptrCast(*Point, raw);
    p.x = x;
    p.y = y;
    return p;
}

The result type is ArenaError![*]u8 — an error union, not an optional. The tools are try (propagate) and catch (handle); orelse is rejected with the message that names the right one: 

error[3016]: orelse requires an optional operand; use 'catch' for error unions

An allocation result also cannot be silently discarded (error[3015]). The full example program runs to this exact output on the fixed compiler: 

cap=32 used=0
p=3 4 used=8
used after reset=0
p2=9 8 reused p.x=9
caught: error.OutOfMemory
perm=3 4 scratch=5 6
perm used=8 scratch used=8
scratch used after reset=0 perm used=8

Reclaiming memory: reset, not free

There is no per-object free and no deinit. reset sets used back to zero, and reclamation is all-at-once. Three rules follow from that shape:

  • An object that owns an external resource — a file handle, a socket — must release it before the reset; the arena knows nothing about it.
  • Memory obtained from std.arena.alloc must not be passed to free().
  • After a reset the old pointers are not invalidated, only reused: the next alloc hands out the same addresses. The transcript above shows p.x reading the new object's 9. Ownership ended at the reset; the address did not.

The dual-arena pattern

One arena forces long-lived and transient data to share a fill level, so the short-lived tier can never be reset without losing the long-lived one. The standard answer is two arenas with two lifetimes:

Arena Holds Reset
Permanent Data that lives for the whole run: global symbols, persistent nodes, the structures the program is "about". Never, or once at the very end.
Scratch (transient) Temporary data: per-file, per-request, or per-phase working memory. At every phase boundary, after the phase's results are copied or summarized.

The pattern is two Arena values, not a library feature. The compiler extends it to five tiers (below), and the coroutine Context is a per-task tier built on the same buffer-plus-cursor shape.

The compiler's allocator: five tiers, one pool

The compiler is itself an arena program. sf/src/allocator.zig defines Sand — a named bump arena that tracks a peak and can grow — and a CompilerAlloc of five tiers backed by a single static pool: 

pub const Sand = struct {
    start: [*]u8,
    pos: usize,
    end: usize,
    peak: usize,
    name: []const u8,
    growable: ?*GrowableSand,
};

pub const CompilerAlloc = struct {
    permanent: Sand,
    module: Sand,
    scratch: Sand,
    lir_read: Sand,
    emission: Sand,
    max_mem: u32,
};
Tier Lifetime / contents
permanent The whole compile: interned strings, the module registry, types that survive every phase.
module Per module and per phase, reset at phase boundaries: the AST and the lowering structures.
scratch Short-lived working memory, reset aggressively during analysis so the peak is the largest single function, not their sum.
lir_read LIR structures read back after lowering.
emission C89 emission working memory.

All five are growable sub-arenas drawn from one Sand that is never reset: 

pub const POOL_SIZE: usize = 268435456; // 256 MiB measurement pool; sized to measured peak + margin in Task 12
var memory_pool_buf: [POOL_SIZE]u8 = undefined;
var pool: Sand = undefined; // monotonic bump over memory_pool_buf; never reset

Sand exposes sandInit, sandAlloc, sandReset, sandResetPeak, and the in-place realloc helpers; GrowableSand wraps a Sand as a chain of doubling segments drawn from a backing tier (the five tiers start at 4 KB each). The --markers --track-memory pair prints the per-tier peaks (perm, mod, scr, type_db, pool, and total); --track-memory emits through the marker channel, so both flags are required.

The -mm budget gate and the 16 MB target

The compiler carries two budget numbers in sf/src/allocator.zig beside the gate's host default: 

pub const DEV_MAX_MEM: usize = 16 * 1024 * 1024;
pub const RELEASE_MAX_MEM: usize = 16 * 1024 * 1024;
pub const DEFAULT_MAX_MEM_KB: usize = 64 * 1024;

DEV_MAX_MEM and RELEASE_MAX_MEM are both 16 MiB and state the target-build policy: the peak the compiler is designed to hold when it runs on the 1998 machine. DEFAULT_MAX_MEM_KB is 64 MB and supplies the host default of the -mm<N> gate. The two numbers answer different questions on purpose — policy versus host tripwire — and the measured accounting is on Memory budgets.

Flag Meaning Default
-mm<N> Stop the compile when the pool high-water exceeds N MB. The gate checks the pool, not the live tier sum. As a host tripwire it defaults high so ordinary host work does not trip it. 64 MB (DEFAULT_MAX_MEM_KB)
-mm0 Relax path: checkCombinedPeak falls back to the static pool size as the limit. This is "no gate", not "zero megabytes". off
-s<N> Spill ladder, N = 0..6: how many of the six spills live in RAM instead of on disk (order AST, LIR, HASH, RES, SIDE, EXTRA). -s0 is all on disk, -s6 all in RAM; emission is identical in every mode. -s0 (all on disk)

checkCombinedPeak divides the pool high-water by 1024, compares it to max_mem (in KB), and on overflow prints 

memory limit exceeded: pool limit=<N>K pool=<M>K

then aborts with status 3. A malformed gate is a clean command-line error with status 1: 

error: -mm<N> requires a decimal MB size (e.g. -mm64)
error: -s<N> requires a decimal level 0..6 (e.g. -s0 all on disk, -s6 all in RAM)

-mm<N> is clamped to the static pool ceiling (POOL_SIZE = 256 MiB), so a budget at or above it can never trip the gate. The measured self-compile figures and the choice between -mm<N>, -mm0, and the spill levels are on Memory budgets; the full flag catalogue is on The command line.
