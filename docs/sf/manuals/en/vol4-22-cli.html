The command line

zig1 is the Z98 compiler. It reads one input file, runs the pipeline, and, when asked, writes C89 to standard output or to an output directory. This page is the lookup for every option the shipped zig1 accepts, quoted from sf/src/main.zig (parseArgs, main.zig:1551-1711, and the helper parsers through main.zig:1881).

Options may appear before or after the input file, in any order. Each is applied as it is read, so when two options set the same thing the last one wins. Any argument that is not a recognized option is taken as the input file, and the last such argument wins. With no input file at all, zig1 prints its short usage text and exits 0.

Synopsis

zig1 [options] <input.z98>

The text below is what zig1 prints when it is invoked with no input file (to stderr, exit 0). It documents only a subset of the options; the full set is the table further down. 

zig1 - Z98 self-hosted compiler - usage: zig1 [options] <input.zig>
  -mm<N>    hard pool budget in MB (default 64; pool.peak over budget -> ICE rc=3)
  -s<N>     spill level 0..6 (default 0 = all spills on disk; -s1..-s6 deactivate the
            first N spills to RAM in order AST,LIR,HASH,RES,SIDE,EXTRA: higher -s = more RAM,
            less disk I/O (pool= rises; -s6 = all in RAM -> pair with -mm128)
  -osl       compile target = linux (default); -osw = windows
  --target <linux|windows>  long-form target alias for -osl/-osw

The input file

The one positional argument is the file to compile. It may appear anywhere among the options; the last non-option argument seen becomes the input file. If no input file is given, zig1 prints the usage text and returns 0. If the file cannot be read, it prints error: could not read input file and exits 1. The input path may be absolute or relative to the current directory.

Output and the emitted files

With -o DIR the compiler writes a self-contained C89 tree into DIR (the directory must already exist) and returns. The emitted set is:

File Content
<module>_<hash>.c, .h One pair per emitted module, carrying that module's functions, types, and declarations.
zig_special_types.h, zig_compat.h, zig_runtime.h Shared type and runtime headers.
zig_runtime.c, zig_pal.c, c_exit.c The runtime and platform sources needed to link the output.
net_prelude.h Emitted when std_net is in the module set.
build_target.sh A build script, sh build_target.sh [TARGET] [OUT], with TARGET linux (default) or mingw.
build_target.bat, build_owc.bat The MSVC and OpenWatcom scripts, emitted only for the Windows target (-osw).

With --dump-c89 and no -o, the compiler writes one combined C translation unit to standard output instead, for pasting into a single-file build. c89_emit.zig:10358-10506 emits the build scripts; main.zig:1182-1544 drives the two paths.

Memory and spill options

The pool budget (-m/--max-mem, or -mm<N>) and the spill level (-s<N>) trade RAM for disk I/O. Both are checked from the source of record: main.zig:1723-1851 and allocator.zig:288-302. The budget is compared against the pool peak after each phase; over budget prints memory limit exceeded and exits 3. Because the six spills hold AST, LIR, HASH, RES, SIDE, and EXTRA data, -s0 is the low-memory default and -s6 keeps everything in RAM.

Target and safety options

The target defaults to Linux and is set by the last of -osl, -osw, or --target. It selects the emitted build scripts and the platform headers; it does not change the Z98 source. Safety defaults to -fsafe (runtime checks plus the undefined poison); the last of -fsafe and -ffast wins.

Diagnostic and analyzer options

-e/--max-errors caps the count of diagnostics. The three --no-*-check options switch off the corresponding static analyzers. -W/--warnings-as-errors and --warn-error make any warning a failure; --warn-all lets the analyzer raise reports it would otherwise suppress. --color, --error-format, and -q/--quiet are accepted and stored but have no reader at seed v90.

Declared but not wired

The following spellings are present in main.zig but no branch of parseArgs matches them. An argument that is one of them therefore falls through to the input-file case and is used as the file name:

Spelling Status
--dump-types Declared (main.zig:73, main.zig:1584); never matched. zig1 --dump-types alone tries to read a file named --dump-types.
--dump-lir Declared (main.zig:74, main.zig:1585); never matched, same fall-through.
-t, -a, -y, -l Declared (main.zig:1605-1608); never matched in zig1, same fall-through. -t is matched only by the separate sf/src/main_dump.zig entry.
--dump-tokens, --dump-ast Not options of zig1 at all; they belong to the separate sf/src/main_dump.zig entry (main_dump.zig:221-222).

There are no data-file options: no --d* spelling is parsed. --dump-c89 is the only dump option of the shipped zig1.

The seed build recipe

The compiler under test is rebuilt from the committed seed, not from a retired bootstrap. The recipe, the fixed-point gate, and the current seed values are in docs/sf/QUICK_REF.md; the one-command form is bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz <out_dir>, which produces <out_dir>/zig1_5_clean and <out_dir>/lib/.

Exit status

Code Meaning
0 Success; also the no-input-file case, where the usage text is printed.
1 A malformed -mm/-s value; a missing output directory; an unreadable input file; --test; an invalid --target; or warnings present under -W/--warn-error.
3 Pool peak over the -mm/-m budget (memory limit exceeded; the usage text calls this an ICE).
