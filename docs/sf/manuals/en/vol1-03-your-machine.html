Your Machine

The last chapter described the machine Z98 was built for: a 32-bit Pentium-class computer of 1998, running Windows 95 or 98, or a Linux of the era. This chapter turns that description into a checklist. It says which two machines you can use, what to do if you do not own one, what the manual's disk already carries, and how to tell that your machine is ready for the work ahead.

There is no code in this chapter, and no program to build. It is the last of the three framing chapters. Read it before you install anything, so that the next chapter's instructions land on a machine you already understand.

Two machines are enough

Z98 compiles to C89, and C89 compilers were everywhere in 1998. That fact gives you two supported paths, and you only need one of them. The language and the compiler are the same on both; what differs is the ordinary C compiler that finishes the job at the end of the build.

Path one is a Linux machine with gcc. The compiler is rebuilt from a small committed archive called the seed, and that rebuild needs nothing but gcc. The emitted C89 is then compiled with gcc -m32, the 32-bit mode of the same compiler.

Path two is a Windows 95 or 98 machine with OpenWatcom. OpenWatcom is a compiler suite of the era, and the manual ships a companion script that drives it. Its wcc386 compiles the emitted C89 in strict ANSI mode, and wlink links the result into a console program.

The two paths are not a competition. A Linux machine is the easier one to script and the one the manual's own scripts assume; a real Windows 95 or 98 machine is the more faithful one, because it is the machine the programs are meant to run on. Either is enough to follow this volume.

Path one: Linux with gcc

The manual's examples are built on Linux, and its helper script src/build_linux.sh shows the whole shape of a build. It runs the seed-built compiler over each example, and the compiler writes a self-contained tree of C89 files plus a small build_target.sh. That emitted script compiles the C with gcc -m32 and links the program.

What you need, then, is a Linux machine with a working gcc that can produce 32-bit code. The seed rebuild asks nothing more of the system: no package manager, no network, no modern language runtime. If your Linux is modern, that is fine — the programs still target the era; only the machine doing the building is new.

The 32-bit part is worth stating plainly. Z98 targets 32-bit x86, so the emitted C89 is compiled with gcc -m32. A gcc that cannot do 32-bit builds is the one thing that will stop this path, and it is the first thing to check.

Path two: Windows 95 or 98 with OpenWatcom

If you have the target machine itself, you can build on it. The manual's src/build_owc.bat is the Win9x companion to build_linux.sh. The order is a little different, because the compiler first has to be told to emit Windows-target C89:

You run the compiler with the Windows output option, for example zig1 -osw -o out hello.z98. The compiler writes a self-contained tree into out\, and with it two build scripts of its own: a build_target.bat for MSVC and a build_owc.bat for OpenWatcom. The manual's companion follows those emitted conventions. Run it from inside the emitted directory and it compiles every .c and links one console executable.

Under the hood it is short. wcc386 compiles the C89 in strict ANSI mode, with warnings treated as errors, so a build that succeeds is a build the compiler had no complaint about. wlink then links a console program with a 64 KB stack, and adds the WinSock library when the program uses the network. On a real Windows 98 machine, the resulting .exe is the same kind of program the era shipped.

No real machine: 86Box and PCem

Most readers will not have a working Pentium-class machine on the desk, and that is not a problem. The 1998 machine can be emulated on a modern host. 86Box and PCem are two emulators that reproduce era hardware closely enough to install Windows 95 or 98 and a compiler on top of it, and to run the programs this manual builds. They are the recommended path for anyone without real hardware, and a perfectly good one even for those who have it.

Emulation gives you the whole target in one window: the era's BIOS, its sound and video hardware, its disks, and its operating system. You configure a machine of the right vintage, install Windows from the media you already have, and then follow the same Win9x path described above. A modern host runs the emulator; the guest is the 1998 machine.

The choice between 86Box and PCem is not one this manual will make for you. Both emulate the era's PCs, both are free, and both will run Windows 95 or 98 well enough for this volume. Pick the one that installs and starts cleanly on your host, and spend your time on the programs instead.

What ships on the disk

The manual is a book that happens to be a website, and it ships as static HTML on a disk with no network and no server. Beside the pages, the disk carries everything the volume needs to build and run its examples. The pieces are:

  • The manual pages. Every page you are reading is a plain file that opens, prints, and keeps without a network connection.
  • The example programs. Each chapter that introduces code has one example, kept under src/ in a folder named for its volume, such as src/vol1/hello.z98 and src/vol2/error_unions.z98.
  • The compiler's seed. The compiler is rebuilt from a small committed archive, release/seed/zig1-seed.tgz, and that rebuild needs only gcc. The archive also carries the compiler's own C89 source and the runtime it needs, which is what you build for Windows 95 or 98 with OpenWatcom. Its provenance is recorded beside it in release/seed/, and the archive carries its own rebuild recipes.
  • The build helpers. src/build_linux.sh for the Linux path and src/build_owc.bat for the Win9x path drive the examples end to end.

What is deliberately absent matters too. There is no installer, no package manager, no network fetch, and no modern runtime to install first. The disk is meant to be self-contained, the way a 1998 machine had to be.

Confirming the machine is ready

You do not need to build anything to know whether you are ready; you need to know which path you are on and that its one prerequisite is present. On Linux, that prerequisite is a gcc that accepts -m32. On Windows 95 or 98, it is an installed OpenWatcom with wcc386 available. If you have neither, set up 86Box or PCem first and choose a path inside the guest.

The next chapter does the installing and proves the result: it unpacks the seed, confirms the built compiler runs, and builds a bundled example. When that succeeds, your machine is ready, and the first real program is one chapter away.

Where this is going

Chapter 4 installs the toolchain and confirms it works. Chapter 5 is where you write your first Z98 program and watch it print a single line. By then the machine will be a machine you know, not a mystery you are hoping will cooperate.

One machine, two ways to build, and a disk that carries everything. That is the whole of what this chapter asks you to arrange. Do it once, and it will not come up again.
