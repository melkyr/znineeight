Enums

An enum names the members of a small, fixed set over one integer: the compiler assigns each member a number and carries the set as a type. The declaration is const E = enum { Member, ... };; the backing integer may be named with enum(uN). This page is the lookup for the declaration syntax and backing widths, member values and the auto-increment rule, .member access, @enumToInt/@intToEnum, the switch rules (the mandatory else, exact and range prongs, and the qualifier rejects), and the print forms.

The authority is the parser (parserParseEnumType at sf/src/parser.zig:1387-1424), the default backing and member registration (sf/src/symbol_registrator.zig:200-227, default TYPE_U32 at :203), the shared member walk (enumMembersResolve at sf/src/type_resolver.zig:1316-1380), the backing gate (semanticAnalyzerGateEnumTypeDecl at sf/src/semantic_analyzer.zig:2141-2214), the conversion typing (sf/src/semantic_analyzer.zig:4885-4897 and sf/src/lower.zig:6262-6265), the switch-else reject (sf/src/semantic_analyzer.zig:4160-4165), the case-qualifier reject (sf/src/semantic_analyzer.zig:4175-4197), and the case-item lowering (lowerSwitchCaseItemValue at sf/src/lower.zig:2982). Every rule below was reproduced on seed v90; the reused fixture or sample is named where one exists.

Declaration syntax and backing type

An enum declaration is an ordinary const whose value denotes a type. Members are comma-separated identifiers; a trailing comma is optional. The backing integer is inferred (a u32) unless an explicit unsigned backing is written after enum in parentheses. 

const Color = enum { Red, Green, Blue };          // inferred backing: u32
const Code = enum(u8) { Ok = 0, Warning = 4, Error = 9 };
Form Spelling Backing
inferred const E = enum { Member, ... }; u32 (4 bytes / 32 bits), whatever the member count.
explicit const E = enum(uN) { Member, ... }; An unsigned integer of width N; the enum measures as that backing.

The inferred backing is fixed at u32; the compiler does not shrink it to fit the member count. The explicit backing sets both the storage width and the range each member value must fit. Measured on seed v90:

Enum @sizeOf / @bitSizeOf Notes
enum { ... } 4 / 32 Fixed u32.
enum(u8) { ... } 1 / 8 One byte; the wire/table width.
enum(u16) { ... } 2 / 16  
enum(u32) { ... } 4 / 32 Same as the inferred backing.
enum(u64) { ... } 8 / 64 Align 8, like u64.

Only unsigned backings are accepted; the reject is level-0 error[3000]. The reused sample docs/sf/manuals/src/vol2/color.z98 declares the inferred Color and the u8-backed Code and prints Color size=4 bits=32 and Code size=1 bits=8.

Backing written Code Message (measured)
enum(i32), enum(i8), any iN error[3000] enum(iN) signed backings are not supported; use an unsigned backing (enum(uN))
enum(bool) error[3000] bool is not a valid enum backing; use an unsigned integer type (uN)
a non-integer, non-bool name error[3000] invalid enum backing type; enum(uN) requires an unsigned integer type (uN)

The grammar and the gate accept any unsigned width u1…u64, including sub-byte widths (u1…u7). A sub-byte-backed enum measures as the declared width's carrier, and several such enums may coexist in one program; each is a distinct type with its own member set: 

const Small = enum(u3) { A, B, C };        // member values 0, 1, 2 fit u3
const Wide  = enum(u5) { X = 0, Y = 31 };  // explicit top-bit member fits u5
// both compile; Small measures 1/1, bitSize 3; Wide measures 1/1, bitSize 5

Every member value must still fit its declared width; a value that does not is a clean error[3000] (enum tag value does not fit the enum backing width (must fit 2^N - 1); no silent truncation).

Member values and auto-increment

Each member takes an implicit number by declaration order unless a = value is written. The auto counter starts at zero; an explicit value sets the member's number and the next member's auto counter continues from there. Explicit values may be any comptime-known integer expression and need not be contiguous. 

const Level = enum { Low, Mid = 4, High, Neg = 100, After };
//                            Low=0  Mid=4  High=5  Neg=100  After=101
Rule Behavior (measured on seed v90)
Implicit value The current auto counter; it starts at 0 and is set to value + 1 after every member.
Explicit value Member = expr; expr must fold to a comptime-known integer (constant arithmetic is allowed).
Gaps Values need not be contiguous; a range prong over a gap matches only the members, using their exact numbers.
Uniqueness Two members may not share a number; a duplicate is a level-0 reject.
Backing range Every member value must fit the backing width: at most 2^N - 1 for enum(uN); there is no silent truncation.
Construct Code Message (measured)
a non-constant initializer error[3055] enum member value is not a comptime-known integer expression
an out-of-range @as/@intCast initializer error[3055] enum member value is not a comptime-known integer expression (the constant is not materializable at the target width; the reused fixture is repro/mi_matrix/enum_init_cast_range_reject_xmod)
two members with the same value error[3055] duplicate enum tag value (tag values must be unique)
a member value above 2^N - 1 error[3000] enum tag value does not fit the enum backing width (must fit 2^N - 1); no silent truncation

Member access and conversion

A member is named with a leading dot in a typed context (.Green), or qualified by the enum type (Color.Green, colors.Color.Red). Both denote the same value. An enum value is not an integer and an integer is not an enum: crossing between them is an explicit builtin.

Form Result Notes
.Member the enum value Shorthand; needs a known enum type from context.
E.Member the enum value Qualified by the type; works everywhere the type name is in scope, including mod.E.Member.
@enumToInt(e) the backing integer u32 for an inferred enum, u8/u16/u64 for an explicit backing.
@intToEnum(E, n) the enum value Lowers to a plain integer cast; no runtime membership check.

A round trip is exact: @intToEnum(Color, @enumToInt(c)) == c. An integer that names no member is still accepted by @intToEnum and produces an enum value whose only printable name is the fallback spelling @enumFromInt(n); a probe of @intToEnum(Color, 7) on a three-member inferred enum printed @enumFromInt(7). The enum is a typed name for an integer, not a runtime membership test.

The modern Zig spellings @intFromEnum and @enumFromInt are not implemented. Each is rejected with level-0 error[3000] unsupported builtin function. (@enumFromInt(n) appears only as the printer's fallback text for an out-of-range enum value, not as a callable builtin.)

Switch over enums

An enum is a valid switch condition. A prong may list exact members or a range; the short and qualified spellings both work as case items. Every switch in Z98 requires an else prong. 

fn band(c: Color) i32 {
    return switch (c) {
        Color.Red...Color.Green => 10,   // inclusive: Red and Green
        .Blue => 20,
        else => 30,                       // mandatory
    };
}
Rule Behavior (measured on seed v90)
else mandatory A switch without an else rejects level-0 error[3068] switch must have an 'else' prong, in value or statement position.
Exact items A literal member (shorthand or qualified), a compile-time integer literal, or an identifier naming a comptime constant. Several items may share a prong: .Red, .Blue => ....
Inclusive range start...end matches both bounds by their underlying values; expanded to one C case per value.
Exclusive range start..end matches start and stops before end.
Gaps Because endpoints resolve to member values, an enum(uN) with gaps is exact; Code.Ok..Code.Error covers 0…8 and admits Warning (4) but not Error (9).
Mixed endpoints The bounds may be qualified, shorthand, or one of each: .Red...Color.Blue.
Enum capture A prong capture on an enum binds the operand value (type: the enum): .red => |v| .... An unused capture is accepted (a Z98 tolerance).

The reused fixture repro/mi_matrix/stdlib_switch_enum_range_xmod pins all of this in one run: inclusive, exclusive, mixed, shorthand, half-shorthand, enum(u8) gaps, module-qualified (colors.Color.Red...colors.Color.Green), and mixed exact/range prongs all take the expected prong, and the statement form matches the value form. Its output is reproduced verbatim by the seed.

A prong that names a member the enum does not have, or a qualifier that names a different enum, is a level-0 reject rather than a silent fall-through to else:

Shape Code Message (measured)
E.Purple / .Purple (unknown member) error[3071] no field or member function named 'Purple' in enum type, with a related enum declared here span
B.p on an A condition (foreign qualifier) error[3071] type mismatch in switch case item -- case item type may not be compatible with the switch condition type

A same-type alias qualifier (const C = A; C.x) and a module-qualified prong are valid. The rejected shapes and their messages are measured against repro/mi_matrix/switch_case_qualifier_reject_xmod.

Printing an enum

The print forms are chosen by the specifier. A bare {} prints the member name with a leading dot; {d} prints the number in decimal and {x} in hexadecimal. The character and string specifiers are rejects.

Value {} {d} {x}
enum value e (e = .Green, ordinal 1) .Green 1 1
enum value with a value of 16 (enum(u8)) .Member 16 10
@enumToInt(e) used directly as the argument .Green (the printer keeps the member) 1 1
an integer variable holding the ordinal 1 1 1
an out-of-range value from @intToEnum(E, 7) @enumFromInt(7) 7 7
Specifier Result
{c} or {s} on an enum error[3013] invalid print format specifier for the argument type

The reused sample src/vol2/color.z98 shows both sides: std.io.print("c={} int={d}\n", .{ c, @enumToInt(c) }) prints c=.Green int=1. The full print table is on the builtins page; see Builtins.

The .tag field of a tagged union

A tagged union (union(enum)) has a synthetic .tag field typed u32 that holds the variant ordinal (declaration order), independent of any payload. This is the cross-reference point for the enums page; the full rules are on the Unions page.

Use Status (measured on seed v90)
s.tag Reads the ordinal as u32; a pointer base (p.tag) auto-dereferences. p.tag = v stores through it.
s.tag == .m / s.tag != E.m / ordering Member sugar: the member resolves against the union and the comparison is on ordinals, yielding bool.
switch (s.tag) { .m => ..., E.m => ..., else => ... } Member prongs accepted; the switch is on ordinals and never inspects a payload. Numeric prongs (0, 1) are unchanged.
@enumToInt(s.tag) The numeric ordinal, as an ordinary u32.
const t = s.tag; t == .m Rejects level-0 error[3076] unable to infer type of enum literal in comparison with a numeric operand.

A union member named tag is permanently shadowed by the synthetic tag. See Volume II, Unions for the teaching narrative and the unions reference for the variant rules.
