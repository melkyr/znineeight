The Full Grammar

This page is the complete grammar of Z98. It is transcribed from the compiler's parser, sf/src/parser.zig, which is the authority: the Language Specification has no full grammar (section 3.1 carries only a switch fragment), and where the two disagree the parser wins. Every production below is the shape parser.zig accepts; a rule the parser enforces in code rather than as a clean production is described in the text and its source line is cited. The lexical classes come from sf/src/lexer.zig and the token set from sf/src/token.zig.

The parser is recursive descent with a precedence climber for expressions (parserParseExprPrec, parser.zig:272). The productions run from parserParsePrimary (parser.zig:391) and parserParseType (parser.zig:1099) to parserParseStatement (parser.zig:1501) and parserParseBlock (parser.zig:2140).

Notation

  ::=          a production
  |            an alternative
  ( x )        grouping
  { x }        zero or more
  [ x ]        optional
  'x'          a literal token
  IDENT etc.   a lexical class (next section)

Lexical tokens

The lexer (lexer.zig:47) skips spaces, tabs, carriage returns, and comments before each token. Comments are line comments (// to end of line) and block comments (/* ... */); an unterminated block comment is error[1] (lexer.zig:257). The token classes are:

Class Spelling Source
identifier [A-Za-z_][A-Za-z0-9_]* (not a keyword) lexer.zig:436
underscore a lone _ lexer.zig:445
builtin identifier @ immediately followed by a name; @cInclude is its own class lexer.zig:471
integer literal decimal, or 0x/0X hex, 0o/0O octal, 0b/0B binary; _ separators are ignored lexer.zig:377
float literal decimal digits with a . (not followed by another .) or an e/E exponent; no hex floats lexer.zig:399
string literal double-quoted, escape sequences processed, interned lexer.zig:289
character literal single-quoted one character or one escape lexer.zig:344
keywords the 38 words listed below token.zig:149
punctuation / operators the fixed set listed below token.zig:12

The 38 keywords are const, var, fn, pub, extern, export, test, struct, enum, union, packed, if, else, while, for, switch, return, break, continue, defer, errdefer, try, catch, orelse, error, and, or, true, false, null, undefined, unreachable, void, bool, noreturn, c_char, anytype, volatile (token.zig:153-192). The primitive type names i8, u8, i32, usize, isize, f32, f64, the arbitrary-width names (u1…u64, i1… i63), and every user name are identifiers, not keywords; the type resolver gives them meaning.

The punctuation and operator tokens are: 

  ( ) [ ] { } ; : , . @ _ ? ! + - * / % & | ^ ~ << >> == != < <= > >=
  = += -= *= /= %= &= |= ^= <<= >>= +% -% *% +%= -%= *%= +| -| *| <<|
  +|= -|= *|= <<|= .. ... .{ .* =>

A bare @ not followed by a name is error[4] (lexer.zig:163). An integer literal that does not fit in u64 truncates with warning[7] (lexer.zig:426); an unknown escape is warning[6] (lexer.zig:549).

Module and items

A module is a flat sequence of statements. parserParseModuleRoot (parser.zig:1542) calls parserParseStatement for every item, so the item production is exactly the statement production: 

  module_root ::= { item }
  item        ::= statement

On a parse failure the parser records an error[2000] node and skips tokens until a synchronizing one (;, }, fn, const, var, pub, test, or end of file), then keeps parsing, so one bad item does not hide the rest (parser.zig:258,1546-1553).

Declarations

  declaration ::= var_decl | pub_decl | extern_decl | export_decl
                | fn_decl | test_decl | container_decl

  var_decl    ::= ( 'const' | 'var' ) ( IDENT | '_' ) [ ':' type ] [ '=' expr ] ';'

  pub_decl    ::= 'pub' ( fn_decl | var_decl | test_decl | extern_decl | export_decl )
  extern_decl ::= 'extern' [ STRING ] ( fn_decl | var_decl )
  export_decl ::= 'export' ( fn_decl | var_decl )

  test_decl   ::= 'test' [ STRING ] block

  fn_decl     ::= 'fn' IDENT '(' param_list ')' [ ret ] ( ';' | block )
  param_list  ::= [ param { ',' param } [ ',' ] ] [ '...' ]
  param       ::= IDENT ':' type
  ret         ::= ':' type
                | type      ; colon omitted; only when the next token is not ';' or '{'
                | epsilon   ; empty: the return type is void

  container_decl    ::= struct_decl | enum_decl | union_decl
  struct_decl       ::= 'struct' [ IDENT ] '{' [ struct_field { ',' struct_field } [ ',' ] ] '}'
  struct_field      ::= IDENT ':' type
  enum_decl         ::= 'enum' [ '(' type ')' ] [ IDENT ] '{' [ enum_field { ',' enum_field } [ ',' ] ] '}'
  enum_field        ::= IDENT [ '=' expr ]
  union_decl        ::= 'union' [ '(' 'enum' ')' ] [ IDENT ] '{' [ union_field { ',' union_field } [ ',' ] ] '}'
  union_field       ::= IDENT [ ':' type ]

Notes on the declaration forms, all keyed to parser.zig:

  • const and var are the same production; const sets the immutable flag (parser.zig:1596-1633). A declaration may omit its type, its initializer, or both, but must end with ;. The name may be _.
  • pub must be followed by one of fn, const, var, test, extern, or export; anything else is error[2000] “expected fn/const/var after pub” (parser.zig:1634-1645).
  • extern takes an optional calling-convention string. The only accepted values are "c", "cdecl", and "stdcall"; any other string is error[3045] “unknown calling convention in `extern`” (parser.zig:1651-1658,1665-1685). extern and export likewise require fn/const/var (parser.zig:1682,1692).
  • A function parameter is always IDENT ':' type. The variadic ... may appear only once and must be last; it sets the variadic flag and terminates the list (parser.zig:1709-1713).
  • The return type's colon is optional: fn f() i32 and fn f(): i32 are the same. With neither a colon nor a type before ; or {, the return is void (parser.zig:1736-1742).
  • A container declared with container_decl may carry a name after the optional backing clause; a bare struct { ... } used as a type has no name (next section).

Types

  type      ::= '*' ptrquals type
              | '[' '*' ']' ptrquals type
              | '[' ']' [ 'const' ] type
              | '[' expr ']' type
              | '?' type
              | '!' type
              | 'error' '{' [ IDENT { ',' IDENT } [ ',' ] ] '}' [ '!' type ]
              | type_name '!' type
              | 'extern' [ STRING ] 'fn' fnptr_params [ ret ]
              | 'fn' fnptr_params [ ret ]
              | 'struct' '{' struct_body '}'
              | 'packed' 'struct' '{' struct_body '}'
              | 'enum' [ '(' type ')' ] '{' [ enum_field { ',' enum_field } [ ',' ] ] '}'
              | 'union' [ '(' 'enum' ')' ] '{' [ union_field { ',' union_field } [ ',' ] ] '}'
              | 'packed' 'union' '{' [ union_field { ',' union_field } [ ',' ] ] '}'
              | 'anytype'
              | type_name

  ptrquals  ::= { 'const' | 'volatile' }
  type_name ::= IDENT { '.' IDENT }

  fnptr_params ::= '(' [ fnptr_param { ',' fnptr_param } [ ',' ] ] ')'
  fnptr_param  ::= type | IDENT ':' type

  struct_body  ::= [ named_field { ',' named_field } [ ',' ] ]
                 | [ tuple_field { ',' tuple_field } [ ',' ] ]
  named_field  ::= IDENT ':' type
  tuple_field  ::= type

The type forms correspond one-to-one to parser functions: parserParsePtrType (parser.zig:1164), parserParseBracketType (parser.zig:1175), parserParseOptionalType (parser.zig:1206), parserParseErrorUnionType (parser.zig:1214), parserParseErrorSetDecl (parser.zig:1289), parserParseExternFnType (parser.zig:1222), parserParseFnType (parser.zig:1244), parserParseStructType (parser.zig:1318), parserParseEnumType (parser.zig:1387), parserParseUnionType (parser.zig:1427), and parserParseTypeName (parser.zig:1483). The dispatch is parserParseType (parser.zig:1099).

  • Pointers. *T is a single-item pointer; [*]T is a many-item pointer. Both take a qualifier list of const and volatile in any order (*const volatile u8 is legal; parser.zig:1148-1161). A qualifier may not follow []: the slice production admits only const (parser.zig:1186-1196), so []volatile T is a parse error.
  • Arrays and slices. [N]T parses its length as a full assignment-precedence expression, then ], then the element type. There is no separate inferred-length production: [_]T matches the general '[' expr ']' type form with _ parsed as a primary expression, and the length is inferred from the initializer / array literal. Both var a = [_]i32{ 1, 2, 3 }; and the bare type [_]i32 are accepted.
  • Error sets and unions. error { ... } is a set; error { ... } ! T and Name ! T are error unions (parser.zig:1107-1116,1137-1145,1294-1316).
  • Function-pointer types. A parameter may be a bare type or IDENT ':' type. The variadic ... is rejected here with error[2000] “varargs not allowed in function pointer types” (parser.zig:1250-1256).
  • Structs and tuples. struct { name: T, ... } is a named struct; struct { T1, T2, ... } is a positional tuple type. The two kinds may not be mixed: the parser rejects a mixture with error[2000] “struct fields must be all named or all positional (tuple)” (parser.zig:1326-1369). A packed struct may not use positional tuple fields (parser.zig:1358-1361).
  • Enums. The backing type is optional and appears before the brace: enum(u8) { ... } (parser.zig:1390-1394).
  • Unions. union { ... } is bare, union(enum) { ... } is tagged, and packed union { ... } is packed. A tagged union field may omit its type (a naked tag, treated as void); a bare-union field may also omit it at parse time, and the resolver rejects that afterward (parser.zig:1427-1481). A packed union may not be tagged: packed union(enum) is error[2000] “packed unions cannot be tagged (union(enum)); packed union is an untagged container” (parser.zig:1437-1441).
  • packed. The packed keyword must be followed by struct or union; otherwise error[2000] (parser.zig:1121-1128).
  • anytype. The parser accepts anytype as a type leaf (parser.zig:1130-1136); it is the semantic analyzer that rejects it in every signature and type position with error[16] since Amendment A1 (analyzer.zig:449,513).

Expressions

Expressions are parsed by precedence climbing. The precedence levels are the Prec enum (parser.zig:2185) and the operator-to-level map is getInfixInfo (parser.zig:2216). Higher binds tighter.

Level Name Operators Assoc.
1assignment= += -= *= /= %= &= |= ^= <<= >>= +%= -%= *%= +|= -|= *|= <<|=right
2orelseorelseright
3catchcatchright
4bool ororleft
5bool andandleft
6comparison== != < <= > >=left
7bit or|left
8bit xor^left
9bit and&left
10shift<< >> <<|left
11additive+ - +% -% +| -|left
12multiply* / % *% *|left
13prefix- -% ! ~ &—
14postfixcall, index, slice, field, deref, struct init—

The assignment, orelse, and catch levels are right-associative; the binary arithmetic, bit, shift, comparison, and logical levels are left-associative. The prefix operators and the postfix chain are not binary levels. catch and orelse are handled specially rather than as ordinary binary operators because each may take a capture and a block right-hand side (parser.zig:304-314,566-593). 

  expr       ::= assignment

  assignment ::= orelse [ assign_op assignment ]
  orelse     ::= catch [ 'orelse' ( block | orelse ) ]
  catch      ::= bool_or [ 'catch' [ '|' capture '|' ] ( block | catch ) ]
  bool_or    ::= bool_and { 'or' bool_and }
  bool_and   ::= comparison { 'and' comparison }
  comparison ::= bit_or { cmp_op bit_or }
  bit_or     ::= bit_xor { '|' bit_xor }
  bit_xor    ::= bit_and { '^' bit_and }
  bit_and    ::= shift { '&' shift }
  shift      ::= additive { shift_op additive }
  additive   ::= multiply { add_op multiply }
  multiply   ::= prefix { mul_op prefix }
  prefix     ::= prefix_op prefix | postfix
  postfix    ::= primary { postfix_op }

  assign_op  ::= '=' | '+=' | '-=' | '*=' | '/=' | '%=' | '&=' | '|=' | '^='
               | '<<=' | '>>=' | '+%=' | '-%=' | '*%=' | '+|=' | '-|=' | '*|=' | '<<|='
  cmp_op     ::= '==' | '!=' | '<' | '<=' | '>' | '>='
  shift_op   ::= '<<' | '>>' | '<<|'
  add_op     ::= '+' | '-' | '+%' | '-%' | '+|' | '-|'
  mul_op     ::= '*' | '/' | '%' | '*%' | '*|'
  prefix_op  ::= '-' | '-%' | '!' | '~' | '&'

  postfix_op ::= '.*'
               | '.' ( IDENT | INT )
               | '[' index_or_slice ']'
               | '(' [ arg_list ] ')'
               | '{' [ field_init_list ] '}'
  index_or_slice    ::= expr | expr '..' [ expr ]
  arg_list          ::= expr { ',' expr } [ ',' ]
  field_init_list   ::= field_init { ',' field_init } [ ',' ]
  field_init        ::= '.' IDENT '=' expr

The postfix chain is applied left to right (parserParsePostfixChain, parser.zig:460). The valid starts of a primary expression are: 

  primary ::= INT | FLOAT | STRING | CHAR
            | 'true' | 'false' | 'null' | 'undefined' | 'unreachable'
            | '_'
            | IDENT
            | IDENT '!' type            ; error-union type in expression position
            | IDENT ':' block           ; labeled block expression
            | builtin_call
            | '@cInclude' '(' STRING ')'
            | 'error' '.' IDENT         ; error literal
            | 'error' '{' ... '}' [ '!' type ]
            | 'try' prefix
            | '(' expr_orelse ')'
            | anon_literal
            | '.' IDENT                 ; enum literal
            | if_expr
            | switch_expr
            | array_type [ array_init ]
            | type                      ; any other type form in expression position
            | 'return' [ expr ]
            | 'break' [ ':' IDENT ]
            | 'continue' [ ':' IDENT ]
            | block

  builtin_call ::= BUILTIN '(' [ builtin_arg { ',' builtin_arg } [ ',' ] ] ')'
  builtin_arg  ::= type | expr

  anon_literal ::= '.{' '}'                                      ; empty struct literal
                 | '.{' field_init { ',' field_init } [ ',' ] '}' ; named struct literal
                 | '.{' expr { ',' expr } [ ',' ] '}'             ; tuple literal

  array_type   ::= '[' '*' ']' ptrquals type
                 | '[' ']' [ 'const' ] type
                 | '[' expr ']' type
  array_init   ::= '{' [ expr { ',' expr } [ ',' ] ] '}'

  if_expr     ::= 'if' '(' expr_orelse ')' [ capture ] expr [ 'else' expr ]
  switch_expr ::= 'switch' '(' expr_orelse ')' '{' { switch_prong [ ',' ] } '}'
  switch_prong ::= 'else' '=>' [ capture ] prong_body
                 | case_item { ',' case_item } '=>' [ capture ] prong_body
  case_item   ::= expr_assign [ ( '..' | '...' ) expr_assign ]
  prong_body  ::= block | expr_assign

  capture      ::= IDENT | '_'
  expr_orelse  ::= expr restricted to precedence 2 and tighter (assignment excluded)
  expr_assign  ::= expr restricted to precedence 1 and tighter

Where the parser deviates from a clean production:

  • Assignment is not an expression in a condition. Conditions and parenthesized expressions are parsed at the prec_orelse level, which excludes the assignment level, so if (a = 3), while (a = 3), switch (a = 3), and (a = 3) fail at the closing delimiter with error[2000]: expected ')' but found token — a missing-delimiter diagnostic, not a dedicated assignment message (parser.zig:721-731,939-947,979-984,1776-1780,1854-1859).
  • Expression depth. The climber increments a depth counter and calls @panic("max expression recursion depth exceeded") past 12 nested expression levels (parser.zig:272-277). This is a hard compiler abort, not a diagnostic.
  • Numeric members. .0, .1, … are parsed as field accesses, but the integer token is canonicalized to its decimal text and interned rather than read as a string id (parser.zig:493-506). The resolver later decides whether the base is a tuple; a numeric member on a non-tuple is error[3060].
  • Call arguments and builtin arguments. A call argument is an expression. A builtin argument is a type when it begins with *, [, ?, !, fn, struct, enum, union, error, or anytype, and an expression otherwise (parser.zig:748-772).

Statements

  statement ::= declaration
              | if_stmt | while_stmt | for_stmt | switch_stmt
              | return_stmt | break_stmt | continue_stmt
              | defer_stmt | errdefer_stmt
              | block
              | ';' statement
              | IDENT ':' statement
              | expr_stmt

  expr_stmt   ::= expr_assign [ ';' ]   ; the ';' may be omitted iff the next token is '}'

  if_stmt     ::= 'if' '(' expr_orelse ')' [ capture ] ( block | expr_assign )
                  [ 'else' ( if_stmt | block | expr_assign ) ]
  while_stmt  ::= 'while' '(' expr_orelse ')' [ capture ] [ ':' '(' expr ')' ]
                  ( block | expr_assign ) [ ';' ]
  for_stmt    ::= 'for' '(' for_pattern ')' [ for_capture ] ( block | expr_assign ) [ ';' ]
  for_pattern ::= expr [ '..' expr ]
                | expr ',' expr '..' [ expr ]
  for_capture ::= '|' capture [ ',' IDENT ] '|'

  switch_stmt ::= switch_expr
  return_stmt ::= 'return' [ expr ] ';'
  break_stmt  ::= 'break' [ ':' IDENT ] ';'
  continue_stmt ::= 'continue' [ ':' IDENT ] ';'
  defer_stmt  ::= 'defer' statement
  errdefer_stmt ::= 'errdefer' statement

  block ::= '{' { statement } '}'
  • The dispatcher. parserParseStatement (parser.zig:1501) chooses by the first token. A leading ; is consumed recursively as an empty statement, so runs of semicolons are accepted (parser.zig:1524-1527). An identifier followed by : is a labeled statement; otherwise the statement is an expression statement (parser.zig:1528-1531).
  • Statement body braces. The bodies of if, while, for, defer, and errdefer may be a block or a single statement/expression; no synthetic braces are inserted by the parser. Only if requires an explicit else when it is used as a value (enforced by the analyzer, semantic_analyzer.zig:3640).
  • switch as a statement. parserParseSwitchStmt wraps the switch expression in an expression statement (parser.zig:1981-1983), so a statement-position switch needs no semicolon; the mandatory else prong is a semantic rule (error[3068], semantic_analyzer.zig:4164), not a parse rule.
  • The semicolon before else. The statement if form rejects a ; that immediately precedes else with error[2000] “';' not allowed before 'else' - use braces: if (cond) { ... } else { ... }” (parser.zig:1836-1843). Write the braces, or omit the semicolon as in if (a) return 1 else return 0;.
  • Loop captures. while and for accept a capture after the ); for allows a second, comma-separated index capture. The capture name may be _. The optional while ... : (expr) continue expression is parsed at the lowest precedence (parser.zig:1861-1875,1877-1883,1944-1961).
  • For patterns. for accepts a plain expression, a start..end range, or an explicit index range: an iterable, a comma, then start.. or start..end. The index range builds a for_index_range node; no other multi-object for form is accepted (parser.zig:1906-1941).
  • defer and errdefer. Both take a single statement, which is usually a block or an expression statement (parser.zig:2049-2062).

Two further boundaries are parser facts rather than diagnostics: the expression-nesting depth cap (12, then @panic, parser.zig:274), and the module-level recovery described above. There is no comptime, no generics, no @cImport, no value-producing labeled block, and no anyerror type in the grammar; those absences are the grammar, not omissions from it.
