Port a C File to Z98

This guide translates a small C89 program to Z98 one idiom at a time, then builds both programs and runs them to show they behave the same. The pairing is the one printed in the manual: the C89 evaluator from Volume II, Honesty: When C89 Is the Better Choice, and its Z98 twin. The C original is committed at docs/sf/manuals/src/vol5/portc/lisp_eval.c; its Z98 twin is the shipped sample docs/sf/manuals/src/vol2/lisp_eval.z98.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc. The C original and the emitted Z98 build script both use gcc -m32 -std=c89.
  • The repository checked out, so the two source files above are present. Every command runs from the repository root, /workspace/znineeight.
  • The language practices behind the port: Model and propagate errors for error unions and Use the arena correctly for the node pool. The C89 seam itself is Link Z98 output against C89 libraries.

The idea

A port is not a rewrite. Most of the C file survives line for line: the arithmetic, the recursion, the shape of the switch. What changes is the small set of C89 conventions that Z98 moves into the type system. This guide names those conventions, shows the Z98 replacement for each, and then proves the two programs agree. The checklist is deliberately short — types, arrays to slices, errors, cleanup to defer, and ownership to the arena — because those five are where a C89 file carries its discipline by hand.

Steps

  1. Read the C original. It is the Volume II evaluator completed into one buildable file: an enum tag and a union payload per node, a status int threaded through every call, and a hand-rolled pool of nodes freed once at the end. 

    #include <stdio.h>
#include <stdlib.h>

typedef enum { E_NUM, E_NEG, E_ADD, E_SUB, E_MUL, E_DIV } EKind;

typedef struct Expr {
    EKind kind;
    union {
        int num;
        struct Expr *neg;
        struct { struct Expr *l, *r; } bin;
    } u;
} Expr;

/* 0 = success, -1 = divide by zero; the result comes back through *out */
static int eval(const Expr *e, int *out)
{
    int l, r;
    switch (e->kind) {
    case E_NUM: *out = e->u.num; return 0;
    case E_NEG:
        if (eval(e->u.neg, &l) != 0) return -1;
        *out = -l; return 0;
    case E_ADD:
        if (eval(e->u.bin.l, &l) != 0) return -1;
        if (eval(e->u.bin.r, &r) != 0) return -1;
        *out = l + r; return 0;
    case E_SUB:
        if (eval(e->u.bin.l, &l) != 0) return -1;
        if (eval(e->u.bin.r, &r) != 0) return -1;
        *out = l - r; return 0;
    case E_MUL:
        if (eval(e->u.bin.l, &l) != 0) return -1;
        if (eval(e->u.bin.r, &r) != 0) return -1;
        *out = l * r; return 0;
    case E_DIV:
        if (eval(e->u.bin.l, &l) != 0) return -1;
        if (eval(e->u.bin.r, &r) != 0) return -1;
        if (r == 0) return -1;
        *out = l / r; return 0;
    default: return -1;
    }
}

/* A hand-rolled arena: one malloc'd block of nodes, bump-allocated. */
typedef struct Pool { Expr *nodes; int used; } Pool;

static Expr *make(Pool *p, EKind kind)
{
    Expr *e = &p->nodes[p->used++];
    e->kind = kind;
    return e;
}

    The driver below allocates a 64-node block, builds (2+3)*(10-4)/2, evaluates it, then evaluates 10/(10-10) and reports the failure, before freeing the block once. The rest of the file (mknum, mkbin, and main) is the same construct-and-evaluate shape as the Z98 twin.

  2. Build and run the C original, so you have a baseline to compare against. The flags are the era set: 32-bit, C89, no optimization, warnings on. 

    $ cd /workspace/znineeight
$ timeout 120 gcc -m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign \
      -o /tmp/portc_c docs/sf/manuals/src/vol5/portc/lisp_eval.c
$ timeout 120 /tmp/portc_c
eval((2+3)*(10-4)/2) = 15
eval(10/(10-10)) caught DivideByZero

    That clean compile and the two lines are the contract the port must meet.

  3. Translate the five C idioms. Work through them in this order; each has a short before and after taken from the two files.

    Types: tag plus union to union(enum)

    C89 keeps the discriminator and the payload in two places, and nothing ties them together. Z98 makes them one sum type whose switch binds the payload: 

    typedef enum { E_NUM, ... } EKind;          /* C89: tag ... */
typedef struct Expr { EKind kind;
    union { int num; ... } u; } Expr;       /* ... plus a separate union payload */

    const Expr = union(enum) {                  /* Z98: one type */
    num: i32,
    neg: u32,
    add: Bin, sub: Bin, mul: Bin, div: Bin,
};

    The bounded integer types (i32, u32) replace int, and the recursion by pointer becomes a recursion by index.

    Arrays to slices: a base pointer plus a count to []Expr

    The C node pool is an Expr * and a separate used count, so every access carries an implied bound the compiler cannot see. The Z98 twin hands eval a slice, which carries its own length: 

    int eval(const Expr *e, int *out);          /* C89: pointer, no length */

    fn eval(nodes: []Expr, i: u32) error{DivideByZero}!i32

    Indexing a slice is checked in the default safety mode. Integer indices (i32, u32, usize) are accepted directly; the @intCast(usize, i) in the twin is not required, it records that the value is an offset and keeps the arithmetic explicit. A non-integer index is the actual mistake, and the emitter does not catch it — the generated C then fails to compile.

    Errors: a status int and an out-parameter to an error union

    The C evaluator signals failure with -1 and writes its result through *out; the caller is trusted to check the status. Z98 puts the failure in the return type, so the result and the error travel together: 

    static int eval(const Expr *e, int *out)    /* C89: -1 = divide by zero */
{
    ...
    if (r == 0) return -1;
}

    fn eval(nodes: []Expr, i: u32) error{DivideByZero}!i32 {
    ...
    if (rhs == 0) return error.DivideByZero;
    return (try eval(nodes, b.l)) / rhs;
}

    try propagates the error and the compiler refuses to let it be dropped; the call site uses catch. This is the error-union material of Model and propagate errors.

    Cleanup to defer: hand-written release to scope exit

    C89 runs its cleanup by hand on every path: the C original frees the block after the last evaluation. Where the resource is not arena-backed — a file, a writer, a lock — Z98 states the release once with defer (always) and errdefer (only on the error path), and the language runs it at scope exit. In this particular port the arena removes the release entirely, so there is nothing left to defer; the committed sample docs/sf/manuals/src/vol2/defer.z98 is the worked demonstration of the idiom.

    Ownership to the arena: malloc/free to std.arena

    The C original already hand-rolls an arena: one malloc for a block of nodes, bump allocation through pool.used, and one free at the end. The port keeps that idea and drops the two libc calls, because Z98 ships the arena: 

    pool.nodes = (Expr *)malloc(sizeof(Expr) * 64);   /* C89: allocate ... */
...
free(pool.nodes);                                  /* ... and free by hand */

    var buf: [8192]u8 = undefined;
var arena = std.arena.init(buf[0..]);
const raw = try std.arena.alloc(&arena, @sizeOf(Expr) * 64);
var pool = Pool{ .nodes = @ptrCast([*]Expr, raw)[0..64], .used = 0 };

    There is no per-object free to match, so an early return cannot leak and a stale pointer cannot be freed twice. Exhausting the arena is a caught error, not a null dereference.

  4. Read the Z98 twin. It is the whole program, and it already ships at docs/sf/manuals/src/vol2/lisp_eval.z98: 

    const std = @import("std");

const Bin = struct { l: u32, r: u32 };

const Expr = union(enum) {
    num: i32,
    neg: u32,
    add: Bin,
    sub: Bin,
    mul: Bin,
    div: Bin,
};

const Pool = struct { nodes: []Expr, used: u32 };

fn make(pool: *Pool, e: Expr) u32 {
    const i = pool.used;
    pool.nodes[@intCast(usize, i)] = e;
    pool.used = i + 1;
    return i;
}

fn eval(nodes: []Expr, i: u32) error{DivideByZero}!i32 {
    switch (nodes[@intCast(usize, i)]) {
        .num => |v| return v,
        .neg => |j| return -(try eval(nodes, j)),
        .add => |b| return (try eval(nodes, b.l)) + (try eval(nodes, b.r)),
        .sub => |b| return (try eval(nodes, b.l)) - (try eval(nodes, b.r)),
        .mul => |b| return (try eval(nodes, b.l)) * (try eval(nodes, b.r)),
        .div => |b| {
            const rhs = try eval(nodes, b.r);
            if (rhs == 0) return error.DivideByZero;
            return (try eval(nodes, b.l)) / rhs;
        },
        else => unreachable,
    }
}

pub fn main() !void {
    var buf: [8192]u8 = undefined;
    var arena = std.arena.init(buf[0..]);
    const raw = try std.arena.alloc(&arena, @sizeOf(Expr) * 64);
    var pool = Pool{ .nodes = @ptrCast([*]Expr, raw)[0..64], .used = 0 };

    const two = make(&pool, .{ .num = 2 });
    const three = make(&pool, .{ .num = 3 });
    const ten = make(&pool, .{ .num = 10 });
    const four = make(&pool, .{ .num = 4 });

    const sum = make(&pool, .{ .add = .{ .l = two, .r = three } });
    const diff = make(&pool, .{ .sub = .{ .l = ten, .r = four } });
    const product = make(&pool, .{ .mul = .{ .l = sum, .r = diff } });
    const answer = make(&pool, .{ .div = .{ .l = product, .r = two } });

    std.io.print("eval((2+3)*(10-4)/2) = {}\n", .{ try eval(pool.nodes, answer) });

    const zero = make(&pool, .{ .sub = .{ .l = ten, .r = ten } });
    const bad = make(&pool, .{ .div = .{ .l = ten, .r = zero } });
    _ = eval(pool.nodes, bad) catch {
        std.io.print("eval(10/(10-10)) caught DivideByZero\n", .{});
        return;
    };
    std.io.print("unreachable\n", .{});
}

    make is the pool bump in one place, exactly as the C make; eval is the same recursion with try where C checked -1. The nodes reference each other by u32 index rather than by pointer, which is what lets the whole graph live in one slice.

  5. Build and run the Z98 twin, exactly as in Build a single file. The emitted gcc prints many warnings from the runtime's unused static helpers; the build is not red and the binary runs. 

    $ rm -rf /tmp/portc_z98
$ mkdir -p /tmp/portc_z98
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/portc_z98 docs/sf/manuals/src/vol2/lisp_eval.z98
$ cd /tmp/portc_z98 && timeout 120 sh build_target.sh linux lisp_eval
Building for linux...
Built: lisp_eval
$ timeout 120 ./lisp_eval
eval((2+3)*(10-4)/2) = 15
eval(10/(10-10)) caught DivideByZero

    The compiler requires the output directory to exist, which is why the commands create /tmp/portc_z98 first.

  6. Confirm the port by the emitted type. The error union the C status encoded by convention is now a real return type in the generated C89: 

    $ grep -n 'eval(' /tmp/portc_z98/lisp_eval_69EA6B8C.c | head -1
34:zT_0DA61B72_EU_6 zF_08D22E0F_eval(zT_C1D41244_Slice_zT_3D06A9CE_E nodes, unsigned int i) {

    zT_..._EU_6 is the emitted error-union struct, the slice type carries the length into the function, and the mangled name is the ordinary C symbol the linker sees. The mangling rules are in docs/reference/name_mangling.md and docs/reference/c89_emission.md; the emitted file is the subject of Link Z98 output against C89 libraries.

Verify it worked

Both programs print the same two lines and exit 0: 

eval((2+3)*(10-4)/2) = 15
eval(10/(10-10)) caught DivideByZero

The first line is the successful evaluation: (2+3) is 5, (10-4) is 6, the product is 30, and 30/2 is 15. The second line is the error path: the evaluator reaches a zero divisor and reports it.

Agreement of the two outputs is the port's acceptance test. The C version returns -1 and the Z98 version returns error.DivideByZero, but the observable behavior is identical, and the Z98 side did it without a per-node free and without an unchecked status. If you see both lines from both binaries, the translation holds at the one place a port can silently break: the failure path.

Common mistakes

  • Ignoring the error union. The direct translation of C89's unchecked status is a dropped Z98 result, which the compiler rejects: 
    error[3015]: error union result is ignored; use 'try', 'catch', or assign the result
    Use try to propagate or catch to handle, as main does.
  • Returning an error from a void function. C's int status can be dropped from any function; a Z98 try needs a return type that can carry the error: 
    error[3075]: expected type 'void', found error set
note: function cannot return an error
    Declare the function error{DivideByZero}!i32, not void.
  • Using a non-integer index. An integer index — i32, u32, usize — is fine; the @intCast in the twin is optional, not required. A float is the real error, and the compiler emits it without complaint, so the failure surfaces only in the generated C: 
    error: array subscript is not an integer
    zT_5 = zT_2[i];
    Index with an integer type, or cast to usize at the use as the twin does.
  • Porting the pointer graph instead of the indices. Keeping struct Expr * links in Z98 fights the arena and the checks. Store indices into one []Expr as the twin does; the recursion is the same and the graph stays in one buffer.
  • Forgetting a literal bound is still a bound. The C pool is fixed at 64 nodes; in the twin a slice index past 64 traps under the default safety mode. That is the point — a bound bug that corrupts memory in C89 stops and reports in Z98.
  • Writing the free by hand. The arena has no per-object release. Porting the free(pool.nodes) line is not only unnecessary, it has no counterpart; lifetime is the arena's reset. Use defer only for resources the arena does not own.
