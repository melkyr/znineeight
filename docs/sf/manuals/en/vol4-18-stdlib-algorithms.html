Algorithms

The algorithm modules are imported by path with @import("std_rand.zig"), @import("std_pathfind.zig"), and so on. None is in the thirteen-name std re-export list. They are concrete and free-function based: random number generators are structs with explicit seeds, the ODE stepper and the physics world are caller-owned values, and the pathfinders allocate scratch or maps from a caller arena.

The page is organised from the deterministic seed contract outward: std_rand supplies the generators, std_noise builds on them, std_num is numeric integration, std_pathfind supplies grid search, std_physics uses the random generator for its constraint order, and std_hpa builds on the pathfinder.

std_rand

std_rand has two concrete generators, each with an explicit u64 seed and no clock, environment, address, or process id input. pcg32Init follows O'Neill's pcg32_srandom_r seeding: the stream argument becomes the odd increment, the state is advanced, the seed is added, and the state is advanced again. xoshiroInit expands its seed through SplitMix64 into four 64-bit words. Both bounded functions use rejection sampling, not a modulo reduction. A zero bound is a panic.

pcg32Next pub fn pcg32Next(r: *Pcg32) u32 u32 Return the next 32-bit value and advance the state.
pcg32Bounded pub fn pcg32Bounded(r: *Pcg32, bound: u32) u32 u32 in [0, bound); panics when bound == 0 Uniform bounded value by rejection sampling.
pcg32Advance pub fn pcg32Advance(r: *Pcg32, delta: u64) void void Advance the PCG state by delta steps without generating intermediates.
xoshiroInit pub fn xoshiroInit(seed: u64) Xoshiro256 Xoshiro256 Expand a u64 seed with SplitMix64.
xoshiroNext pub fn xoshiroNext(r: *Xoshiro256) u64 u64 Return the next 64-bit value and advance the state.
xoshiroBounded pub fn xoshiroBounded(r: *Xoshiro256, bound: u64) u64 u64 in [0, bound); panics when bound == 0 Uniform bounded value by rejection sampling.

The generators are deterministic: the same state and call sequence produce the same values on every run. They do not self-seed. Callers that need a different reproducible sequence choose a different seed; callers that need non-reproducibility must obtain a seed from their own entropy source.

std_noise

std_noise implements Kurt Spencer's 2014 OpenSimplex noise, not OpenSimplex2. The state is the 256-byte permutation plus its 256-byte gradient table, 512 bytes in all. Initialisation builds the permutation with a seeded xoshiro256** Fisher-Yates shuffle, so there is no heap, clock, environment, pid, or address input. All arithmetic is f64. The 2D gradients are the eight compass gradients and the 3D gradients are the 24 rhombicuboctahedron gradients. The 2014 reference lattice is preserved: at seed 0 the origin is zero but the neighbouring lattice points are not all zero.

The noise functions allocate nothing and take the state by const pointer, so one initialised state can serve any number of samples. The seed is the only input to opensimplexInit; the seed contract is the same deterministic one as std_rand.

std_num

std_num is a Dormand-Prince 5(4) adaptive Runge-Kutta step, the same seven-stage pair used by MATLAB's ode45. It is an explicit method, so stiff problems may reject down to min_step. The function is FSAL: on entry dy must hold f(t, y), and on a successful return it holds f(t_new, y_new). The error norm is a scaled root-mean-square over the state vector. There is no allocation; the stage scratch is fixed in the function and the maximum state dimension is 64.

Name Signature / declaration Returns / error Purpose
Rk45Config pub const Rk45Config = struct { abs_tol: f64, rel_tol: f64, min_step: f64, max_step: f64, max_steps: u32 }; — Tolerances, step bounds, and retry limit.
Rk45State pub const Rk45State = struct { t: f64, y: []f64, dy: []f64, cfg: Rk45Config }; — Current time, state, derivative, and configuration.
rk45Step pub fn rk45Step(state: *Rk45State, f: fn (f64, []const f64, []f64) void, dt: *f64) !void !void; error.StepTooSmall Attempt one adaptive step, updating the state and the next-step suggestion.

On entry dt is the requested step, clamped to max_step; on return it is the next suggested step, grown by 1.5 after a sufficiently accurate accepted step and capped at max_step. state.t advances by the step actually accepted. error.StepTooSmall is returned when the initial step is below min_step, when a retry would fall below min_step, or when max_steps attempts are exhausted. An empty state vector or one longer than 64 is a panic.

std_pathfind

std_pathfind searches an 8-connected grid. A tile value of zero is blocked and one is walkable. Cardinal moves cost 10, diagonal moves cost 14, and the heuristic is the octile distance 10*max(dx,dy) + 4*min(dx,dy). A diagonal move is legal only when both adjacent cardinal cells are walkable, so corner cutting is strictly forbidden. The plain search is JPS; the preprocessed search is JPS+.

Both search functions treat out as a capacity in u32 slots. They write at most out.len / 2 complete (x, y) pairs, ignore an odd trailing slot, and never write past the slice. The return value is always the full path tile count, so a caller detects truncation with 2*return > out.len. A walkable start == goal returns 1 and writes the single pair when out.len >= 2.

Name Signature / declaration Returns / error Purpose
Point pub const Point = struct { x: u32, y: u32 }; — A grid coordinate.
Grid pub const Grid = struct { tiles: []u8, width: u32, height: u32 }; — Row-major tiles, zero blocked and one walkable.
jpsFind pub fn jpsFind(arena: *arena_mod.Arena, grid: *const Grid, start: Point, goal: Point, out: []u32) !u32 !u32; error.NoPath or error.OutOfMemory Plain JPS search with a heap open set and arena scratch.
JpsPlus pub const JpsPlus = struct { dist: []i32, width: u32, height: u32 }; — The persistent JPS+ distance table.
jpsPlusBuild pub fn jpsPlusBuild(arena: *arena_mod.Arena, grid: *const Grid) !JpsPlus !JpsPlus; error.OutOfMemory Precompute the eight directional distances for every tile.
jpsPlusFind pub fn jpsPlusFind(arena: *arena_mod.Arena, map: *const JpsPlus, grid: *const Grid, start: Point, goal: Point, out: []u32) !u32 !u32; error.NoPath or error.OutOfMemory Search using the precomputed table.

JpsPlus.dist stores eight signed i32 distances per cell in direction order N, NE, E, SE, S, SW, W, NW. A positive value is the distance to the next static jump point in that direction, a negative value is the distance to the wall when there is no jump point first, and zero means the cell is blocked or the move is illegal. The persistent table is exactly 32 bytes per cell. The build also uses one transient N-byte jump-point bitmap, so peak build memory is 33 bytes per cell; the bitmap is not retained.

The table is a static snapshot; rebuild it after any tile change. The find validates the map dimensions and the table length against the grid. The open set is the std_heap min-heap keyed by the composite (f << 32) | (~g & 0xffffffff), so equal f prefers the larger g.

std_physics

std_physics is position-based dynamics with distance constraints. A world is allocated once at pbdInit with fixed capacities. The slices are capacities; particle_count and constraint_count are the live entries. order is the constraint-count scratch array used for the per-iteration shuffle. The world carries its own xoshiro256** generator, seeded explicitly at init.

Name Signature / declaration Returns / error Purpose
Particle pub const Particle = struct { pos: [3]f32, prev: [3]f32, inv_mass: f32 }; — Current position, previous position, and inverse mass.
DistanceConstraint pub const DistanceConstraint = struct { a: u32, b: u32, rest: f32, stiffness: f32 }; — A distance constraint between two particle indices.
PbdWorld pub const PbdWorld = struct { particles: []Particle, constraints: []DistanceConstraint, order: []u32, particle_count: u32, constraint_count: u32, gravity: [3]f32, damping: f32, iterations: u8, rng: rand_mod.Xoshiro256 }; — Capacities, live counts, solver settings, and random state.
pbdInit pub fn pbdInit(arena: *arena_mod.Arena, particle_count: u32, constraint_count: u32, seed: u64) !PbdWorld !PbdWorld; error.OutOfMemory (inferred) Allocate the three arrays and initialise the generator.
pbdAddParticle pub fn pbdAddParticle(w: *PbdWorld, pos: [3]f32, inv_mass: f32) u32 u32 index; panics on over-capacity or a negative inverse mass Append a particle with its position and inverse mass.
pbdAddDistance pub fn pbdAddDistance(w: *PbdWorld, a: u32, b: u32, stiffness: f32) u32 u32 index; panics on over-capacity, equal indices, or an out-of-range index Add a distance constraint, using the current positions to set its rest length.
pbdPin pub fn pbdPin(w: *PbdWorld, i: u32) void void; panics on a bad index Pin a particle by setting its inverse mass to zero.
pbdStep pub fn pbdStep(w: *PbdWorld, dt: f32) void void; no error Integrate, shuffle the constraints, and run the projection iterations.

A step integrates every non-pinned particle with new = pos + (pos-prev)*(1-damping) + gravity*dt*dt and then stores prev = old pos. Each projection iteration identity-fills order[0..constraint_count], Fisher-Yates shuffles it with xoshiroBounded(i+1), and projects constraints in that order. A distance projection uses inverse-mass projection and skips a constraint when the current length is zero or the two inverse masses sum to zero. Pinned particles have inverse mass zero and do not move. Version 1 has no collision constraints; stiffness is the per-iteration fraction. Use std_rand for the same deterministic seed contract outside the world.

std_hpa

std_hpa is an exact-cost HPA* layer over std_pathfind. Clusters are clipped row-major rectangles, using the requested cluster width and height and truncated at the grid edge. A transition tile is a walkable tile with at least one legal cross-cluster 8-neighbour, with diagonal corner cutting forbidden. One abstract node exists per transition tile, cluster-major then row-major. Cross-cluster adjacencies become directed edges of cost 10 or 14, and every reachable same-cluster node pair gets exact cluster-restricted jpsFind costs in both directions. Edges are sorted by destination.

Cluster pub const Cluster = struct { x0: u32, y0: u32, w: u32, h: u32 }; — A clipped cluster rectangle.
AbstractNode pub const AbstractNode = struct { x: u32, y: u32, cluster: u32 }; — A transition tile and its cluster.
AbstractEdge pub const AbstractEdge = struct { to: u32, cost: u32 }; — A directed abstract edge.
AbstractMap pub const AbstractMap = struct { width: u32, height: u32, cluster_w: u32, cluster_h: u32, cluster_cols: u32, cluster_rows: u32, clusters: []Cluster, node_start: []u32, nodes: []AbstractNode, edge_start: []u32, edges: []AbstractEdge }; — The persistent static abstraction.
hpaBuild pub fn hpaBuild(arena: *arena_mod.Arena, grid: *const pf.Grid, cluster_w: u32, cluster_h: u32) !AbstractMap !AbstractMap; error.OutOfMemory; panics on a zero cluster size Build the map, restoring build scratch before returning.
hpaFind pub fn hpaFind(arena: *arena_mod.Arena, m: *const AbstractMap, grid: *const pf.Grid, start: pf.Point, goal: pf.Point, out: []u32) !u32 !u32; error.NoPath or error.OutOfMemory Search the abstraction and refine to a tile path.

The build allocates the persistent map from the caller's arena, uses temporary counting, scatter, and cluster-local search scratch, then restores the arena's used bytes so only the map remains. Size the build arena for the peak scratch plus the map, not just the final map. The build cost is O(sum_c k_c^2 * A_c) for k_c transition tiles and cluster area A_c. The map is a static snapshot; rebuild it after any tile change.

hpaFind uses its arena as query scratch and may be reset after each call; it must not be the arena that owns the map. The search adds virtual start and goal nodes, connects them with exact intra-cluster costs, and runs A* with the octile heuristic and the same composite key (f<<32)|(~g) as the pathfinder. The abstract path is refined with cluster-local jpsFind, dropping duplicate boundary tiles. The output contract matches std_pathfind: at most out.len / 2 pairs, an odd trailing slot untouched, and the full tile count returned so 2*return > out.len detects truncation.
