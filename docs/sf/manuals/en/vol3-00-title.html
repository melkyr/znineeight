Volume III — Working in the Era

Enter here if you can write Z98. Leave able to ship software for 1998 hardware — and able to say, without hedging, what Z98 is good for and when to reach for C89, C++98, or assembly instead.

Volume II — Learning Z98 taught the language. This volume teaches the machine, the toolchain, and the limits. It assumes the fluency Volume II produced: that you can read Z98 syntax and idioms without stopping, that you know error unions, optionals, the arena, the introspection builtins, and coroutines, and that you have compiled and run a program on the seed-built compiler. Every chapter here takes all of that as given and does not repeat it.

This volume is about the discipline, not the syntax. Naming a type and calling a function were the language's problems, and Volume II answered them. The problems left are the era's: a 32 MB machine, a C89 toolchain, no garbage collector, no threads, and a small standard library. There is more judgement in these pages than in the two volumes before them, and more prose. That is the subject.

Honest note. Some of this volume is opinion — a judgement about what a 1998 project should do, not a measurement of what the compiler does. Where a passage is opinion, the text says so, in the sentence or in a box like this one. Where a passage is a fact about Z98 or the era toolchain, it was checked against docs/reference/Language_Spec_Z98.md, the compiler source, and the compiler built from the committed seed. The two are never mixed without a mark.

How to read this

The manual is six volumes. Each states an entry state and an exit state, and a reader enters at the volume that matches their background and reads forward; nobody reads all six cover to cover. The paths printed on the back cover of every volume are:

  • Never programmed → I → II → III → IV/V as needed
  • Knows C, C++, Java, or Python → skim I → II → III → IV/V as needed
  • Knows modern Zig → II (for the differences) → III → IV/V
  • Wants to use it now → V → IV
  • Maintainer → VI → IV → the engineering docs

This volume is the whole of the third path and the third stop on the first two. It is shorter than it looks: the honesty chapters are read once as an argument, and the chapters after them are looked up when a specific decision arrives. A reader shipping a program for a 1998 machine is the reader this volume was written for.

What this volume is not

It is not an apology. Z98 does not carry a modern runtime, and the target machine cannot afford one; that is a design decision, not a shortfall, and this volume does not defend it page after page. It is also not a scoreboard. A modern toolchain was never a candidate for a Pentium II running Windows 95/98 — it cannot be built for that machine or run on it — so comparing the two measures the wrong thing. The comparison that decides an era project is against the tools that actually ran there: C89, C++98, and assembly.

The register is the tradeoff. Every limit is a fact, and every fact in this volume is paired with its way over: a Z98 idiom, a standard module, an era tool, or another language. When the other tool wins, the chapter says so outright. Chapters 3, 4, and 5 are nothing but that statement, one language each, and the through-line is not "Z98 is always right" but Z98 emits C89, so you can mix the two freely.

How this volume is built

How a chapter is built

A chapter is 10–18 pages, heavier on prose than code, because the era has more opinions than the language does. A chapter whose subject has a program opens with the argument, then works a real program in full: the page shows the source, which is a real file under docs/sf/manuals/src/vol3/, and the transcript that file produced when it was compiled and run. The chapter closes with Common mistakes — the thing you will reach for from the language you already know, and the era way instead — and Where to go next, which points at the nearest shipped chapter and the Reference pages for the same subject. A chapter that carries no program still ends with Where to go next. There is no "Check yourself" here; Volume I has the exercises, and this volume is for readers who already write the language.

The callouts

When a passage is a limit, a friction point, or an honest word about the era's other tools, it is set off as an Honest note in a warm grey box. The five callouts — note, tip, warn, caution, and honest — are the ones Volume I introduces and displays on its title page. In this volume the honesty chapters carry the argument in the body and reserve the callout for the one thing on the page worth stopping for. The warm grey box is also where an opinion is marked when the opinion is the point.

The examples and the compiler

The examples live in docs/sf/manuals/src/vol3/, beside the pages that use them. They are compiled with the compiler rebuilt from the committed seed, the same toolchain Volume I, Installing the Toolchain builds, and this volume does not repeat that chapter's commands. The seed rebuild is two hops: the committed seed compiles the current compiler source, and the result compiles the source again to the same binary. Run from the repository root, because the source is read by a relative path: 

$ bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed
...
[seed] two-hop closure OK: hop1 == hop2 == 8216fedc8dd69db084d453be80f3c010
=== [seed] Done: /tmp/manual_seed ===

The two builds agreeing is the gate that the compiler is self-hosting and deterministic; the recorded fixed point for the shipped seed is kept in release/seed/CHANGELOG.md, and this manual quotes it as the run that produced the pages. With the compiler in place, a Volume III program is emitted and built the same way as any other: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol3/tasks.z98
$ cd /tmp/manual_out && sh build_target.sh linux tasks

A Win9x-only program is a different case. The pages that ship one state exactly what was verified on the development host — the emitted C89 cross-compiled with the mingw toolchain and run under wine, with line-ending normalized output — and what is left to the real-machine screenshot. No page claims that OpenWatcom was run here when it was not.
