Making Decisions

The last chapter made numbers do arithmetic. A program that can only compute the same answer every time is still a very literal assistant; it cannot react. This chapter gives it a choice. It adds the if statement, the six comparison operators that ask yes-or-no questions, the bool type those questions produce, and the if expression, which chooses a value rather than a block of statements. After this chapter the program can take a different path for each kind of input, which is the first real decision it has made.

The program

const std = @import("std");

pub fn main() void {
    var a: i32 = 7;
    var b: i32 = -3;
    var c: i32 = 0;

    if (a > 0) {
        std.io.print("{} is positive\n", .{a});
    } else if (a < 0) {
        std.io.print("{} is negative\n", .{a});
    } else {
        std.io.print("{} is zero\n", .{a});
    }

    if (b > 0) {
        std.io.print("{} is positive\n", .{b});
    } else if (b < 0) {
        std.io.print("{} is negative\n", .{b});
    } else {
        std.io.print("{} is zero\n", .{b});
    }

    if (c > 0) {
        std.io.print("{} is positive\n", .{c});
    } else if (c < 0) {
        std.io.print("{} is negative\n", .{c});
    } else {
        std.io.print("{} is zero\n", .{c});
    }

    var n: i32 = -3;
    var sign: i32 = if (n > 0) 1 else if (n < 0) -1 else 0;
    std.io.print("sign of {} is {}\n", .{n, sign});

    var above: bool = n > 0;
    if (above) {
        std.io.print("{} is above zero\n", .{n});
    } else {
        std.io.print("{} is not above zero\n", .{n});
    }
}

It does four things. It classifies three values — a positive one, a negative one, and zero — printing which kind each is. It computes the sign of a value with an if expression, the form that chooses a value instead of running a block. It stores the result of a comparison in a bool variable. And it uses that variable as the question for one more if. Each of those is a separate piece of the chapter.

Choosing with if

An if statement asks a question and runs a block of statements only when the answer is yes: 

if (a > 0) {
    std.io.print("{} is positive\n", .{a});
}

The word if is followed by a condition in parentheses, and then a block in braces. The condition is the question; the block is what happens when the answer is yes. The question a > 0 is not a number. It is a truth value: either true or false. When it is true the block runs; when it is false the block is skipped and the program continues after it.

A question with only one answer is rarely enough, so if can carry an else block that runs when the answer is no: 

if (b > 0) {
    std.io.print("{} is positive\n", .{b});
} else {
    std.io.print("{} is not positive\n", .{b});
}

Exactly one of the two blocks runs, never both and never neither. For a third possibility the else can itself hold another if. That chain is written else if and reads as "otherwise, if…": 

if (b > 0) {
    std.io.print("{} is positive\n", .{b});
} else if (b < 0) {
    std.io.print("{} is negative\n", .{b});
} else {
    std.io.print("{} is zero\n", .{b});
}

The program uses that three-way shape for each of its three values. Read the first question first: b > 0. If it is true, the value is positive and the rest of the chain is skipped. If it is false, the next question is asked: b < 0. If that is true, the value is negative. If both are false, the only possibility left is zero, and the final else handles it without asking anything.

Note. Only the first true branch runs. In the chain above, a value of -3 fails b > 0, passes b < 0, and never reaches the final else. The order of the questions is part of the meaning.

The comparison operators

The questions in the program are built from comparison operators. Each one takes two values and answers with a truth value, not a number. There are six, and they come in three pairs:

Operator Reads as Example Answer for 5
== equal to n == 5 true
!= not equal to n != 5 false
< less than n < 10 true
> greater than n > 10 false
<= less than or equal to n <= 5 true
>= greater than or equal to n >= 5 true

The two-character operators are easy to mistype. == is a question ("are these equal?"); a single = is an instruction ("store this value"), and it is the subject of a common mistake below. The same is true of !=: the exclamation mark means not, so != asks whether two values differ.

Comparison sits below arithmetic in the precedence table from the last chapter, so the arithmetic on either side is settled first. a + 1 > b compares the sum to b; it does not add a truth value to anything. When in doubt, parentheses make the grouping explicit and cost nothing.

The type of an answer: bool

Every comparison produces a value of type bool, the boolean type you met in chapter 6. It has exactly two values, written true and false, and if is the statement that acts on one: 

var n: i32 = -3;
var above: bool = n > 0;
if (above) {
    std.io.print("{} is above zero\n", .{n});
} else {
    std.io.print("{} is not above zero\n", .{n});
}

The third line of the program stores the result of n > 0 in a bool variable named above, and the if asks about above directly. A comparison and a bool variable are interchangeable as conditions; naming the result is often clearer when the same question is asked more than once.

Two more operators build larger questions out of smaller ones. and is true only when both sides are true, and or is true when at least one side is true: 

if (n > 0 and n < 10) {
    std.io.print("{} is a single digit\n", .{n});
}

and binds tighter than or, the same way multiplication binds tighter than addition. Both sit below the comparison operators, so the comparisons are answered before the logical operators combine them. The arithmetic and logical levels were listed together in the last chapter's precedence table; the only new row this chapter adds is the comparisons, which sit just below the arithmetic.

Braces and the else rule

The braces around a block are optional when the block holds a single statement. All three of these are legal: 

if (n > 0) std.io.print("positive\n", .{});

if (n > 0) {
    std.io.print("positive\n", .{});
}

The first is a bare statement; the second wraps the same statement in a block. They mean the same thing, and the compiler treats the bare form as if the braces were there. For a beginner the braces are worth writing even when they are not required, because they make the extent of the branch visible at a glance.

Tip. Always write the braces. They are one extra line, they never change the meaning you intended, and they keep an else attached to the if you meant when a branch grows a second statement.

There is one place where the bare form bites. In C, and in several other languages, it is common to write a one-line if and else with a semicolon after the first branch: 

if (n > 0) n = 1; else n = -1;

Z98 rejects that line. The semicolon before else ends the if statement, so the else has nothing to attach to. The compiler says so plainly, and the message names the fix: 

classify.z98:5:22: error[2000]: ';' not allowed before 'else' - use braces: if (cond) { ... } else { ... }
    if (n > 0) n = 1; else n = -1;
                      ^^^^

The cure is to put braces around both branches. A brace-less if with no else is fine, and a brace-less if and else written without the offending semicolon is accepted too; it is the semicolon between them that the compiler refuses. Writing the braces removes the question entirely.

if as an expression

So far if chooses which statements run. It can also choose which value is produced. Written without braces and with an else, an if expression yields one of two values: 

var sign: i32 = if (n > 0) 1 else if (n < 0) -1 else 0;

Read it as a sentence: sign is 1 if n is positive, otherwise −1 if n is negative, otherwise 0. The whole thing is an expression, so it can stand on the right of an = or anywhere else a value is allowed. The two branches should produce the same type — here both produce an i32 — and the result takes that type. If the two branches disagree, the compiler warns about the mismatch, the same warning chapter 6 showed for mixing two integer types. The program uses this form to compute the sign of -3, which is −1.

The difference between the two forms is what they are for. An if statement is used for its effect: it runs code. An if expression is used for its value: it selects one of two values to be used somewhere else. Both appear in the program, and both read from the same question.

Note. An if expression has two branches; the else supplies the second. When you want a value and there are three cases, nest the else if as the program does, so that every path still produces a value.

Building and running it

The commands are the ones from the last two chapters, with classify in place of math. The compiler is still at /tmp/manual_seed, built in chapter 4: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/classify.z98
$ cd /tmp/manual_out && sh build_target.sh linux classify
Building for linux...
Built: classify
$ ./classify
7 is positive
-3 is negative
0 is zero
sign of -3 is -1
-3 is not above zero

Read the output against the source. The first three lines are the three classifications: 7 takes the first branch of its chain, −3 the second, and 0 the final else. The fourth line is the if expression: the sign of −3 is −1. The fifth is the bool variable: −3 is not above zero, so the else branch ran. The program exits with status 0, because no branch failed; choosing a path is not an error.

Common mistakes

These are the mistakes a first decision attracts. Each one has a symptom you can recognize.

Writing the C one-liner: a semicolon before else. The habit from C and other languages is to end the first branch with a semicolon and put else after it on the same line. Z98 rejects that, because the semicolon ends the if and leaves the else unattached: 

classify.z98:5:22: error[2000]: ';' not allowed before 'else' - use braces: if (cond) { ... } else { ... }
    if (n > 0) n = 1; else n = -1;
                      ^^^^

The caret points at the else, and the message tells you what to do. Put braces around the branches. The braces are optional in Z98, but they are the only way to write an if and else that each hold a full statement ending in a semicolon.

Using = where you meant ==. A single = is assignment; == is the question. In Z98, assignment is a statement, not an expression, so it cannot appear inside a condition. This complete program does not compile: 

const std = @import("std");

pub fn main() void {
    var n: i32 = 7;
    if (n = 0) {
        std.io.print("{} is zero\n", .{n});
    } else {
        std.io.print("{} is not zero\n", .{n});
    }
}

The parser stops at the = and reports: 

assign_mistake.z98:5:10: error[2000]: expected ')' but found token
    if (n = 0) {
          ^

The caret points at the =. The condition in the parentheses must be a complete expression, and an assignment is not one — the compiler will not quietly perform the assignment and then test the value it stored the way C does. A few follow-on error[2000] messages trail the first one as the parser recovers; the first is the one to fix. The same rule applies to every other condition: while (n = 0) and switch (n = 0) are rejected too, and so is a condition that is not a bool at all — if (n) with an integer n does not compile either. When a condition misbehaves, check first that it says == and not =.

Check yourself

Answer these before moving on. The last three ask you to change the program and run it.

  1. What does an if statement do, and what does the condition in parentheses produce?
  2. Name the six comparison operators and say what question each one asks.
  3. When an if chain has an else if, how many of its branches run? Why does the order of the questions matter?
  4. What type does n > 0 have, and what are its two possible values?
  5. What is the difference between an if statement and an if expression? Which one does var sign: i32 = if (n > 0) 1 else -1; use?
  6. Are the braces around an if body required? What happens if you put a semicolon before else?
  7. Change a from 7 to 0, rebuild, and run it. Which branch of the first chain runs, and why?
  8. Change the if expression to if (n > 0) 1 else 0, rebuild, and run it. What does the program print for the sign of −3 now, and what case has been lost?
  9. Add a fourth value of 100 and classify it. Which branch of its chain runs? Then change its value to −100 and run it again.
