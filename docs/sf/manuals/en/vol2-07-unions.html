Aggregates IV: Unions

A union is the aggregate that overlaps its members instead of stacking them. A struct gives every field its own bytes; a union gives every member the same bytes. Written down, a union looks like a struct with the fields on top of each other, and that is exactly the layout: one storage, read through whichever member the program names.

The last three chapters built records out of structs and packed structs and gave small sets of numbers names with enums. This chapter adds the third aggregate shape, and it comes in three forms, because "one storage, many readings" means three different things:

Form Declaration What it is for
Bare union union { … } The C union: overlapping storage, interpreted by the program.
Packed union packed union { … } Overlapping bit storage with no padding: registers, wire bytes, file fields.
Tagged union union(enum) { … } A closed set of shapes with exactly one active; the compiler stores a tag that says which.

This chapter declares all three, reads and writes them, and switches over the tagged form with payload captures. The example is docs/sf/manuals/src/vol2/variant.z98.

Bare unions: one storage, many readings

The bare union is the C union. The syntax is union, braces, and a comma-separated field list; the members share their bytes: 

const Bits = union {
    f: f32,
    u: u32,
};

The members overlap at offset 0, and the size of the union is the size of its largest member, rounded up to the union's alignment (the largest member alignment). Bits holds an f32 and a u32, both four bytes, so the type measures 4 bytes, aligns to 4, and is 32 bits wide. The chapter's program asks the compiler: 

bits size=4 align=4 bits=32

Construction names the member that is being written, using the same dotted form as a struct: .{ .f = 1.5 }. Reading goes through a field access: bits.f or bits.u. Nothing stops the program from writing one member and reading another; that is what a union is for, and this compiler accepts it as the C reinterpretation it is. The program writes the float 1.5 and reads the same four bytes as an unsigned integer: 

var bits: Bits = .{ .f = 1.5 };
std.io.print("bits f={} u={x}\n", .{ bits.f, bits.u });
// bits f=1.5 u=3fc00000

3fc00000 is the bit pattern of the 32-bit float 1.5, printed in hex by the {x} format. The pun works the other way too: the program then stores the integer 0x3FC00000 into bits.u and reads bits.f back as 1.5.

A bare union is an ordinary value in every other respect. It can be assigned, passed to a function, and returned from one; each of those copies the same bytes. A probe on this compiler sent 0x11223344 through a parameter and a return and read a=11223344 b=11223344 c=11223344. Field access to a member the union does not have is the same unknown-member reject as any other aggregate: error[3060]: no field or member function named 'nope' in union type, with a union declared here note at the declaration.

The reason to reach for a bare union is a task where the bytes are the point: talking to a C interface that uses a union, or reinterpreting one value's storage as another, where the program itself knows which member is live. The program must know: nothing in a bare union records which member was last written, and no read is checked. A naked member in a bare union — union { x: i32, empty } — is accepted by the compiler as a void field, but it is not a tag: the type still has no .tag, and asking for one is error[3060]. That mistake has its own item in the Common mistakes list.

One layout builtin does not work on a union. @offsetOf and @bitOffsetOf take a struct type; a union target is rejected outright: 

error[3072]: expected struct type, found 'Bits'

There is nothing to compute: every member of a union is at offset 0 and no union member has a distinct bit offset. When a union sits inside a struct, the struct's own layout is still measurable the normal way. A probe's struct { a: u8, bits: Bits } measured @sizeOf 8, @offsetOf(holder, "bits") 4, and @alignOf 4 — the union participates in the surrounding layout like any other field.

Packed unions: exact bits, no padding

A packed union overlaps its members at bit offset 0, with no padding at all. Every member is a bool, an integer of at most 31 bits, or a packed struct of such fields; this is the same 31-bit rule the packed structs of chapter 5 obey, for the same reason. The chapter's example views one byte as a whole, or as two nibbles: 

const Halves = packed struct { lo: u4, hi: u4 };
const Flags = packed union {
    whole: u8,
    halves: Halves,
};

A packed struct packs its fields LSB-first, so Halves puts lo in the low nibble and hi in the high nibble, and the packed union overlays whole on top of both. Writing .whole = 0xAB and reading the nibbles shows the packing directly: 0xAB is 1010 1011 in binary, and the program prints lo=b hi=a.

Whole-member moves work: assigning a Halves value to flags.halves and reading flags.whole back is supported, and the compiler lowers the move leaf by leaf — one bitfield store or load per scalar field, with the offsets composed. The chapter's program copies .{ .lo = 2, .hi = 7 } into the union and prints flags2 lo=2 hi=7 whole=72; the byte is the two nibbles in place. That per-leaf copy is bounded: a whole-member move nested past the compiler's recursion cap (34 packed levels in the compiler's own fixture) is a clean error[3000], never a bad store.

The size rules are the packed rules from chapter 5. The union's total bits are the widest member's bits; @sizeOf is that total rounded up to whole bytes, at least one; @alignOf is 1. Flags measures 1 byte, align 1, 8 bits, and a two-u4 union measures 1, 1, and 4.

The type gate is strict, and the diagnostics name the exact rule. A u32 member is rejected because no packed field may exceed 31 bits: 

error[3000]: packed union field width must be <= 31 bits (u32/i64 etc. packed fields are not supported yet)

A float or pointer member names the other half of the rule: error[3000]: packed union fields must be bool or an integer type (uN/iN); this field type is not allowed in a packed union. There is no f32 register member and no pointer member; if you need either, wrap the bytes in an integer and convert at the edges.

The reason to reach for a packed union is the one from the packed structs chapter: a place where the bit layout is the contract. Hardware registers that alias one address in two ways, a byte that is sometimes a count and sometimes two flags, a file header field — those are packed-union jobs. The price is the same as before: members that are not byte-sized integers, and values that belong to the wire rather than to the program.

Tagged unions: a tag beside the payload

The third form is the one C programmers end up building by hand: a value that is exactly one of several different shapes. The declaration adds (enum) to the union, which tells the compiler to store a tag — a small number naming the active variant: 

const Shape = union(enum) {
    circle: i32,
    empty,
    box: struct { w: i32, h: i32 },
};

Three declaration shortcuts are on display. A normal variant gives a name and a payload type (circle: i32). A variant written as a bare name (empty,) is a naked tag: it has no payload, and the compiler treats it as a void variant. And a variant's payload may be an anonymous struct written in place (box: struct { w: i32, h: i32 }) — the compiler declares the internal struct for you. Naked-tag sugar is a tagged-union feature: a bare member in a plain struct is a parse reject, and a bare member in a bare union is accepted only as a void field, not as a tag. The anonymous payload is the same struct syntax as everywhere else.

Construction names the variant and gives its payload: .{ .circle = 2 }, .{ .box = .{ .w = 3, .h = 4 } }, or just .empty for a naked tag. The payload is read through the variant name: s.circle, s.box.w. The tag is read as s.tag, and it is a number, not an enum: it is stored as a 32-bit unsigned value and prints with {} as a plain number. The variants number from zero in declaration order, so the chapter's program prints circle tag=0, empty tag=1, and box tag=2 as it rotates through the three.

The layout follows from that description: a tagged union is a struct-like pair of the tag and the payload union. Shape's tag is 4 bytes, its largest payload is the 8-byte box struct, and the type measures 12 bytes at alignment 4, 96 bits total. The width of the tag is fixed at one 32-bit unit whatever the variant count; a probe measured a two-u8 tagged union as 8 bytes, align 4, 64 bits, and a tagged union with only naked tags as 4, 4, and 32 (just the tag). The layout table for this chapter's types is:

Type Form @sizeOf @alignOf @bitSizeOf
Bits bare union (f32/u32) 4 4 32
Flags packed union (u8/two u4) 1 1 8
Shape tagged (i32, naked, 8-byte struct) 12 4 96

The tag is managed by the compiler at construction, but the payload is still read by the name you write; the tag tells you which name is live. The compiler-native way to act on it is the switch in the next section. To change which variant is active, assign the whole value: s = .{ .box = … }; or s = .empty; stores the new tag and payload together. A tagged union can also be compared whole against a variant as a condition — if (s == Shape.empty) — which is how the chapter's program records the answer eq=true.

The reason to reach for a tagged union is a closed set of shapes: an interpreter's values, a protocol message that is one of a handful of forms, a state that carries different data in different states. The C version of this pattern is a struct with a numeric tag and a bare union, plus a comment promising to keep them in sync. The Z98 version stores the tag for you, gives the variants names, and lets the switch name them. That is the shape to reach for by default; the bare and packed unions are the specialized ones.

Switching on a tagged union

A tagged union is made for switch. The condition is the union value; a prong names a variant, and by adding => |name| the prong also binds that variant's payload to name. Both spellings of a prong work and bind identically: the qualified Shape.circle and the shorthand .box. The chapter's area function uses one of each: 

fn area(s: Shape) i32 {
    return switch (s) {
        Shape.circle => |r| r * r * 3,
        .box => |b| b.w * b.h,
        else => 0,
    };
}

Inside the first prong r is the i32 payload of circle; inside the second, b is the anonymous struct payload of box, so b.w and b.h read its fields. The capture is immutable, like every loop and switch capture in Z98. A naked tag needs no capture; name in the example matches .empty with no binding. A statement switch uses the same shape, prong bodies with a |capture| and std.io.print inside.

Two rules come with the feature. First, else is mandatory in every Z98 switch, switch expressions included; a switch that lists every variant still has to spell one out. Leaving it off is a compile-time reject: 

error[3068]: switch must have an 'else' prong

In area the else is the real answer for empty: the naked tag has no measurement, and 0 is its area. In name every variant is listed and the else is redundant; Z98 tolerates a redundant else (unlike the Zig it is a subset of, which rejects one), so the fail-safe habit is always to keep it.

Second, a prong that names something the union does not have is rejected instead of falling to else. A typo such as .bogus reports error[3071]: no field or member function named 'bogus' in union type with a union declared here note, and a qualifier that names a different type reports the type mismatch error[3071]: type mismatch in switch case item -- case item type may not be compatible with the switch condition type. As with enums, a renamed variant stops compiling at every switch that still spells the old name.

Honest note. The union surface is small, and its edges are worth knowing before they surprise you. The tag is one 32-bit number, not a named enum type: there is no @tagName and no reflection over variants, and the numbers live in declaration order. Whole-union printing is uneven. A bare union always compiles and prints the placeholder .{ ... }, never its fields. A tagged union prints its fields (.{ .circle = 3 }) as long as every variant carries a non-void, printable payload; a naked tag, an explicit void variant, or an unprintable payload (a packed struct, a pointer-to-array such as *const [4]u8, a struct wrapping a packed struct) makes printing reject error[3063]: print argument type is not supported (no std.fmt printer), even when that variant is not active. A packed union of bool/integer members prints its fields too, and a packed-struct member rejects the same way. The example prints fields directly. @offsetOf and @bitOffsetOf reject a union target with error[3072], as the first section shows. A packed union admits only bool, ≤31-bit integers, and packed structs of them, and the per-leaf whole-member copy is bounded at the compiler's nesting cap. A bare union is unchecked reinterpretation: reading a member the program did not write gives the bytes read through that type, not an error. And payload construction narrows a float literal to an f32 payload (.{ .f = 2.0 } prints f=2), but a typed f64 value aimed at an f32 payload is a compile-time error[3000] — there is no silent narrowing of runtime values.

The example

The whole chapter in one program. It declares the bare Bits, the packed Flags, and the tagged Shape, prints each type's layout, puns through Bits, copies nibbles through Flags, and switches over Shape with both prong spellings and a payload capture each. It is docs/sf/manuals/src/vol2/variant.z98: 

const std = @import("std");

// A bare union: the C union. Its members overlap at offset 0, and the
// program tracks which one is live; nothing else does.
const Bits = union {
    f: f32,
    u: u32,
};

// A packed union: members overlap at bit offset 0, no padding, and every
// member is a bool, an integer of at most 31 bits, or a packed struct of
// them.
const Halves = packed struct { lo: u4, hi: u4 };
const Flags = packed union {
    whole: u8,
    halves: Halves,
};

// A tagged union: the compiler stores a tag beside a payload union.
// `empty` is a naked tag (no payload); `box` carries an anonymous struct.
const Shape = union(enum) {
    circle: i32,
    empty,
    box: struct { w: i32, h: i32 },
};

// Both prong spellings bind the payload capture: qualified and shorthand.
// The else prong is mandatory even when every variant is listed.
fn area(s: Shape) i32 {
    return switch (s) {
        Shape.circle => |r| r * r * 3,
        .box => |b| b.w * b.h,
        else => 0,
    };
}

fn name(s: Shape) []const u8 {
    return switch (s) {
        Shape.circle => "circle",
        .box => |b| if (b.w == b.h) "square" else "box",
        .empty => "empty",
        else => "unknown",
    };
}

pub fn main() void {
    // Bare union: one storage, read through either member.
    var bits: Bits = .{ .f = 1.5 };
    std.io.print("bits f={} u={x}\n", .{ bits.f, bits.u });
    bits.u = 0x3FC00000;
    std.io.print("bits back f={}\n", .{bits.f});
    std.io.print("bits size={} align={} bits={}\n", .{ @sizeOf(Bits), @alignOf(Bits), @bitSizeOf(Bits) });

    // Packed union: one byte, members are bit fields.
    var flags: Flags = .{ .whole = 0xAB };
    std.io.print("flags lo={x} hi={x} whole={x}\n", .{ flags.halves.lo, flags.halves.hi, flags.whole });
    var h: Halves = .{ .lo = 2, .hi = 7 };
    flags.halves = h;
    std.io.print("flags2 lo={d} hi={d} whole={x}\n", .{ flags.halves.lo, flags.halves.hi, flags.whole });
    std.io.print("flags size={} align={} bits={}\n", .{ @sizeOf(Flags), @alignOf(Flags), @bitSizeOf(Flags) });

    // Tagged union: tag, payload, and the switch.
    var s: Shape = .{ .circle = 2 };
    std.io.print("circle tag={} area={d}\n", .{ s.tag, area(s) });
    s = .{ .box = .{ .w = 3, .h = 4 } };
    std.io.print("box tag={} area={d} name={s}\n", .{ s.tag, area(s), name(s) });
    s = .empty;
    var is_empty: bool = false;
    if (s == Shape.empty) {
        is_empty = true;
    }
    std.io.print("empty tag={} area={d} eq={}\n", .{ s.tag, area(s), is_empty });
    std.io.print("shape size={} align={}\n", .{ @sizeOf(Shape), @alignOf(Shape) });
}

Ten lines, in four groups. The first three are the bare union: 1.5 with its integer bit pattern beside it, that integer pattern written back and read as 1.5 again, and the 4/4/32 layout. Common mistakes

The mistakes below are the ones a programmer arriving from C (or from a newer Zig) makes first with unions. Each one has a corrected shape, and the corrected shape is the compiler's rule, not a style preference.

Reaching for C's untagged union. In C, a union of shapes and a separate int tag next to it is the idiom, and the compiler checks nothing. Here the tagged union exists: union(enum) stores the tag beside the payload, and the switch names the variants. Use a bare union only when the bytes themselves are the task, not when the set of shapes is.

Reading the wrong member. A union read is a reinterpretation: read bits.u after writing bits.f and the program gets the bit pattern, with no diagnostic. On a tagged union the tag records which variant is live, so read the payload through the variant the switch selected; the switch with captures is the shape that keeps the two together.

Assuming a bare union has a tag. It does not. union { f: f32, u: u32 } has no .tag, and asking for one rejects with error[3060]: no field or member function named 'tag' in union type. A naked member such as union { x: i32, empty } is accepted as a void field, which can make the declaration look tagged, but no tag is stored and nothing is tracked; only union(enum) manages the tag for you.

Printing a whole union with {}. Each form behaves differently. A bare union compiles and prints the placeholder .{ ... }, not the value behind it. A tagged union prints its fields (.{ .circle = 3 }) as long as every variant carries a non-void, printable payload; a naked tag, an explicit void variant, or an unprintable payload (a packed struct, a pointer-to-array, a struct wrapping a packed struct) makes printing reject with error[3063]: print argument type is not supported (no std.fmt printer), even when that variant is not the active one. A packed union of bool/integer members prints; a packed-struct member rejects the same way. Print the fields you mean, as the example prints flags.whole and s.tag.

Asking @offsetOf for a union member. Union members all sit at offset 0, so the builtin takes a struct and rejects a union outright: error[3072]: expected struct type. Put the union in a struct and ask for the struct field's offset instead, or read the union's member through a normal field access.

Assuming any member type works in a packed union. Packed members are limited to bool, integers of at most 31 bits, and packed structs of them. A u32 member rejects with the width rule, and an f32 member rejects with the integer-only rule. Keep the wide fields in a bare or tagged union and use the packed form for the exact-bit layouts.

Coming from Zig

The tagged union is one of the places where this dialect is closest to the Zig it is a subset of, and one of the places where the remaining differences matter when porting code.

The union switch is the same. switch (u) { .a => …, else => … } works as it does in Zig, with the payload captures and the mandatory else the earlier section described.

Pointer captures do not exist. Zig's in-place mutation idiom, .a => |*p| p.* = …, is a parse reject here: error[2000]: expected identifier but found token points at the *. The supported mutation stores the whole union — tag and payload together: 

u = .{ .a = 5 };

The same through a pointer: p.* = .{ .a = 21 };.

Tag inspection. Zig has no .tag field; the oracle spells tag comparison std.meta.activeTag(u) (or @as(std.meta.Tag(U), u)) and dispatch switch (u). Z98 keeps the whole-union forms — switch (u), and equality with the variant named qualified when it has a payload (u == Shape.a) or shorthand for a naked variant (u == .empty; the shorthand on a payload variant rejects error[3008]: enum literal member requires payload) — and adds a direct u.tag access typed as a u32 ordinal whose member-shaped uses are contextually sugared: u.tag == .a, u.tag != Shape.a, the relational comparisons, and switch (u.tag) { .a => …, else => … } all compare and switch ordinals. The sugar is per use, not per value: const t = u.tag; is a plain u32 copy, and t == .a rejects error[3076]: unable to infer type of enum literal in comparison with a numeric operand. Numeric uses are unchanged: u.tag == 0, @enumToInt(u.tag).

Payload stores are whole-union assignments. A per-member store (x.i = 5), a whole nested payload store (b.box = .{ … }), and taking a payload member's address (&x.i, b.box.w = 7) are clean rejects that name the supported form: 

error[3000]: cannot store to a tagged-union payload member; assign the whole union instead (e.g. x = .{ .i = 5 })

The address forms use the twin wording, cannot take the address of a tagged-union payload member; assign the whole union instead. The mutation is the assignment above: x = .{ .i = 5 };.

When a value needs frequent in-place mutation, the practical pattern is the one this manual's interpreter examples use: split the discriminant from the storage with a plain struct, a tag enum, and a bare union. 

const Tag = enum { i, s };
const Data = union { i: i32, s: u8 };
const Value = struct { tag: Tag, data: Data };

The struct travels as one value, the tag is an enum (so chapter 6's switch rules apply), and the bare union's member is an ordinary field: v.data.i = 9; stores in place with no whole-value rebuild. That is the shape the interpreter's token and value types use, and the one to reach for when the tagged union's rebuild-a-whole-value style stops fitting.
