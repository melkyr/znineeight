Build a Multilingual Manual

This guide produces one language's edition of the manual from the shipped English tree. It copies the flat en/ directory as the base, translates the page text while keeping the page skeleton, and states the encoding rule for scripts that ISO-8859-1 cannot carry. It ships no program: the thing being translated is the HTML in en/. The other editions, es/ (Spanish) and zh-cn/ (Simplified Chinese), are (planned) and out of scope; what this guide fixes is the recipe and the checker's language rules, so a translator knows which tree to copy and which constants gate it before an edition can be linked.

Prerequisites

  • The repository checked out at /workspace/znineeight, with the shipped English edition under docs/sf/manuals/en/. This guide needs no compiler; it is a documentation task.
  • Python 3, which docs/sf/manuals/check.sh runs through check.py, and the page template at docs/sf/manuals/en/vol4-24-html-style.html.
  • The HTML contract every page obeys, on Volume IV — HTML style: the doctype, the ISO-8859-1 meta, the rel links, the sidebar, the language bar, and the prev/contents/next footer.
  • The HOWTO index, for how the volume is laid out. The companion the future translator will also want is the static-site guide Build the Static Site, which owns the search index this guide only points at.

The idea

The manual is one flat HTML tree per language. en/ is the shipped edition; the top-level index.html is a language selector that points at it. Every page inside a language root sits at depth one and links its neighbours by bare filename, so an edition is a self-contained directory: copy it, translate the words, and the internal navigation keeps resolving with no link rewriting. The one property a copy cannot inherit blindly is encoding. The English pages declare ISO-8859-1, and a script outside that charset has to be written in a form the declared charset can hold.

Steps

  1. Read the language layout. Confirm the shape the copy follows: a selector at the top, one flat directory per language, and English shipped today. 

    $ cd /workspace/znineeight/docs/sf/manuals
$ ls -d en
en
$ grep -n 'Espa&ntilde;ol\|&#31616;' index.html
21:Espa&ntilde;ol (not yet available) |
22:&#31616;&#20307;&#20013;&#25991; (not yet available)
56:<td valign="top"><font size="4"><b>Espa&ntilde;ol</b></font></td>
60:<td valign="top"><font size="4"><b>&#31616;&#20307;&#20013;&#25991;</b></font></td>

    The selector at line 52 links the English edition as en/index.html; the Spanish and Chinese rows (lines 56 and 60) are plain text, not links, because those editions have not shipped. The tree layout is the one in docs/sf/manuals/README.md: root pages plus a flat en/ holding every page, the stylesheets, doc.js, the gfx/ assets, and the generated search-data.js.

  2. Start the new edition by copying the English root. A language edition is a sibling directory of en/. Stage the copy under /tmp while trying the recipe; the real edition is created beside en/ when it ships. 

    $ cd /workspace/znineeight
$ rm -rf /tmp/z98_ml
$ mkdir -p /tmp/z98_ml
$ cp -R docs/sf/manuals/en /tmp/z98_ml/es
$ ls /tmp/z98_ml/es/*.html | wc -l
106
$ ls /tmp/z98_ml/es | grep -v '\.html$' | tr '\n' ' '
doc.js gfx search-data.js z98-print.css z98.css

    The copy carries the stylesheets, the one behaviour script, the GIF assets, and the 106 English pages. Because the edition keeps the same filenames, the sibling links a page carries (toc.html, vol5-01-build-compiler.html, and so on) all stay inside the new root and keep resolving with no editing.

  3. Translate the text, keep the skeleton. For each page, replace the <title>, the keywords meta, the <h1>, and the body prose. Keep the doctype, the rel links, the sidebar, the language bar, the prev/contents/next footer, and the closing doc.js include exactly as the template ships them. The template is en/vol4-24-html-style.html; every page is a fill-in of its skeleton. The language bar is the one inline element to revisit in every page: 

    $ grep -n 'Espa&ntilde;ol' /tmp/z98_ml/es/vol5-00-index.html
21:Espa&ntilde;ol (not yet available) |

    In a finished edition the active language is plain text and the others are either links (once shipped) or the same (not yet available) note. The bar is short and identical on every page, so it is a copy-and-paste edit rather than a per-page decision.

  4. Write non-Latin scripts as character references. A page declares ISO-8859-1, and its bytes must stay inside that declaration. The English pages show both cases: &ntilde; is the named entity for the Latin-1 letter ñ, and anything outside Latin-1 is a numeric character reference. The language bar's Chinese name is four such references, not raw multi-byte text: 

    $ grep -o '&#31616;&#20307;&#20013;&#25991;' docs/sf/manuals/en/vol5-00-index.html
&#31616;&#20307;&#20013;&#25991;
$ LC_ALL=C grep -oP '[\x80-\xff]' docs/sf/manuals/en/vol5-00-index.html | wc -l
0

    &#31616;&#20307;&#20013;&#25991; is &#x7B80;&#x4F53;&#x4E2D;&#x6587; — four decimal references for the four zh-cn glyphs. The second command counts bytes above 0x7F and gets 0: the page is pure 7-bit ASCII, so it is valid under the declared ISO-8859-1 without any code-point fitting. A glyph outside Latin-1 is therefore written as a decimal or hex reference; writing the raw UTF-8 bytes would put code points the declaration does not name into the file. An edition whose own script needs a different charset is a separate decision — it would declare its own <meta> and <html lang> when it ships — and is (planned).

  5. Know how the checker treats a translation. check.py carries a one-element set of shipped languages and enforces it in the language bar: 

    $ grep -n 'SHIPPED_LANGS' docs/sf/manuals/check.py
37:SHIPPED_LANGS = frozenset(("en",))
241:            if match and match.group(1) not in SHIPPED_LANGS:

    check_langbar (check.py:235) reads every href/src, matches a leading <lang>/ path component, and fails if it is not in SHIPPED_LANGS. So a language bar that links es/index.html or zh-cn/index.html is rejected until the edition is added to that set; the entries must stay plain text until then. check_lang_charset (check.py:249) is stricter still: it requires lang="en" and the ISO-8859-1 meta on every page it finds, so today's gate validates the English edition only — a translated page with <html lang="es"> would fail. That is the honest state: the recipe is ready, the gate is deliberately English-only, and a shipped language needs the check extended in the same change that adds the tree. The selector mirrors the rule, English a link and the other two rows plain text, so shipping an edition turns it into a link in exactly two places: the top-level index.html and the language bar repeated on every page.

  6. Run the gate. check.sh parses every *.html under docs/sf/manuals/ except dist/, so a language root placed beside en/ is scanned as soon as it exists and must satisfy every rule, including the English-only lang/charset check above. 

    $ cd /workspace/znineeight
$ bash docs/sf/manuals/check.sh
check.py: OK - 109 HTML pages, links, rel, lang, forbidden list, figures, no-CSS baseline

    The count is the number of pages the checker walked, this guide included; a green run means every link resolved, every page carried its rel links and its language bar passed, and the no-CSS baseline held.

  7. Know how the index treats a translation. Two indexes are involved, and neither indexes a translation today. The top-level index.html is the hand-authored selector already seen in step 1; the search index is generated from en/ only. The generator loop names its directory once: 

    $ grep -n 'EN_DIR=' /tmp/z98_build_tmp.sh
5:EN_DIR="$SCRIPT_DIR/en"
$ grep -n 'for page in' /tmp/z98_build_tmp.sh
14:	for page in "$EN_DIR"/*.html; do

    search-data.js is regenerated by scanning en/*.html for the title, keywords, and first heading (this is the same loop build.sh runs). A translated edition produces its own index only when its own generator pass is added; until then the search box serves the English edition. The generated file is data, not hand-edited, which is why it is copied with the tree rather than translated.

Verify it worked

The edition base is correct when the copy holds the whole English page set plus its assets, and the gate is still green with the copy staged outside the tree: 

$ ls /tmp/z98_ml/es/*.html | wc -l
106
$ ls /tmp/z98_ml/es | grep -v '\.html$' | tr '\n' ' '
doc.js gfx search-data.js z98-print.css z98.css
$ bash docs/sf/manuals/check.sh
check.py: OK - 109 HTML pages, links, rel, lang, forbidden list, figures, no-CSS baseline

The 106 pages are every page in en/, and the five non-page entries are the stylesheets, the behaviour script, the asset directory, and the generated index data — the same tree en/ carries. The language bar still renders its two non-English names, and the Chinese name adds no byte above 0x7F: it is four character references, so the page stays valid under the ISO-8859-1 meta it declares. A raw byte above 0x7F is allowed only when it is itself a Latin-1 code point. When a translation is committed beside en/, check.sh is the one gate that must be extended for it (step 5); the rest of the recipe is the copy and the text.
