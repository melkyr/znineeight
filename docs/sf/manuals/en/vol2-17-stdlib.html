The Standard Library Tour

Chapter 14 used the arena. Chapter 16 built a shape interface by hand. Both leaned on code that already arrives with the compiler: std.arena, std.io, and the rest of the std namespace. This chapter is the tour. It does not list every function in every module; it names every module the std namespace actually exports, says what each one is for, and gives the smallest call that proves it is there. The chapter's program, docs/sf/manuals/src/vol2/stdio.z98, touches all thirteen modules in one run.

Thirteen is a small number, and the size is deliberate. The compiler's runtime library directory carries more files than the std namespace re-exports; only the names in this chapter resolve as std.<name>. The formal lookup for the language-level calls these modules are built from is Volume IV — Builtins. The planned Reference stdlib page, which will document every function of every module, does not ship yet.

Honest note. You will reach for a standard library; here is how small this one is. The library is thirteen modules, and most of them are short. There is no formatted input, no floating-point math beyond the printer, no dynamic array in the compiler sense, no hash map, no string object. What exists is a set of concrete, hand-written helpers: an arena you own, byte slices you slice yourself, a formatting engine behind print, and thin wrappers over the operating system. The list below is not a subset chosen for a tour; it is the whole surface. What you gain is that every function is a plain Z98 function you can read in the compiler's source, with no hidden allocation and no dispatch you did not write. What you lose is the convenience layer a larger language would have built on top of it.

What ships in std

The module sf/src/std.zig is nothing but a list of re-exports. It declares exactly thirteen names; each maps to one std_*.zig file in the compiler's library directory. Every name is reachable as std.<name> and nothing else is. The blueprint for this volume named eight of them; the other five are part of the same surface and are covered here so the list is complete.

Name Source file What it holds
std.io std_io.zig Byte and string output, single characters, a signed-integer printer, the print entry point, file I/O, sleep.
std.fmt std_fmt.zig The formatting bodies behind print; auto-imported when a print is lowered.
std.arena std_arena.zig The bump allocator of chapter 14.
std.str std_str.zig Byte-slice string operations: compare, search, trim, split, join, replace.
std.mem std_mem.zig Raw copy, zero, and compare over many-item pointers with a count.
std.math std_math.zig Integer min/max, clamp, absolute value, power-of-two and alignment helpers.
std.debug std_debug.zig Logging, assert, panic, the trap handler, and core-dump writing.
std.net std_net.zig Target-selected TCP and UDP bindings, byte-order helpers, select, non-blocking modes.
std.async std_async.zig The cooperative scheduler and per-task child-frame pool for coroutines.
std.bits std_bits.zig Integer bit operations: popcount, leading/trailing zeros, rotate, extract, insert.
std.os std_os.zig Process-level information: arguments, environment, current directory, exit.
std.time std_time.zig Monotonic and wall-clock time, and sleep.
std.buf std_buf.zig A growable byte buffer backed by an arena.

The directory holds more std_*.zig files than these thirteen. A name that is not in the table above is not part of the std namespace. The compiler rejects it rather than resolving it, for example: 

const S = @sizeOf(std.base64);
// error[3074]: unable to resolve type argument

That is the measured diagnostic for a name outside the re-export list. The same file may exist on disk and be used internally; it is simply not part of the public surface a program can name through std.

std.io

std.io is where bytes leave and enter the program. Output splits into two families, and the difference matters when you mix them. The builtin-backed functions (write, writeByte, printInt) write through the standard output builtins; print is the compiler's format-string entry point and routes through std.fmt. On the POSIX target the builtin path is buffered and the print path is not, so a program that interleaves the two can see its lines reorder. Use one family for a single output stream. 

pub fn writeByte(c: u8) void
pub fn write(data: []const u8) void
pub fn writeStr(s: [*]const c_char) void
pub fn print(s: [*]const c_char, ...) void
pub fn printInt(n: i32) void
pub fn readByte() u8
pub fn sleepMs(ms: u32) void

File I/O is a small PAL surface, not C's stdio.h. There is no FILE* and no fopen; a handle is a usize that arrives as an optional because open can fail: 

pub fn fileOpen(path: []const u8, write_mode: bool) ?usize
pub fn fileWrite(fd: usize, data: []const u8) void
pub fn fileRead(fd: usize, buf: []u8) usize
pub fn fileClose(fd: usize) void

fileOpen returns null on failure, so it is consumed with orelse, not catch; fileRead returns the byte count and reports 0 at end of file.

std.fmt

std.fmt is the engine under std.io.print. You almost never call it directly: whenever the compiler lowers a print, it auto-imports this module and emits a call into the right formatting body for each argument's type. The functions are public so that the generated code can name them, and they are listed here so the surface is not a mystery. 

pub fn printI32(v: i32) void
pub fn printU32(v: u32) void
pub fn printI64(v: i64) void
pub fn printU64(v: u64) void
pub fn printF64(v: f64) void
pub fn printBool(v: bool) void
pub fn printChar(c: u8) void
pub fn printStr(ptr: [*]const u8, len: usize) void
pub fn printHexU32(v: u32) void
pub fn printHexI32(v: i32) void
pub fn printHexU64(v: u64) void
pub fn printHexI64(v: i64) void

The format string itself, the accepted specifiers, and the rejections are the subject of chapter 15's Group F and of chapter 18. This page only claims the module exists and that print is built on it.

std.arena

The arena is the volume's second mental shift and chapter 14 is devoted to it. The whole module is four declarations: a struct, an initializer, one fallible allocator, and a reset. There is no free and no deinit; reclaiming memory means resetting the bump pointer. 

pub const Arena = struct { data: [*]u8, capacity: usize, used: usize };
pub fn init(data: []u8) Arena
pub const ArenaError = error{OutOfMemory};
pub fn alloc(self: *Arena, size: usize) ArenaError![*]u8
pub fn reset(self: *Arena) void

alloc returns a raw [*]u8, not a typed pointer. Casting it to the type you asked for is the caller's job, which is why the sample casts the result to *Point before storing fields. The arena never allocates: you hand it a slice you already own.

std.str

std.str operates on byte slices, never on NUL-terminated strings. The original helpers cover the common inspection tasks; the additions cover the string work a 1998 program actually does, including allocation. The allocating functions take an arena and return an error union whose only error is the arena's OutOfMemory. 

pub fn len(s: []const u8) usize
pub fn eql(a: []const u8, b: []const u8) bool
pub fn copy(dst: []u8, src: []const u8) void
pub fn copyZ(dst: [*]u8, src: []const u8) usize
pub fn findChar(s: []const u8, c: u8) ?usize
pub fn startsWith(s: []const u8, prefix: []const u8) bool
pub fn endsWith(s: []const u8, suffix: []const u8) bool
pub fn toUpper(s: []u8) void
pub fn toLower(s: []u8) void
pub fn split(arena: *Arena, s: []const u8, sep: u8) ![][]const u8
pub fn splitLines(arena: *Arena, s: []const u8) ![][]const u8
pub fn join(arena: *Arena, parts: [][]const u8, sep: []const u8) ![]u8
pub fn trim(s: []const u8) []const u8
pub fn trimLeft(s: []const u8, chars: []const u8) []const u8
pub fn trimRight(s: []const u8, chars: []const u8) []const u8
pub fn indexOf(s: []const u8, needle: []const u8) ?usize
pub fn lastIndexOf(s: []const u8, needle: []const u8) ?usize
pub fn eqIgnoreCase(a: []const u8, b: []const u8) bool
pub fn replace(arena: *Arena, s: []const u8, from: []const u8, to: []const u8) ![]u8
pub fn count(s: []const u8, needle: u8) usize
pub fn repeat(arena: *Arena, s: []const u8, n: usize) ![]u8

The zero-copy functions return views into the input: split and splitLines allocate only the outer array of slices, and the trim family returns a narrower slice over the same bytes. Only join, replace, and repeat allocate a new string, and they read their input without mutating it, so from and to may alias s.

std.mem

std.mem is the lowest-level module: raw memory over many-item pointers with an explicit count. There is no allocation here and no length tracking. Every call names its element width in the function name, because Z98 has no generic copy. 

pub fn copyU8(dst: [*]u8, src: [*]const u8, n: usize) void
pub fn copyU32(dst: [*]u32, src: [*]const u32, n: usize) void
pub fn copyU64(dst: [*]u64, src: [*]const u64, n: usize) void
pub fn zeroU8(dst: [*]u8, n: usize) void
pub fn eqlU8(a: [*]const u8, b: [*]const u8, n: usize) bool

The sample calls zeroU8 on a small stack array to show the shape: cast the array to [*]u8, pass the count, and read the elements back. This is the module you reach for when you have bytes and a count, and nothing else.

std.math

std.math is integer-only and concrete: the signed helpers take i32 and the unsigned helpers take u32. It is not a floating-point library. One result is out of range: abs of the most negative i32 negates -2147483648, which overflows i32 and traps under the default safety checks. 

pub fn min(a: i32, b: i32) i32
pub fn max(a: i32, b: i32) i32
pub fn minU(a: u32, b: u32) u32
pub fn maxU(a: u32, b: u32) u32
pub fn abs(n: i32) i32
pub fn clamp(v: i32, lo: i32, hi: i32) i32
pub fn clampU(v: u32, lo: u32, hi: u32) u32
pub fn isPowerOfTwoU32(n: u32) bool
pub fn alignUp(n: u32, alignment: u32) u32
pub fn alignDown(n: u32, alignment: u32) u32

If you need a float square root or a sine, you write it yourself or call a C function through an extern declaration. The forty builtins of chapter 15 do not include a math library either.

std.debug

std.debug is the logging and assertion module. log and logInt write to standard output; assert and panic write a message and then trap, which means they never return. That is the point: a failed assertion is a termination, not an error to recover from. 

pub fn log(msg: []const u8) void
pub fn logInt(tag: []const u8, n: i32) void
pub fn assert(cond: bool) void
pub fn panic(msg: []const u8) noreturn
pub const DebugError = error{CoreDumpWriteFailed};
pub fn writeCoreDump(ctx: *const TrapContext, path: []const u8) DebugError!void

The module also owns the trap surface. setTrapHandler installs a handler that receives the register context, and backtrace walks the frame chain into a std.buf buffer. The default handler writes core.dump and aborts. This is the machinery behind a real crash report, and it is small enough to read in one sitting.

std.net

std.net is a set of target-selected bindings, not a protocol framework. On Windows it reaches Winsock 1.1; on the POSIX target it reaches libc. The public API hides the per-OS symbols behind names such as accept and close, and the byte-order helpers have portable manual variants so a program can be tested without a live socket. 

pub const Socket = i32;
pub const NetError = error{ WouldBlock, Timeout, ConnRefused, ConnReset, NotConnected, AddrInUse, InvalidAddr, Io };
pub const IpAddr = struct { a: u8, b: u8, c: u8, d: u8 };
pub fn init() i32
pub fn cleanup() void
pub fn createTcpServer(port: u16) i32
pub fn createTcpClient(port: u16) i32
pub fn udpBind(port: u16) NetError!Socket
pub fn udpSendTo(s: *Socket, addr: IpAddr, port: u16, data: []const u8) NetError!void
pub fn udpRecvFrom(s: *Socket, buf: []u8, out_addr: *IpAddr, out_port: *u16) NetError!usize
pub fn select(nfds: i32, readfds: ?*u8, writefds: ?*u8, exceptfds: ?*u8, timeout_ms: i32) i32
pub fn setNonBlocking(s: *Socket) NetError!void
pub fn htonsManual(x: u16) u16
pub fn htonlManual(x: u32) u32

The sample calls htonsManual, the portable byte swap, so the transcript is deterministic and needs no network. A real program calls init once before any socket operation and cleanup when it is finished.

std.async

The coroutine builtins live in the language; the bookkeeping lives here. std.async supplies a cooperative scheduler and a per-task child-frame pool. The caller owns every buffer: the root frame is a slice you pass in, and the Context sits at the head of another slice you supply. The header is sixteen bytes, and the buffer must be eight-aligned so that child frames holding eight-byte members stay aligned. 

pub const TaskState = enum(u8) { ready, running, suspended, done, cancelled };
pub const FrameError = error{OutOfFrame};
pub const HEADER_SIZE: usize = 16;
pub const Context = struct { used: usize, capacity: usize, oom: bool };
pub fn contextInit(buf: []u8) *Context
pub fn contextAlloc(ctx: *Context, size: usize) FrameError![*]u8
pub fn contextMark(ctx: *Context) usize
pub fn contextRelease(ctx: *Context, mark: usize) void
pub const Scheduler = struct { tasks: [*]*Task, capacity: usize, count: usize, current: usize, in_task: bool };
pub fn schedulerInit(tasks: []*Task) Scheduler
pub fn addTask(s: *Scheduler, t: *Task) bool
pub fn tick(s: *Scheduler) FrameError!void
pub fn waitAll(s: *Scheduler) FrameError!void

The sample initializes a Context over a stack buffer that is backed by [16]u64, which forces the eight-byte alignment the module requires, and reads back the usable capacity. The builtins that drive the frames, and the shape of a suspending function, are chapter 15's Group D.

std.bits

std.bits is pure computation on u32 and u64. Z98 has no bit builtins beyond @bitCast, so every operation is a hand-written loop. All functions are total except extract and insert, which trap when the offset and length fall outside a 32-bit word. 

pub fn popcount32(x: u32) u32
pub fn popcount64(x: u64) u32
pub fn clz32(x: u32) u32
pub fn ctz32(x: u32) u32
pub fn rotl32(x: u32, n: u32) u32
pub fn rotr32(x: u32, n: u32) u32
pub fn bitrev32(x: u32) u32
pub fn mask(bits: u32) u32
pub fn extract(x: u32, off: u32, len: u32) u32
pub fn insert(x: u32, val: u32, off: u32, len: u32) u32
pub fn isPow2(x: u32) bool
pub fn nextPow2(x: u32) u32

clz32(0) and ctz32(0) return the width (32), and nextPow2(0) returns 1, so the total functions stay total even at their edges.

std.os

std.os exposes process-level information. The argument surface is deliberately explicit: the compiler's main wrapper forwards argc and argv only when the Z98 main declares them, and the user passes them to initArgs once. After that, argc and argv are ordinary reads. 

pub fn initArgs(arg_count: i32, arg_values: [*]*const u8) void
pub fn argc() usize
pub fn argv(i: usize) []const u8
pub fn exit(code: i32) noreturn
pub fn env(name: []const u8) ?[]const u8
pub fn cwd(arena: *Arena) OsError![]u8
pub const OsError = error{ OutOfMemory, CwdFailed };

env returns an optional because the name may be unset; cwd takes an arena because the current directory is copied into memory you own. The sample calls initArgs at the top of main and later checks that argc is at least one and that the current directory is non-empty.

std.time

std.time provides a monotonic counter, a wall clock, and sleep. ticksMs is milliseconds since boot on Windows and wall-clock milliseconds since the epoch on POSIX, truncated to 32 bits; it wraps every 49.7 days. highRes is the monotonic source, with its unit given by highResFreq. 

pub fn ticksMs() u32
pub fn highRes() u64
pub fn highResFreq() u64
pub fn clockMonotonicAvailable() bool
pub fn wallClockUnix() i64
pub fn sleepMs(ms: u32) void

The sample only asserts that ticksMs is non-negative, a comparison that is always true for an unsigned value but proves the call links and runs. Timing code belongs in a program that can afford to sleep; here the goal is only to show the module is present.

std.buf

std.buf is a growable byte buffer. It is bytes only, not a general container, and it owns no storage: the arena behind it does. Growth doubles the capacity, and clear keeps the storage while resetting the length. There is no deinit; resetting the arena reclaims everything. The endian-tagged append functions exist because wire formats and file formats need them. 

pub const Buf = struct { arena: *Arena, data: []u8, len: usize };
pub fn init(arena: *Arena) Buf
pub fn initCapacity(arena: *Arena, cap: usize) !Buf
pub fn capacity(b: *Buf) usize
pub fn slice(b: *Buf) []u8
pub fn clear(b: *Buf) void
pub fn append(b: *Buf, bytes: []const u8) !void
pub fn appendByte(b: *Buf, byte: u8) !void
pub fn appendU16BE(b: *Buf, v: u16) !void
pub fn appendU16LE(b: *Buf, v: u16) !void
pub fn appendU32BE(b: *Buf, v: u32) !void
pub fn appendU32LE(b: *Buf, v: u32) !void
pub fn appendU64BE(b: *Buf, v: u64) !void
pub fn appendU64LE(b: *Buf, v: u64) !void

The sample appends a single little-endian u32 and reads the first byte back: 0x11223344 stored little-endian puts 0x44 at index zero. That one line exercises the arena-backed buffer, the append path, and the slice view.

The example

The whole tour in one program. It calls every one of the thirteen modules and prints one line for each result. It is docs/sf/manuals/src/vol2/stdio.z98: 

const std = @import("std");

const Point = struct { x: i32, y: i32 };

pub fn main(argc: i32, argv: [*]*const u8) void {
    std.os.initArgs(argc, argv);

    std.io.print("std.io ready\n", .{});

    const greeting: []const u8 = "hello, z98";
    const prefix: []const u8 = "hello";
    std.io.print("str len={} starts={} find={}\n", .{ std.str.len(greeting), std.str.startsWith(greeting, prefix), std.str.findChar(greeting, ',') != null });

    var bytes: [4]u8 = undefined;
    std.mem.zeroU8(@ptrCast([*]u8, &bytes), 4);
    std.io.print("mem zeroed={} {} {} {}\n", .{ bytes[0], bytes[1], bytes[2], bytes[3] });

    std.io.print("math max={} clamp={}\n", .{ std.math.max(3, 4), std.math.clamp(9, 0, 5) });

    std.debug.assert(greeting.len > 0);
    std.io.print("debug assert ok\n", .{});

    var backing: [256]u8 = undefined;
    var arena = std.arena.init(backing[0..256]);
    const p = std.arena.alloc(&arena, @sizeOf(Point)) catch return;
    const pt = @ptrCast(*Point, p);
    pt.x = 3;
    pt.y = 4;
    std.io.print("arena used={} point={} {}\n", .{ arena.used, pt.x, pt.y });
    std.arena.reset(&arena);

    std.io.print("bits pop={} clz={}\n", .{ std.bits.popcount32(0xF0), std.bits.clz32(1) });

    std.io.print("net port={x}\n", .{ std.net.htonsManual(0x1234) });

    var pool: [16]u64 = undefined;
    const ctx = std.async.contextInit(@ptrCast([*]u8, &pool)[0..128]);
    std.io.print("async header={} capacity={}\n", .{ std.async.HEADER_SIZE, ctx.capacity });

    var cwdbuf: [4096]u8 = undefined;
    var cwd_arena = std.arena.init(cwdbuf[0..4096]);
    const cwd = std.os.cwd(&cwd_arena) catch return;
    std.io.print("os argc>=1={} cwd_nonempty={}\n", .{ std.os.argc() >= 1, cwd.len > 0 });

    var bufbuf: [64]u8 = undefined;
    var buf_arena = std.arena.init(bufbuf[0..64]);
    var b = std.buf.init(&buf_arena);
    std.buf.appendU32LE(&b, 0x11223344) catch return;
    const bs = std.buf.slice(&b);
    std.io.print("buf len={} byte0={x}\n", .{ bs.len, bs[0] });

    std.io.print("time ticks>=0={}\n", .{ std.time.ticksMs() >= 0 });

    std.fmt.printI32(-99);
    std.io.print("\n", .{});
}

Thirteen lines, one per module, and an exit status of 0. Read the numbers back against the sections above. The arena reports eight bytes used for one Point; the async header is the declared sixteen, leaving 112 of the 128-byte pool; the network helper turns port 0x1234 around to the byte-swapped 3412; the buffer's first little-endian byte is 0x44. The final -99 is std.fmt.printI32 writing the last value with no format string, which is why it has no label and no trailing newline of its own.

Running under Windows 98

The same program builds for Win9x. src/build_owc.bat compiles the emitted C89 with OpenWatcom's wcc386 and links a console stdio.exe; run from a Windows 98 command prompt, it prints the same thirteen lines. Every module in the tour is target-selected already: std.net, std.os, and std.time choose their OS binding at compile time, so the same source emits the Win9x calls when it is built for that target. Common mistakes

The mistakes below come from arriving with a C standard library in your head. Each has a measured correction.

Assuming stdio.h and POSIX APIs. There is no FILE, no fopen, no printf with percent verbs, and no errno. std.io.print is a format-string entry point whose only specifier syntax is the brace form of chapter 15; it is not printf. Files are opened with std.io.fileOpen, which returns ?usize, so failure is handled with orelse: 

const fd = std.io.fileOpen(name, false) orelse return;

A C errno check after a failed call has nothing to read. Error information in Z98 is in the return type, which is why the arena returns ArenaError![*]u8 and the socket functions return NetError!T.

Assuming more modules ship than the thirteen. The library directory holds more std_*.zig files than the std namespace re-exports, and a name that is not in the table above is not reachable through std. The compiler says so at the point of use: 

const S = @sizeOf(std.base64);
// error[3074]: unable to resolve type argument

Check the re-export list in sf/src/std.zig before you reach for a name. If it is not one of the thirteen, it is not part of the documented surface, whatever else exists on disk.

Mixing the buffered and unbuffered output paths. std.io.write and std.io.printInt go through the standard output builtins, while std.io.print goes through std.fmt. On the POSIX target the first path is buffered and the second is not, so interleaving them can reorder the transcript. This is why the sample uses std.io.print for every line and calls std.fmt.printI32 only at the very end, with no other family's output in flight.
