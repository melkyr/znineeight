Types

A type is a name for a set of values and the operations that are legal on them. This page is the lookup for the Z98 type system: the primitive scalars, the arbitrary-width integers, the four special scalars, the list of type kinds, the coercion rules, and the frozen 32-bit layout model.

The authority is the compiler's type registry, sf/src/type_registry.zig. The TypeKind enum (type_registry.zig:41-60) is the complete list of kinds the compiler knows; the primitives are registered with their size and alignment in typeRegistryRegisterPrimitives (type_registry.zig:722-764). The size, alignment, and bit-width values below are measured on seed v90 with a @sizeOf/@alignOf/ @bitSizeOf probe; the same values appear in the reused Volume II sample src/vol2/types2.z98.

Primitive scalars

The scalar names, their C89 carrier, and their model size, alignment, and bit width (measured on seed v90). The special scalars bool, c_char, void, and noreturn are explained after the table.

isize int (32-bit) 4 4 32 yes

c_char is the C char type: a 1-byte scalar whose signedness is implementation-defined; the registry models it as signed (type_registry.zig:318-320). bool is an unsigned byte holding 1/0 and prints as true/false. The noreturn row is the registry's model (type_registry.zig:726); noreturn is the type of a diverging expression and the sole exemption from the anytype rule below, but it is not accepted as a @sizeOf/@alignOf/@bitSizeOf operand (measured: @sizeOf(noreturn) is a parse error[2000]).

Arbitrary-width integers

Any uN or iN name whose width is in range is an arbitrary-width integer. The legal ranges are u1…u64 and i1…i63 (parseArbIntWidth, type_registry.zig:774-797). The power-of-two names u8/u16/u32/u64 and i8/i16/i32/i64 are the fixed-width scalars above (the name cache binds them to the primitive, so they are not separate arbitrary-width kinds); the remaining widths — u1…u7, u9…u15, u17…u31, u33…u63 and the signed twins through i63 — are stored in the smallest power-of-two C carrier that holds the declared width. The arbitrary-width kinds are arb_uint_type and arb_int_type (type_registry.zig:58).

Declared width N Carrier @sizeOf / @alignOf Example: @bitSizeOf
1–8 1 / 1 u1 = 1, u7 = 7, i1 = 1
9–16 2 / 2 u9 = 9, i9 = 9
17–32 4 / 4 u17 = 17, i17 = 17
33–64 8 / 8 u33 = 33, i63 = 63

@sizeOf and @alignOf report the carrier; @bitSizeOf reports the declared width (type_registry.zig:799-826). Arithmetic results are masked (unsigned) or sign-extended (signed) back to the declared width. A value may be written in its declared range (const a: u3 = 7;, const b: i7 = -64;) but an overflowing runtime operation is a checked trap under the default -fsafe; under -ffast the wrap is visible (measured: u3 7 + 1 = 0, i7 63 + 1 = -64). @intCast to an arbitrary width is range-checked (an out-of-range value is error[3000]); the range check, like the other runtime checks, is enabled by default and disabled by -ffast (see the command line).

A width outside the ranges is not a type: parseArbIntWidth returns 0 and no type is registered for the name, so a resolved use reports the ordinary unresolved identifier — measured, fn f(x: u65) gives error[20]: identifier 'u65' is not declared or imported in this module. An enum may also take an explicit arbitrary backing width, enum(uN).

The reused Volume II program src/vol2/types2.z98 prints the carrier and bit-width rules; its measured output on seed v90 is:

usize and isize

usize and isize are the platform-sized integers. Z98 is single-target and its usize/isize are the 32-bit unsigned and signed int: both are size 4 and alignment 4 (type_registry.zig:735-736). They are distinct kinds (usize_type/isize_type) even though they share the i32/u32 C carrier.

bool, void, noreturn, and c_char

  • bool — the two values true and false, stored as an unsigned char 1/0; size 1, alignment 1, @bitSizeOf 1.
  • void — the empty type, size 0, alignment 0; the return type of a function that produces no value and the element type of nothing.
  • noreturn — the type of a diverging expression (a return, break, continue, unreachable, or a call to a never-returning function). It is the one exemption to the anytype rejection (next section) and degrades to void with no diagnostic; it is not a usable @sizeOf operand (see above). A switch whose every prong diverges has result type noreturn.
  • c_char — the C char type, 1 byte; signedness is implementation-defined and the registry models it as signed.

The remaining TypeKind members are either the scalar kinds listed above (void_type, bool_type, noreturn_type, the i*/u*/f* kinds, isize_type/usize_type, c_char_type), the arbitrary-width kinds, or compiler-internal transient kinds that are not written in source (type_type, module_type, null_type, undefined_type, integer_literal_type, unresolved_name, the anon_* literals, va_list_type, and none_sentinel). Aliases name a type but are erased at registration: diagnostics and emitted C report the underlying type, never the alias name.

Coercions

Z98 accepts a value of one type where another is expected only in the cases below. A coercion that fails is a compile-time error[3000] unless the row names another code. The set is quoted from the compiler's coercion rules and the Type Coercions section of the specification; the dedicated Reference page for each target is planned, so each row links the current Volume II coverage.

The specification's section 5 wording — "there is no implicit coercion between i32 and usize" — is superseded by the Type Coercions section and by measured behaviour: integer-to-integer conversion of any width and signedness (including i32 ↔ usize and narrowing) is accepted implicitly, and @intCast is the explicit, range-checked form rather than a requirement. The reused sample src/vol2/types2.z98 demonstrates this: the declaration var a: usize = v; and the assignment a = v; from v: i32 compile with warning[3000], and passing v to a usize parameter is silent. The const-discard and function-pointer rules, by contrast, are level-0 rejects and emit no C.

Layout and alignment (the align-8 model)

The compiler is single-target 32-bit and its layout model is the contract (FX14). The scalar sizes and alignments are in the first table; the composite rules are:

  • i64, u64, and f64 are size 8 and alignment 8. A struct, union, tagged union, optional, error union, tuple, or array inherits the maximum alignment of its members/elements, so any composite containing an i64/u64/f64 is alignment 8 and is padded accordingly.
  • Packed aggregates are the exception: their fields are bit-packed LSB-first with alignment 1 and size (total_bits + 7) / 8. A 64-bit packed field rejects error[3000] (typeRegistryComputePackedLayout, type_registry.zig:1052-1087).
  • Emitted C pins the model on every supported host: the 64-bit carriers are declared with Z98_ALIGN8 (__attribute__((aligned(8))) on GCC/Clang/mingw; empty on MSVC/Watcom, whose 32-bit defaults already align 64-bit scalars to 8). A /Zp4 or -zp4 packing override is not supported.
Type @sizeOf @alignOf Notes
*i32 4 4 All pointers are 32-bit in the model.
[]u8 8 4 A slice is a .ptr plus a .len.
?i32 8 4 Payload plus a presence flag.
error{ Foo, Bar }!i32 8 4 Payload plus an error code.
[3]i32 12 4 element size × length.
struct { a: u8, b: i64, c: u8 } 24 8 Offsets a=0, b=8, c=16; padded to alignment 8.

The struct row is the specification's worked example; its offsets were measured with @offsetOf and reproduce exactly. Because the 64-bit scalar forces alignment 8, b starts at 8 and the trailing byte c is followed by seven bytes of padding. See the Structs page (planned) for the packed bit rules and the Builtins page for @sizeOf, @alignOf, @offsetOf, @bitOffsetOf, and @bitSizeOf.
