Targeting Linux

This guide builds the default Linux target: it emits the C89 tree, reads the generated build_target.sh, compiles the emitted C with gcc -m32, and runs the 32-bit ELF result.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host whose gcc can target 32-bit x86. The emitted Linux script builds with gcc -m32, so the host needs the 32-bit C library and startup objects as well as the compiler; without them the link fails but the emit step still succeeds.
  • The repository checked out, so the shipped sample docs/sf/manuals/src/vol1/hello.z98 is present. Every command runs from the repository root, /workspace/znineeight.

The sample

The sample is the hello from Volume I, kept at docs/sf/manuals/src/vol1/hello.z98. It uses nothing but std.io.print, so the target choice changes only the emitted build scripts and platform headers, never the source: 

const std = @import("std");

pub fn main() !void {
    std.io.print("Hello from Z98!\n");
}

Steps

  1. Start at the repository root. 

    $ cd /workspace/znineeight

  2. Create the output folder. The compiler writes its emitted tree there but will not create the folder itself. 

    $ mkdir -p /tmp/manual_linux

  3. Emit the Linux tree. Linux is the default target, so no target flag is needed: -o names the output folder and the last argument is the source file. The explicit spelling of the same target is -osl; both produce the identical tree. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_linux docs/sf/manuals/src/vol1/hello.z98

    The command is silent on success and exits 0.

  4. Read the emitted build_target.sh. It is the whole Linux build: one script with a linux branch and a mingw branch, defaulting to linux. Its first argument is the target word the script builds, linux or mingw — not the compiler's -osl flag. The measured script is: 

    #!/bin/sh
chmod +x "$0" 2>/dev/null || true
# build_target.sh - generated by zig1
# usage: sh build_target.sh [TARGET] [OUT]
#   TARGET: linux (default) or mingw
#   OUT:    output binary (default: prog on linux, prog.exe on mingw)
# WARNING POLICY: this script does NOT enable warnings-as-errors (no -Werror here),
# so compiler warnings are non-fatal and the build still produces the binary.
# If the build stops with a hard error, the emitted C is invalid for this toolchain:
# please report it as a bug (include the failing compiler output above).
# If you add -Werror yourself, drop it to see the warning without failing.
set -e
cd "$(dirname "$0")"
TARGET=${1:-linux}
OUT=$2
case "$TARGET" in
  linux)
    CC=gcc
    CFLAGS="-m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign -Wno-implicit-function-declaration -I ."
    LDFLAGS="-m32 -O0"
    LIBS=""
    [ -n "$OUT" ] || OUT=prog
    ;;
  mingw)
    CC=i686-w64-mingw32-gcc
    CFLAGS="-m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign -Wno-implicit-function-declaration -I ."
    LDFLAGS="-m32"
    LIBS="-lwsock32"
    [ -n "$OUT" ] || OUT=prog.exe
    ;;
  *)
    echo "Unknown target: $TARGET"; exit 1
    ;;
esac
echo "Building for $TARGET..."
$CC $CFLAGS -c hello_F63FD80A.c
$CC $CFLAGS -c std_io_59DB29D9.c
$CC $CFLAGS -c std_net_A15200CC.c
$CC $CFLAGS -c zig_runtime.c
$CC $CFLAGS -c zig_pal.c
$CC $CFLAGS -c c_exit.c
# Link order: modules first, runtime sources last (intentional).
# The GNU linker is link-order-sensitive; this is our deterministic order,
# not the seed recipe's alphabetical *.o glob.
$CC $LDFLAGS hello_F63FD80A.o std_io_59DB29D9.o std_net_A15200CC.o zig_runtime.o zig_pal.o c_exit.o -o "$OUT" $LIBS
echo "Built: $OUT"

    The module file names are <source-basename>_<hash>.c; the hash is derived from the module's resolved path, so it changes if you move the tree and you should not hard-code it. The runtime sources (zig_runtime.c, zig_pal.c, c_exit.c) are always linked; every @import("std") program also emits the network module, std_net, even when it opens no socket.

  5. Read the linux branch, because it is the Linux target. CC is the host gcc; -m32 pins the output to 32-bit x86; the linux branch links no extra library (LIBS=""). The -std=c89 -O0 pair asks for the dialect the emitted code targets; the -Wno-* switches keep the generated C's known warnings non-fatal, and no -Werror is passed. 

      linux)
    CC=gcc
    CFLAGS="-m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign -Wno-implicit-function-declaration -I ."
    LDFLAGS="-m32 -O0"
    LIBS=""
    [ -n "$OUT" ] || OUT=prog
    ;;

    The mingw branch is the Windows side of the same script; it swaps in i686-w64-mingw32-gcc and adds -lwsock32. That path is the subject of Target Win9x.

  6. Build the executable with the emitted script's default linux branch. Run it from inside the output folder and give it the target word and the program name: 

    $ cd /tmp/manual_linux
$ timeout 120 sh build_target.sh linux hello
Building for linux...
Built: hello

    The generated C draws a long list of gcc warnings. They are expected and do not stop the build, because the script does not pass -Werror. A successful build ends with Built: hello.

  7. Run it, and confirm the artifact is a 32-bit ELF executable. 

    $ timeout 120 ./hello
Hello from Z98!
$ file hello
hello: ELF 32-bit LSB pie executable, Intel 80386, version 1 (SYSV), dynamically linked, interpreter /lib/ld-linux.so.2, BuildID[sha1]=fc3a7a60aa4b8c01c615ddd7b599f623a561c934, for GNU/Linux 3.2.0, not stripped

    -m32 is why the type line reads ELF 32-bit ... Intel 80386, not 64-bit; that is the ABI the emitted C89 and the runtime are built for.

Choosing the target

The compile target is a compiler flag; the default is Linux. The last one on the command line wins:

Flag Effect
(none) Linux. The same as -osl.
-osl Linux target, written out explicitly.
-osw Windows target. Also emits build_target.bat and build_owc.bat beside build_target.sh.
--target linux Long-form Linux spelling.
--target windows Long-form Windows spelling; any other value prints error: --target must be 'linux' or 'windows' and exits 1.

The flag selects the emitted build scripts and platform headers; it does not change the parser or the type checker. The emitted build_target.sh is the same file for both targets, carrying both branches, so you choose twice: the compiler flag chooses the tree, and the script's first argument (linux or mingw) chooses which branch to build. On a Linux host, the default — no flag, then sh build_target.sh linux hello — is the whole procedure.

Verify it worked

A clean run produces exactly this transcript, with the gcc warning text omitted. The emit prints nothing, the build script reports Built: hello, and the program prints its one line. 

$ cd /workspace/znineeight
$ mkdir -p /tmp/manual_linux
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/manual_linux docs/sf/manuals/src/vol1/hello.z98
$ cd /tmp/manual_linux && timeout 120 sh build_target.sh linux hello
Building for linux...
Built: hello
$ timeout 120 ./hello
Hello from Z98!

The compile-to-C89 step is silent on standard output; the build script reports Building for linux.../Built: hello, and its gcc warnings go to standard error. ./hello prints Hello from Z98! and exits 0.

Common mistakes

  • Forgetting to create the output folder. The compiler requires the folder to exist and fails with error: output directory does not exist: /tmp/manual_linux (exit code 1). Run mkdir -p first.
  • Confusing the compiler flag with the script argument. The compiler takes -osl/-osw (or --target) at emit time; the generated script takes the bare word linux or mingw as its first argument. sh build_target.sh windows hello fails with Unknown target: windows; use sh build_target.sh linux hello.
  • Running the build script from the wrong folder. build_target.sh uses relative paths and a current-directory include root, so cd into the output folder before running it.
  • A host without 32-bit support. The linux branch builds with gcc -m32; on a host missing the 32-bit C library it fails at the link with missing Scrt1.o/-lc. That is a host setup gap, not an emission bug; the emit in step 3 still succeeds.
  • Reading the gcc warnings as failure. The build prints hundreds of warnings but succeeds; look for Built: hello, not for an empty error stream.
  • Expecting --target to accept other names. Only linux and windows are accepted; anything else prints error: --target must be 'linux' or 'windows' and exits 1.
  • Assuming the target changes the program. It selects the emitted build scripts and headers, not the parser or the type checker. A source-level target predicate, if you need one, is @isWindows().
