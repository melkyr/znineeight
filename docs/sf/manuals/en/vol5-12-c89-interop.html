Link Z98 Output Against C89

This guide emits a Z98 module to a tree of C89 files, adds a hand-written C89 translation unit beside it, and links the two objects into one program, with calls crossing the seam in both directions.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • A Linux host with a 32-bit-capable gcc (the emitted script uses gcc -m32 -std=c89).
  • The repository checked out, so the two committed samples docs/sf/manuals/src/vol5/c89link/c89link.z98 and docs/sf/manuals/src/vol5/c89link/c89lib.c are present. Every command runs from the repository root, /workspace/znineeight.
  • Call C from Z98 first: this guide assumes you can already write an extern declaration and read the emitted C. For the full contract beneath the procedure, keep Volume III — Talking to C open.

The idea

A Z98 module is not a closed box: zig1 -o DIR writes a self-contained tree of .c/.h files and a companion build_target.sh, and a Z98 function is a C function by the time the linker sees it. A hand-written C89 file joins that tree as one more translation unit, compiled by the same gcc and linked into the same image. There is no runtime shim and no loader.

Two keywords define the seam. extern "c" borrows an existing C symbol into Z98; export fn lends a Z98 function to C under its plain source name. Every other name Z98 defines stays mangled, so the two namespaces cannot collide. The guide 11 samples covered borrowing; this one covers lending and the link.

Steps

  1. Emit the Z98 module. Start at the repository root, create the output folder (the compiler requires it to exist), then emit: 

    $ cd /workspace/znineeight
$ rm -rf /tmp/c89link
$ mkdir -p /tmp/c89link
$ timeout 120 /tmp/manual_seed/zig1_5_clean -o /tmp/c89link docs/sf/manuals/src/vol5/c89link/c89link.z98

    The command is silent on success. The module is tiny: it borrows one C function and lends one Z98 function back. 

    const std = @import("std");

extern "c" fn c89_apply(base: i32, rate: i32) i32;

export fn z98_tax(amount: i32) i32 {
    return amount + 5;
}

pub fn main() void {
    std.io.printInt(c89_apply(200, 10));
    std.io.writeByte('\n');
}

    extern "c" states that c89_apply already exists; the Z98 compiler emits the call but not the definition. export fn is the reverse: it defines z98_tax and writes the plain, unmangled name into the object file so the C unit can call it. pub fn main is the ordinary entry point and stays internal.

  2. Read the seam off the emitted C. The exported function keeps its source name, and the borrowed call appears under the C name too. In /tmp/c89link/c89link_2D0F3921.c: 

    /* z98_tax */
int z98_tax(int amount) {

    and, in the body of the mangled entry point: 

        zT_7 = c89_apply((int)((int)zT_3), (int)((int)zT_5));

    The module header carries the prototype a C caller needs. It is the contract you include or copy into the hand unit: 

    /* Forward declarations */
int z98_tax(int);
void zF_EA90E208_main(void);

    z98_tax is written unmangled because it was declared export; main is written zF_EA90E208_main because Z98 mangles every definition that is not exported. Once Step 4 has linked the program, list the symbols to see what the linker gets: 

    $ nm c89link | grep -E 'T (z98_tax|c89_apply|main)$'
0000134d T c89_apply
0000257a T main
0000248f T z98_tax

    All three are ordinary external T symbols. c89_apply is undefined in this tree until the hand unit supplies it, and z98_tax is already defined and exported. The mangling rules behind this are docs/reference/name_mangling.md and docs/reference/c89_emission.md.

  3. Write the hand C89 unit. It is plain C89 with no Z98 header and no runtime include: one extern prototype for the symbol Z98 lends, and one function Z98 borrows. 

    /* c89lib.c - a hand-written C89 translation unit that calls back into Z98.
 * The Z98 module c89link.z98 exports z98_tax; this plain C file takes its
 * address by an ordinary extern prototype and the linker resolves it across
 * the object boundary. Builds under gcc -m32 -std=c89.
 */

extern int z98_tax(int amount);

int c89_apply(int base, int rate) {
    return base * rate / 100 + z98_tax(base);
}

    The prototype int z98_tax(int) matches the emitted header line for line. Nothing else is needed: no #include of the Z98 module, no compatibility header. The seam is the C ABI.

  4. Copy the hand unit into the emitted tree and link the whole directory as one C program. zig1 -o made the tree self-contained, so -I . is enough and the emitted modules, runtime, and your file compile together: 

    $ cp /workspace/znineeight/docs/sf/manuals/src/vol5/c89link/c89lib.c /tmp/c89link/
$ cd /tmp/c89link
$ gcc -m32 -std=c89 -O0 -Wall -Wno-long-long -Wno-pointer-sign \
      -Wno-implicit-function-declaration -I . *.c -o c89link
$ timeout 120 ./c89link
225

    225 is the round trip: c89_apply(200, 10) computes 200 * 10 / 100 with C arithmetic, calls back into Z98 for z98_tax(200) = 205, and returns 20 + 205. The C object called Z98, and Z98 called C, across one ordinary link.

    gcc prints many warnings (unused static helpers in the emitted runtime), which is why the supported build flags include -Wno-... and the emitted script omits -Werror. They are not errors; the binary runs.

  5. Make it repeatable with the emitted build script. The compiler writes build_target.sh beside the C, and it already carries the exact flags and a deterministic link order. Its compile and link lines are flat lists: 

    $CC $CFLAGS -c c89link_2D0F3921.c
$CC $CFLAGS -c std_io_59DB29D9.c
$CC $CFLAGS -c std_net_A15200CC.c
$CC $CFLAGS -c zig_runtime.c
$CC $CFLAGS -c zig_pal.c
$CC $CFLAGS -c c_exit.c
# Link order: modules first, runtime sources last (intentional).
$CC $LDFLAGS c89link_2D0F3921.o std_io_59DB29D9.o std_net_A15200CC.o zig_runtime.o zig_pal.o c_exit.o -o "$OUT" $LIBS

    Add the hand unit in two places: a compile line for c89lib.c, and c89lib.o on the link line (append it after c_exit.o). Then run the script: 

    $ sh build_target.sh linux c89link
Building for linux...
Built: c89link
$ timeout 120 ./c89link
225

    That is the whole build-script recipe: one more gcc -c and one more object on the link. Keep the flags and the order the emitter already chose; the link order is intentional (see Build multiple modules and the multi-module section of docs/sf/QUICK_REF.md). The same two edits work in the mingw branch when the tree was emitted with -osw.

Verify it worked

The transcripts in Steps 4–5 are the recorded output of the committed samples; re-running those commands reproduces them. The linked program prints 225 and exits 0. That single number proves both directions at once: the C c89_apply ran, because the Z98 main called it, and the Z98 z98_tax ran, because C called it back. The nm listing in Step 2 shows the two unmangled external symbols (c89_apply, z98_tax) next to the mangled main, which is what makes the cross-object call resolve. If you see 225, the C89 seam is wired in both directions.

Common mistakes

  • Declaring the Z98 function pub fn instead of export fn. pub gives the function external linkage but keeps the Z98-mangled name, so a C caller looking for z98_tax does not find it. Change the sample to pub fn z98_tax and the emitted header and definition become: 
    int zF_275E47BE_z98_tax(int);
...
int zF_275E47BE_z98_tax(int amount) {
    and the link stops with: 
    c89lib.c:(.text+0x35): undefined reference to `z98_tax'
    Use export fn for every function C must call by its source name.
  • Forgetting the hand unit on the link line. The emitted tree alone defines the Z98 side but not c89_apply, so a build without c89lib.o reports: 
    c89link_2D0F3921.c:(.text+0x11b7): undefined reference to `c89_apply'
    Compile and add the object, or use the two-line build-script edit from Step 5.
  • Letting the prototype drift from the emitted header. The C compiler checks the hand unit against the prototype you wrote, not against Z98. Write int z98_tax(int) exactly as the generated .h declares it; a wrong return type or an extra parameter compiles cleanly in both languages and corrupts the call at run time.
  • Passing a Z98-only type across the seam. Slices, error unions, and optionals have no C representation. Pass a pointer plus a length, an integer code, or a plain struct, and translate the result once at the call, exactly as guide 11 does for @cInclude and extern.
  • Expecting zig1 to compile the C unit. The compiler emits C; it does not build it. The hand .c is compiled by the same gcc as the emitted files, and the emitted build_target.sh is the place to name it (Step 5).
  • Turning warnings into errors. The emitted runtime is warning-heavy by design; the supported flags disable the noisy warnings and the generated script does not pass -Werror. Adding -Werror turns a working build red over unused static helpers.
