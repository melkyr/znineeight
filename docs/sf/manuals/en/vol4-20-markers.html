Pipeline markers

With --markers, zig1 writes a stream of measurement markers to standard error, one per line, as it runs the compilation pipeline. Each marker is a terse record keyed to the phase or component that produced it. This page is the lookup for that stream.

The markers are produced by pal.measureMarkerWrite, pal.measureMarkerWriteInt, and pal.measureMarkerWriteInt64 (sf/src/pal.zig:252). Every call site in the compiler is listed below.

Enabling the channel

--markers calls pal.markersEnabled(1) (sf/src/main.zig:149). A marker is written only while isMarkersEnabled() is true; each measureMarkerWrite* function tests that flag before writing anything. Without the flag the compiler is silent on this channel.

--track-memory rides the same channel: its one-line report is written through measureMarkerWrite, so the memory report also needs --markers on. The marker stream and the compiler's diagnostics both go to standard error; redirect one to separate them.

The g_markers_debug gate

A second gate, pal.g_markers_debug (sf/src/pal.zig:210), is 0 in the shipped compiler. It controls the older debug channel (markerWrite, markerWriteInt, markerWriteInt64), which is therefore compiled off. The letter-code pipeline markers (I, S, T, A, L, C, M, R, F, ., and E) and the per-node debug traces (INT:dup, IRD:, IRV:, E2B:, VFLOW:, FL:) are not live output of the current compiler. They are source-level debug instrumentation; only the measureMarkerWrite* sites tabulated below are emitted by --markers.
