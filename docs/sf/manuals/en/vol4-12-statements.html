Statements

A statement is one action inside a block or at module scope: a declaration, an assignment, an expression evaluated for its effect, a nested block, a control-flow construct, or a defer/errdefer. This page is the lookup for the statement forms, the declaration and assignment rules, the explicit discard _ = expr;, blocks and scope, defer/errdefer ordering, and the statement-level syntax rules.

Authority: the spelling is docs/reference/Language_Spec_Z98.md §3.1; the statement dispatcher is parserParseStatement (parser.zig:1501), with declarations in parserParseVarDecl (parser.zig:1596), defer/errdefer in parserParseDeferStmt (parser.zig:2049), and blocks in parserParseBlock (parser.zig:2140). The const write guard is semantic_analyzer.zig:4105, the missing-initializer guard is semantic_analyzer.zig:5891, the ignored-error guard is semantic_analyzer.zig:6107, and the defer control-flow guard is semantic_analyzer.zig:473. Every rule below was reproduced on the fixed compiler (md5 821481e69df63fc0cf69176fdaaf9dd9); reused repro/mi_matrix/* fixtures and docs/sf/manuals/src/vol2/defer.z98 are named where one exists.

Declarations

A var binding is mutable; a const binding is immutable. The type annotation is optional and the initializer supplies the type when it is omitted. An initializer is required unless it is undefined.

Form Result (measured)
var x: u32 = 0;Mutable local.
const limit: u32 = 3;Immutable local.
var x = 0;Type inferred from the initializer.
var x: u32 = undefined;Accepted; the binding is uninitialized until the first store (verified: assigns then prints).
var x: u32;error[3014] variable must be initialized; use '= undefined' to opt out, rc 2, 0 .c.
var total: i32 = 0;
const limit: i32 = 3;
var scratch: i32 = undefined;
total = limit;
scratch = total;

Assignment

lhs = rhs; stores rhs into the mutable place lhs. The compound spellings fold the operator into the store. All assignment operators share the assignment precedence and associate to the right.

Operators Meaning
=Plain store.
+= -= *= /= %=Arithmetic compound store.
<<= >>= &= |= ^=Shift and bitwise compound store.
+%= -%= *%=Wrapping compound store.
+|= -|= *|= <<|=Saturating compound store.

Only a mutable l-value may be assigned. Writing to an immutable l-value — a const binding, a module const, a function parameter, a loop capture, a *const T dereference, or a []const T element — is level-0 error[3002] cannot assign to immutable variable with rc 2 and 0 .c. A const binding whose pointee is mutable (const p: *T, const s: []T) still allows a write through the pointee. 

// accepted -- repro/mi_matrix/const_assign_ok_xmod
var v: u32 = 1;
v = 2;
v += 1;                       // prints 3

var arr: [3]u32 = .{ 10, 20, 30 };
const p: *u32 = &arr[0];
p.* = 5;                      // prints 5 (mutable pointee)

const s: []u32 = &arr;
s[1] = 7;                     // prints 7

// rejected -- repro/mi_matrix/const_assign_reject_xmod (12 sites)
const x: u32 = 1;
x = 2;                        // error[3002]: cannot assign to immutable variable

fn setParam(x: u32) void {
    x = 2;                    // error[3002] -- parameters are immutable
}

Assignment is a statement, not an expression: it cannot appear in a condition (if (a = 3), while (a = 0), switch (a = 3)) or inside a parenthesized expression (var b = (a = 3);). Each is a parse-level error[2000] (expected ')' but found token / unexpected token), fixture repro/mi_matrix/cond_assign_reject_xmod.

Expression statements and discard

An expression statement evaluates an expression for its effect and drops the result. A call whose value is unused is the common case; _ = expr; is the explicit discard, used to consume a value on purpose (and to silence an otherwise unused binding). An undeclared name on the right of a discard is still resolved: _ = nope; is level-0 error[20] identifier 'nope' is not declared or imported in this module, rc 2, 0 .c. 

const unused: u32 = 42;
_ = unused;                   // explicit discard, accepted

fn mightFail() !void { return error.Bad; }

pub fn main() void {
    mightFail();              // error[3015]: error union result is ignored;
                              // use 'try', 'catch', or assign the result
}

Ignoring an error-union result without try, catch, or an assignment is level-0 error[3015] (repro/mi_matrix/diag_ignored_error_xmod). The check is error-union-only.

Blocks and scope

{ ... } groups statements into a scope. A binding declared inside the block is scoped to it. The block is a statement in its own right, and the bodies of if, while, and for take either a braced block or a single statement; a single statement is normalized into a synthetic block, so braces are optional there. An empty statement ; is parsed and skipped. 

{
    defer note("block-defer");
    note("block-body");
}                             // prints "block-body" then "block-defer"

repro/mi_matrix/stdlib_defer_switch_block_xmod pins the block body/defer ordering inside a bare block and a switch prong.

defer and errdefer

defer statement schedules the inner statement to run when the enclosing scope exits; errdefer statement schedules it only when that scope exits with an error. Both take an optional braced body and the inner statement carries its own terminating ;. Deferred statements run in reverse order of declaration (LIFO) and on every exit path of the scope — normal completion, return, break, and continue. 

// docs/sf/manuals/src/vol2/defer.z98 (trimmed)
fn loadConfig(ok: bool) !i32 {
    defer note("config: defer (always)");
    errdefer note("config: errdefer (rollback)");
    note("config: body");
    if (!ok) return error.BadConfig;
    return 11;
}
// success prints: config: body, config: defer (always)
// failure prints: config: body, config: errdefer (rollback), config: defer (always)

{
    defer note("inner B");
    defer note("inner A");
    note("block body");
}                             // prints: block body, inner A, inner B

Control flow out of a defer body is rejected, matching official Zig. A nested fn resets the restriction, and a break/continue whose target loop or labeled block is declared inside the body is allowed.

Code Message Shape
error[3051]cannot return from defer expressionreturn anywhere inside a defer/errdefer body.
error[3052]cannot break out of defer expressionbreak that transfers control out of the body.
error[3053]cannot continue out of defer expressioncontinue that transfers control out of the body.
error[3054]'try' not allowed inside defer expressiontry inside the body.

All four reject at level 0 (rc 2, 0 .c); the rejected and accepted halves are pinned by repro/mi_matrix/defer_control_flow_reject_xmod and repro/mi_matrix/stdlib_defer_control_flow_xmod.
