Pack for a Diskette

This guide assembles the self-contained tree the compiler emits into a distributable directory and packs that directory into a tar (or zip) diskette image. It ships no program of its own: the thing being packed is the output of Target Win9x, and the archive is a documented recipe rather than a committed artifact. The dist/ tree stays gitignored and no image is committed to the repository.

Prerequisites

  • The compiler rebuilt from the seed at /tmp/manual_seed/zig1_5_clean, with the standard library beside it in /tmp/manual_seed/lib/. If it is not there yet, follow Rebuild the compiler from seed first.
  • The repository checked out, so the sample docs/sf/manuals/src/vol1/hello.z98 is present. Every command runs from the repository root, /workspace/znineeight.
  • tar and gzip, which every Linux host has, and optionally zip for the zip form. The transcript below used tar; the zip command is the same packing operation with the era's archiver.
  • The emit step is the one Target Win9x already explains; this guide starts where that one ends, at the self-contained output directory. The sample here is Volume I's src/vol1/hello.z98 rather than Win9x's src/vol3/hello.z98, but the recipe is identical for any emitted tree. Volume III's Packaging and Shipping carries the framing for what belongs on a release.

Steps

  1. Start at the repository root and clear a staging directory. Everything is built under /tmp so nothing lands in the working tree. 

    $ cd /workspace/znineeight
$ rm -rf /tmp/z98_disk
$ mkdir -p /tmp/z98_disk/out

    The compiler will not create its output directory, so mkdir -p comes first.

  2. Emit the self-contained Windows tree into the staging directory. -osw selects the Windows target; drop it (or use -osl) for the Linux distribution. The command is silent on success. 

    $ timeout 120 /tmp/manual_seed/zig1_5_clean -osw -o /tmp/z98_disk/out docs/sf/manuals/src/vol1/hello.z98
$ echo "emit rc=$?"
emit rc=0

  3. Read what the compiler wrote. It is not one .c file; it is every translation unit the build needs, side by side. 

    $ cd /tmp/z98_disk/out && ls -1
build_owc.bat
build_target.bat
build_target.sh
c_exit.c
hello_F63FD80A.c
hello_F63FD80A.h
net_prelude.h
std_io_59DB29D9.c
std_io_59DB29D9.h
std_net_A15200CC.c
std_net_A15200CC.h
zig_compat.h
zig_pal.c
zig_runtime.c
zig_runtime.h
zig_special_types.h

    Read the listing in four groups, because that is what a release is:

    Group Files Ship it?
    Your module hello_F63FD80A.c and .h yes — this is the program
    Standard modules pulled in by @import("std") std_io_59DB29D9, std_net_A15200CC (.c/.h) yes — the build needs them
    Runtime and platform layer zig_runtime.c/.h, zig_pal.c, c_exit.c, zig_compat.h, zig_special_types.h, net_prelude.h yes — dropping them breaks the link
    Build scripts build_target.sh, build_target.bat, build_owc.bat yes — one per era toolchain

    The _F63FD80A suffix is derived from the module's source path and the compiler's install path, so it is stable for this emit and changes if the tree moves. Do not hard-code it; ship the scripts the compiler wrote.

  4. Drop the compiler's scratch files. It leaves hidden intermediate state beside the sources; none of it is source. 

    $ ls -1a /tmp/z98_disk/out | grep '^\.'
.
..
.zig1_ast.tmp
.zig1_extra_ec.tmp
.zig1_extra_er.tmp
.zig1_hash.tmp
.zig1_lir.tmp
.zig1_res.tmp
.zig1_side.tmp
.zig1_side_iv.tmp
$ rm -f /tmp/z98_disk/out/.zig1_*.tmp

  5. Create the distributable directory and copy only the files the release needs. The explicit .c/.h/.sh/.bat globs copy the sources and scripts and leave the dot-files behind. 

    $ mkdir -p /tmp/z98_disk/floppy1
$ cp /tmp/z98_disk/out/*.c /tmp/z98_disk/out/*.h /tmp/z98_disk/out/*.sh /tmp/z98_disk/out/*.bat /tmp/z98_disk/floppy1/
$ ls -1 /tmp/z98_disk/floppy1
build_owc.bat
build_target.bat
build_target.sh
c_exit.c
hello_F63FD80A.c
hello_F63FD80A.h
net_prelude.h
std_io_59DB29D9.c
std_io_59DB29D9.h
std_net_A15200CC.c
std_net_A15200CC.h
zig_compat.h
zig_pal.c
zig_runtime.c
zig_runtime.h
zig_special_types.h

    If you prefer to keep the compiled hello.exe in the image, build it first with the emitted script (sh build_target.sh mingw hello) and it will sit beside the sources. The archive described below is the source-and-build shape from Volume III.

  6. Add the one file the compiler does not write: a short readme that says which script to run and what the program does. This is the only hand-written file in the release. Write it into the distributable directory with a here-document: 

    $ cd /tmp/z98_disk/floppy1
$ cat > README.TXT <<'EOF'
Z98 hello - diskette 1 of 1
===========================

Program: hello.exe
Source:  docs/sf/manuals/src/vol1/hello.z98

To run:      hello.exe
To rebuild:  run the script for the compiler you have -
             build_owc.bat    (OpenWatcom wcc386/wlink), or
             build_target.bat (MSVC cl), or
             build_target.sh mingw (gcc/mingw).
             All three compile the same emitted C89 in this directory.
EOF

  7. Pack the diskette image. Change into the distributable directory and archive its contents from the top, so unpacking recreates the directory rather than nesting it. 

    $ cd /tmp/z98_disk/floppy1
$ wc -c * | tail -1
124763 total
$ timeout 120 tar czf /tmp/z98_disk/z98-hello-floppy1.tar.gz .
$ ls -l /tmp/z98_disk/z98-hello-floppy1.tar.gz
-rw-r--r-- 1 node node 25391 Oct  5 17:52 /tmp/z98_disk/z98-hello-floppy1.tar.gz

    The zip form is the same operation with the era's archiver: 

    $ cd /tmp/z98_disk/floppy1
$ timeout 120 zip -r /tmp/z98_disk/z98-hello-floppy1.zip .

    About 122 KB of C89 and scripts compress to roughly 25 KB, well inside the 1.44 MB of a 3.5-inch floppy. Size is not the binding constraint here; self-description is.

  8. Check the image by listing it and by unpacking it into a fresh directory. The listing is the same 17 files; the round-trip proves the archive is complete. 

    $ timeout 120 tar tzf /tmp/z98_disk/z98-hello-floppy1.tar.gz | wc -l
18
$ rm -rf /tmp/z98_disk/verify && mkdir -p /tmp/z98_disk/verify
$ timeout 120 tar xzf /tmp/z98_disk/z98-hello-floppy1.tar.gz -C /tmp/z98_disk/verify
$ ls -1 /tmp/z98_disk/verify | wc -l
17

    The 18 entries are the leading ./ directory entry plus the 17 files. The extracted directory has the 17 files the build needs and nothing else.

Verify it worked

The archive is correct when its listing is exactly the emitted tree plus the readme, sorted: 

$ timeout 120 tar tzf /tmp/z98_disk/z98-hello-floppy1.tar.gz | sort
./
./README.TXT
./build_owc.bat
./build_target.bat
./build_target.sh
./c_exit.c
./hello_F63FD80A.c
./hello_F63FD80A.h
./net_prelude.h
./std_io_59DB29D9.c
./std_io_59DB29D9.h
./std_net_A15200CC.c
./std_net_A15200CC.h
./zig_compat.h
./zig_pal.c
./zig_runtime.c
./zig_runtime.h
./zig_special_types.h

Every .c in the listing has a matching .h where the emitter wrote one, the three build scripts are present, the runtime sources zig_runtime.c, zig_pal.c, and c_exit.c are present, and no .zig1_*.tmp scratch file survived. Unpacking to a fresh directory yields the same 17 files, and the compressed image is about 25 KB — one floppy with room to spare. That is the acceptance test: a self-describing directory that another person can copy and build from, with the archive itself left out of the repository.

Where to go next

The emit this guide packs is the subject of Target Win9x, and the shape of a release — what belongs on the diskette and why — is Volume III's Packaging and Shipping. To build the tree in the first place, go back to Build a single file or Build multiple modules; the Linux image is Target Linux. The Volume IV Reference carries the rules the emitted tree relies on: The command line for -osw and -osl, The Platform Layer for the zig_pal.c the image ships, and The Standard Library for the standard modules pulled into the tree.
