Limits

The honest list. This page states what Z98 is known to limit and what it does not yet support, drawn from the Language Spec's §5 (known limitations and workarounds) and §7 (not yet supported) and checked against the compiler built from the committed seed. Each entry is a fact; where the language provides a way over it, the way over is named in the same row.

Three lists follow. The first is the set of limits that ship with the language and their workarounds. The second is the set of features permanently dropped from the design. The third is the set of features designed but not implemented in the current self-hosted zig1. The exact codes and messages are quoted from the Language Spec and the shipped pages; the snippet diagnostics below were re-run on the seed compiler.

Known limitations and workarounds

These are the limits the language itself carries, from spec §5. None is silent: a limit that reaches the compiler is a numbered diagnostic, and a limit that does not is paired with the idiom that works.

Limit The way over Diagnostic or source
No anyerror Declare the set (const MyError = error{ Bad };) or use an anonymous error union !T. Failures are declared, not erased. error[20] for the undeclared name; spec §1.5, §7.2
No generics Write one concrete function or container per type; use a *void plus a function pointer where the type genuinely varies. The standard library's containers are written out concretely. anytype parameter is error[16]; a comptime parameter is error[2000]; spec §4
No anonymous aggregate type declarations Name the type with a const assignment. Anonymous struct type expressions, tuple literals .{}, and anonymous struct payloads in tagged-union variants are parsed. spec §1.3, §5
Strict coercion There is no implicit conversion between i32 and usize; spell it: @intCast(usize, x) or @intCast(i32, x). spec §1
No method syntax Call a free function with the receiver as an ordinary parameter: update(&e, dt), never e.update(dt). The one exception is a call whose callee is named print, which gets format-string lowering. error[3060]: no field or member function named '...' in struct type; spec §4
AST lifting Most control-flow expressions (if, switch, try, catch, orelse) are transformed into statement blocks with temporaries, so they can be used inside expressions while the output stays C89. automatic; no diagnostic; spec §5
Runtime safety is a mode -fsafe (the default) enables six runtime checks: checked cast, division and modulo by zero, shift count, null unwrap, index out of bounds, and integer overflow. A failed check calls pal_trap. -ffast disables all six. unreachable and @panic trap in both modes, and under -fsafe storage set to undefined is byte-filled with 0xAA so a read is visible. The command line for -fsafe/-ffast; spec §5
Compile-time rejects Several constructs C89 accepts silently are rejects here: an uninitialized var (error[3014]), a discarded error union (error[3015]), a non-void function that can fall off its end (error[3003]), orelse on a non-optional operand (error[3016]), indexing a single-item pointer (error[3066]), an illegal single-item-pointer slice bound (error[3067]), a call whose argument count does not match (error[3061]), a call argument in a different type family (error[3000]), a print argument container that is not a tuple (error[3065]), a non-comptime tuple index (error[3069]), and an out-of-range tuple ordinal (error[3070]). Diagnostics lists every code; spec §5

Two of these limits have a direct snippet. A function parameter declared anytype and one declared with a comptime type are both rejected at the signature: 

fn f(x: anytype) void { _ = x; }
// error[16]: anytype not supported in Z98

fn id(comptime T: type, x: T) T { return x; }
// error[2000]: expected ':' but found identifier

A member call on a value is rejected where it appears, with a note naming the declaration: 

const s = S{ .x = 1 };
s.bar();
// error[3060]: no field or member function named 'bar' in struct type
// note: struct declared here

Permanently dropped

These features were considered for Z98 and are not planned for zig1 (spec §7.1). The documented idiom replaces each. One earlier entry has moved: volatile qualifiers are no longer dropped, so *volatile T, [*]volatile T, and @volatileCast are supported.

static declarations

The static keyword is not in the token set, so static var does not parse. Use a container-level var for state that persists across calls: 

static var g: i32 = 0;
// error[2000]: expected ';' but found 'var'

var g: i32 = 0; // file/container scope, persists across calls
fn bump() void { g = g + 1; }

do ... while loops

do ... while is dropped. Use the equivalent while (true) with an early break: 

do {} while (cond);
// error[2000]: expected ';' but found 'while'

while (true) {
    body();
    if (!cond) break;
}

Caveat: continue in this emulation skips the condition test and re-enters the body, unlike a real do ... while.

Designed, not implemented

These features appear in Z98 design and plan documents but are not implemented in the current self-hosted compiler (spec §7.2). Do not rely on them. Each row names the shipped substitute.

Feature Status The way over
Value-producing labelled blocks const n = blk: { ... break :blk 1; }; does not parse. Only value-less break :blk; is supported. Assign through an ordinary statement or a named local instead of producing a value from the block.
@errorName Not implemented; the builtin is error[3000]: unsupported builtin function. Keep the failing error in a declared set and switch on it; format the name yourself.
extern struct, opaque, vector types Not accepted as types. extern struct rejects error[2000]: expected 'fn' after extern calling convention; opaque is error[20]. Use a plain struct and reach a C ABI through extern fn declarations and @cInclude.
Generics, anytype parameters, @Type, @typeInfo, and comptime Not implemented. anytype is error[16]; @Type, @typeInfo, and any comptime parameter reject (error[3000] or error[2000]). Concrete code per type plus the fixed builtin catalog; the introspection builtins (@sizeOf, @alignOf, @offsetOf, @bitSizeOf) answer the representation questions.
anyerror Not a type. It is not exempt from the signature name rule: fn f(e: anyerror) rejects error[20]. A declared error set or an anonymous !T.
noreturn as a signature type Not registered as a type name. In a signature it degrades with no diagnostic: a parameter becomes C int and a return becomes void. The exemption is keyed on the identifier text noreturn at any signature, not only the six std ones, so fn f(x: noreturn) void and fn f() noreturn {} both compile rc 0. Outside a signature the name rejects: a local var x: noreturn; gives error[20] and error[3000]. A real noreturn type with a C companion is deferred; noreturn remains usable as the compiler's internal divergence result type. Do not spell noreturn in a declaration; a signature silently degrades. Use void, or an error union when the call can fail.
@cImport Not implemented; it rejects error[3000]: unsupported builtin function. Bare extern declarations plus a module-level @cInclude("header.h");.
std.Io / an event-loop interface, preemption, threads, and typed futures (Future(T)) The @async* coroutines are cooperative and round-robin only, and coroutine state is type-erased to *void. The std.async scheduler; real parallelism stays an operating-system concern reached through extern declarations, not through the language.
Arbitrary compile-time integer semantics Implemented, with a 256-bit magnitude cap; values are signedness-free until materialised. A bounded set of divergences remains in spec §7.2. Use @intCast/@as at materialisation sites; the arrays page and the diagnostics page carry the rejection shapes.

The compile-time integer divergences in spec §7.2 are deliberate and documented rather than silent: a stack value needing more than 64 bits in a runtime slot (const BIGFOLD = 1 << 100;) rejects error[3000]; an array size above 0xFFFFFFFE is error[3050] because the array-length field is u32; % on a signed compile-time integer and ~ on a comptime_int are accepted where Zig 0.15.2 requires @rem or rejects; float comparisons fold at the compiler's f64 precision; and runtime signed slice bounds (such as arr[i..4] with a runtime i32) are not rejected where Zig compile-rejects. The arrays and slices page states the array-size boundary.

Spec snippet checks

The value-producing labelled block and the unsupported builtins above are verified against the seed compiler; each line is a fragment of a function body, shown with the diagnostic it produces: 

const n = blk: { break :blk 1; };
// error[2000]: expected ';' but found integer literal

_ = @typeInfo(i32);
// error[3000]: unsupported builtin function

_ = @errorName(e);
// error[3000]: unsupported builtin function

The substitutes compile: a value-less labelled block (blk: { break :blk; }), a named struct, and a module-level @cInclude are all accepted with no diagnostic.

Absences of tooling

Three items are absences of tooling rather than of the language. Each has the era's answer, and each is measured in Volume III, the honesty inventory.

Absent The era alternative
A package manager Vendor the third-party source into the tree, which is what a 1998 project shipped.
IDE integration A text editor and the compiler's numbered diagnostics; the build is a plain script you can read.
Dynamic linking to modern libraries Link the era's C89 static libraries and object files; Z98's output is C89, so it links with them directly.

The concurrency and networking limits are the compiler's own and are stated in the spec: no thread API and no preemption, and the network surface is the classic socket API, not an HTTP or TLS stack. The Pentium II limits chapter pairs each machine limit with its way over.
