Doing Arithmetic

The last chapter gave values names and types. This chapter makes them work. It introduces the five arithmetic operators, the order the compiler applies them, and the one place where a calculation can do something the source does not say: when the result no longer fits the type it is stored in. That last part is the first time the compiler's default safety checks earn their keep, and the first time a program can stop without printing what you expected.

The program

const std = @import("std");

pub fn main() void {
    var a: i32 = 17;
    var b: i32 = 5;

    std.io.print("a + b = {}\n", .{a + b});
    std.io.print("a - b = {}\n", .{a - b});
    std.io.print("a * b = {}\n", .{a * b});
    std.io.print("a / b = {}\n", .{a / b});
    std.io.print("a % b = {}\n", .{a % b});

    var p: i32 = -7;
    var q: i32 = 2;
    std.io.print("-7 / 2 = {}\n", .{p / q});
    std.io.print("-7 % 2 = {}\n", .{p % q});

    var two: i32 = 2;
    var three: i32 = 3;
    var four: i32 = 4;
    std.io.print("2 + 3 * 4 = {}\n", .{two + three * four});
    std.io.print("(2 + 3) * 4 = {}\n", .{(two + three) * four});

    var max: i32 = 2147483647;
    var one: i32 = 1;
    var over: i32 = max + one;
    std.io.print("max + 1 = {}\n", .{over});
}

It does four things. It applies all five operators to the same two numbers. It shows what integer division does when one number is negative. It shows two ways to group the same three numbers, so the difference precedence makes is visible. And it ends by adding one to the largest value an i32 can hold, which is where the chapter's last section comes in.

The five operators

Five symbols do arithmetic on integers. Each takes two values, one on either side, and produces a third.

Operator Name Example Result
+ addition 17 + 5 22
- subtraction 17 - 5 12
* multiplication 17 * 5 85
/ division 17 / 5 3
% remainder 17 % 5 2

The first three behave the way you expect. The last two are the pair that surprises people, and they are worth reading carefully because they are the reason a program that looks like it does one thing can do another.

/ gives the whole quotient

The slash is integer division. Both values are integers, so the answer is an integer, and any fractional part is thrown away rather than rounded. 17 / 5 is 3, not 3.4 and not 4. The fraction that is discarded is the subject of the next section.

% gives what is left over

The percent sign is the remainder, often called the modulus. It answers "after dividing as many whole times as possible, what is left?" Five goes into seventeen three times (fifteen), and two is left, so 17 % 5 is 2. The two operators fit together: for a positive divisor, a / b times b plus a % b gives back a.

Integer division truncates

The discarded fraction is worth its own heading because it is the first arithmetic mistake a new programmer makes, and because the compiler does not warn about it. The rule is that the result is truncated toward zero: the part after the decimal point is cut off, and the sign of the result is the sign the ordinary division would have had.

For positive numbers that matches intuition: 17 / 5 is 3. The negative case is where it bites. -7 / 2 is not -3.5 and it is not -4; it is -3. The program prints exactly that: 

-7 / 2 = -3
-7 % 2 = -1

The remainder keeps the sign of the dividend, so -7 % 2 is -1. This is the behaviour C89 has, and Z98 compiles to C89, so the two agree. When you want the other rounding, you have to say so in your own code; the operators will not do it for you.

Precedence: which operator goes first

An expression with more than one operator needs a rule for the order they are applied in, and that rule is precedence. The program makes it visible with the same three numbers grouped two ways: 

2 + 3 * 4 = 14
(2 + 3) * 4 = 20

In the first line, multiplication is applied before addition, so it is 2 + (3 * 4) and the answer is 14. In the second line, the parentheses force the addition first, so it is (2 + 3) * 4 and the answer is 20. Parentheses always win; they are the one tool that removes all doubt.

The compiler sorts the operators into levels. A higher level is applied before a lower one. The table below lists the levels a beginner meets, from tightest (highest) to loosest (lowest):

Level Operators How they group
highest -x, !x (one value) bind to the value on their right
*  /  % left to right
+  - left to right
== != < > <= >= left to right
and left to right
lowest or left to right

The two operators above the arithmetic operators are the unary operators, which take one value instead of two: -x negates, and !x is logical not. They bind to the nearest value, so -2 * 3 is (-2) * 3, which is -6.

Note the last two rows: and and or are not on the same level. and binds tighter than or, so true or false and false is true or (false and false), which is true. The comparison operators sit below the arithmetic, so arithmetic is settled before any comparison is made; later chapters use comparisons and the logical operators.

This table is scoped to the operators this chapter introduces. The compiler has more levels: below or sit catch, orelse, and assignment, and between the comparison row and the +/- row sit the bitwise &, ^, | and the shifts. They arrive in later chapters, and the Reference volume will list them all. What matters here is the arithmetic levels and the rule that a tighter level is applied first.

When two operators are on the same level, they group left to right: the left one is applied first. That is why 20 / 5 % 3 is (20 / 5) % 3, which is 4 % 3, which is 1. The same left-to-right rule gives 1 + 2 * 3 - 4 the value 3: the multiplication is done first because it is a higher level, then the addition and subtraction run left to right.

Tip. When you are not sure, add parentheses. They cost nothing at run time, they never change the meaning you intended, and they spare the next reader (often you) the job of reconstructing the precedence table in their head.

When a result no longer fits

An i32 is four bytes, and four bytes hold a fixed range of values: -2147483648 to 2147483647. The program's last two lines push against that ceiling. It declares max as the largest i32, declares one as 1, and adds them: 

var max: i32 = 2147483647;
var one: i32 = 1;
var over: i32 = max + one;

The true answer, 2147483648, is one past the top. There is no bit pattern for it in an i32, so the addition overflows. Z98 gives you two behaviours for that moment, and which one you get is chosen when the program is compiled, not when it runs.

-fsafe: stop before the wrong value exists

The default is -fsafe. Before the addition is performed, the emitted C checks whether the result would leave the range of the type. If it would, the program is stopped on the spot. Nothing after the check runs, so the max + 1 line never prints, and the program does not exit normally. This is the point of the default: a wrong number is worse than a stopped program, because a wrong number travels.

-ffast: let it wrap

The other mode is -ffast, which turns the checks off. The addition is emitted as a plain C addition, and the value wraps around the way the hands of a clock wrap past twelve. One past the top of the range becomes the bottom of the range, so 2147483647 + 1 prints as -2147483648. The program keeps running and prints a value, but that value is not the arithmetic answer.

Warn. Wrapping is silent. Under -ffast the compiler emits no diagnostic for an overflow it cannot see coming, and the program reports success. Use -ffast only when you have measured the cost of the checks and know the values cannot overflow.

The safety checks are not free: each one is a comparison and a branch around the operation. On a 1998 machine those branches are cheap for a handful of values and not cheap in a tight loop over a large array. That is the trade the two modes offer. The default is the safe one, and you opt out deliberately.

Building and running it

The commands are the ones from the last two chapters, with math in place of types. The compiler is still at /tmp/manual_seed, built in chapter 4. Build the program with the default -fsafe first: 

$ mkdir -p /tmp/manual_out
$ /tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/vol1/math.z98
$ cd /tmp/manual_out && sh build_target.sh linux math
Building for linux...
Built: math
$ ./math
a + b = 22
a - b = 12
a * b = 85
a / b = 3
a % b = 2
-7 / 2 = -3
-7 % 2 = -1
2 + 3 * 4 = 14
(2 + 3) * 4 = 20
Trace/breakpoint trap (core dumped)

The first nine lines are the arithmetic. The tenth line of output never comes: the overflow check fires on the max + one addition and stops the program. The shell reports the trap, and the program's exit status is 133. A trap is not a crash in the sense of a bug you have to find; it is the check doing exactly what it was compiled to do. But it does mean the program did not finish, and on a real machine a reader would see the same thing.

Now build the same source with the checks off. Only the compiler flag changes; the .z98 file is untouched: 

$ mkdir -p /tmp/manual_fast
$ /tmp/manual_seed/zig1_5_clean -ffast -o /tmp/manual_fast docs/sf/manuals/src/vol1/math.z98
$ cd /tmp/manual_fast && sh build_target.sh linux math
Building for linux...
Built: math
$ ./math
a + b = 22
a - b = 12
a * b = 85
a / b = 3
a % b = 2
-7 / 2 = -3
-7 % 2 = -1
2 + 3 * 4 = 14
(2 + 3) * 4 = 20
max + 1 = -2147483648

This time all ten lines print, and the last one shows the wrap. The program exits with status 0 and reports success. Nothing in the output says that the last number is not the arithmetic answer; that is the difference between the two modes in one line.

Running under Windows 98

The program builds for Win9x exactly as hello and types did. The same build_target.sh script, or src/build_owc.bat with OpenWatcom, produces a console math.exe. Built with the default -fsafe it stops at the same overflow as on Linux; built with -ffast it prints all ten lines, ending with the wrapped value. Common mistakes

These are the arithmetic mistakes that do not announce themselves. Each one has a symptom you can recognize.

Expecting a fraction from integer division. This is the first one, and it is silent. The compiler accepts 17 / 5 and gives you 3. If you meant 3.4, you wanted a floating-point type, not i32: 

a / b = 3

There is no warning, because the program is not wrong; it is doing integer division, which is what the types said to do. The fix is either to use f32 or f64, or to accept that you are counting whole things and that the remainder is a separate value.

Letting a result overflow. The program's last line is the example. Under the default -fsafe the check stops the program; under -ffast it wraps and prints a wrong number. Neither one is a compile error, because the compiler cannot always know the values that will arrive at run time: 

max + 1 = -2147483648

If you see a value that should have grown jump to a large negative number, you have an overflow. The cure is to choose a wider type for the variable that holds the running total, or to keep the values small enough that the range is never reached.

Dividing by zero. This is not arithmetic with a wrong answer; it is arithmetic with no answer at all. Under -fsafe the division check catches it and stops the program with the same kind of trap as the overflow above. Under -ffast the check is gone and the machine raises its own fault, which on this target is reported as a floating-point exception. The lesson is the same in both modes: a divisor that can be zero needs a check in your own code before the division, because no compiler can guess whether the value will be zero.

Check yourself

Answer these before moving on. The last three ask you to change the program and run it.

  1. Name the five arithmetic operators and say what each produces for 17 and 5.
  2. What is 7 / 2, and what is 7 % 2? What are they for -7 / 2 and -7 % 2?
  3. What is the value of 2 + 3 * 4, and how do you make it 20 instead?
  4. On the same precedence level, does the compiler group operators left to right or right to left? What is 20 / 5 % 3?
  5. What does the default -fsafe do when an addition would overflow, and what does -ffast do instead?
  6. Change max to 2147483640 and rebuild with the default mode. Does the program still stop? Why or why not?
  7. Change the type of over to i64 (and max and one with it), rebuild, and run it. What does max + 1 print now, and why does the overflow no longer happen?
  8. Write an expression that computes the average of a and b as an integer, then change b to 4 and run it. What does the expression print, what is the true average, and where did the difference go?
