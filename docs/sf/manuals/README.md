# Z98 Manual - contributor guide

This directory is the source of the Z98 manual: a hand-authored, offline,
era-accurate static website. It documents the **current** compiler only. Every
claim must reproduce; a claim that cannot be verified against
`docs/reference/Language_Spec_Z98.md` and the compiler source is fixed or
dropped (design spec §3).

The binding program spec is
`docs/superpowers/specs/2026-09-20-z98-manual-phase0-design.md`. This guide
covers how to build, validate, serve, and extend the site.

## Tree layout (spec §4)

Root: `docs/sf/manuals/`. Pages are flat within `en/` (depth always 1) so the
diskette/CD build stays a plain file copy.

```
docs/sf/manuals/
  index.html              language selector (English active)
  readme.html             what this is / how to read / colophon
  todo-figures-list.html  every pending Win9x screenshot (1:1 with the pages)
  en/
    index.html  readme.html  toc.html  search.html
    search-data.js        generated by build.sh (do not hand-edit)
    doc.js                the only hand-authored JavaScript (search-data.js is generated)
    z98.css  z98-print.css   external CSS1 stylesheets
    gfx/                  GIF assets (logo, bullets, icons, buttons, navrule)
    gfx/xbm/              XBM alternates of the button GIFs
    vol4-24-html-style.html   the HTML contract + copyable page template
  src/                    example programs (one subdir per volume)
  build.sh  check.sh  check.py  serve.sh
  dist/                   generated by build.sh (gitignored)
```

Volume pages follow `vol<volume>-<chapter>-<slug>.html`; title pages use
chapter `00` (`vol1-00-title.html`). Example programs live at
`src/vol<volume>/<prog>.z98`. The cross-archetype content pages and their
examples are authored in the content tasks; this guide describes the layout and
workflow they follow.

`en/vol4-24-html-style.html` is the canonical page skeleton: copy it for every
new page, keep the `rel="home|up|prev|next"` links, the sidebar TOC, the
language bar, and the prev/contents/next footer.

## Scripts

### `build.sh` - assemble `dist/`

```bash
bash docs/sf/manuals/build.sh
```

Clears and recreates `dist/`, regenerates `en/search-data.js` by scanning every
`en/*.html` for its `<title>`, `<meta name="keywords">`, and first `<h1>`, then
copies the top-level pages and the whole `en/` tree into `dist/`. Idempotent and
offline; paths resolve relative to the script, so it runs from any working
directory. `dist/` is gitignored.

### `check.sh` - the validator

```bash
bash docs/sf/manuals/check.sh
```

Runs `check.py` (Python 3 standard library only, no network). It parses every
`*.html` under this directory (skipping `dist/`) and fails nonzero on the first
problem, naming the offending file. It checks, in order:

1. every local `href`/`src` resolves to an existing file;
2. every `en/` page carries `rel="home"`, `rel="up"`, `rel="prev"`, `rel="next"`;
3. the language bar links only to shipped languages (English);
4. `lang="en"` and the ISO-8859-1 charset `<meta>` are present;
5. the forbidden list (spec §6.5, below);
6. `en/doc.js` is at most 2048 bytes (`search-data.js` is search index data and
   is deliberately not size-capped);
7. the two stylesheets carry no CSS2/CSS3 tokens;
8. the figure placeholder ↔ `todo-figures-list.html` 1:1 match (spec §7);
9. the no-CSS baseline: with the stylesheet links stripped, each page still
   parses and contains its heading and prev/contents/next footer.

### `serve.sh` - local browsing

```bash
bash docs/sf/manuals/serve.sh        # http://127.0.0.1:8000/
bash docs/sf/manuals/serve.sh 8765   # http://127.0.0.1:8765/
```

Serves this directory with `python3 -m http.server`. The port is the first
argument (default 8000); the script works from any working directory. Python's
server binds all interfaces (its default `0.0.0.0`), so it is reachable on the
local network; the site itself never fetches anything external.

## Seed compiler (for example verification)

The examples are compiled with the compiler rebuilt from the committed seed,
**not** with `zig0`. Run this from the repository root; the relative `sf/src`
path is required because module basename-hash tokens are path-derived:

```bash
bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/manual_seed
# gate:   === [seed] Done: /tmp/manual_seed ===
# result: /tmp/manual_seed/zig1_5_clean   plus   /tmp/manual_seed/lib/
```

`zig1_5_clean` is the seed-built compiler; `lib/` is the standard library it
needs (kept binary-relative). Rebuild once per session and reuse it.

## Example verification workflow (spec §8)

Every content page's example must actually compile and run:

1. The example lives in `docs/sf/manuals/src/`, is compiled with the seed-built
   `zig1` and `gcc -m32`, and is actually executed.
2. The captured transcript is embedded in the page and matches the prose.
3. `-osw`/Win9x claims are run under `wine`.
4. Every syntax and builtin claim is cross-checked against
   `docs/reference/Language_Spec_Z98.md` and, for builtins, the compiler source.

Emit, build, and run:

```bash
/tmp/manual_seed/zig1_5_clean -o /tmp/manual_out docs/sf/manuals/src/<vol>/<prog>.z98
cd /tmp/manual_out && timeout 120 sh build_target.sh linux <prog>
```

`zig1 -o DIR` emits a self-contained C89 tree plus the companion
`build_target.sh`; the script compiles with `gcc -m32` and links the program.
Capture stdout, stderr, and the exit code as the transcript, then paste that
transcript into the page's `<pre>` block byte-for-byte. If the emitted script's
argument order or default name differs, follow `docs/sf/QUICK_REF.md`
("Multi-Module Build — self-contained output dir") verbatim.

## Figure / screenshot workflow (spec §7)

Every illustrative figure is one of two kinds:

- **Terminal transcript** - AI-produced, captured from a *real* `*nix` or
  `wine` run, rendered in `<pre>`.
- **Win9x screenshot** - a reserved era-styled placeholder box on the page
  (`Figure N — Win9x screenshot pending`) naming the exact claim it illustrates.
  The operator captures these on real Win9x after the plan.

A screenshot placeholder is a `<table class="placeholder">` box; each one needs
a matching row in `docs/sf/manuals/todo-figures-list.html` (columns: Page |
Figure | Caption | Claim | What to capture). `check.sh` enforces a 1:1 match by
figure number in both directions - no orphan figures in either the pages or the
list. `en/vol4-24-html-style.html` is excluded from the placeholder scan.

## HTML / CSS / JS restrictions (spec §6)

The site targets 1998 browsers - Netscape 4.x, Internet Explorer 4, and Lynx -
on Win9x and era Linux. These rules are checker-enforced where noted.

**HTML (§6.1).** HTML 4.0 Transitional doctype, authored in the conservative
HTML 3.2/4.0 intersection. No HTML5 structural elements (`<section>`,
`<article>`, `<nav>`, `<header>`, `<footer>`, `<main>`, `<figure>`). No `<div>`
for structure - layout uses `<table>`. Encoding is ISO-8859-1, declared as
`<meta http-equiv="Content-Type" content="text/html; charset=iso-8859-1">`.
Baseline appearance is carried by presentational attributes (`bgcolor`, `align`,
`width`, `border`, `cellpadding`, `cellspacing`, `valign`) and by `<font>`,
`<b>`, `<i>`, `<center>`. Every page carries `<link rel="home|up|prev|next">`, a
sidebar TOC, a language bar, and a prev/contents/next footer.

**CSS (§6.2).** CSS1 only, as external linked stylesheets: `z98.css` (screen)
and `z98-print.css` (print). No inline `<style>` blocks. CSS carries no meaning
and no layout - with both stylesheets removed the site must remain legible,
navigable, and correctly ordered (the mandatory no-CSS baseline). No CSS2/CSS3:
no `page-break`, no `position`, no `@media` beyond a `media="print"` link, no
web fonts, no `:hover`/`:nth`.

**JavaScript (§6.3).** One file, `en/doc.js`, at most 2048 bytes, with four
functions (`swap`, `tocToggle`, `doSearch`, `preload`). No `document.write`, no
browser sniffing, no external calls. Every feature degrades to working HTML;
JavaScript is optional.

**Assets (§6.4).** GIF only - no PNG, no SVG, no web fonts. Logo 240×48,
bullets 8×8, icons 16×16 (`note`, `tip`, `warn`, `caution`, `era`, `honest`),
buttons 88×24 plus `-over` rollover pairs, navrule 150×8. XBM alternates live
under `en/gfx/xbm/`.

**Forbidden list (§6.5, checker-enforced).** HTML5 structural tags; `<div>`
structure; PNG/SVG/web fonts; external resources (any `http://`/`https://` in
`href`/`src`); inline `<style>`; `<script src>` other than `doc.js` (and
`search-data.js` on `search.html`); more than 2048 bytes of JS; CSS2/CSS3
properties or selectors.

## Ground rules

- **Website only, with scoped compiler exceptions (Amendments 1–13).** No
  `sf/src/**`, `scripts/**`, fixture, or `release/seed/**` change - except the
  inserted compiler-fix tasks enumerated in the design spec §11 (Amendments
  1–13). Only those tasks may touch the compiler, run its gate battery, and
  rotate the seed. See
  `docs/superpowers/specs/2026-09-20-z98-manual-phase0-design.md` §11 and
  `docs/superpowers/plans/2026-09-20-z98-manual-phase0-plan.md`.
- All files live under `docs/sf/manuals/`; `dist/` is gitignored.
- English only in Phase 0; the language bar lists only shipped languages.
- Accuracy over volume. Never ship a claim that does not reproduce.
- Edit via `edit`/`fastedit` only; no bulk transforms.
- **STOP on a real compiler defect** found while verifying a claim - report it;
  do not fix `sf/src`, do not document around it.
