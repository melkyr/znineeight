# Design: Migration from logfmt Memory Store to Mnemoria

**Date:** 2026-06-27
**Status:** Draft

## Overview

Migrate ~2035 memory entries (1604 active + 431 deleted) from the current flat logfmt file format in `.opencode/memory/` to the mnemoria CLI tool for structured, searchable, git-friendly memory storage.

## Architecture

### Phased Approach

**Phase 1 — Validation (deletions first)**
- Process `deletions.logfmt` (431 entries) as a validation batch
- These are the least important entries — ideal for proving the pipeline
- Parse, convert, generate summaries via subagent, import into mnemonia
- Verify: stats, timeline order, search/ask queries

**Phase 2 — Active memories (reverse chronological)**
- Process 52 daily logfmt files from newest (2026-06-27) to oldest (2026-04-27)
- Newest-first ensures the "anchor" (latest entries) lands first in the store
- Each file dispatched to its own subagent

**Phase 3 — Documentation**
- Write AGENTS.md section with conventions and usage patterns

### Per-Subagent Pipeline

```
logfmt file → subagent reads file
  → parse each line (key=value, handles multi-line quoted content)
  → for each entry:
      - extract ts, type, scope, content, tags
      - convert timestamp to epoch ms
      - map logfmt type → mnemonia entry_type
      - embed scope in content as "[scope=<scope>]"
      - append tags as "Tags: t1, t2, t3"
      - assign agent_name: "legacy-zni" (active) / "legacy-deleted" (deletions)
      - generate a concise summary from content
      - emit JSON entry in mnemonia import format
  → write JSON array to /tmp/migrate-json/<filename>.json
```

### Final Import

```
merge all batch JSON files into one array
mnemoria --path <STORE_PATH> import <merged.json>
verify with: stats, timeline --limit 5, search --agent legacy-zni
```

## Type Mapping

| logfmt type | mnemonia type | Rationale |
|---|---|---|
| `learning` | `discovery` | "Something learned or observed" |
| `decision` | `decision` | Direct 1:1 |
| `plan` | `intent` | "A goal or intention to accomplish something" |
| `blocker` | `problem` | "A problem or issue encountered" |
| `pattern` | `pattern` | Direct 1:1 |
| `context` | `discovery` | Factual context = learned info |
| `preference` | `discovery` | Best fit in available types |

## Agent Naming

| Entry source | agent_name |
|---|---|
| Active entries (from `*.logfmt`) | `legacy-zni` |
| Deleted entries (from `deletions.logfmt`) | `legacy-deleted` |

## Field Conversion

| logfmt field | → mnemonia field | Conversion |
|---|---|---|
| `ts=2026-06-27T00:05:07.998Z` | `timestamp` | ISO 8601 → epoch ms |
| `type=learning` | `entry_type` | Type mapping table |
| `scope=semantic_analyzer` | embedded in `content` | Prefixed as `[scope=semantic_analyzer]` |
| `content="..."` | `content` | As-is, with scope/tags appended |
| `tags=t1,t2,t3` | embedded in `content` | Appended as `\nTags: t1, t2, t3` |
| n/a | `agent_name` | `legacy-zni` or `legacy-deleted` |
| n/a | `summary` | Generated by subagent LLM |
| n/a | `id` | New UUID v4 per entry |
| n/a | `embedding` | `null` |
| n/a | `checksum` | `0` |
| n/a | `prev_checksum` | `0` |

## Summary Generation

Each subagent is responsible for generating a concise summary for every entry in its assigned file. The summary should:
- Be 5-15 words capturing the essence of the entry
- Include the scope if relevant
- Be useful for future `mnemoria search` and `mnemoria ask` queries

## Store Location

The mnemonia store lives under `.opencode/memory/` alongside the logfmt files:
- Init: `mnemoria --path /workspace/znineeight/.opencode/memory init` (no name — creates `.../memory/mnemoria/` subdirectory with log.bin, manifest.json, mnemoria.lock)
- All subsequent commands use `--path /workspace/znineeight/.opencode/memory` (auto-resolves to the `mnemoria` subdir)

Note: The existing `mnemoria` subdirectory created during exploration must be removed before Phase 1 init.

## Verification

After each phase:
- `mnemoria stats` — verify entry count matches expected
- `mnemoria timeline --limit 10` — verify chronological order
- `mnemoria search --agent legacy-zni "keyword"` — verify search works
- `mnemoria ask --agent legacy-zni "question"` — verify RAG works

## Future Usage (for AGENTS.md)

Once migration is complete, agents should:
- Query legacy memories via `mnemoria search` and `mnemoria ask`
- Store new memories via `mnemoria add` under appropriate agent names
- Reference conventions in AGENTS.md
