# Z98 0.21.0 "Terephthalic Acid" Release — Design

> Status: OPERATOR-APPROVED (2026-10-29). Version 0.21.0, codename
> "Terephthalic Acid" (standard chemical spelling).

## 1. Purpose

Produce the first release after Z98 0.20.0 "Oxalic Acid": update the root
`RELEASENOTES.md`, `CHANGELOG.md`, and `README.md`; re-measure the compiler at
the current seed (v128); and stage a full 0.20.0-style artifact set. The
release covers the 1,864 commits from the 0.20.0 finalize commit (`ab49e167`)
to the release content freeze (`d609186c`), including the new syntax, the
standard-library growth, the debugger, the GUI/editor, and the Win9x fixes.

## 2. Operator decisions (binding)

1. Version **0.21.0**, codename **"Terephthalic Acid"**.
2. Full 0.20.0-style artifact staging, in a **new versioned directory**
   `release/staging/0.21.0/`; the existing 0.20.0 staging is left untouched.
3. Ship **zig1 + seed, no zig0**: `zig1_linux32`, `zig1_w32.exe`,
   `src_c_zig1_linux.tgz`, `src_c_zig1_w32.zip`, `zig1_src.tgz`,
   `zig1_src.zip`, the v128 seed `.tgz`/Win9x `.zip`, and `MANIFEST.txt`.
4. **Fresh v128 measurements**: no v123 figure may be presented as current.
5. The existing `[Unreleased]` block is unverified. It must be checked against
   commit history; content is rebuilt from evidence, not copied blindly.
6. `README.md` is bumped too (title, timeline, measurements, artifacts, and
   the stale 9-file std line).
7. No `sf/src` changes, no seed rotation, no tag, no push. Artifacts stay
   git-ignored and uncommitted.
8. Build/measurement runs are sequential (the `.zig1_*.tmp` CWD collision).
9. **Win9x binary truth.** The Win9x-class `zig1_w32.exe` is the
   **operator-built static-CRT binary** from the v128 seed zip's `win/`
   sources (`build_target_crt.bat` = MSVC `/MT`, or `build_owc_crt.bat` =
   OpenWatcom static CLIB). It embeds the C runtime and has **no
   `msvcrt.dll` dependency**; verify with `check_win9x_imports.sh … 9x`.
   The MinGW CRT build is a different artifact and **does require
   `msvcrt.dll`**; it is not the Win9x binary and is not shipped as one.
   A future packaging task will offer OWC/MSVC/MinGW variants for users to
   choose. Staging waits for the operator-built exe; every other artifact is
   prepared now.

## 4. Release content scope

The release notes and changelog summarize the work since 0.20.0 in these
groups (exact bullets are produced by the commit/seed audit in Task 1):

- **Self-hosting and seed**: seed bootstrap migration; zig0 retired from the
  build path and from the release; deterministic seed rebuild; v128 fixed
  point; Win9x seed zip.
- **Language and compiler**: mutable `for` capture (`|*item|`, `|*item, index|`,
  `|*_|`), sema-only `--check` mode, `error[3077]`/`error[3078]`, string-literal
  typing `*const [N]u8`, strict rejection of implicit enum-to-int and invalid
  Zig coercions, iterative lowering / C-stack depth fix, warning-clean
  emission at the origin, D11 declarations-before-statements, CRLF Windows
  batch files, MinGW fallback build scripts.
- **Standard library**: networking (`std_net`, `std_tcpip`), crypto/TLS
  (`std_crypto`, `std_cipher`, `std_ecc`, `std_asn1`, `std_x509`, `std_tls`),
  WireGuard, compression (`std_noise`, `std_lz4`, `std_zstd`), algorithms
  (`std_num`, `std_pathfind`, `std_physics`, `std_hpa`), `std_async`, and
  `std_fold`; the `lib/` payload is 50 files.
- **Debugger (Phase 2 P3)**: `z9dbg` with `-d`/`--debug` map emission, Linux
  ptrace + DWARF, Win9x backend with COFF line records and DWARF-in-PE, and
  the debugger tiers.
- **GUI/editor (Phase 2 P4)**: `std_gfx` (DirectDraw7 cell layer with a GDI
  16-color fallback), `gfx_demo`, `z9edit` (gap buffer, lexer/syntax colors,
  declared-identifier colors, bracket matching, undo, clipboard, themes
  white/solarized/dark, config file and F2 switching).
- **Win9x conformance**: 16-color GDI fallback, visible error dialogs, CRLF
  batch files, generated-script flag cleanup, warning-clean emission, MinGW
  CRT fallback scripts, and the Win9x import gate.
- **Windows binary note**: the prebuilt `zig1_w32.exe` in this release is the
  **operator-built static-CRT** binary (MSVC `/MT` or OpenWatcom static CLIB)
  and has **no `msvcrt.dll` dependency**; it must pass the `9x` import gate.
  The MinGW CRT build is a separate, optional artifact that does require
  `msvcrt.dll` and is not the Win9x binary. A future packaging task will offer
  OWC/MSVC/MinGW variants for users to choose. The release notes must state
  this split accurately.
- **Async/coroutines**: multi-module `__Z98Step_<f>`, `std.async` scheduler
  fixes, async documentation, and the suspending `export fn` driver.
- **Examples**: `z9play`, `z9torr`, `z9dbg`, `gfx_demo`, `z9edit`,
  `demo/wireguard_demo`, plus the upgraded showcases.
- **Fixes**: the verified post-0.20.0 corrections (Windows update-stream
  spill bug, debugger map durability, editor save/clipboard/Delete/minimize
  defects, theme compositing, D11, and others proven by the audit).

### Breaking changes / upgrade notes (must be documented)

- Implicit `enum` to `int` now requires `@enumToInt`; other previously
  tolerated invalid coercions are now `error[3000]`.
- String literals are typed `*const [N]u8`; code depending on the old bare
  pointer type may need an annotation or coercion.
- `-d`/`--debug` requires `--output-dir`.
- `zig0` is retired; the seed archive is the supported rebuild path.
- Generated Windows scripts no longer pass `/Za`, `/WX`, `/za`, or `/we`.

### Known issues (point to the open-only defects document)

Open entries after Phase 2.5: D3, D4, D5, D7.3, D8, D10, D12. The release
notes list them with one-line impact statements; no fixed defect is listed.

## 6. Measurement battery (fresh at v128)

All runs: fresh scratch dir; sequential; `/usr/bin/time -v`; median of 3;
record rc, wall, max RSS, and emitted `.c` count. Build via
`scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz <out>` with
`FIXED_POINT_MD5=18b4b10c8e014b486b648392d55ccdbe` (two-hop closure).

| Row | Workload |
|---|---|
| D-safe | `zig1 -s0 --dump-c89 --output-dir <out> sf/src/main.zig` (default `-fsafe`) |
| D-fast | same with `-ffast` (the self-build mode) |
| E | `sh build_target.sh linux zig1_next` in the D-fast output dir (gcc `-m32` compile+link) |
| Ladder | `-s0`..`-s6` (`-mm128` for `-s2+`) with `-ffast --markers --track-memory`; pool + RSS |
| Deep input | 120-term `+` chain and 300-deep blocks at `ulimit -s 1024` (rc/wall/RSS); optional evidence row |

Derive PII (~300-450 MHz) and PIII (~700-1000 MHz) estimates from the measured
wall times using the 0.20.0 method (clock scaling, 1.5-3x band for
memory-bound phases), and label them engineering estimates.
