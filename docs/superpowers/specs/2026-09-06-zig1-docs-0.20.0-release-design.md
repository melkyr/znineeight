# Zig1-Era Docs Restructure + Z98 0.20.0 "Oxalic Acid" Release — Design

> Status: OPERATOR-APPROVED (2026-09-06). Version 0.20.0 codename "Oxalic Acid" is a MAJOR release marking the self-hosted (zig1) era.

## 1. Purpose

The repository's entry documentation (root `README.md`, `RELEASENOTES.md`, `CHANGELOG.md`) still describes only the bootstrap (C++98, `zig0`) era, even though the project has completed the self-hosted milestone on branch `zig1_start` (1500 commits since the self-hosted milestone0 commit). A visitor to the branch today is pointed at the bootstrap as if it were current.

This design makes the SELF-HOSTED (`zig1`) era the immediately-visible front of the documentation, preserves the bootstrap README verbatim, records 0.20.0 release notes with a project timeline, and produces a real release artifact set (binaries + source archives) plus the measurements those documents must carry.

## 2. Operator Rulings (binding, verbatim-intent)

1. **README structure**: rename the current root `README.md` to `README_zig0_bootstrap.md` **inside the repo root folder**, byte-verbatim (content unchanged); write a NEW root `README.md` that is the self-hosted (`zig1`) main document, visible immediately.
2. **Release notes**: add NEW self-hosted entries **on top** of the existing `RELEASENOTES.md` / `CHANGELOG.md`; bootstrap entries (0.10.0→0.13.0) stay untouched below as history.
3. **Identity**: version **0.20.0** (major), codename **"Oxalic Acid"**; neutral-era title used alongside ("Self-Hosted Compiler (zig1)"), version number fixed as 0.20.0.
4. **Release notes content** must also document: elapsed time of this release; the project timeline (bootstrap/`zig0` started at repo creation; where zig1 development began = the `zig1_start` branch); the machine where the 0.20.0 binaries were built; minimum requirements (why re-measure wall-clock and RAM); a Pentium II / Pentium III wall-time estimate derived from the measured times on the build machine.
5. **README minimum requirements**: Linux/Windows rows for RUNNING vs BUILDING the self-hosted compiler. Explicitly note: zig1 runs within ~16 MB at `-s0`, but the gcc backend compiling/linking the emitted C (the "zig1_5"-style next-gen hop and any compiler-from-source build) can require ~80 MB — that must be stated so nobody assumes a 16 MB machine can build the compiler from source.
6. **Measurements**: produce fresh wall-clock AND peak-RAM measurements for: g++ generating zig0; zig0 generating zig1; zig1 `-s0` self-compiling; and gcc compiling+linking the emitted C89 (zig1 and every zig1_5-style hop).
7. **Artifacts (built to a git-ignored staging dir, NOT committed)**: `zig0_linux32`, `zig0_w32.exe`, `zig1_linux32`, `zig1_w32.exe`; generated-C source archives; `zig1_src` archive with a RELEASE_README stating it must be compiled with `zig0` (where + how). **No C++ bootstrap (`zig0`) source archive** in the release. No `zig0_src.tgz`.
8. **Archive formats**: win9x must unpack the win-facing archives → win-facing artifacts are **`.zip`**; linux-facing are **`.tgz`**. Final set: `src_c_zig1_w32.zip`, `src_c_zig1_linux.tgz`, `zig1_src.zip`, `zig1_src.tgz` (the two `zig1_src.*` contain identical content).
9. **Staging**: artifacts staged under a repo-root **git-ignored** `release/staging/` directory (add `.gitignore` entry). Operator attaches them to the release externally.

## 5. Measurement battery (produced during this plan)

Units: wall-clock seconds (h:mm:ss or s) + peak resident set (max RSS) via `/usr/bin/time -v` "Maximum resident set size (kbytes)"; each row measured 3× on the build machine, median reported. Rows:

| Row | Command being measured | Meaning |
|---|---|---|
| A | `g++ -std=c++98 -Isrc/include src/bootstrap/bootstrap_all.cpp -o zig0_tmp` | g++ generating the C++98 bootstrap |
| B | `zig0_tmp --dump-c89 --output-dir <W> sf/src/main.zig` | zig0 generating zig1's C89 |
| C | `gcc ...` compile+link of `<W>/*.c` + runtime → zig1 binary | gcc compiling/linking the emitted C (the ~80 MB row; identical for every `zig1_5`-style hop because emission is byte-identical) |
| D | `zig1 -s0 --dump-c89 --output-dir <W2> sf/src/main.zig` | zig1 self-compiling (the ~16 MB `-s0` row) |

Optional/cheap extras if time permits: gcc `-m32` compile of row C (linux32 binary build), and the mingw cross compile (row C for win32). These strengthen the min-requirements table; not mandatory.

The plan also captures (read-only) the git/dates timeline table above and the machine facts above verbatim into the docs — no reinvention.

## 6. PII/PIII time estimates

Framing: **clock-scaled table** with a stated methodology and uncertainty band. Given measured row wall-times T_m on the ~GHz-class build machine (single-core scaling assumption), estimate PII (representative ~300–450 MHz) and PIII (~700–1000 MHz) wall times as `T_p = T_m * f_m / f_p * k` where `k` is an uncertainty multiplier (default 1.0; note PII has no out-of-order execution and slower memory — state 1.5–3× additional for memory-bound phases, present a range). Rows mirror the measurement battery (A-D). Mark all as engineering estimates to be verified on the operator's real VM; do not present as measurements.
