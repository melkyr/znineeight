### Task TE: Win9x truth hotfix (release blocker, operator-authorized 2026-10-29)

**Why:** the promise "the Win9x compiler works" is false today. MSVC 6 and OpenWatcom reject the emitted C (`sf/src/main.zig:949` `var cdecl` → emitted `AstNode cdecl;`; both reserve `cdecl` as an extension keyword, so no `main_*.obj` exists in either folder); the generated `.bat` files are not `command.com`-safe (`Out of environment space`, `Syntax error`) and print `Built:` after a failed link. The zig0-era samples in `lin_bin/error/zigb/samples/` are the proven recipes (trivial batch, `*.obj` link, `/d_WIN32 /dWINVER=0x0410`, `-m32 -mconsole -static-libgcc`).

**Interfaces:**
- Consumes: the existing `z_<name>` escape (`nameManglerInit` keyword_set), the zig0 samples as the flag baseline.
- Produces: emitted C with no MS/OW-reserved identifiers; `command.com`-safe `.bat` files with real error stops; `gate_win_compat.sh`; seed **v129**; re-staged 0.21.0 artifacts. Milestone 3.5's D5/D10 must keep convention tokens (`Z98_STDCALL`, `"stdcall"`) raw — the mangler escapes source identifiers only.

**Decisions from the I-task (binding; full evidence in `.superpowers/sdd/2026-10-29-win9x-truth-hotfix/i-{1,2}-report.md`):**
- **Reserved list:** use the I-1 report's documented-reserved list verbatim. **Exclude bare `self`** (not reserved by VC6/MS C 6.0/OWC; 10,464 occurrences; including it moves all 8 pins). Add the Z98 runtime names (`Z98_*`, `zig_*`, `pal_*`, `zT_*`, `zF_*`, `zG_*`).
- **Escape point:** apply the `z_<name>` escape in `MintRaw` only (the local/param/field path, `c89_emit.zig:4040` from `MintLocal`); never to extern/export names or `nameManglerMangle` outputs. An `export fn` whose name is reserved keeps its ABI symbol raw (escape bypassed) and is flagged by `gate_win_compat.sh` — a documented edge, no fixture.
- **MinGW link:** use gcc `@z98_link.rsp`, not the explicit 1,145-char line. Root cause of the missing `.o`: `command.com` truncates long lines (~1 KiB); the `emit_support_51C949E9.o` token sits at bytes 994–1017. The object set is complete (local 52-`.o` relink via rsp = rc 0, PE32 i386).
- **command.com rules:** no `set`/`setlocal`/`%ERRORLEVEL%`/`&&`/`||`/`exit /b`/`goto :eof`; use `if errorlevel 1 goto z98_fail`; the fail path echoes `BUILD FAILED` and must never print `Built:`. Do not depend on `CHOICE.COM`; command.com cannot reliably set a process exit code — document that.
- **Script shape:** hardcode the output name `prog.exe` (samples style, no `%1` argument handling) in the CRT scripts; keep the 2 MiB stack; keep `winmm` unconditional and `wsock32` conditional (`scriptNetEmitted`).
- **Defines:** every TU needs `_WIN32` (OWC `/d_WIN32` — it does not predefine it; MSVC/MinGW do) plus `WINVER=0x0410`/`_WIN32_WINNT=0x0410` and `_CRT_SECURE_NO_WARNINGS`/`_CRT_NONSTDC_NO_DEPRECATE` per the samples.
- **8.3:** deferred. The failure is the line truncation, not long names; do not rename emitted files.
- **Tool-path override (operator quirk, 2026-10-29):** the MSVC script carries `set CL_EXE=cl` (default: bare `cl`, PATH lookup) and `set LINK_EXE=link`; every compile/link invocation uses `%CL_EXE%` / `%LINK_EXE%`, and the script's REM header tells the operator to edit them to absolute paths (space-free; use the 8.3 `PROGRA~1` form if the install path has spaces). Rationale: a second toolchain on the VM can shadow `cl.exe`/`link.exe`. One short `set` per variable is acceptable; if a `set` fails under env-space pressure, the `if errorlevel` check reports it instead of a false `Built:`.
- **Supersede:** the final v129 values are already written into Tasks 2/3 and Task TW2 — fixed point / binary `c1bb4c0e7cbb3d9f4a808491f1a5772d`, archive `af4a480f16e833a26f29210fec9a30b5`, Win9x zip `f6aa60cb05e7533b9f24afa1040ad0d3`, markers 3397/39012. Any remaining `18b4b10c…`/`1422368e…` value is stale.
