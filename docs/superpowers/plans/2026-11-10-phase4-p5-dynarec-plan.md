# Phase 4 P5 — SM83 Dynarec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full SM83 block dynarec with a 1 MiB executable code cache and interpreter fallback, integrated into `z9gb`, with full P2–P4 parity and measured numbers.

**Architecture:** The dynarec is Win32/x86 only. It translates a basic block into x86 machine code written by pure Z98 byte emitters, calls memory helpers for MMU access, and stores the generated block in a direct-mapped 1 MiB cache. The interpreter remains the oracle and executes any untranslated or unsupported path.

**Tech Stack:** Z98, `std_page`-free `VirtualAlloc` externs, x86 32-bit encoding, P2–P4 emulator core, MinGW/Wine gates.

**Spec:** `docs/superpowers/specs/2026-11-10-phase4-project1-gameboy-design.md`

## Global Constraints

- Pure Z98: no `asm`, intrinsics, C macros, `@cImport`, generics, methods, `anytype`, or `@alignCast`.
- Generated code is written as bytes; no inline assembly.
- Code cache is **1 MiB**, separate from the 1 MiB stack. It is never a stack array and never in static BSS.
- `VirtualAlloc(NULL, 1 MiB, MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE)`; `PAGE_EXECUTE_READWRITE = 0x40`. `VirtualFree(ptr, 0, MEM_RELEASE)`.
- If `VirtualAlloc` fails, dynarec is disabled and the interpreter runs — but a `--dynarec` run must say so loudly (`dynarec=disabled reason=...`) and the dynarec gate **fails** (or is a recorded SKIP for the host), never a silent interpreter-vs-interpreter PASS. The spec anti-goal is "falls back silently".
- **Anti-vacuous gates:** `--dynarec` runs print `dynarec=on blocks=<translated> executed=<translated-block calls> fallback=<interpreter instructions>` counters; gates assert `dynarec=on`, `blocks > 0`, and `executed > 0` before comparing outputs. A run where nothing translated cannot pass.
- **Translation scope:** dynarec translates ROM space (`0000-7FFF`) only. A PC in WRAM/HRAM/VRAM runs the interpreter (counted in `fallback`) — this removes RAM self-modifying-code invalidation entirely. Any cart-control write (`0000-7FFF` MBC registers) **ends the current block at the write** and invalidates the affected bank's cache entries. A block also ends before `LD B,B` (`0x40`), before `LD A,(DE)` (`0x1A`; DE may address a PPU register at runtime, so this dynamic PPU read is always interpreted with full PPU sync), and before a statically-known PPU-register read (`LDH A,(a8)` with `a8` in `0x40..0x4B`, or `LD A,(a16)` with `a16` in `0xFF40..0xFF4B`); a block starting at such an instruction is rejected so the interpreter executes it with full PPU sync. Dynamic PPU reads through `HL` remain helper-routed and are a documented limitation.
- **Safe direct memory set:** direct page-table access is allowed only for ROM reads, WRAM, echo, and HRAM at `addr >= 0xFF80`; cart RAM is direct only when the page base is not the disabled-RAM stub; ROM writes are MBC control writes and must go through the helper/dispatch path, never a direct store; `.rtc`, IO (`FF00-FF7F`), OAM, and VRAM use helpers. A block is not started while OAM DMA is active (the interpreter handles DMA); an IO write that starts DMA already ends the containing block.
- **Peripheral time sync:** `DynCtx.cycles` accumulates block cycles; every memory helper that touches IO/PPU/timer state (`FF00-FF7F`, `FF0F`, LY/STAT paths) first charges `ctx.cycles` to the bus (`busTick`) and zeroes it, so peripheral state is never read stale mid-block. The block epilogue charges any residual `ctx.cycles` through `busTick` exactly once, so pure-ALU blocks still advance timer/APU/serial/OAM-DMA; never double-tick a cycle already charged.
- **Interrupt early exit (required):** after every cycle-charging helper call, generated code tests the pending-interrupt condition (`cpu.ime` and `bus.if & bus.ie & 0x1F`) and jumps to the block epilogue when it holds. Without this, a long block defers interrupt dispatch up to 64 instructions and the `interrupt_time`/Mooneye latency gates drift versus the interpreter.
- **Frame-loop integration:** after a generated block returns, `emuRunFrame` must still perform the interpreter loop's `ppuSyncIn` / `ppuTick(dot_delta)` / `ppuSyncOut` sequence (`dot_delta = cycles/2` in double speed). The Mooneye `LD B,B` breakpoint is enabled by `emuSetMooneye`/`--mooneye` at the dispatch boundary; `LD B,B` is a block boundary, and `--mooneye` no longer forces the interpreter. Normal games without it treat `LD B,B` as a NOP. On non-Win32 hosts, `--dynarec` prints `dynarec=disabled reason=...`; the dynarec gate SKIPs/FAILs and never silently passes.
- After writing generated bytes, call `FlushInstructionCache` on the mapping (`FlushInstructionCache` is already whitelisted — `scripts/win32_cross/check_win9x_imports.sh:26` — and precedented in `sf/src/std_os.zig`, `examples/z98/z9dbg`).
- **Emitted-call ABI:** generated blocks are `extern "c"` cdecl `fn (*DynCtx) u32`; the stack is 4-byte aligned at every helper call boundary; `u8`/`u16` arguments travel in 32-bit stack slots/registers per cdecl; callee-saved `ebx/esi/edi/ebp` preserved. MinGW/Wine crash class — pin and test.
- Block max 4 KiB; direct-mapped 4,096-entry table keyed by `(effective_rom_bank, pc)`; per-bank invalidation on bank switches (including MBC1 mode-1 ROM0), per-slot replacement, full reset only when the 1 MiB arena is exhausted.
- All SM83 instructions are supported by translation or fall back to the interpreter. No silent wrong-code path. The BlockOp IR need not encode every opcode inline: an instruction with no BlockOp ends the block (or lowers to a helper call) and the interpreter executes it; a **256-opcode + full CB-page coverage test** proves each opcode's dynarec path matches the interpreter.
- CGB double-speed cycle unit (P4→P5 contract): `DynCtx.cycles` and block return values are CPU T-cycles at the current speed (2x per dot in double speed); peripherals charge via `busTick` in the same unit. PPU dots are never doubled.
- P2–P4 gates must pass with dynarec on and with dynarec off. Audio sample counts compare with the documented frame-boundary tolerance `16 * frames + 64`; exact equality is not required.
- No fixed speedup gate. Report measured wall/CPU/RSS and frames/sec.
- No seed rotation; P5 changes only the example and its tests.

## Review Focus

1. Code cache ownership and W^X: mapping size/address, release, no stack/BSS cache, no double free.
2. Block boundary correctness: PC, interrupts, HALT/STOP, memory helpers, and bank-switch invalidation.
3. Emitter correctness for flags, carries, signed offsets, and 16-bit pairs.
4. Interpreter fallback on every unsupported path; no silent divergence.
5. Parity: same framebuffer, serial log, saves, and audio counts with dynarec on/off.

- [ ] **Step 2: Emit prologue/epilogue with register-cached locals**

Ordinary ROM reads/RAM/stack accesses must not call a helper; DMA is excluded at block entry (Task 5).

- [ ] **Step 1: Write the failing test**
Tests: open maps 1 MiB; two blocks with different PCs get distinct entries; **two identical PCs in different ROM banks get distinct entries**; a bank switch invalidates only that bank's entries; a third block that fills the cache resets the arena and rewrites; close releases the mapping; double close is a no-op. Expected: fails.
- [ ] **Step 2: Implement cache**
Direct-mapped table keyed by **`(effective_rom_bank, pc)`** — keying by `pc` alone forces a full flush on every MBC switch, which is a performance killer in real games. Compute the effective bank for the address from the current cart mapping, including the MBC1 mode-1 ROM0 window (`cart.rom0_off`), not only the switchable-bank register. Each entry stores `bank`, `pc`, `code_off`, `len`, `valid`, plus a successor patch slot. Slot collision replaces that one entry (keep the old bytes until the arena is reset); bump allocation within the 1 MiB and reset the whole arena/table only when a block does not fit. On a bank-register write that changes the effective bank for an address range, invalidate all entries whose `pc` lies in that range, not merely entries matching the new bank: a ROMX change invalidates the old ROMX bank's entries (`pc >= 0x4000`); an MBC1 mode-1 ROM0 change invalidates **all** entries with `pc < 0x4000` because the old ROM0 mapping is no longer valid. The write still ends the containing block per the Global Constraints rule. Only ROM-space PCs (`0000-7FFF`) are ever translated.
- [ ] **Step 3: Implement trampoline**
Translate, copy bytes into the cache, call `FlushInstructionCache` on the written range, `@ptrCast(fn (*DynCtx) u32, code_ptr)`, call with a stack `DynCtx{cpu, bus, 0}` (4-byte aligned call boundary, cdecl 32-bit arg slots). Return cycles. Catch no errors; any invalid block flushes and falls back (counted in `fallback` statistics).
- [ ] **Step 4: Implement block chaining and call/return linking**
A block's fall-through/direct-jump exit ends in a per-entry patch slot instead of always returning to `emuRunFrame`. When the successor `(effective_bank, pc)` is already translated, patch a direct relative jump guarded by an effective-bank/PC check; otherwise jump to the shared C dispatch stub (which translates-or-interprets and then re-enters). **CALL/RET linking:** a translated `CALL` links to the translated callee the same way (guard on bank/PC) and keeps the return address on the emulated stack; a translated `RET` links through a one-entry return-address cache (`ret_target`/`ret_bank` per block) — on match, patch/jump direct to the translated return block; on miss, return to the dispatcher. This closes the biggest dispatch round-trip cost (RET/CALL per function call). Chained transitions must still count `executed` and must revalidate the bank before entry. Test: a hot two-block loop and a hot call/ret pair stay inside generated code (successor executions ≥ chained counter) with byte-identical interpreter output.
- [ ] **Step 5: Verify**
Expected: `dynarecEnabled=true` under Wine; generated blocks return exact interpreter cycles; chained and unchained paths produce identical results.
