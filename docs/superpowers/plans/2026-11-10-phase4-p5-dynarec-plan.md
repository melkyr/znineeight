# Phase 4 P5 — SM83 Dynarec Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a full SM83 block dynarec with a 1 MiB executable code cache and interpreter fallback, integrated into `z9gb`, with full P2–P4 parity and measured numbers.

**Architecture:** The dynarec is Win32/x86 only. It translates a basic block into x86 machine code written by pure Z98 byte emitters, calls memory helpers for MMU access, and stores the generated block in a direct-mapped 1 MiB cache. The interpreter remains the oracle and executes any untranslated or unsupported path.

**Tech Stack:** Z98, `std_page`-free `VirtualAlloc` externs, x86 32-bit encoding, P2–P4 emulator core, MinGW/Wine gates.

**Spec:** `docs/superpowers/specs/2026-11-10-phase4-project1-gameboy-design.md`

## Global Constraints

- Pure Z98: no `asm`, intrinsics, C macros, `@cImport`, generics, methods, `anytype`, or `@alignCast`.
- Generated code is written as bytes; no inline assembly.
- Code cache is **1 MiB**, separate from the 1 MiB stack. It is never a stack array and never in static BSS.
- `VirtualAlloc(NULL, 1 MiB, MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE)`; `PAGE_EXECUTE_READWRITE = 0x40`. `VirtualFree(ptr, 0, MEM_RELEASE)`.
- If `VirtualAlloc` fails, dynarec is disabled and the interpreter runs — but a `--dynarec` run must say so loudly (`dynarec=disabled reason=...`) and the dynarec gate **fails** (or is a recorded SKIP for the host), never a silent interpreter-vs-interpreter PASS. The spec anti-goal is "falls back silently".
- **Anti-vacuous gates:** `--dynarec` runs print `dynarec=on blocks=<translated> executed=<translated-block calls> fallback=<interpreter instructions>` counters; gates assert `dynarec=on`, `blocks > 0`, and `executed > 0` before comparing outputs. A run where nothing translated cannot pass.
- **Translation scope:** dynarec translates ROM space (`0000-7FFF`) only. A PC in WRAM/HRAM/VRAM runs the interpreter (counted in `fallback`) — this removes RAM self-modifying-code invalidation entirely. Any cart-control write (`0000-7FFF` MBC registers) **ends the current block at the write** and invalidates the affected bank's cache entries.
- **Peripheral time sync:** `DynCtx.cycles` accumulates block cycles; every memory helper that touches IO/PPU/timer state (`FF00-FF7F`, `FF0F`, LY/STAT paths) first charges `ctx.cycles` to the bus (`busTick`) and zeroes it, so peripheral state is never read stale mid-block.
- **Interrupt early exit (required):** after every cycle-charging helper call, generated code tests the pending-interrupt condition (`cpu.ime` and `bus.if & bus.ie & 0x1F`) and jumps to the block epilogue when it holds. Without this, a long block defers interrupt dispatch up to 64 instructions and the `interrupt_time`/Mooneye latency gates drift versus the interpreter.
- After writing generated bytes, call `FlushInstructionCache` on the mapping (`FlushInstructionCache` is already whitelisted — `scripts/win32_cross/check_win9x_imports.sh:26` — and precedented in `sf/src/std_os.zig`, `examples/z98/z9dbg`).
- **Emitted-call ABI:** generated blocks are `extern "c"` cdecl `fn (*DynCtx) u32`; the stack is 4-byte aligned at every helper call boundary; `u8`/`u16` arguments travel in 32-bit stack slots/registers per cdecl; callee-saved `ebx/esi/edi/ebp` preserved. MinGW/Wine crash class — pin and test.
- Block max 4 KiB; direct-mapped 4,096-entry table keyed by `(rom_bank, pc)`; per-bank invalidation on bank switches, per-slot replacement, full reset only when the 1 MiB arena is exhausted.
- All SM83 instructions are supported by translation or fall back to the interpreter. No silent wrong-code path. The BlockOp IR need not encode every opcode inline: an instruction with no BlockOp ends the block (or lowers to a helper call) and the interpreter executes it; a **256-opcode + full CB-page coverage test** proves each opcode's dynarec path matches the interpreter.
- CGB double-speed cycle unit (P4→P5 contract): `DynCtx.cycles` and block return values are CPU T-cycles at the current speed (2x per dot in double speed); peripherals charge via `busTick` in the same unit. PPU dots are never doubled.
- P2–P4 gates must pass with dynarec on and with dynarec off.
- No fixed speedup gate. Report measured wall/CPU/RSS and frames/sec.
- No seed rotation; P5 changes only the example and its tests.

## Review Focus

1. Code cache ownership and W^X: mapping size/address, release, no stack/BSS cache, no double free.
2. Block boundary correctness: PC, interrupts, HALT/STOP, memory helpers, and bank-switch invalidation.
3. Emitter correctness for flags, carries, signed offsets, and 16-bit pairs.
4. Interpreter fallback on every unsupported path; no silent divergence.
5. Parity: same framebuffer, serial log, saves, and audio counts with dynarec on/off.

**Interfaces:**

  - `pub const Emit = struct { code: [*]u8, len: usize, cap: usize };`

- [ ] **Step 1: Write the failing emitter test**
For each ALU opcode, emit a block that computes on `Cpu.a` and returns; compare CPU flags/registers to the interpreter. Expected: fails on missing emitter.
- [ ] **Step 2: Emit prologue/epilogue with register-cached locals**
Generated function is `fn (*DynCtx) u32` cdecl. **Register allocation (required, not optional):** cache the CPU pairs in callee-saved host registers across the block — `BC→ebx`, `DE→esi`, `HL→edi`, `SP→ebp`; `A` and `F` stay in `Cpu` memory (or `A` in a volatile reg reloaded after calls); `PC` is written back to `Cpu` at block end. Prologue loads the pairs from `DynCtx.cpu`; epilogue stores them and returns `cycles` in `eax`. Because helpers are cdecl, they preserve `ebx/esi/edi/ebp`, so the cached pairs survive helper calls without spills. Do not reload/store the whole CPU state per instruction (the memory-backed v1 is the slow fallback, not the target).
- [ ] **Step 3: Emit ALU/loads with an inline memory fast path**
Use `Cpu` field offsets from `@offsetOf(Cpu, ...)` for `A`/`F` and cached pairs for the rest. Implement `LD r,r'`, `LD r,n`, ALU A,r/n, INC/DEC, flags, 16-bit pair loads/stores. For memory operands, emit an **inline fast path**: load the 256-byte page entry from `bus->pages[addr >> 8]`, switch on `kind`, and do a direct `mov` from/to `base[addr & 0xFF]` for `rom0/romx/wram/cart_ram/echo/hram`. **HRAM and echo must be direct** — PUSH/POP/CALL/RET stack traffic lives in HRAM and a helper call per stack op is a serious tax. Call a helper only for `io/oam/vram` (VRAM carries the mode-3 lockout check). Ordinary ROM/RAM/stack accesses must not call a helper.
- [ ] **Step 4: Verify**
Expected: emitted block output matches interpreter for the test matrix under `-ffast` and `-fsafe`.

  - `pub fn dynarecRunBlock(d: *Dynarec, cpu: *Cpu, bus: *Bus) u32;`
  - `pub fn dynarecEnabled(d: *const Dynarec) bool;`

- [ ] **Step 1: Write the failing test**
Tests: open maps 1 MiB; two blocks with different PCs get distinct entries; **two identical PCs in different ROM banks get distinct entries**; a bank switch invalidates only that bank's entries; a third block that fills the cache resets the arena and rewrites; close releases the mapping; double close is a no-op. Expected: fails.
- [ ] **Step 2: Implement cache**
Direct-mapped table keyed by **`(rom_bank, pc)`** — keying by `pc` alone forces a full flush on every MBC switch, which is a performance killer in real games. Each entry stores `bank`, `pc`, `code_off`, `len`, `valid`, plus a successor patch slot. Slot collision replaces that one entry (keep the old bytes until the arena is reset); bump allocation within the 1 MiB and reset the whole arena/table only when a block does not fit. On a bank-register write, invalidate only entries whose `bank` matches the switched bank (the write still ends the containing block per the Global Constraints rule). Only ROM-space PCs (`0000-7FFF`) are ever translated.
- [ ] **Step 3: Implement trampoline**
Translate, copy bytes into the cache, call `FlushInstructionCache` on the written range, `@ptrCast(fn (*DynCtx) u32, code_ptr)`, call with a stack `DynCtx{cpu, bus, 0}` (4-byte aligned call boundary, cdecl 32-bit arg slots). Return cycles. Catch no errors; any invalid block flushes and falls back (counted in `fallback` statistics).
- [ ] **Step 4: Implement block chaining and call/return linking**
A block's fall-through/direct-jump exit ends in a per-entry patch slot instead of always returning to `emuRunFrame`. When the successor `(bank, pc)` is already translated, patch a direct relative jump guarded by a bank/PC check; otherwise jump to the shared C dispatch stub (which translates-or-interprets and then re-enters). **CALL/RET linking:** a translated `CALL` links to the translated callee the same way (guard on bank/PC) and keeps the return address on the emulated stack; a translated `RET` links through a one-entry return-address cache (`ret_target`/`ret_bank` per block) — on match, patch/jump direct to the translated return block; on miss, return to the dispatcher. This closes the biggest dispatch round-trip cost (RET/CALL per function call). Chained transitions must still count `executed` and must revalidate the bank before entry. Test: a hot two-block loop and a hot call/ret pair stay inside generated code (successor executions ≥ chained counter) with byte-identical interpreter output.
- [ ] **Step 5: Verify**
Expected: `dynarecEnabled=true` under Wine; generated blocks return exact interpreter cycles; chained and unchained paths produce identical results.
