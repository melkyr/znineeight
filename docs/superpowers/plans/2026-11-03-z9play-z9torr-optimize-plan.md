# z9play / z9torr runtime optimization Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a reusable split-radix (radix-2/4) complex FFT to the std lib, make the delivered z9play (OGG/Vorbis) decoder real-time on Pentium-II-class hardware using it, and cut z9torr's per-block accounting overhead — without changing decoded audio beyond the existing 2-LSB golden tolerance or the downloaded file's bytes.

**Architecture:** `sf/src/std_fft.zig` is a new standalone std module (direct import, deliberately NOT in the `std.zig` barrel) whose final core is an iterative Yavne/Sorensen split-radix (radix-2/4) FFT with precomputed bit-reversal and twiddle tables. z9play keeps only the Vorbis-specific pre/post-rotation wrapper in `examples/z98/z9play/dsp.zig` and calls `std_fft` for the butterflies; window/slope tables are cached per block shape. z9torr keeps its safe write-through disk model and replaces O(nblocks) rescans with O(1) counters. One seed rotation at the end.

**Tech Stack:** Z98 (`sf/src/std_fft.zig`), `examples/z98/z9play`, `examples/z98/z9torr`, compiled by `zig1` to C89 and built by the emitted `build_target.sh` / Windows `.bat` scripts.

**Spec:** None. This plan implements operator-approved performance work; the executable contracts are the committed goldens and tiers named below. The target environment (Pentium II, 1 MB stack, Win9x memory budget) comes from `docs/superpowers/specs/2026-10-24-phase2-gfx-editor-design.md` §12 and the examples' own limits.

## Global Constraints

- **No compiler change.** No change to `sf/src/main.zig`, `sf/src/c89_emit.zig`, `sf/src/lower.zig`, or any other compiler-pipeline file. `sf/src/std.zig` (the barrel) is **not** modified. The only `sf/src` addition is `sf/src/std_fft.zig`.
- **Direct import.** `std_fft` is imported as `@import("std_fft.zig")`; it is never re-exported from `std.zig`. This keeps the 8 pins unmoved.
- **Audio contract.** `z9play --pcm` / `--wav` output must stay within **max |delta| <= 2 LSB and RMS <= 0.1 LSB** of the committed `oggdec`/libvorbis golden PCM, and two runs must be byte-identical. The golden is generated by libvorbis; do not re-baseline it.
- **File contract.** `z9torr` must produce the same output-file bytes for the same torrent; existing resume/rehash behaviour is unchanged.
- **Release emission is `-ffast`.** Release build recipes in the example READMEs add `-ffast`; tests keep the default (safe) emission. Never remove `-fsafe` from a test.
- **Memory.** No new static buffers. z9play's tables/window cache come from the existing decoder arena (`examples/z98/z9play/main.zig:113`, 16 MiB). z9torr's static arenas stay exactly as they are (total 10 MiB; `g_work_buf` is 1 MiB and is reset per `onBlock`). Do not add per-peer or per-piece persistent buffers.
- **Stack.** Every new loop is iterative. No recursion. No large stack arrays (tables live in the arena). The examples must still run at 1 MB stack.
- **Build.** `bash scripts/seed/build_from_seed.sh release/seed/zig1-seed.tgz /tmp/<dir>`; then `mkdir -p out && /tmp/<dir>/zig1_5_clean -o out main.zig && sh out/build_target.sh linux prog`. Windows recipes keep `-I lib` (never `/lib`).
- Runs are sequential, in fresh `/tmp` directories (`.zig1_*.tmp` collision).
- **One seed rotation**, in Task 4. `scripts/seed/build_from_seed.sh` must copy `std_fft.zig` into `lib/` from Task 0 onward (needed by the Task 0 gate); `scripts/seed/archive_seed.sh` is updated only in Task 4. The trailing idiom tasks (T5-pre, 5–8) run after Task 4, touch only `examples/z98/`, and therefore need no further rotation and **no compiler battery** — their only validation is the two examples' tiers and the examples matrix.

## Review Focus

- **FFT correctness:** wrong bit-reversal, twiddle sign, or butterfly index yields wrong spectra. The std fixtures pin a delta impulse (flat spectrum) and forward+inverse identity; the z9play `dsp_test` additionally pins `imdctFft` against the exact `dsp.imdct` reference for every block size.
- **Long↔short block transitions and the priming frame:** cached tables/windows must be selected by the frame's actual `n` and `(blockflag, prev_wf, next_wf)`; the first frame (`prev_n == 0`) and tail carry must be unchanged.
- **z9torr block accounting:** duplicate, out-of-order, and malformed blocks must not corrupt the received/outstanding counters; a short write or seek failure must still surface as `DiskFailed`; resume rehash is unchanged.
- **Memory budget:** no static growth; 16 concurrent peers each keep exactly one claimed piece; the 1 MiB work arena is not held across messages.
- **Stack:** no recursion and no large stack locals in the new FFT/twiddle/window code; verified by a 1 MB-stack run.

## Explicit non-goals (decisions from the analysis)


- **No piece-buffered z9torr writes.** `peer.zig:152` documents that the 1 MiB work arena is reset per `onBlock` for read-back scratch, and up to 16 peers each hold one claimed piece (`scheduler.zig:13`, `MAX_RUNTIME_PEERS = 16`), with piece lengths up to 16 MiB (`torrent.zig:42`). A cross-message piece buffer would need up to 16 x piece_length and cannot fit the budget. Write-through + one read-back per piece is retained.
- **No barrel change** (`std.zig` untouched) so the pins do not move.
- **No pruned FFT, no SIMD, no whole-decoder fixed-point conversion, no FLAC algorithm change** (FLAC is already O(n); its clipping is correct saturation).
- **No new audio formats, no compiler change.**
- **No re-baseline of the z9play golden** (libvorbis-generated, 2-LSB tolerance).
