# X.509 — `std_x509`

| | |
|---|---|
| **Modules** | `std_x509` |
| **Layers** | `L5` — certificate parse, chain verification, pinned trust store |
| **Import (by path)** | `const std_x509 = @import("std_x509.zig");` |
| **Consumes** | `std_asn1` (DER), `std_crypto` (SHA-256/384/512, RSA verify), `std_ecc` (ECDSA verify), `std_arena` (trust-store copies) |

`std_x509` is not re-exported through `std`; import it by path.

## Module overview

`std_x509` parses DER certificates and verifies a leaf-to-anchor chain against a
caller-supplied trust store. Parsing is **allocation-free**: every returned slice
(subject, issuer, SPKI, TBS, signature, SAN entries) points into the caller's DER
buffer, which must outlive the `Cert`. Chain verification is **browser-grade and
policy-bound** — it is intentionally narrower than a general certificate library:

- **Path build** is exact DER `Name` equality: the current certificate's issuer
  must equal an anchor's subject or an intermediate's subject. Intermediates are
  considered in caller order; a candidate must have `basicConstraints` `cA`.
  Paths are bounded to `MAX_CHAIN` (8) certificates including the leaf.
- **Signatures** are verified over the exact `TBSCertificate` bytes:
  ECDSA P-256/SHA-256, ECDSA P-384/SHA-384, and RSA PKCS#1 v1.5 with
  SHA-256/384/512 and a modulus of at least 2048 bits. SHA-1, RSA-PSS, unknown
  algorithms, unsupported curves, and small RSA keys return
  `error.UnsupportedAlgorithm`.
- **Validity** is checked against the caller's `now_unix` for every certificate
  in the path and for the matched anchor. Boundaries are inclusive (`not_before
  <= now <= not_after`). `std_x509` never reads the clock.
- **Trust anchors are trusted by fiat**: the anchor's self-signature is not
  checked. Anchor subject, SPKI, and validity come from the loaded store.
- **Hostname matching uses SAN dNSName only**: case-insensitive exact match, or
  a wildcard only in the leftmost label (`*.example.com`). The wildcard matches
  exactly one non-empty label and never a dot. There is no CN fallback and no
  IP-address SAN support.

The trust-store binary format is pinned by the TLS design spec §5.5 and the
implementation is:

```
offset 0 : magic "Z98CA100" (8 bytes ASCII)
offset 8 : u32 anchor_count
offset 12: u32 file_total_len (must equal the byte length)
offset 16: anchor_count entries, each:
           u16 subject_der_len, u16 spki_der_len,
           u32 not_before, u32 not_after,
           subject_der bytes, spki_der bytes
```

All integers are little-endian. `subject_der` is the full DER `Name` TLV
(header included) and `spki_der` is the full `SubjectPublicKeyInfo` TLV. Raw
certificate DER is not retained. The shipped asset is
`examples/z98/demo/tls_demo/ca_store.bin`, generated by the
[`caconv`](../../../examples/z98/demo/tls_demo/caconv/README.md) tool from
Mozilla's `cacert.pem`.

## Quick start

Parse a certificate, then verify a chain against a loaded store.

```zig
const std = @import("std");
const std_x509 = @import("std_x509.zig");

var arena_buf: [65536]u8 = undefined;
var store_buf: [1024]u8 = undefined;

pub fn main() void {
    var cert: std_x509.Cert = undefined;
    std_x509.x509Parse(leaf_der, &cert) catch return;

    var arena = std.arena.init(arena_buf[0..]);
    var store: std_x509.TrustStore = undefined;
    std_x509.trustStoreLoad(&arena, store_buf[0..], &store) catch return;

    var inters: [1][]const u8 = undefined;
    inters[0] = intermediate_der;
    std_x509.x509VerifyChain(
        &arena, leaf_der, inters[0..], &store, "example.com", 1760000000,
    ) catch |err| {
        if (err == error.HostnameMismatch) return;
        return;
    };

    std.io.write("verified\n");
}
```

## API

### `X509Error`

**Purpose** — parse error set.

**Signature** — `pub const X509Error = error{Corrupt};`

**Errors** — `error.Corrupt` for any malformed/unsupported DER shape described
in `x509Parse`.

### `SAN_MAX`

**Purpose** — capacity of the fixed SAN array inside `Cert`.

**Signature** — `pub const SAN_MAX: usize = 32;`

**Gotchas** — a certificate with more than 32 dNSName entries fails parsing
with `error.Corrupt`; the parse API has no arena to grow a list.

### `SigAlg`

**Purpose** — signature-algorithm classification.

**Signature** — `pub const SigAlg = enum { ecdsa_sha256, ecdsa_sha384, rsa_pkcs1_sha256, rsa_pkcs1_sha384, rsa_pkcs1_sha512, rsa_pss, unknown };`

**Gotchas** — `rsa_pss` is recognized but reserved (not implemented);
SHA-1 and every other OID classify as `unknown`. Chain verification maps both
to `error.UnsupportedAlgorithm`.

### `PkAlg`

**Purpose** — subject-public-key classification.

**Signature** — `pub const PkAlg = enum { ec_p256, ec_p384, rsa, unknown };`

### `Cert`

**Purpose** — parsed certificate view, with all slices aliasing the input DER.

**Signature** — `pub const Cert = struct { subject: []const u8, issuer: []const u8, spki: []const u8, tbs: []const u8, sig: []const u8, sig_alg: SigAlg, pk_alg: PkAlg, not_before: i64, not_after: i64, is_ca: bool, san_dns: []const []const u8, san_storage: [SAN_MAX][]const u8, san_count: usize };`

**Fields**
- `subject` / `issuer` — full DER `Name` TLVs, headers included. Path building
  compares these raw bytes.
- `spki` — full DER `SubjectPublicKeyInfo` TLV.
- `tbs` — the exact `TBSCertificate` DER (header and body), used as the signed
  input.
- `sig` — signature BIT STRING octets with the unused-bits byte stripped.
- `sig_alg` / `pk_alg` — classifications from the certificate OIDs.
- `not_before` / `not_after` — Unix seconds. Only RFC 5280 DER forms are
  accepted: `UTCTime` `YYMMDDHHMMSSZ` (1950–2049) and `GeneralizedTime`
  `YYYYMMDDHHMMSSZ`.
- `is_ca` — `basicConstraints` `cA`; default `false`. A `pathLenConstraint` is
  not stored or enforced.
- `san_dns` — dNSName SAN entries in DER order. Entries point into
  `san_storage`, whose slices point into the input DER.
- `san_storage` / `san_count` — fixed backing array and count. Treat as
  implementation detail; use `san_dns`.

**Gotchas** — the DER buffer must outlive the `Cert`; `Cert` owns no memory.
The parser does not validate extension criticality or unknown extensions beyond
requiring well-formed extension values, and v1 certificates get no
`basicConstraints`/SAN data.

### `x509Parse`

**Purpose** — parses one DER certificate into `out`.

**When to use** — before inspecting a certificate or as the first stage of
manual chain handling. `x509VerifyChain` calls it internally.

**Signature** — `pub fn x509Parse(der: []const u8, out: *Cert) X509Error!void`

**Parameters**
- `der` — one complete DER certificate. Trailing bytes are rejected.
- `out` — caller-owned destination; overwritten on success.

**Returns** — nothing; fills `out`.

**Errors**
- `error.Corrupt` — malformed DER/TLV, trailing data, unsupported version
  shape, malformed time, a non-zero BIT STRING unused-bits count, malformed
  extension encoding, more than `SAN_MAX` dNSName entries, or any other
  structural violation.

**Example**
```zig
var cert: std_x509.Cert = undefined;
try std_x509.x509Parse(der, &cert);
std.io.write(cert.subject);
```

**Gotchas**
- It does **not** verify signatures, validity, or hostnames; those are
  `x509VerifyChain`'s job.
- Only dNSName SAN entries are extracted; email, URI, and IP SANs are ignored.
- The certificate's algorithm OIDs are classified rather than rejected; an
  unknown algorithm parses successfully as `.unknown`.

### `X509VerifyError`

**Purpose** — chain-verification error set (spec §5.4, exact).

**Signature** — `pub const X509VerifyError = error{ CertificateExpired, CertificateNotYetValid, UnknownIssuer, HostnameMismatch, BadSignature, ChainTooLong, Corrupt, UnsupportedAlgorithm };`

| Error | Meaning |
|---|---|
| `CertificateExpired` | `now_unix > not_after` for a path certificate or the anchor. |
| `CertificateNotYetValid` | `now_unix < not_before` for a path certificate or the anchor. |
| `UnknownIssuer` | no anchor subject or CA intermediate matches the current issuer. |
| `HostnameMismatch` | no leaf SAN dNSName matches the requested hostname. |
| `BadSignature` | a signature or its encoding is invalid (ECDSA `r`/`s` or RSA signature/SPKI parsing), or the cryptographic verify failed. |
| `ChainTooLong` | adding another intermediate would exceed `MAX_CHAIN`. |
| `Corrupt` | the leaf or an intermediate failed `x509Parse`. |
| `UnsupportedAlgorithm` | SHA-1/PSS/unknown signature, unsupported key algorithm/curve, unsupported key encoding, or RSA modulus below 2048 bits. |

### `TrustStoreError`

**Purpose** — trust-store load error set.

**Signature** — `pub const TrustStoreError = error{ Corrupt, OutOfMemory };`

**Errors** — `error.Corrupt` for a bad magic/count/total-length/entry layout;
`error.OutOfMemory` when the arena cannot hold an anchor array or a
subject/SPKI copy.

### `MAX_CHAIN`

**Purpose** — maximum path length in certificates including the leaf.

**Signature** — `pub const MAX_CHAIN: usize = 8;`

**Gotchas** — a chain that needs an eighth intermediate fails with
`error.ChainTooLong`; the leaf plus seven issuers is the accepted maximum.

### `TrustAnchor`

**Purpose** — one store entry.

**Signature** — `pub const TrustAnchor = struct { subject: []const u8, spki: []const u8, not_before: i64, not_after: i64 };`

**Gotchas** — slices are arena-owned copies made by `trustStoreLoad`; they stay
valid until the arena is reset.

### `TrustStore`

**Purpose** — a loaded anchor array.

**Signature** — `pub const TrustStore = struct { anchors: []TrustAnchor };`

### `trustStoreLoad`

**Purpose** — validates and decodes the pinned §5.5 binary store.

**When to use** — once at startup, with a caller arena sized for the anchor
copies; pass the resulting store to `x509VerifyChain`.

**Signature** — `pub fn trustStoreLoad(arena: *arena_mod.Arena, bytes: []const u8, out: *TrustStore) TrustStoreError!void`

**Parameters**
- `arena` — owns the anchor array plus every subject/SPKI copy.
- `bytes` — the complete store asset.
- `out` — caller-owned destination; `out.anchors` is set on success.

**Returns** — nothing; fills `out.anchors`.

**Errors**
- `error.Corrupt` — shorter than the 16-byte header, wrong magic, `total_len`
  not equal to `bytes.len`, an impossible count, a truncated entry header/body,
  a zero-length subject or SPKI, or trailing bytes after the declared entries.
- `error.OutOfMemory` — the arena cannot satisfy an allocation.

**Example**
```zig
var store: std_x509.TrustStore = undefined;
try std_x509.trustStoreLoad(&arena, store_bytes, &store);
```

**Gotchas**
- It copies only subject, SPKI, and validity; raw DER is discarded.
- `not_before`/`not_after` are unsigned `u32` Unix seconds in the format and are
  widened to `i64` in `TrustAnchor`.
- A failed load may leave arena allocations consumed; reset the arena if you
  retry.

### `x509VerifyChain`

**Purpose** — verifies a leaf-to-anchor path, signatures, validity windows, and
the hostname under the binding policy above.

**When to use** — TLS/HTTPS certificate validation with a caller-supplied trust
store and time. It is the only verification entry point.

**Signature** — `pub fn x509VerifyChain(arena: *arena_mod.Arena, leaf_der: []const u8, intermediates: []const []const u8, store: *TrustStore, hostname: []const u8, now_unix: i64) X509VerifyError!void`

**Parameters**
- `arena` — reserved for future path allocations; the current implementation
  does not allocate from it.
- `leaf_der` — the server/leaf certificate DER.
- `intermediates` — candidate intermediate certificates in caller preference
  order; each is parsed while building the path, and the first subject match
  with `is_ca` is selected.
- `store` — anchors from `trustStoreLoad`.
- `hostname` — requested DNS name; ASCII case-insensitive.
- `now_unix` — validation time in Unix seconds; the only time source.

**Returns** — nothing on success.

**Errors** — the exact `X509VerifyError` table above. In particular, a leaf or
intermediate that fails to parse is `error.Corrupt` (not `BadSignature`), and a
matched anchor whose validity has lapsed still fails
`CertificateExpired`/`CertificateNotYetValid`.

**Example**
```zig
std_x509.x509VerifyChain(
    &arena, leaf_der, inters[0..], &store, "www.example.com", now,
) catch |err| {
    switch (err) {
        error.HostnameMismatch => std.io.write("wrong name\n"),
        error.UnknownIssuer => std.io.write("no anchor\n"),
        else => std.io.write("reject\n"),
    }
    return;
};
```

**Gotchas**
- The anchor is trusted by fiat; its self-signature is never checked.
- There is no CRL, OCSP, revocation, or path-length-constraint processing.
- A wildcard certificate `*.example.com` does **not** match `example.com` or
  `a.b.example.com`.
- Intermediates beyond the first subject match are not tried if that first
  candidate later fails signature verification; supply a non-ambiguous pool or
  pre-select the intended issuer.
- `now_unix` at exactly `not_before` or `not_after` is accepted.
