## Implementation

- `sf/src/std_pathfind.zig` — `Point`, `Grid`, `jpsFind` (§6.7 verbatim).
  - 8-connected, cardinal 10 / diagonal 14, octile `10*max+4*min`.
  - Strict no-corner-cut diagonal legality; JPS successor rules follow the
    SoCS 2012 pruning (cardinal forced neighbors appear when the diagonal
    behind the perpendicular cell is blocked; diagonal moves have no forced
    neighbors because the side diagonals are dominated and the perpendicular
    cardinal would be an illegal corner cut).
  - Iterative `jump`/`jumpCardinal` (no recursion).
  - `std_heap` open set, key `(f<<32)|(~g & 0xffffffff)` (higher g on f ties).
  - g/parent/closed and the expanded path scratch are arena allocations; no
    frees, no hidden heap.
  - Full tile-by-tile path expansion from the jump-point parent chain: `out`
    gets up to `out.len/2` forward `(x,y)` pairs, an odd slot is ignored, and
    the return is the full tile count.
- Algorithm prototype (Python, /tmp only) validated against Dijkstra on 3000
  random 2x2..12x12 grids and 200 random 64x64 grids: all costs matched before
  porting.

## Perf note (report only; no timing gate)

The blueprint's "5× faster than A*" is not reproduced by these measurements.
Two algorithm-only benchmarks (grid built in-process, 200 runs, same gcc
`-m32 -std=c89 -O0` flags, 256×256, start (0,0) → goal (255,255)):

| grid | Z98 JPS | C89 A* | JPS/A* |
| --- | ---: | ---: | ---: |
| 22% obstacles (LCG, seed 12345) | 1.79 s | 0.55 s | 0.31× |
| fully open | 0.68 s | 0.013 s | 0.02× |

Why: on an open grid the octile heuristic is exact, so A* expands essentially
the optimal corridor, while JPS's diagonal scan probes both cardinal components
at each step (O(n²) scans). The earlier crosscheck-driver timing (2.29 s vs
ref 0.04 s on 200×128² vectors) was dominated by `std_stdin.readLine` doing one
syscall per input byte, so it is not an algorithm measurement. Cost agreement is
verified independently by the crosscheck.

## Concerns

- Static Python prototype lived only in `/tmp`; the committed evidence is the
  C89 A* crosscheck plus the fixture assertions.
- JPS is correct/optimal on all vectors but not faster than A* on the measured
  maps (see perf note); this is report-only per the brief.
- The path is materialised tile-by-tile via one extra arena scratch buffer of
  `count*8` bytes, so a large reachable path can raise `error.OutOfMemory` even
  when the search arrays fit. The contract permits OutOfMemory and does not
  bound `arena`; callers size the arena for grid + path scratch.
- Seed rotation itself (archive md5 / manifest) is the M5 closeout's job; this
  task only updated the copy lists and file-count text.
