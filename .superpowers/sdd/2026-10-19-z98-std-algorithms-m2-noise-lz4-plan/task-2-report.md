## Step 3 — decoder

Created `sf/src/std_lz4.zig`:

```
pub fn lz4DecompressBlock(src: []const u8, dst: []u8) !u32
```

Token split 4+4 literals/match; extension loops `15 -> +255...` for both
lengths with pre-add bounds checks; match offset little-endian u16 rejected when
zero or greater than current output; overlap-safe byte copy; every read/write is
bounds-checked before it happens; end conditions enforce final literals >= 5 and
last match start >= 12 bytes before output end (when a match exists). Error set
is exactly `error.Corrupt` / `error.OutputTooSmall`.

Installed the new module into the test compiler's sibling lib (the gate and
`run_crosscheck.sh` resolve std modules binary-relatively; the seed copy lists
now include it):

## Concerns

- The official LZ4 v1.9.4 safe decoder accepts some truncation points that
  violate the documented "last match starts at least 12 bytes before end"
  rule (e.g. `binary.block[0..730]` -> `ok 937`). The plan explicitly requires
  the strict rejection, so the module rejects it; that ambiguous truncation is
  kept only in the basic fixture (as an invalid block), not in the crosscheck
  corpus. All committed crosscheck vectors agree three ways.
- `ref.c` vendors the complete official LZ4 v1.9.4 `lz4.h` + `lz4.c` as one
  self-contained BSD-attributed translation unit so the ref build needs no
  extra header file or host runtime dependency.
