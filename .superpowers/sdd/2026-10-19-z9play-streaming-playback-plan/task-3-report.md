## 2. Implementation decisions

- **File-backed MSB reader.** `StreamBitReader` pulls one byte at a time from
  `BufferedFile` (`bufferedFileReadByte`) and consumes it MSB-first. No
  frame-sized buffer exists; `decodeStreamFrame` walks the header, subframes,
  and Rice residuals through this reader.
- **Frame-header CRC-8.** While the reader is in header mode it captures loaded
  bytes in a fixed `[64]u8` buffer; at the byte-aligned CRC point it compares
  the stored CRC-8 with the existing `crc8` over those bytes. Header capture is
  bounded and disabled before reading the CRC byte.
- **Frame CRC-16.** Read (16 bits) and discarded, as M8 allowed; decoding
  remains sequential.
- **Metadata bounded.** `openStream` reads `fLaC` and each 4-byte metadata
  header, parses `STREAMINFO` into a fixed `[34]u8`, and skips every other block
  through a fixed `[4096]u8` stack chunk. Block lengths are never allocated.
- **Fixed scratch.** `openStream` allocates exactly one
  `channels * max_block` i64 block, initialized once; `decodeStream` allocates
  nothing per frame.
- **EOF.** `decodeStream` reports 0 and sets `eof` when the logical file cursor
  reaches the cached file size; a short read inside a frame is `Truncated`.
- **Failure cleanup.** `openStream` closes the `BufferedFile` on metadata or
  scratch-allocation failure. `closeStream` delegates to the idempotent
  `bufferedFileClose`.
- **Minimal frontend switch.** `main.zig` `--wav`/interactive and `ui.zig`
  `playTrack` now hold `flac.StreamFlacDecoder`, open with
  `flac.openStream(..., path)`, and close on every existing failure/stop path
  (plus `stopPlayback` for the TUI). `readAll` and the OGG paths are untouched,
  as required for T4/T5.
- **Test oracle.** `flac_test.zig` keeps the byte-slice 3x check and adds a
  streaming 3x check. The first streaming pass is compared with the first
  byte-slice pass by frame count and SHA-1; both are compared with the raw PCM
  golden (`max_delta = 0`).

Because Z98 has no generics/`anytype`, the subframe/residual helpers are
duplicated for the stream reader; the exact-oracle test is what pins them
together.

## 4. Concerns

1. **Duplicated decode helpers** (`decodeResidual`/`decodeSubframe` and the
   stream copies) exist because Z98 has no generics. The exact-oracle test
   (frame count + SHA-1 + `max_delta 0`, 3x each path) is the guard; future
   FLAC tuning must keep both paths in sync.
2. **CRC-16 is read but not verified**, unchanged from M8 and explicitly
   allowed by the plan.
3. **`readAll` remains** in `main.zig`/`ui.zig`; T3 only switches the FLAC
   decoder. T4/T5 own removing whole-file reads and finishing OGG streaming.
4. **Frontend file handles** are closed on all inspected FLAC failure/stop
   paths, but T4/T5 will restructure those paths; the TUI `stopPlayback` close
   must stay in front of the `g_dec_arena` reset.
5. **Win9x** uses the same `std_file` calls as before; PE/import checks pass,
   but real Win98/Me hardware verification remains operator-pending.
